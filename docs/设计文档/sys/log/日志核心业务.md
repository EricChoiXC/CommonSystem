# 日志核心业务设计

## 权限

| 权限名 | 中文名 | 描述 |
| --- | --- | --- |
| SYS_LOG_ADMIN | 日志管理员 | 拥有查看全部日志（操作日志、登录日志）的后台管理权限 |

## 核心功能

### 通用操作日志

#### 定位与范围

为全系统提供统一的「操作日志 / 审计日志」能力，替代各业务模块自行建表、自行写入的模式（如附件模块 `sys_att_operation` 仅覆盖附件场景，且与业务同事务同步写入）。

记录「谁、在什么时间、对哪个业务文档、执行了什么动作、结果如何」，用于业务追溯与安全审计。

覆盖动作：保存、更新、删除、提交、导入、导出、批量操作、权限变更、修改密码等写类动作；

查询类动作（load / list）默认不记录，避免日志量爆炸；个别敏感查询（如导出）按业务需要记录。

#### 接入方式

两种方式可混用：

1. **公共 Service 调用**：业务 Service 注入 `LogService`，在关键业务节点调用 `record(...)`，适用于需要携带自定义业务描述（备注、变更内容）的场景；
2. **注解 + AOP**：在 Service 方法上标注 `@OperationLog(module=..., action=...)`，由切面在方法执行成功后自动采集入参、执行人、结果并落库，适用于 save / update / delete 等统一动作，侵入最小。

#### 记录规则

- **操作人**：从 `CurrentUserHolder` 获取当前用户 ID；姓名从用户信息冗余快照写入（日志是历史事实，用户后续改名或删除不影响历史记录，不依赖联表查询）；
- **业务文档 ID**：单据类操作遵循接口规范必须携带文档 ID，作为 `field_business_id` 记录，便于按单据追溯全链路操作；
- **敏感信息**：`field_password` 等敏感字段不写入变更内容与备注；`field_before` / `field_after` 写入前按字段级脱敏处理；
- **结果**：以业务执行结果为准，成功记录 `SUCCESS`；业务异常由全局异常处理兜底，失败记录 `FAILED` 及失败原因。

#### 事务与性能

- **事务隔离**：日志落库与主业务事务隔离——业务提交成功（`@TransactionalEventListener(AFTER_COMMIT)`）后异步落库，日志写入失败不影响主业务流程（区别于附件模块与业务同事务同步写日志的做法）；
- **只增流水**：日志表不允许更新、删除（运营清理除外），无并发写冲突；批量异步写入，降低日志 IO 对业务线程的影响。

### 登录与安全日志

#### 登录日志

记录登录成功、登录失败、登出行为：

- **登录成功**：记录用户 ID、登录名、IP、UA、操作时间；
- **登录失败**：记录登录名（此时可能无对应用户，`field_user_id` 为空）、失败原因（账号不存在 / 密码错误 / 账号禁用等）、IP、UA、操作时间；
- 失败原因由登录流程返回，不记录密码等敏感信息。

#### 安全审计

- **鉴权拒绝**：resolver 返回 FORBIDDEN 时，由统一鉴权入口记录「当前用户、接口动作、文档 ID、拒绝原因」，用于定位越权尝试；
- **会话失效**：UNAUTHORIZED 可按需记录为提示性日志，默认不记录（登录态自然过期不视为安全事件）。

### 后台日志列表

仅 `SYS_LOG_ADMIN` 权限用户可见「后台操作 → 日志管理」菜单，页面结构遵循列表查询页面三段式规范（筛选条件区 → 工具区 → 列表区）：

- **日志类型切换**：操作日志 / 登录日志，默认操作日志，不可「全部」；
- **筛选区**：日志类型、模块、动作、操作人（姓名 / 登录名）、业务文档 ID、结果、操作时间范围；
- **排序区**：操作时间（默认降序）；
- **列表区**：操作时间、操作人、模块、动作、业务文档 ID、结果、IP、备注；操作列提供「详情」查看失败原因与变更内容（before / after）；
- 日志只读，不提供删除、编辑；导出按需另议。

### 日志清理与归档

日志为流水表，数据量随时间线性增长，需配套清理策略：

- 默认保留最近 12 个月在线可查；
- 超期数据由运维定期归档 / 清理，`field_operate_time` 建索引支撑按时间清理；
- 本期仅约定策略，定时归档任务后续按需补充。

### 接口约定（摘要）

- 日志写入为内部服务（`LogService`），不直接暴露给前端写日志；
- 查询接口：
  - `POST /backend/sys/log/operation/list`：分页查询，`field_log_type` 区分操作日志 / 登录日志；
  - `GET /backend/sys/log/operation/load?fieldId=${id}`：日志详情；
- 鉴权：均需 `SYS_LOG_ADMIN` 权限，走 `sys.log` 模块 resolver，遵循「接口 + 文档 ID」鉴权规范（列表查询以日志 ID 为文档 ID 预判，详情接口以目标日志 ID 为文档 ID 最终鉴权）。
