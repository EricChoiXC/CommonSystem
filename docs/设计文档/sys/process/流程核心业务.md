### 流程模板

#### `process_template` 配置项 和 field_model_name 取值

`process_template` 配置段由**各业务模块在自身 application.yml 中自行维护**（流程模块按 `classpath*:properties/**/application.yml` 通配扫描聚合，如 `properties/erp/project/application.yml`、`properties/erp/contract/application.yml`），二级配置项即为 `sys_process_template.field_model_name` 值，`process_template.${fieldModelName}.name` 值即为前端 `模板管理` 页面上，模板分类列表项的显示名， `process_template.${fieldModelName}.class` 为该分类的流程对应的文档实体类，`process_template.${fieldModelName}.ops` 为该分类可配置的「操作标识」字典（key=操作标识，value=中文描述，可为空，见下方「审批中审批人特定操作业务」）；`process_template.${fieldModelName}.fields` 为该分类文档实体字段字典（key=文档实体字段属性名，value=中文描述），供节点「审批来源=表单字段」选择审批人字段（见下方「审批人配置」）；多个 yml 重复定义同一分类 key 时启动报错（fail-fast）。配置示例：

```yaml
# properties/erp/project/application.yml（项目管理模块自行维护）
process_template:
  erp_project: # 流程模板的 field_model_name
    name: "项目" # 前端显示名
    class: "com.project.backend.erp.project.model.ErpProjectMain" # 流程对应的文档实体类
    desc: "..." # 描述
    ops: # 审批中业务权限
      attachment: "允许修改附件" # 业务权限码值和中文描述
    fields: # 文档实体字段字典（key=实体类字段属性名，value=中文描述），供节点「审批来源=表单字段」选择审批人字段
      fieldCreator: "创建人" # 实体类上的字段属性名和中文描述
```

#### 页面信息

`模板管理` 页面：

左侧从各模块 application.yml 聚合的 `process_template` 为配置信息列表结果展示，选中项作为 `sys_process_template.field_model_name` 字段值固定放入查询；

右侧为列表查询页面：

筛选区：模板名称、模板编号、使用启用

排序区：创建时间、更新时间

按扭区：新建（限 `SYS_PROCESS_TEMPLATE_ADMIN` 级权限用户）

列表显示：模板名称、模板编号、使用启用、创建时间、更新时间、版本号、操作

操作列按钮：编辑（限 `SYS_PROCESS_TEMPLATE_ADMIN` 级权限用户）、详情（限 `SYS_PROCESS_TEMPLATE_VIEWER` 级权限用户）、启停用（限 `SYS_PROCESS_TEMPLATE_ADMIN` 级权限用户）

`模板详情/模板编辑` 页面：

顶部显示操作按钮：保存、编辑、启停用、关闭

上部按序显示字段：模板名称、模板编号、备注

下部显示节点配置列表：节点编号、节点名称、节点类型、节点配置（按钮，点击弹出多标签配置弹窗，配置项保存在 `sys_process_template_node.field_node_config` 中）；其中固定[1 开始节点 START]，[2 草稿节点 DRAFT]，[3 结束节点 END]三个固定节点，且没有节点配置；结束节点编号随节点的创建往后顺延；

节点配置弹窗采用多标签结构，配置项统一保存在 `sys_process_template_node.field_node_config` 中：

- **基础** 标签：
  - 审批来源：组织架构 / 表单字段，默认组织架构；
  - 审批人：`审批来源=组织架构` 时为地址本，多选，限岗位+用户；`审批来源=表单字段` 时为从分类 `process_template.${fieldModelName}.fields` 字典中选择的字段，单选，见下方「审批人配置」；
  - 审批模式：单签 / 会审，默认单签；
  - 节点触发：固定 / 条件判断；
  - 触发条件：不可编辑输入框 + 「编辑」按钮；点击「编辑」打开独立的公式编辑弹窗填写判断公式，确认后回填到输入框，见下方「触发条件编辑弹窗」；
  - 是否允许自动跳过：跟随系统 / 是 / 否；
  - 是否允许连续跳过：跟随系统 / 是 / 否；
- **审批权限** 标签：
  - 操作标识：开关列表，按分类 `process_template.${fieldModelName}.ops` 字典动态渲染，见「审批中审批人特定操作业务」；

#### 审批人配置

审批人配置分「审批来源」与「来源明细」两步，统一保存在 `sys_process_template_node.field_node_config`：

1. **审批来源 `handlerSource`**：`org`=组织架构（默认）/ `field`=表单字段；

2. **来源明细**：
   - `审批来源=组织架构`：配置 `handlerIds`/`handlerNames`，为地址本多选结果（限岗位+用户），即固定的审批人；
   - `审批来源=表单字段`：配置 `handlerField`，从分类 `process_template.${fieldModelName}.fields` 字典（key=文档实体字段属性名，value=中文描述）中单选一个字段，审批时以该字段值为准动态确定审批人；

3. **运行期解析**：
   - `审批来源=组织架构`：直接取配置的 `handlerIds` 作为审批人；
   - `审批来源=表单字段`：读取流程实例对应文档实体 `handlerField` 字段值，从字段值中解析出具体组织架构（岗位/用户）作为审批人；
   - 解析结果为空（`handlerField` 未配置、字段值为空或无法解析出组织架构）时，按「实际处理人计算结果为空时，跳过该节点」处理；
   - `handlerField` 必须是文档实体类中存在的字段（与「触发条件的判断规则」一致），否则配置无效；
   - 流程实例创建时节点配置原样复制到 `sys_process_example_node.field_node_config`，运行期按实例节点配置解析，保证按流程创建时的版本配置执行。

#### 触发条件的判断规则

1. 必须是判断公式

2. 使用占位符(`${field}`)的字段，必须是文档实体类中存在的字段

#### 触发条件编辑弹窗

节点配置「基础」标签中的「触发条件」为不可编辑输入框 + 「编辑」按钮，只做展示与承接回填；点击「编辑」打开独立的公式编辑弹窗，弹窗左右分栏：

- **左侧**为可点选内容区，分两块：
  - **fields**：当前分类文档实体字段项（取自 `process_template.${fieldModelName}.fields` 字典，key=字段属性名，value=中文描述），点击后以 `${字段属性名}` 占位符形式插入；
  - **公式计算符**：判断公式可用的运算符（如 `+ - * / ( ) > >= < <= == != && || !` 等），点击后以对应符号插入；
- **右侧**为可编辑文本域，显示当前公式内容，支持直接键盘输入公式；
- 左侧点选某项时，将对应文本插入到右侧文本域的**当前光标处**（若当前有选中文本则替换选中内容），插入后光标移动到插入内容之后；
- 点击「确认」将右侧文本回填到「基础」标签的「触发条件」输入框并关闭弹窗，「取消」则放弃本次编辑；
- 回填后的触发条件仍须满足上方「触发条件的判断规则」。

#### 模板维护

更新模板时，将历史版本的模板和所有节点字段信息，统一整理保存到 `sys_process_template_histofy.field_content` 字段中；现版本信息保存到 `sys_process_template` 和 `sys_process_template_node` 表中

#### 默认模板（field_default）

`sys_process_template.field_default` 标识该分类的默认流程模板（`bit`，默认 0）：

- **每分类最多一个默认模板**：模板列表页提供「置为默认」按钮（限 `SYS_PROCESS_TEMPLATE_ADMIN`），置为默认时**替换**同分类现有默认模板（先取消旧默认再设置新默认，数据库生成列唯一索引兜底）；新建/编辑模板勾选「默认」同样按替换语义处理；
- 停用模板不可置为默认；默认模板被停用后该分类无默认模板（允许，流程启动时按「无默认模板启动失败」兜底提示）；
- 存量数据迁移：每个分类最新创建的启用模板自动置为默认（保持原「取分类最新启用模板」语义）；
- 流程启动未指定模板时使用默认模板，**无默认模板则流程启动失败**（见「流程创建和提交」）。

### 流程实例和流转

#### `流程实例`页面

`SYS_PROCESS_EXAMPLE_VIEWER` 级权限用户可访问该页面，该页面为 `sys_process_example` 的列表查询页面：

筛选区：流程名称、流程编号、所属模块、发起人、创建时间、流程状态

排序区：创建时间

按扭区：无

列表显示：流程名称、流程编号、所属模块、发起人、创建时间、当前节点、流程状态、操作

操作列：详情（限 `SYS_PROCESS_EXAMPLE_VIEWER` 级权限用户）

#### `流程实例详情` 页面

显示流程实例、流程实例节点、工作项、审批记录信息；

仅 `SYS_PROCESS_EXAMPLE_ADMIN` 级权限用户显示 `特权操作` 按钮；

特权操作弹窗选择：操作类型（跳转/终审通过/作废/暂停/恢复）、跳转节点（包含起草节点和审批节点）、意见（必填）；提交后生成 `sys_process_audit_note` 记录并进行跳转；

#### 流程流转公共规范

1. 进入流程节点时，为每个审批人创建一个工作项，包含跳过的处理人；

2. 节点实际处理人按节点「审批来源」解析：`组织架构` 时直接取配置的审批人，`表单字段` 时读取文档实体对应字段值并从中解析出组织架构（岗位/用户）作为审批人；实际处理人计算结果为空时，跳过该节点；

3. 审批类型包括单签和会审：单签时，只一个审批人通过即通过该节点，其他审批人的工作项转为 `FINISH`；会审时，需所有审批人都通过才通过该节点；

4. 有一个审批人选择驳回操作，即将该节点其他审批人工作项转为 `FINISH`，流程转为 `RETURN`，固定驳回到起草节点；驳回操作需要选择 `重新提交后流转方式`，选择 `重新流转` 或 `转回本节点`，该内容保存在工作项的 `field_config` 字段中；

5. 节点审批人跳过按照公共配置和具体节点配置的 `是否自动跳过重复审批人`，`自动跳过重复审批人是否包含起草人` 和 `是否连续跳过`，根据审批人是否是上一有效节点的审批人/起草人，自动创建出办结的工作项和 `AUTO_PASS` 的审批记录；

6. 节点的配置信息 `是否连续跳过` 为否，表示在上一有效节点是自动跳过的处理人，在本节点需要进行审批；

#### 流程审批面板

项目前端提供可嵌入审批组件，供插入业务文档页面中进行审批操作，提供除 `起草保存`，`起草提交` 的审批处理，面板不提供接口调用，而是由各业务文档获取面板内填写信息提交给各自模块的后端上，再提交给流程模块做提交操作；

审批面板内包含3块卡片内容：审批，审批记录，流程

1. 审批：仅当前用户拥有可执行的审批操作时可见，选择审批操作，填写审批体检并提交

2. 审批记录：列表显示当前流程的 `sys_process_audit_note` 审批记录；

3. 流程：列表显示当前流程的 `sys_process_node` 节点信息；

面板数据（`panel` 接口响应）额外提供 `nodeOps`：当前用户在该流程当前节点可操作的操作标识集合，供业务文档页控制表单字段/附件等业务操作的可编辑性（见下方「审批中审批人特定操作业务」）；

#### 审批中审批人特定操作业务

用于实现「只允许流程中特定节点审批人，才允许填写某些表单数据/执行某些业务操作」的场景，配置与判定共三层：

1. **分类操作标识字典**：在所属模块 application.yml 的 `process_template.${fieldModelName}.ops` 下按 key:value 配置（key=操作标识，value=中文描述）。当前已配置样例：

   | fieldModelName | ops key | 中文描述 |
   | --- | --- | --- |
   | erp_project / erp_project_change / erp_contract / erp_contract_change | attachment | 允许修改附件 |

2. **节点开关**：模板编辑时，审批节点「节点配置」弹窗「审批权限」标签按分类 `ops` 字典渲染操作标识开关列表；开关状态保存在 `sys_process_template_node.field_node_config`（JSON，`ops` 字段，仅保留开启项）。节点未配置或旧模板（`field_node_config` 无 `ops` 字段）视为未开启任何操作标识——**默认不允许**。

3. **审批中判定与业务接入**：
   - 流程实例创建时将模板节点配置原样复制到 `sys_process_example_node.field_node_config`，审批时直接读实例节点配置；
   - 流程处于 `PROCESSING` 时，仅当前审批节点且持有待处理工作项的审批人，可获得该节点开启的操作标识集合（单签/会审均适用）；
   - 流程实例不存在或非审批中（DRAFT/RETURN 等）无流程约束，按业务自身规则放行（如起草人编辑阶段）；
   - 各业务模块通过 `SysProcessExampleService.resolveNodeOps(modelName, modelId)` 获取当前用户在当前节点的操作标识集合做后端最终校验，前端经 `panel.nodeOps` 控制可编辑性；
   - 附件模块（`sys_att`）已按 `attachment` 操作标识约束 `upload`/`delete`：审批中单据仅当前节点审批人且节点开启「允许修改附件」时可上传/删除附件，其余场景拒绝；`adminDelete`（后台管理删除）不受此约束。

#### 流程创建和提交

由实例所属模块负责创建，保存操作时保存流程实例为 `DRAFT` 状态；提交操作时流程实例状态转为 `PROCESSING` 状态并开始向下流转，生成一条 `DRAFT_SUBMIT` 审批记录；

**启动模板选择规则**：业务单据可自行决定是否添加 `field_process_template_id` 字段（如合同 `erp_contract_main`、项目 `erp_project_main` 已接入）用于选择运行的流程模板：

- 单据指定 `field_process_template_id`：必须存在、启用且属于该模板分类，否则启动失败；
- 单据未指定（字段为空或未接入）：使用该分类默认模板（`field_default=1` 且启用），**分类下无默认模板则流程启动失败**，提示先到「流程管理-模板管理」设置默认模板。

#### 起草人收回

流程处于 `PROCESSING` 状态时，创建人可收回该流程；回收后流程状态转为 `DRAFT`，节点转回起草节点，生成一条 `DRAFTER_BACK` 审批记录；

#### 起草人废弃

流程处于 `DRAFT` 或 `RETURN` 时，创建人可废弃该流程；废弃后流程状态转为 `ABANDON`，节点转入结束节点，生成一条 `DRAFTER_ABANDON` 审批记录；

#### 审批人通过

流程处于 `PROCESSING` 状态时，当前审批人可通过该节点审批，生成一条 `HANDLER_PASS` 审批记录，单签或会签全员通过后，进入下一节点；

#### 审批人驳回

流程处于 `PROCESSING` 状态时，当前审批人可驳回该节点，并选择 `重新流转` 或 `转回本节点`，生成一条 `HANDLER_RETURN` 审批记录，流程节点转入起草节点，流程状态转为 `RETURN`；

#### 管理员跳转

流程处于 `PROCESSING`, `RETURN` 状态时，管理员可在文档审批或流程详情页面中进行跳转操作，选择跳转节点（限审批节点或起草节点），生成一条 `ADMIN_JUMP` 审批记录，流程状态转为 `PROCESSING` 或 `RETURN`；

#### 管理员暂停

流程处于 `PROCESSING` 状态时，管理员可在文档审批或流程详情页面中进行暂停操作，生成一条 `ADMIN_PAUSE` 审批记录，流程状态，工作项状态转为 `PAUSE`；期间流程无法被起草人和当前审批人进行流程操作；

#### 管理员恢复

流程处于 `PAUSE` 状态时，管理员可在文档审批或流程详情页面中进行恢复操作，生成一条 `ADMIN_RESUME` 审批记录，流程状态，工作项状态转为 `PROCESSING`；

#### 管理员作废

流程处于 `PROCESSING`，`RETURN`，`DRAFT`，`PAUSE` 状态时，管理员可在文档审批或流程详情页面中进行废弃操作，生成一条 `ADMIN_ABANDON` 审批记录，流程状态转为 `ABANDON`，节点转入结束节点；

#### 管理员办结

流程处于 `PROCESSING`，`RETURN`，`PAUSE` 状态时，管理员可在文档审批或流程详情页面中进行终审通过操作，生成一条 `ADMIN_FINISH` 审批记录，流程状态转为 `FINISH`，节点转入结束节点；
