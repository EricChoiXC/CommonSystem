### 流程图模型与节点键（node_key）

v1_7 起模板与实例均改为「节点 + 连线」图结构，取代现状按 `field_no` 顺序的线性串行链：

1. **连线为流转唯一依据**：流程流转按连线（`from_key` → `to_key`）进行，节点出边数受节点类型约束（见「节点类型全集」）；`field_no` 保留为节点展示序号，不再参与流转判定。
2. **节点业务键 `node_key`**：节点新增模板内唯一业务键。固定节点为 `N1`（开始）/ `N2`（起草）/ `N3`（结束）；其余节点 `N4`、`N5`… 按创建顺延生成（**中间节点键自 `N4` 起，不得占用 `N3`**）。连线以起始节点键、目标节点键表达。节点展示序号 `field_no` 与键无关：开始 1、起草 2、中间节点 3…n、结束 n+1（随中间节点顺延），与改造前的线性编号口径一致。
3. **固定节点**：`N1`/`N2`/`N3` 三个固定节点不可删除、键值不变，无节点配置（`N2` 起草节点自身仍无配置，但可被人工决策节点列为流向决策来源，见「人工决策流向」）。
4. **实例快照**：流程实例创建时，节点与连线**全量快照复制**（含节点配置与连线分支配置），保证按流程创建时的版本执行（与现状「节点配置快照」语义一致，扩展到连线）。流转只读实例连线快照（`sys_process_example_line`），**模板后续变更不影响在途实例**；实例连线快照缺失属图结构不可用，转流程异常（实例 PAUSE + `SYSTEM_ERROR` 留痕），不回退模板连线、不按节点编号兜底流转（P17-BE-007）。
5. **模板保存图校验**（模板 Service，非法图保存报错且中文提示明确）：
   - 从 `N1` 起沿连线连通可达 `N3`，无孤立节点；
   - 各节点出边数符合类型约束（见「节点类型全集」）；
   - 条件分支节点的出边中**有且仅有一条默认分支**；
   - 并行开始/并行结束节点必须成对，且各分支必须汇聚到对应并行结束节点；**嵌套并行本期不支持**（保存校验拒绝）；
   - 人工决策节点的默认流向必须是其实际出边目标之一；
   - 审批节点「审批操作」配置必须包含且仅包含一个 `handler_pass`；
   - 审批/抄送/机器人节点配置的流程任务须通过 @ProcessTask 注册校验（任务存在、processTemplate 匹配、allowTaskType 包含所选步骤）。
6. **历史版本归档**：模板更新归档内容扩展至包含连线（见「模板维护」）。
7. **存量兼容**：存量线性模板经数据迁移生成线性连线后按图模型流转，语义等价（见「兼容与迁移要点」）。

### 节点类型全集（10 类）

| 类型 | node_type | 图形 | 出边数 | 引擎语义 | 配置要点 |
| --- | --- | --- | --- | --- | --- |
| 开始节点 | START（沿用） | 圆角矩形 | 1（固定到 N2） | 进入后沿唯一出边继续 | 无 |
| 起草节点 | DRAFT（沿用） | 直角矩形 | 1（默认到 N3；存在中间节点时连向其后继节点） | 节点 PROCESSING，等待起草人提交 | 无 |
| 结束节点 | END（沿用） | 圆角矩形 | 0 | 进入即流程办结 | 无 |
| 审批节点 | APPROVE（沿用） | 直角矩形 | 1 | 解析审批人 → 跳过计算 → 生成工作项；单签/串行/会签完成后沿出边继续 | 见「审批节点配置」 |
| 抄送节点 | CC（新增） | 直角矩形 | 1 | 解析抄送对象 → 逐人发待阅（READ）→ 节点自动办结并继续 | 见「抄送节点配置」 |
| 条件分支 | CONDITION（新增） | 斜正方形 | N | 按分支序号依次计算各出边条件，**取第一个 true 的出边**；无 true 走默认分支 | 条件存连线 |
| 并行开始 | FORK（新增） | 上半圆 | N | 各出边按「分支启动条件」并行激活，记录汇聚上下文；无可流转分支按节点配置处理（报错 → 流程异常 / 继续 → 全部出边激活） | 汇聚模式等，见「并行分支」 |
| 并行结束 | JOIN（新增） | 下半圆 | 1 | 等待激活分支到达；满足汇聚模式（全部/任一）后流出 | 无 |
| 机器人节点 | ROBORT（沿用历史拼写） | 直角矩形 | 1 | 进入时按序执行节点配置的 @ProcessTask 任务 → 办结并继续；任一失败转流程异常 | 见「机器人节点配置」 |
| 人工决策 | MANUAL（新增） | 斜正方形 | N | 到达时按「最近一次人工指定流向」流出，无指定走默认流向 | 见「人工决策节点配置」 |

> **ROBORT 拼写沿用说明**：`ROBORT` 为存量历史值（正确拼写应为 ROBOT），为避免数据迁移与兼容负担，**沿用不改名**；代码常量、文档、页面均使用该历史拼写，新增文档不得书写为 ROBOT。

### 流程模板

#### `process_template` 配置项 和 field_model_name 取值

`process_template` 配置段由**各业务模块在自身 application.yml 中自行维护**（流程模块按 `classpath*:properties/**/application.yml` 通配扫描聚合，如 `properties/erp/project/application.yml`、`properties/erp/contract/application.yml`），二级配置项即为 `sys_process_template.field_model_name` 值，`process_template.${fieldModelName}.name` 值即为前端 `模板管理` 页面上，模板分类列表项的显示名， `process_template.${fieldModelName}.class` 为该分类的流程对应的文档实体类，`process_template.${fieldModelName}.ops` 为该分类可配置的「操作标识」字典（key=操作标识，value=中文描述，可为空，见下方「审批中审批人特定操作业务」）；`process_template.${fieldModelName}.fields` 为该分类文档实体字段字典（key=文档实体字段属性名，value=中文描述），供节点「审批来源=表单字段」选择审批人字段、公式编辑弹窗点选文档字段占位符（见下方「审批源与审批人解析规则」「分支条件与公式编辑弹窗」）；多个 yml 重复定义同一分类 key 时启动报错（fail-fast）。配置示例：

```yaml
# properties/erp/project/application.yml（项目管理模块自行维护）
process_template:
  erp_project: # 流程模板的 field_model_name
    name: "项目" # 前端显示名
    class: "com.project.backend.erp.project.model.ErpProjectMain" # 流程对应的文档实体类
    desc: "..." # 描述
    ops: # 审批中业务权限
      attachment: "允许修改附件" # 业务权限码值和中文描述
    fields: # 文档实体字段字典（key=实体类字段属性名，value=中文描述）
      fieldCreator: "创建人" # 实体类上的字段属性名和中文描述
```

#### 审批源与审批人解析规则

审批人/抄送对象解析统一落在解析服务 `ProcessHandlerResolver`（org 模块只读复用，不写组织数据）：

1. **审批来源 `handlerSource`**：
   - `org`=组织架构（默认）：配置 `handlerIds`/`handlerNames`，地址本多选结果（v1_7 扩为机构、部门、人员、岗位、群组、角色全类型）；
   - `field`=表单字段（沿用）：配置 `handlerField`，运行期读取流程实例对应文档实体字段值，从中解析出具体组织架构作为审批人；
   - `formula`=公式定义器（v1_7 新增）：配置 `handlerFormula`，运行期经公式定义器执行后按结果解析审批人（见「公式源解析规则」）。

2. **地址本对象解析规则**（审批人/抄送对象通用，按 `handlerResolveMode` 解析方式展开）：

   | 选中对象 | 解析方式=负责人(leader) | 解析方式=成员(member) |
   | --- | --- | --- |
   | 人员 | 本人 | 本人 |
   | 岗位 | 岗位负责人（`field_leader_id`） | 岗位关联用户 |
   | 部门 | 部门负责人（`field_leader_id`） | 部门下员工 |
   | 机构 | 机构负责人（`field_leader_id`） | 机构下员工 |
   | 群组 | 群组成员 | 群组成员 |
   | 角色 | 持有该角色的用户（经权限体系反查） | 同左 |

   - 解析结果**去重保序**；串行审批顺序 = 地址本选择顺序 + 解析展开顺序；
   - 解析不校验组织对象启用状态（**禁用对象允许**作为审批人/抄送对象）；配置对象不存在（已删除）时按解析结果为空处理。

3. **公式源解析规则**（审批源/抄送源 = formula）：
   - 公式经公式定义器（AviatorScript 沙箱）执行，占位符仅允许引用文档实体字段（`process_template.${model}.fields`），**不引入流程变量**（D8）；
   - 结果解析：
     1. 文本 → 以文本值作为 `field_id` 查询组织架构对象；
     2. JSON/Map → 取其 `field_id` 值查询；
     3. List → 逐项按 1/2 解析后取合集（去重保序）；
     4. 公式执行异常、结果类型不识别、或按结果无法定位组织对象 → 转流程异常（见「流程异常」）；
   - 公式解析结果为空集合时，按节点 `emptyHandlerMode` 处理（同审批源为空语义）。

4. **解析结果为空的统一语义**：实际处理人计算结果为空时，按节点 `emptyHandlerMode` 处理——`system` 同系统（默认跳过）/ `skip` 跳过该节点 / `error` 不跳过（转流程异常）；现状「解析为空跳过节点」对应 `system` 默认值语义。
5. **运行期按实例快照解析**：流程实例创建时节点配置原样复制到 `sys_process_example_node.field_node_config`，运行期按实例节点配置解析，保证按流程创建时的版本配置执行。

#### 分支条件与公式编辑弹窗

- **分支条件承载位置变化**：现状审批节点级「节点触发（固定/条件判断）+ 触发条件」由 v1_7 的**条件分支节点（CONDITION）+ 连线分支条件**承接；并行开始（FORK）出边的「分支启动条件」同样存连线。节点级 `triggerType`/`condition` 存量字段保留原值、不再参与流转判定（不改写存量 JSON）；条件路由统一在设计器中以条件分支节点配置。
- **条件公式规则**（沿用现有触发条件机制）：
  1. 必须是判断公式；
  2. 使用占位符(`${field}`)的字段，必须是文档实体类中存在的字段（取自 `process_template.${fieldModelName}.fields` 字典）；
  3. 执行经公式校验服务（公式定义器）。
- **公式编辑弹窗**（分支条件、审批人公式、抄送对象公式通用）：不可编辑输入框 + 「编辑」按钮，点击打开独立公式编辑弹窗，弹窗左右分栏：
  - **左侧**为可点选内容区，分两块：
    - **fields**：当前分类文档实体字段项（取自 `process_template.${fieldModelName}.fields` 字典），点击后以 `${字段属性名}` 占位符形式插入；
    - **公式计算符**：判断公式可用的运算符（如 `+ - * / ( ) > >= < <= == != && || !` 等），点击后以对应符号插入；
  - **右侧**为可编辑文本域，显示当前公式内容，支持直接键盘输入公式；
  - 左侧点选某项时，将对应文本插入到右侧文本域的**当前光标处**（若当前有选中文本则替换选中内容），插入后光标移动到插入内容之后；
  - 点击「确认」将右侧文本回填原输入框并关闭弹窗，「取消」则放弃本次编辑；
  - 回填后的公式仍须满足上方条件公式规则。

#### 流程流转公共规范（图模型）

1. **流转以连线为唯一依据**：进入节点后按节点类型执行引擎语义（见「节点类型全集」），节点完成后沿出边继续；`field_no` 仅作展示排序，不参与流转。
2. **节点实际处理人按节点「审批源」解析**：`org` 直接取配置并按解析方式展开；`field` 读取文档实体对应字段值并解析；`formula` 经公式执行解析。解析结果为空按 `emptyHandlerMode`（system/skip/error）处理，解析过程失败转流程异常（见「流程异常」）。
3. **进入流程节点时，为每个审批人创建一个工作项，包含跳过的处理人**：自动跳过场景自动创建办结工作项并生成 `AUTO_PASS` 审批记录，留痕须回填该跳过者的工作项 id——连续跳过（`autoContinueSkip`）以留痕的工作项 id 反查「上一有效节点中被自动跳过的处理人」，留痕缺失工作项 id 会使连续跳过判定恒不命中。
4. **审批方式**：单签（一个审批人通过即通过该节点，其余工作项转 FINISH）/ 串行（按审批人列表顺序依次生成工作项，上一人通过后才生成下一人待办，队列走完节点流出，跳过者不占串行序位）/ 会签（所有审批人都通过才通过该节点）。
5. **驳回**：按节点 `rejectTargets` 配置与已流经节点的交集选择驳回目标（空默认起草节点），流程转 `RETURN`，重新提交按 `resumeMode`（restart=重新流转 / backToNode=转回驳回节点）流转，留痕 `HANDLER_REJECT`（见「驳回与重新提交」）。
6. **自动跳过体系**（沿用 + 扩展）：按公共配置 `auto_handle_pass`、`auto_handle_pass_drafter`、`auto_continue_pass` 与节点 `skipMode` 四值（system/none/prev/any）计算；节点 `autoContinueSkip` 为否表示上一有效节点被自动跳过的处理人在本节点需实际审批。
7. **人工决策**：流程到达 MANUAL 节点时按「最近一次人工指定流向」或默认流向流出（D6，见「人工决策流向」）。
8. **并行汇聚**：FORK 激活分支集合与 JOIN 到达进度记录在实例节点运行态字段；满足汇聚模式后流出；**嵌套并行不支持**（见「并行分支」）。
9. **流程异常**：触发条件命中时实例转 `PAUSE` 并生成 `SYSTEM_ERROR` 专用留痕（附错误摘要），异常**不回滚已完成的节点**（见「流程异常」）。
10. **管理员操作**：跳转=废弃在途工作项后从目标节点进入引擎；暂停/恢复/终审/作废语义不变；新增更换审批人（见「管理员特权操作」）。

#### 图遍历引擎实现约定（v1_7 / P17-BE-003 落地）

> 本节记录 `sys/process/service/engine/ProcessFlowEngine` 的实际实现口径，作为上述规范的实现补充；实现与规范不一致处以本节为准并回写规范条目。

1. **实例连线为流转唯一依据，模板连线回退为阶段性桥梁**：引擎优先读 `sys_process_example_line`；实例无连线快照时按 `sys_process_example.field_template_id` 读 `sys_process_template_line` 并 `log.warn` 告警。实例连线快照的复制由 **P17-BE-007** 在 `createDraft` 落地，落地后该回退路径删除（存量在途实例已由 DB-005 回填连线快照）。
2. **节点键**：固定 `N1`(START)/`N2`(DRAFT)/`N3`(END)，其余 `N4`、`N5`…；实例节点与模板节点的 `field_node_key` 缺失时按节点编号兜底生成 `N{no}`（固定节点按类型优先归位），保证存量数据仍可按连线流转。
3. **运行态字段 `sys_process_example_node.field_runtime`**（仅 FORK/JOIN 有值，JSON 固定结构 POJO）：
   - FORK 运行态：`activeBranchKeys`（激活分支首节点键集合）+ `joinMode`；
   - JOIN 运行态：`arrivedBranchKeys`（已到达分支键集合）+ `joinMode`（冗余，JOIN 判定不回溯上游）；
   - 汇聚判定：`arrivedBranchKeys ∩ activeBranchKeys`，`all` 需全部到达、`any` 任一到达；满足后流出，否则节点 `PROCESSING` 等待（等待期间队列其余分支继续展开）。
4. **并行分支归属跨调用恢复**：并行分支内审批节点创建工作项时，在工作项 `field_config` 写入 `flowBranchKey`（分支首节点键）；审批通过后恢复流转时按该键回溯分支归属，保证 JOIN 到达计数按分支去重（`field_runtime` 运行态本身不扩展）。
5. **分支条件/启动条件求值**：连线 `field_condition` 经公式定义器沙箱执行，结果必须为布尔值；条件为空视为无条件成立；公式执行异常或结果非布尔 → 转流程异常。
6. **流程异常出口统一**：引擎捕获节点处理人解析失败、机器人任务失败、分支求值失败、并行无可流转分支（FORK `noBranchMode=error`）与不可恢复错误 → 实例 PAUSE + `SYSTEM_ERROR` 留痕（`[错误码] 场景失败: 原因` 摘要），已完成节点状态与留痕不回滚；引擎不向外抛出流程异常，由 `SysProcessExampleService` 按返回终态回写业务状态。

#### 驳回与重新提交（D3）

- 流程处于 `PROCESSING` 状态时，当前审批人可拒绝该节点：**从节点配置 `rejectTargets` ∩ 已流经节点中选择驳回目标节点**（配置为空时默认仅起草节点），并选择 `重新提交后流转方式`（`restart` 重新流转 / `backToNode` 转回驳回节点），该内容保存在工作项的 `field_config` 字段中；
- 被驳回节点之外的其他审批人工作项转 `FINISH`，流程转为 `RETURN`，生成一条 `HANDLER_REJECT` 审批记录；
- 驳回目标为非起草节点时流程仍转 `RETURN`；重新提交按 `resumeMode` 回到驳回节点（backToNode）或从起草节点重新流转（restart）；
- 兼容：现有 `HANDLER_RETURN` 留痕类型保留，用于历史数据；新操作统一使用 `HANDLER_REJECT`。

#### 人工决策流向（D6）

- 人工决策（MANUAL）节点的 `flowDecisions` 配置为「起草节点 + 该节点图上游的审批节点」；被选中节点上的处理人在提交（起草节点）/通过（审批节点）时可指定该决策节点的流向（`flowChoice`，值为该决策节点出边目标节点 key，可选），存入工作项 `field_config`；
- **后提交覆盖先提交**：多人审批时以最后一次指定为准；流程到达 MANUAL 节点时按审批记录时间倒序取最近一个带 `flowChoice` 的通过记录；
- 无人工指定时走【默认流向】`defaultFlowKey`（必须是该节点出边目标之一，保存校验）；
- `flowChoice` 与通过操作同请求提交（审批面板提供流向选择控件）。

#### 并行分支（FORK/JOIN）

- 并行开始（FORK）进入时按各出边「分支启动条件」逐边求值并激活满足条件的分支，各分支独立向后流转；无可流转分支按 FORK 节点配置处理（报错 → 流程异常 / 继续 → 全部出边激活）；
- 分支末端节点完成流入对应并行结束（JOIN）时计数，实例节点运行态字段记录激活分支集合与到达进度；满足 FORK 配置的汇聚模式（`all` 全部 / `any` 任一）后 JOIN 流出；汇聚模式配置于 **FORK 节点**（`joinMode`），判定时由 FORK 运行态冗余到 JOIN 运行态；
- **嵌套并行本期不支持**（保存校验拒绝）；JOIN 长期等待等极端情况可经管理员跳转兜底。

> 实现补充（P17-BE-003）：
> - FORK 无可流转分支行为键为 `noBranchMode`（`error` 转流程异常（缺省）/ `continue` 全部出边激活）；分支启动条件存连线 `field_condition`，条件为空视为无条件成立。
> - 并行分支内审批节点的工作项 `field_config.flowBranchKey` 记录分支首节点键，供审批通过后跨调用恢复流转时回溯分支归属（详见「图遍历引擎实现约定」第 3、4 条）。
> - 并行展开时，某个分支停留审批或 JOIN 等待汇聚**不会中断其余分支的展开**（仅标记停留节点），避免同批激活的分支被漏跑。

#### 机器人节点与自动流转

- 机器人节点（ROBORT）进入时按 `tasks` 配置顺序执行 @ProcessTask 任务，全部成功后节点 FINISH 并沿出边继续；
- 任一任务执行失败 → 转流程异常（见「流程异常」），任务日志记 failed；
- 任务执行留痕写 `sys_process_task_log`，**审批记录不承载任务留痕**（D7，见「流程任务 @ProcessTask」）。

#### 流程异常（PAUSE + SYSTEM_ERROR）

触发条件（任一命中即转流程异常）：

1. 审批人/抄送对象解析过程失败（公式执行异常、结果类型不识别、按结果无法定位组织对象），或节点配置为不跳过（`emptyHandlerMode=error`）且解析结果为空；
2. 机器人节点 @ProcessTask 任务执行失败；
3. 并行分支无可流转分支且 FORK 配置为「报错」；
4. 其他引擎流转中不可恢复错误。

处理方式：

- 实例转 `PAUSE` 状态，并生成 `ADMIN_PAUSE` 之外的专用留痕 `SYSTEM_ERROR`（新增审批记录类型，附错误摘要）；
- **异常不回滚已完成的节点**（已完成节点状态与留痕保持不变）；
- 由 `SYS_PROCESS_EXAMPLE_ADMIN` 管理员经「更换审批人 / 跳转 / 作废」人工干预后恢复流转；
- 异常期间流程无法被起草人和当前审批人操作（同暂停语义）。

#### 流程审批面板

项目前端提供可嵌入审批组件，供插入业务文档页面中进行审批操作，提供除 `起草保存`，`起草提交` 的审批处理，面板不提供接口调用，而是由各业务文档获取面板内填写信息提交给各自模块的后端上，再提交给流程模块做提交操作；

审批面板内包含3块卡片内容：审批，审批记录，流程

1. 审批：仅当前用户拥有可执行的审批操作时可见；**按节点 `operations` 配置 ∩ 用户身份计算按钮集**（`panel.operations`）：通过 / 拒绝（选择驳回目标 + 重新提交后流转方式）/ 转办 / 转办收回 / 已审批收回 / 抄送 / 催办等；操作按钮名称按节点配置的操作名称显示，审批意见默认值按节点配置的默认审批意见回填；被列为流向决策来源的节点，通过/提交时提供人工决策流向选择控件（附带 `flowChoice`）；抄送操作提供地址本多选组件（v1_7 扩展为全类型筛选）；
2. 审批记录：列表显示当前流程的 `sys_process_audit_note` 审批记录；
3. 流程：v1_7 起渲染只读流程图（节点状态着色），节点列表保留为辅助。

面板数据（`panel` 接口响应）额外提供 `nodeOps`：当前用户在该流程当前节点可操作的操作标识集合，供业务文档页控制表单字段/附件等业务操作的可编辑性（见下方「审批中审批人特定操作业务」）；`nodeOps` 业务标识逻辑**维持现有设计不变**。

#### 审批中审批人特定操作业务

用于实现「只允许流程中特定节点审批人，才允许填写某些表单数据/执行某些业务操作」的场景，配置与判定共三层：

1. **分类操作标识字典**：在所属模块 application.yml 的 `process_template.${fieldModelName}.ops` 下按 key:value 配置（key=操作标识，value=中文描述）。当前已配置样例：

   | fieldModelName | ops key | 中文描述 |
   | --- | --- | --- |
   | erp_project / erp_project_change / erp_contract / erp_contract_change | attachment | 允许修改附件 |

2. **节点开关**：模板编辑时，审批节点「节点配置」弹窗「审批权限」标签按分类 `ops` 字典渲染操作标识开关列表；开关状态保存在 `sys_process_template_node.field_node_config`（JSON，`ops` 字段，仅保留开启项）。节点未配置或旧模板（`field_node_config` 无 `ops` 字段）视为未开启任何操作标识——**默认不允许**。

3. **审批中判定与业务接入**：
   - 流程实例创建时将模板节点配置原样复制到 `sys_process_example_node.field_node_config`，审批时直接读实例节点配置；
   - 流程处于 `PROCESSING` 时，仅当前审批节点且持有待处理工作项的审批人，可获得该节点开启的操作标识集合（单签/会签/串行均适用）；
   - 流程实例不存在或非审批中（DRAFT/RETURN 等）无流程约束，按业务自身规则放行（如起草人编辑阶段）；
   - 各业务模块通过 `SysProcessExampleService.resolveNodeOps(modelName, modelId)` 获取当前用户在当前节点的操作标识集合做后端最终校验，前端经 `panel.nodeOps` 控制可编辑性；
   - 附件模块（`sys_att`）已按 `attachment` 操作标识约束 `upload`/`delete`：审批中单据仅当前节点审批人且节点开启「允许修改附件」时可上传/删除附件，其余场景拒绝；`adminDelete`（后台管理删除）不受此约束。

#### 流程创建和提交

由实例所属模块负责创建，保存操作时保存流程实例为 `DRAFT` 状态；提交操作时流程实例状态转为 `PROCESSING` 状态并开始向下流转，生成一条 `DRAFT_SUBMIT` 审批记录；实例创建时对模板**节点与连线做全量快照复制**（含配置），后续流转按快照执行。

**启动模板选择规则**：业务单据可自行决定是否添加 `field_process_template_id` 字段（如合同 `erp_contract_main`、项目 `erp_project_main` 已接入）用于选择运行的流程模板：

- 单据指定 `field_process_template_id`：必须存在、启用且属于该模板分类，否则启动失败；
- 单据未指定（字段为空或未接入）：使用该分类默认模板（`field_default=1` 且启用），**分类下无默认模板则流程启动失败**，提示先到「流程管理-模板管理」设置默认模板。

#### 审批操作矩阵（14 类）

#### 起草人收回

流程处于 `PROCESSING` 状态时，创建人可收回该流程；回收后流程状态转为 `DRAFT`，节点转回起草节点，生成一条 `DRAFTER_BACK` 审批记录；

#### 起草人取消与废弃（D2）

流程处于 `DRAFT` 或 `RETURN` 时，创建人可废弃该流程（v1_7 起同时覆盖初稿「起草人取消」语义，**取消=废弃合并，不新增 CANCEL 状态**）；废弃后流程状态转为 `ABANDON`，节点转入结束节点，生成一条 `DRAFTER_ABANDON` 审批记录；

#### 管理员特权操作

仅 `SYS_PROCESS_EXAMPLE_ADMIN` 级权限用户可在文档审批或流程详情页面执行：

- **管理员跳转**：流程处于 `PROCESSING`、`RETURN` 状态时可跳转，选择跳转节点（限起草节点、审批节点、人工决策节点），生成一条 `ADMIN_JUMP` 审批记录，流程状态转为 `PROCESSING` 或 `RETURN`；跳转=废弃在途工作项后从目标节点进入引擎；
- **管理员终审通过**：流程处于 `PROCESSING`、`RETURN`、`PAUSE` 状态时可终审通过，生成一条 `ADMIN_FINISH` 审批记录，流程状态转为 `FINISH`，节点转入结束节点；
- **管理员暂停**：流程处于 `PROCESSING` 状态时可暂停，生成一条 `ADMIN_PAUSE` 审批记录，流程状态、工作项状态转为 `PAUSE`；期间流程无法被起草人和当前审批人操作；
- **管理员恢复**：流程处于 `PAUSE` 状态时可恢复，生成一条 `ADMIN_RESUME` 审批记录，流程状态、工作项状态转为 `PROCESSING`；
- **管理员作废**：流程处于 `PROCESSING`、`RETURN`、`DRAFT`、`PAUSE` 状态时可作废，生成一条 `ADMIN_ABANDON` 审批记录，流程状态转为 `ABANDON`，节点转入结束节点；
- **管理员更换审批人**（v1_7 新增）：流程处于 `PROCESSING` 状态时，可将当前节点指定 PROCESSING 工作项的处理人替换为目标用户（仅本实例有效，不改模板配置），生成一条 `ADMIN_CHANGE_HANDLER` 审批记录；换人后新处理人可操作、原处理人工作项失效。

### 流程任务 @ProcessTask

流程任务为随流程流转触发的后端任务体系（v1_7 新增），审批记录不承载任务留痕，执行留痕统一写 `sys_process_task_log`（D7）。

#### 注解与接口

```java
public @interface ProcessTask {
    String name();                                    // 任务名称（唯一，注册键）
    String[] processTemplate() default {};            // 可调用的流程模板分类（field_model_name），空=全部
    boolean isForce() default false;                  // 强制任务：所有流程实例创建/结束时执行
    ProcessTaskType forceTaskType() default ProcessTaskType.StartProcess;
    ProcessTaskType[] allowTaskType() default {};     // 非强制任务允许配置到的步骤，空=不限
}

public enum ProcessTaskType {
    CreateProcess,   // 创建实例
    StartProcess,    // 流程发起
    StartNode,       // 节点进入
    StartWorkitem,   // 工作项开始
    SendTodo,        // 发送待办
    EndWorkitem,     // 工作项结束（审批操作后）
    EndNode,         // 节点结束
    EndProcess       // 流程结束
}

public interface ProcessTask {
    void execute(ProcessTaskContext context);
}

public class ProcessTaskContext {
    private Object model;                       // 业务单据（经文档字段服务的 Mapper 读取）
    private SysProcessExample process;          // 流程实例
    private SysProcessExampleNode node;         // 当前节点（可空）
    private SysProcessExampleWorkitem workitem; // 当前工作项（可空）
}
```

#### 注册与调度

- **注册**：启动期（`SysStartupTask#run` 流程初始化段内）扫描容器中「类上同时标注 `@ProcessTask` 且实现 `ProcessTask`」的 bean，登记 `name → bean`；注解与接口缺一即启动报错（fail-fast）；`name` 重复报错；
- **触发**：引擎在流转各步骤（ProcessTaskType）触发——强制任务（`isForce=true`，仅限 StartProcess/EndProcess 步骤）对所有实例生效；节点/工作项级任务按节点配置 `tasks` 明细执行（执行任务=登记的 name，执行步骤=ProcessTaskType，任务参数=JSON）；
- **校验**：节点配置任务时校验 processTemplate 匹配（不配置=全模板可用）、allowTaskType 包含所选步骤；
- **留痕**：每次执行写 `sys_process_task_log`（任务参数/结果摘要/耗时/是否成功/失败信息）；
- **事务语义**：任务在当前流转事务内同步执行；抛异常 → 转流程异常（PAUSE + SYSTEM_ERROR 留痕），任务日志记 failed。

### 通知

v1_7 起流程通知收口为引擎统一发送（决策 D4 与现状核对建议 5）：

- **审批待办（TODO）**：节点进入产生待办、办结产生待阅；标题消费既有 4 个模板（`notify_handle_subject` / `notify_refuse_subject` / `notify_finish_drafter_subject` / `notify_finish_handler_subject`），经 `NotifySendEvent` 发送；
- **抄送与催办待阅（READ）**：抄送节点与抄送动作（`notify_cc_subject`）、起草人/已审批人催办（催办标题模板）均以 READ 待阅呈现；**不新增 CC 通知类型，通知中心不加新页签**（D4）；
- **业务侧兼容策略**：现状「接入流程的业务模块自行发送待办」模式**不强制下线**；引擎收口后存在重复发送风险，业务侧按需切换为引擎统一发送（风险 R05 已在改造方案中明确）；
- 催办/抄送待阅在通知中心「待阅」列表呈现，与既有待阅体验一致。

### 流程监控与统计

- **流程监控**（`SYS_PROCESS_EXAMPLE_ADMIN`）：管理员视图列表，覆盖全部在途/全部实例，支持按流程状态与异常状态筛选；详情跳转复用实例详情页，特批操作入口复用现有 `adminOperate` 并扩展更换审批人；
- **流程统计（管理员）**：按模块/模板/状态/时间区间的数量、效率（平均耗时）、人员工作量 TopN 聚合，只读查询，不侵入流转 SQL；
- **我的流程统计**：今日发起、我的未办结、待审、今日已审、平均耗时；
- **审批一级菜单**：`我发起的`（scope=myCreated）/ `我参与的`（scope=myJoined，作为审批人/已审批人参与）两个列表页，全员可见，本人数据强制过滤，越权数据零泄露；
- 统计口径明细与接口契约详见 v1_7 API 接口设计分册（P17-DOC-002）。

3. **HANDLER_RETURN 保留**：历史驳回留痕类型保留，新操作统一使用 `HANDLER_REJECT`；
4. **节点级触发条件不再参与流转**：存量 `triggerType`/`condition` 字段保留原值，条件路由改由条件分支节点 + 连线分支条件表达；
5. **存量数据迁移**（`SourceDataMigration` SPI，code 格式 `DM-yyyyMMdd-nnn`，不新增 SQL 迁移脚本）：
   - `DM-xxx-001`：为全部存量模板节点回填 `node_key`（按 `field_no` 顺序 N1..Nn）；
   - `DM-xxx-002`：为存量模板按 `field_no` 顺序生成线性连线（N1→N2→…→N3），并写入实例连线快照（含在途实例）——迁移后旧模板/在途实例全部按新引擎照常流转；
   - 迁移幂等（存在 SUCCESS 记录跳过）、失败阻断启动；
6. **表结构**：3 张新表（模板连线/实例连线快照/任务执行日志）+ 4 处列变更（节点键 ×2、实例节点运行态、转办来源工作项）由实体注解声明并经注解同步引擎同步，明细见 v1_7 数据库设计分册（P17-DOC-003）与《流程表结构.md》。
