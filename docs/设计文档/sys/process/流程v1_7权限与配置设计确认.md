### 2.2 新增权限码 `SYS_PROCESS_MY_VIEWER` 定名与语义

**定名结论**：`SYS_PROCESS_MY_VIEWER`（与《改造分析与方案设计》§10、UI 设计分册 §2.2/§3.3、API 分册权限章节保持一致，无别名、无 `SYS_PROCESS_APPROVAL_*` 变体）。

**语义边界**：

| 项 | 约定 |
| --- | --- |
| 授予对象 | 全部登录且账号启用的用户（默认全员）——审批中心是个人工作台属性页面，不是管理页 |
| 覆盖页面 | `/approval/created`（我发起的）、`/approval/joined`（我参与的）、`/approval/statistic`（我的流程统计）三个页面；菜单项叶子 `auth` 声明 `['SYS_PROCESS_ADMIN','SYS_PROCESS_MY_VIEWER']` |
| 不覆盖 | 后台管理 → 流程管理下的公共配置/模板管理/流程实例/流程监控/流程统计（仍由模板、实例、配置三类权限码准入） |
| 数据边界 | 该权限码**只决定页面可见性**；`scope=myCreated/myJoined` 的**本人数据强制过滤由 Service/Mapper 承担**（本人维度不可越权），统计口径同理——权限码不承担数据行级过滤 |
| 与 `SYS_PROCESS_EXAMPLE_VIEWER` 的关系 | **互不派生**：`SYS_PROCESS_MY_VIEWER` 不包含查看全量流程实例的能力；持有它不等价于持有 `SYS_PROCESS_EXAMPLE_VIEWER` |
| 上下级关系 | 无上下级声明（不做 `SYS_PROCESS_*` 层级继承），仅由 `SYS_ADMIN` 超管短路天然可见 |

**默认全员授予的落地方式**：与既有 6 个权限码一致，权限码经 `roles.yml` 的 `ROLE_LIST` / `ROLE_MAP` 增量同步到 `sys_org_auth`（`SysOrgAuthService` 启动同步）。「默认全员」在权限体系中的落地口径：

- `roles.yml` 与库两处**同批**落定（P17-BE-008），`ROLE_LIST` 追加 `SYS_PROCESS_MY_VIEWER`，`ROLE_MAP` 追加 `NAME` / `DESC`；
- 因本仓库权限为「角色 → 权限码」授权模型（非默认放行模型），「全员」的实现口径为：**部署侧将该权限码授予全体业务角色（或全员角色）**，`roles.yml` 不提供自动授予字段；该口径已在 P17-FE-008 走查项中登记（无权限时页面隐藏，不报错）；
- 若后续确需“无需授权即全员可用”，应改走 resolver 登录即放行口径（见 3.3 备选方案），**需先补需求文档**，本期不采用。

### 3.2 resolver 判定口径（`ProcessResolver`）

现状 `ProcessResolver` 为「登录且启用 → `SYS_PROCESS_ADMIN` 放行 → 按 action 前缀分发」结构。v1_7 补充分支如下（`SYS_ADMIN` 由 `BaseResolver#hasAnyRoleOrName` 自动放行，**分支内不得再列举**）：

| action 前缀 / 后缀 | 判定 | v1_7 变化 |
| --- | --- | --- |
| `sys.process.setting.` | `SYS_PROCESS_SETTING_ADMIN` | 不变 |
| `sys.process.module.` + 后缀 `.save` / `.update` / `.enable` / `.setDefault` | 仅 `SYS_PROCESS_TEMPLATE_ADMIN`（`isTemplateWriteAction` 写操作判定，保持现状） | 不变 |
| `sys.process.module.` 其他 | `SYS_PROCESS_TEMPLATE_ADMIN` 或 `SYS_PROCESS_TEMPLATE_VIEWER` | 不变 |
| `sys.process.example.` + 后缀 `.adminOperate` | 仅 `SYS_PROCESS_EXAMPLE_ADMIN` | 不变 |
| `sys.process.example.` + 后缀 `.monitorList` | **仅 `SYS_PROCESS_EXAMPLE_ADMIN`** | **新增分支** |
| `sys.process.example.` 其他（含 `.operate`） | `SYS_PROCESS_EXAMPLE_ADMIN` 或 `SYS_PROCESS_EXAMPLE_VIEWER` | `operate` 落入该分支（后缀非 `adminOperate`/`monitorList`） |
| `sys.process.statistic.` | **`.admin` → `SYS_PROCESS_EXAMPLE_ADMIN`；`.my` → 登录即可（`resolveLoggedIn()`）** | **新增前缀分支** |
| 其他 / 未登记 | 拒绝（最小授权） | 不变 |

**判定顺序约束**（实现时不得颠倒）：

1. 先判 `sys.process.statistic.`（新前缀，与既有三个前缀互不包含）；
2. `sys.process.example.` 分支内**先判后缀** `.adminOperate` → `.monitorList` → 其余；`.operate` 属「其余」，走 admin/viewer 口径；
3. `sys.process.module.` 分支内保持「先写操作后缀、后读操作」的现状顺序。

### 3.3 备选方案（本期不采用，仅登记）

| 备选 | 内容 | 不采用原因 |
| --- | --- | --- |
| `sys.process.my.` 前缀 | 审批中心三页面各设 `sys.process.my.created` / `.joined` / `.statistic` 三个 ACTION | 三接口请求体/响应结构同构（仅 scope 与过滤维度不同），拆三个 ACTION 徒增前端预判与 resolver 分支，收益不足 |
| `sys.process.statistic.my` 复用 `.admin` 的 `SYS_PROCESS_EXAMPLE_ADMIN` | 我的统计也要求实例管理员权限 | 与「审批中心全员可用」的页面定位冲突 |
| `SYS_PROCESS_MY_VIEWER` 改为登录即放行（不落权限码） | 三页面不设权限码，resolver 直接 `resolveLoggedIn()` | 与《改造分析与方案设计》§10 已评审结论（新增权限码、roles.yml 默认全员授予）不一致；且失去后续按角色收缩的能力。**如需求方最终选择本方案，须先补需求文档并同步 `roles.yml` 不新增** |
| 「全员授予」由 `roles.yml` 自动授予 | 新增 `DEFAULT_ALL: true` 类字段 | 现有 `ROLE_LIST` / `ROLE_MAP` 结构无此语义，扩展同步逻辑影响全部模块，超出本期范围 |

### 3.4 操作人身份校验（引擎内，与 resolver 双层）

resolver 只做「接口级」准入；**操作级**身份校验落在引擎方法内（对齐现状模式，见《流程核心业务》「审批操作矩阵」）：

| 身份 | 判定依据 |
| --- | --- |
| 起草人 | `sys_process_example.field_creator_id` = 当前用户 |
| 当前处理人 | 该实例当前节点存在 `field_handler_id` = 当前用户且 `field_status = PROCESSING` 的工作项 |
| 已处理人 | 该实例存在 `field_handler_id` = 当前用户且已办结的工作项（转办收回 / 已审批人收回 / 已审批人催办） |
| 流程管理员 | `SYS_PROCESS_EXAMPLE_ADMIN`（或 `SYS_PROCESS_ADMIN` / `SYS_ADMIN`） |

越权一律 `FORBIDDEN`、未登录 `UNAUTHORIZED`（HTTP 200 + code 体系）；详细的操作 × 身份 × 状态矩阵见《流程核心业务》「审批操作矩阵（14 类）」与 API 分册。

### 4.4 三段式配置说明（新增配置项的书写口径）

《改造分析与方案设计》§10 要求的 `${CS_X:${SETTING.a.b:default}}` 三段式，**适用对象是「Java 侧经 Spring 属性读取的配置」**（先例：`application.properties` 的 `spring.datasource.*`、`common.org.openid.*`）。本任务两项新增配置的定位与书写口径如下：

| 配置项 | 读取通道 | 是否需三段式 | 说明 |
| --- | --- | --- | --- |
| `notify.notify_cc_subject` | `CommonSettingService` 读 `common_setting`（运行期可经「流程管理-公共配置」页维护） | **不需要**（保持 `SETTING` 单段式） | 属**业务配置**，必须可由公共配置页在线修改；如写成 `${CS_X:${SETTING...}}` 的 Spring 属性，环境变量将硬覆盖页面维护值，破坏「重置/提交」语义 |
| `notify.notify_expedite_subject` | 同上 | **不需要**（同上） | 同上 |
| （如实现期为性能引入本地缓存开关等） | Spring 属性 | **需要** | 若新增「属部署运行参数」的进程级配置（如缓存 TTL、批量发送线程数），一律按 `${CS_X:${SETTING.<type>.<key>:<default>}}` 三段式写在 `application.properties`；且此类参数**不入 `common_setting`**（对齐 `CS_SOURCE_SYNC_MODE` / `CS_API_DOCS_ENABLED` 先例） |

> 判定口径（供实施期遵循）：能由业务管理员在「流程管理-公共配置」页维护的 → `SETTING` 单段式入 `common_setting`；只能由部署侧决定的 → `application.properties` 三段式 + `CS_*` 环境变量，**两者不混用**。
