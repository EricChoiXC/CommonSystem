## 2. 全局接口约定

### 2.1 路径与方法规则

- 统一前缀：`/backend/sys/process/{次级模块}/{方法}`；`{次级模块}` ∈ `setting` / `module` / `example` / `operation` / `statistic`。
- 方法规则（对齐仓库全局规范）：单 `id` 或无查询条件读取用 `GET`；含复合查询条件的检索用 `POST`；变更类用 `POST`（新建、动作型提交）或 `PATCH`（更新、启停用）；删除用 `DELETE`；**全局禁用 `PUT`**。
- 列表请求体统一 `{ body, pages: { pageNo, pageSize, needPage }, sortField, sortOrder }`；总数经 `metadata.total` 返回。
- 响应统一 `BaseResponse`（`{ code, message, data, metadata }`，HTTP 状态恒 200），异常交 `GlobalExceptionHandler`。

### 2.2 鉴权与文档 ID 规则

- 每个接口必须定义 `ACTION_*` 常量（`SysProcessConstants`），Controller 与 `ProcessResolver` 静态引用，**禁止手写字符串**；Controller 经 `authorize(action, documentId)` 做最终鉴权。
- 涉及具体实例/模板的读写接口传被操作对象 ID 作为 `documentId`（`load`/`panel`/`adminOperate`/`operate` 传 `fieldId` 或 `exampleId`）；纯动作型接口（`models`/`list`/`monitorList`/`statistic`）不传。
- 失败语义：未登录 → `BaseResponse.code = UNAUTHORIZED`；无权限 → `FORBIDDEN`（HTTP 均 200 + code 体系，全工程惯例）。
- `SYS_ADMIN` 由 `BaseResolver` 自动放行，resolver 分支不得重复列举。
- **双层鉴权**：resolver 只做「接口级」准入；14 类操作另需引擎内「操作人身份」校验（起草人 / 当前处理人 / 已处理人 / 流程管理员），见 §6.3。

### 4.3 `/save` 与 `/update` 请求契约（v1_7 扩展）

- 请求体 = `SysProcessTemplateVo`（含 `nodes` + **`lines`**）；`update` 的 `fieldId` 必填，`save` 由前端经 `GET /backend/common/initID` 预生成 32 位 ID。
- **连线全量替换**：服务端删除该模板现有全部连线后按请求 `lines` 重建（同节点模式一致），不做差量更新。
- 节点与连线的**节点键一致性**：`lines` 中 `fieldFromKey`/`fieldToKey` 必须存在于请求 `nodes` 的 `nodeKey` 集合中，否则拒绝保存。
- **节点键归一**：服务端按节点类型归一键值——`START`=`N1`、`DRAFT`=`N2`、`END`=`N3`、中间节点按出现顺序自 `N4` 起顺延（**`N3` 保留给结束节点**）；请求携带的 `nodeKey` 仅作对照，与归一结果不一致即拒绝（`nodeKey` 可空，由服务端归一后落库）。节点展示序号 `field_no` 与键无关：开始 1、起草 2、中间 3…n、结束 n+1。
- 历史版本归档（`sys_process_template_history.field_content`）**扩展为含连线快照**（模板 + 全部节点 + 全部连线）。

### 4.4 服务端图校验规则（保存/更新时，非法图拒绝并返回中文提示）

| # | 校验 | 失败语义 |
| --- | --- | --- |
| G1 | 从 `N1` 沿连线连通可达 `N3` | 拒绝保存，提示首尾不连通 |
| G2 | 无孤立节点（每个节点至少有一条入边或出边，`N1` 无入边、`N3` 无出边除外） | 拒绝保存，提示存在孤立节点 |
| G3 | 各节点出边数符合类型约束：`START`=1（固定指向 `N2`）、`DRAFT`=1（无中间节点时默认指向 `N3`；存在中间节点时连向其后继节点）、`END`=0、`APPROVE`/`CC`/`ROBORT`=1、`CONDITION`/`FORK`/`MANUAL`≥1、`JOIN`=1 | 拒绝保存，提示出边数不合法 |
| G4 | 条件分支（`CONDITION`）出边中**有且仅有一条** `fieldIsDefault=true` | 拒绝保存 |
| G5 | 并行开始（`FORK`）与并行结束（`JOIN`）成对，各分支必须汇聚到对应 `JOIN`；**嵌套并行拒绝** | 拒绝保存 |
| G6 | 人工决策（`MANUAL`）的 `defaultFlowKey` 必须是其实际出边目标之一 | 拒绝保存 |
| G7 | 审批节点 `operations` **必须包含且仅包含一个 `handler_pass`** | 拒绝保存 |
| G8 | 节点 `tasks` 经 `ProcessTaskRegistry` 校验：任务 name 已注册、`processTemplate` 匹配（不配置=全模板可用）、`allowTaskType` 包含所选步骤 | 拒绝保存 |
| G9 | `rejectTargets` 候选限定为起草节点 + 图上游审批节点 | 拒绝保存 |
| G10 | `flowDecisions` 候选限定为起草节点 + 该 `MANUAL` 节点图上游审批节点 | 拒绝保存 |

**兼容口径**：`operations` 由「操作标识字符串数组」升级为「按钮对象数组」，前端审批面板与业务模块 `audit` 转发通道按新结构消费；旧字段语义（操作标识）以 `operateType` 承载，不新增并列字段。节点无配置（旧模板/空 `operations`）时按既有逻辑兜底（起草人收回/废弃、当前处理人通过/拒绝，默认名，保证旧模板面板不塌）。

**观察项（QA-003 遗留②，P17-DOC-010 落注，不改冻结契约）**：`drafter_submit` 面板流向控件在公共系统当前面板计算口径下**不可达**——`computeOperations` 的配置行仅取当前在途节点（DRAFT 态恒空，兜底仅产出 `drafter_cancel`），`panel.operations` 在任何状态下都不会产出 `drafter_submit` 行；前端面板的流向控件消费逻辑（带 `flowChoices` 的 `drafter_submit` 行常驻渲染、变更即 emit `submit` 同步宿主缓存）已实现且与本节冻结口径一致，引擎侧 `flowChoice` 读取与「后提交覆盖先提交」已经 INT-003 实测落库。属契约自洽观察项而非缺陷：公共系统无宿主业务文档页，起草提交动作由业务模块承载（经 §6.5 `audit` 转发通道携带 `flowChoice`），流向控件可达性取决于宿主提交场景接入形态——**宿主提交场景接入后复核**。

身份不符 → `CS_PROCESS_OPERATE_FORBIDDEN`（`FORBIDDEN` 语义）；实例不存在 → `CS_PROCESS_EXAMPLE_NOT_FOUND`。

### 6.4 抄送对象与转办对象参数形态

- `handler_cc` 的抄送对象、`handler_transfer` 的转办对象均支持**地址本多选**（机构/部门/人员/岗位/群组/角色全类型）；接口侧以 `transferToIds`（转办）与 `ccToIds`（抄送）承载——**抄送对象字段名定稿为 `ccToIds`**（P17-BE-008 定稿并回写本节，2026-11-20），与 `transferToIds` 同构的 ID 列表字段（`';'` 分隔或多值）；本期仅在请求体承载，消费由 P17-BE-012 落地。
- 成员/负责人展开规则（部门/岗位/机构 leader|member、群组/角色成员）由 `ProcessHandlerResolver` 承担，接口层不做解析。

### 6.5 业务模块 `audit` 转发通道

- 业务模块（如 ERP 侧单据页）现状经各自后端把审批操作转发至流程模块 `SysProcessExampleService#operate(...)`；v1_7 起该内部通道**同步扩展 `operateType` 取值与新增参数**（`rejectTargetKey`/`flowChoice`/`transferToIds`/`changeToId`/`resumeMode`），保持**向后兼容**：旧调用（通过/驳回/收回/废弃）不传新参数时按原语义执行。
- 该通道为**服务内调用**，不经 HTTP，不打流程模块的 `ACTION_*` 鉴权；业务模块须自行完成单据权限判定（沿用「流程模块不替业务模块做单据权限判定」的既有边界），流程模块在引擎内完成操作人身份校验（§6.3）。

> **实现补充（P17-BE-016，2026-11-23）**：契约字段与鉴权不变，实现口径如下——
> ① **handlerWorkloads**（§7.1，文档未冻结处按既有口径落定）：事实来源 = `sys_process_audit_note` 中 `HANDLER_PASS` 通过留痕（AUTO_PASS 自动跳过者无通过留痕、不计工作量），关联其工作项取实际处理人（`field_expect_handler_id` 优先、回退 `field_handler_id`，皆空行不计，与办结待阅收件人口径一致）；`handledCount` = 通过留痕条数（同一工作项收回后再审批按多次计）；`avgDurationMs` = 该处理人经办的 `FINISH` 实例平均办结耗时（自然时长毫秒）；处理人名称经 `sys_org_element`（`field_org_type = 3`）只读关联补全；排序按已办工作量降序、处理人 id 升序稳定排序后 `LIMIT topN`。三组数量分布（statusCounts/modelCounts/templateCounts）同序按数量降序、键升序稳定排序。
> ② **my 五项指标**（§7.2）：「本人」条件与「我发起的 / 我参与的」列表（§5.2）同口径——发起类用 `field_creator_id = 会话用户`，参与类（待审 / 今日已审 / 平均耗时的参与判定）用工作项 `field_handler_id = 会话用户`；`pendingApproveCount` 按工作项状态 `PROCESSING` 计（不做实例状态二次过滤，流程 PAUSE 期间仍属待本人处理）；「今日」窗口 = 应用服务器时区今日零点（含）至明日零点（不含），由 Service 计算后传入 Mapper（不依赖数据库时区函数）；未登录注入 null，本人条件比对 NULL 恒不成立，五项指标全为 0（零泄露）。
> ③ **实现自由度登记**：`topN` 缺省或小于 1 按默认 10 处理、不设上限；admin 统计筛选条件（模块/模板/状态/创建时间区间）对实例维度的全部聚合（含 handlerWorkloads）一致生效；`avgDurationMs` 取自然时长毫秒（`ROUND(AVG(TIMESTAMPDIFF(MICROSECOND, …)) / 1000)`），无 FINISH 实例时为 0。
> ④ **统计联调偏差登记（P17-INT-004，2026-11-23，均为口径既定行为与观察项，不改契约）**：
> - `AUTO_PASS`（自动跳过）工作项**计入** `todayApprovedCount`——my 统计按工作项维度取 `FINISH` 且完成于今日，不区分是否自动跳过（与「我参与的」工作项口径一致）；`admin` 的 `handlerWorkloads` 不受影响（AUTO_PASS 无 HANDLER_PASS 留痕、不计工作量）。如需区分待后续版本裁决。
> - `fieldTemplateId` 为**统计专有筛选**（`example/list` 查询契约 §5.2 无该条件字段，两处各自冻结、无冲突）；统计与明细列表的交叉核对只能按 list 支持维度（状态/时间/scope）进行，模板维度以 SQL 复算核对。
> - 「expect_handler_id 优先回退 handler_id」的回退分支**无法以运行数据验证**：全部写入路径（`insertWorkitem`/转办/管理员换人）均同时写 `field_expect_handler_id = field_handler_id`，两字段在运行数据中恒等；口径由 `SysProcessStatisticMapper.xml` SQL 文本断言（`SysProcessStatisticMapperXmlTest`）覆盖。观察项，不改实现。
> - 「按模块数量」`modelCounts` 的键上限无实现约束（联调时仅能构造单模块分类属联调环境限制，非实现限制）。

## 10. 错误码与承载方式

对齐数据源 `CS_DATASOURCE_*` 与公式 `CS_FORMULA_*` 口径：**业务错误码以异常 message 前缀承载，`BaseResponse.code` 统一为 `BAD_REQUEST`（鉴权类除外）**，前端按 message 前缀识别具体错误码。图校验与操作前置条件失败**以错误信息直接返回**（面向配置者/操作者，需中文可读），不引入仅机器可读的静默失败。

| 错误码 | 触发场景 | `BaseResponse.code` |
| --- | --- | --- |
| `CS_PROCESS_EXAMPLE_NOT_FOUND` | 流程实例不存在（`load`/`panel`/`operate`/`adminOperate`） | `BAD_REQUEST`（`load`/`panel` 现状返回 `E_NOT_FOUND`，v1_7 保持现状，不强制改名） |
| `CS_PROCESS_OPERATE_TYPE_INVALID` | `operateType` 不在 14 类取值内 | `BAD_REQUEST` |
| `CS_PROCESS_OPERATE_PARAM_MISSING` | 操作类型对应的必填参数缺失（如 `handler_reject` 缺 `rejectTargetKey`/`resumeMode`） | `BAD_REQUEST` |
| `CS_PROCESS_OPERATE_STATE_CONFLICT` | 流程状态不满足该操作前置条件（如非 `PROCESSING` 执行 `handler_pass`） | `BAD_REQUEST` |
| `CS_PROCESS_OPERATE_FORBIDDEN` | 操作人身份不符（非起草人/当前处理人/已处理人/流程管理员） | `FORBIDDEN` |
| `CS_PROCESS_NODE_TARGET_INVALID` | 跳转/驳回目标节点非该实例节点或不满足范围约束 | `BAD_REQUEST` |
| `CS_PROCESS_GRAPH_INVALID` | 模板保存图校验不通过（G1~G10，逐条附中文原因） | `BAD_REQUEST` |
| `CS_PROCESS_TASK_INVALID` | 节点 `tasks` 未通过 `ProcessTaskRegistry` 校验（任务未注册、`processTemplate` 不匹配、`allowTaskType` 不含步骤） | `BAD_REQUEST` |
| `CS_PROCESS_HANDLER_PARSE_FAILED` | 运行期审批人/抄送对象解析失败（公式异常、结果类型不识别、无法定位组织对象）→ 转流程异常（`PAUSE` + `SYSTEM_ERROR`） | `BAD_REQUEST`（同步响应） |
| `CS_PROCESS_TASK_EXECUTE_FAILED` | 机器人节点任务执行失败 → 转流程异常（`PAUSE` + `SYSTEM_ERROR`，任务日志记 failed） | `BAD_REQUEST`（同步响应） |

> `UNAUTHORIZED` / `FORBIDDEN` 为鉴权类 code，直接作为 `BaseResponse.code` 返回（不经 message 前缀）。

## 12. 当前冻结的接口方向

1. **审批操作单入口**：14 类操作统一经 `POST /operation/operate` 提交，不再为每类操作增设独立接口；业务模块 `audit` 转发通道为服务内调用、同步扩展操作类型并保持向后兼容。
2. **图数据随契约透出**：模板 `load`/`save`/`update` 与实例 `load`/`panel` 均以 `nodes[] + lines[]` 承载图，前端设计器与只读流程图共用同一契约。
3. **`operations` 双层语义并存**：面板按钮集 `panel.operations`（节点 `operations` 配置 ∩ 用户身份）与业务操作标识 `panel.nodeOps`（`ops` 开关体系）**语义分离、互不替代**，`nodeOps` 维持现状设计不变。
4. **`scope` 承载数据范围**：`myCreated`/`myJoined` 由 Service/Mapper 强制本人过滤，不新增 ACTION、不信任前端传入的用户标识；统计 `/my` 同理，不接收 userId。
5. **统计只读隔离**：统计聚合走专用 Mapper XML，不侵入流转 SQL、不写任何流转表。
6. **错误码前缀承载**：`CS_PROCESS_*` 以 message 前缀承载，`code` 保持 `BAD_REQUEST`/`FORBIDDEN` 体系；图校验与操作前置条件失败返回中文可读原因。
7. **API 文档同批**：新增/修改接口与 `@Tag`/`@Operation`/`@Parameter`/`@Schema` 同批更新，`@Operation.description` 以「鉴权动作 …」开头。
