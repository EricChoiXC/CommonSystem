# 组织架构后端业务设计

> 本文档描述组织架构（org）模块后端的分层结构、鉴权链路、各服务业务规则与配置约定，依据现有实现（`backend/src/main/java/com/common/system/sys/org` 及 `resources/mappers/sys/org`、`resources/properties/sys/org`）回写。
> 业务规则见 [组织架构核心业务设计.md](./组织架构核心业务设计.md)，接口约定见 [组织架构接口清单.md](./组织架构接口清单.md)。

## 1. 分层结构

```text
com.common.system.sys.org
├─ controller   # SysOrgElementController / SysOrgUserController / SysOrgAddressBookController
│               # SysOrgRoleController / SysOrgRolePreviewController（继承 BaseController / BaseCrudController）
├─ service      # SysOrgElementService / SysOrgUserService / SysOrgAddressBookService
│               # SysOrgRoleService / SysOrgRolePreviewService / SysOrgAuthService
├─ dao          # 与 mapper 一对一（SysOrgElementDao / SysOrgUserDao / ...）
├─ mapper       # 与 resources/mappers/sys/org/*.xml 对应
├─ model        # SysOrgElement(主表) / SysOrgUser(继承 SysOrgElement) / SysOrgRole / SysOrgAuth / SysOrgUserPwdHistory
├─ enums        # SysOrgAccountStatus / SysOrgJobStatus
├─ properties   # SysOrgElementProperties / SysOrgUserProperties / SysOrgRoleProperties / SysOrgAddressBookProperties / SysOrgGroupProperties（ACTION_* 常量）
├─ request      # SysOrgElementRequest / SysOrgUserRequest / SysOrgLoginRequest
├─ response     # SysOrgElementVo / SysOrgRoleVo / SysOrgUserResponse / SysOrgUserVo / AuthGroupVo / AuthItemVo / RolePreviewVo / PreviewTreeChildVo
├─ resolver     # ElementResolver / UserResolver / AddressBookResolver / RoleResolver（继承 BaseResolver）
└─ utils        # CurrentUserHolder（登录人 ThreadLocal）
```

- Controller 只做接收/校验/返回，业务在 Service；Service 不直连 Mapper，经 Dao 访问；
- `SysOrgUser extends SysOrgElement`：人员模型 = 主表公共字段 + 人员扩展字段，人员写操作由 `SysOrgUserDao`
  双写主表 `sys_org_element` 与扩展表 `sys_org_user`（insert 走主表公共列 + 扩展表专有列两条 SQL）。

## 2. 鉴权链路

### 2.1 会话与登录人

```text
请求头 X-Login-Token → CurrentUserFilter → CurrentUserHolder(ThreadLocal) → Controller / Resolver 读取
```

- 会话由 `LoginSessionService` 维护（内存 Map，TTL 8 小时，token 为 UUID 去横线）；
- 未登录请求访问需登录接口时抛 `UNAUTHORIZED`，已登录但无权限抛 `FORBIDDEN`，统一交 `GlobalExceptionHandler`；
- 登录成功后 token 经响应 `metadata.X-Login-Token` 下发，前端由 `api/index.js` 拦截器统一携带。

### 2.2 ACTION 常量与 Resolver 分支

接口标识（action）定义在各 properties 常量类，Controller 与 resolver 静态引用，禁止手写字符串。
Controller 经 `authorize(action, documentId)` 做最终鉴权；`SYS_ADMIN` 在 `BaseResolver.hasAnyRole` 中自动放行，模块分支不重复列举。

| Controller（基础路径） | action | 放行角色（满足其一） |
| --- | --- | --- |
| SysOrgElementController（`/backend/sys/org/element`） | `sys.org.element.save` / `delete` | SYS_ORG_ADMIN / SYS_ORG_ELEMENT_ADMIN / SYS_ORG_ELEMENT_ADD |
| 同上 | `sys.org.element.update` / `enable` | SYS_ORG_ADMIN / SYS_ORG_ELEMENT_ADMIN / SYS_ORG_ELEMENT_EDIT |
| 同上 | `sys.org.element.list` / `load` | 已登录且账号启用（查询不设权） |
| SysOrgUserController（`/backend/sys/org/user`） | `sys.org.user.save` / `delete` | SYS_ORG_ADMIN / SYS_ORG_USER_MANAGER |
| 同上 | `sys.org.user.update` / `changePwd` / `checkPwdChange` | SYS_ORG_ADMIN / SYS_ORG_USER_MANAGER / 本人（fieldId = 当前登录人） |
| 同上 | `sys.org.user.load` / `list` / `login` / `logout` | 已登录（load/list 按可见性裁剪，见 2.3；login/logout 登录前无身份、凭证即身份） |
| SysOrgAddressBookController（`/backend/sys/org/addressbook`） | `sys.org.addressbook.tree` / `list` / `load` | 已登录且账号启用（只读不设权） |
| SysOrgRoleController（`/backend/sys/org/role`） | `sys.org.role.list` / `load` / `save` / `update` / `authOptions` | SYS_ORG_ADMIN / SYS_ORG_ROLE_ADMIN（统一分支） |
| SysOrgRolePreviewController（`/backend/sys/org/preview`） | `sys.org.preview.preview` / `treeChildren` | SYS_ORG_ADMIN / SYS_ORG_ROLE_ADMIN（统一分支） |

`UserResolver.resolve(String)`（无 AuthorizationContext 的重载）默认返回 `true`，供登录/登出等非鉴权路径使用。

### 2.3 人员字段可见性（双保险）

- 判定入口：`UserResolver#loadVisibleResult`——当前登录人具备
  `SYS_ORG_ADMIN` / `SYS_ORG_USER_MANAGER` / `SYS_ORG_ELEMENT_*` 任一权限，或目标人员在本人直属组织架构链路上
  （本人为该链路机构/部门的负责人/管理员）时，返回 `SYS_ORG_ADMIN`（完整列）；否则返回 `SYS_ORG_USER_VISITOR`（受限列）；
- 落地方式一：`SysOrgUserMapper` 的 `BaseColumns`（完整列）与 `NormalColumns`（脱敏列：登录名不可见、
  电话/邮箱/地址脱敏）由 `selectByIdWithFields` / `selectListWithFields` 按可见性标识二选一；
- 落地方式二：`SysOrgElementService` 列表查询对返回 VO 再做一次登录名裁剪兜底；
- 模型 `SysOrgUser.fieldPassword` 标注 `@JsonProperty(WRITE_ONLY)`，任何响应永不回显密码。

## 3. 各服务业务规则

### 3.1 SysOrgElementService（组织架构元素）

- `list` / `count`：按 `parentId`（空=根级，SQL 兼容 `field_parent_id IS NULL OR ''`）、名称/编码模糊、类型、启用状态过滤；
  排序走白名单（`createTime` / `updateTime` / `code`，默认创建时间降序），防注入；
- `load`：主表 + 按类型归一的扩展字段（父级名称、负责人名称经 JOIN 元素表取得）；
- `save`：写主表 + 类型扩展表；`rebuildHierarchy` 计算 `field_hierarchy` / `field_level`（父级 hierarchy 前缀 + 自身 id，level = 父 level + 1）；
- `update`：父级变更语义——请求未携带 `fieldParentId`（null）= 保留原值；携带空串 = 移至根级；
  `validateParentChange` 防环（新父 hierarchy 以旧 id 为前缀则拒绝）；父级变更后 `rebuildChildren` 递归修正子树的
  hierarchy / level；父级未变更时恢复请求未携带的 hierarchy / level（通用 update 对 field_level 无条件赋值，必须回填防清空）；
- 扩展表保护：`hasOrgFields / hasDeptFields / hasPostFields` 为空时跳过对应扩展表 update，防止空 SET 清空扩展数据；
- `updateEnable`：仅更新自身 `field_enable` 与修改人/时间，不级联后代；
- `delete`：物理删除（主表 + 对应类型扩展表同事务），仅允许无直接下级（`countChildren = 0`）。

### 3.2 SysOrgUserService（人员/登录）

- `insert` / `update` 校验：登录名不可为邮箱格式、不可为 11 位纯手机号；登录名唯一（库上 `uk_org_user_login_name` 兜底）；
  电话/邮箱在人员间唯一；密码策略见 3.3；
- `login`：按登录名查（开启邮箱登录时邮箱可登录、开启电话登录时 11 位手机号可登录，配置见第 5 节）→
  `PasswordUtil.matches` 校验 BCrypt 哈希 → 校验 `field_enable` 与 `field_account_status`（仅 NORMAL 可登录）→
  更新最后登录时间 → 组装 roles / auths / posts / virtuals（权限码列表）→ 返回前清空密码；
  登录响应 `metadata` 携带 `X-Login-Token` 与 `forceChangePwd` 标记；
- `changePassword`：长度 6–32 校验 → 历史重复校验（`sys_org_pwd_history` 全量比对，最近 N 次由配置决定）→
  encode 后仅更新 `field_password` + `field_last_chg_pwd_time`（专用 SQL `updatePassword`）→
  写 pwd_history（version = max+1）→ `deleteExcess` 只保留最近 N 条；
- `isPasswordChangeRequired`：改密周期配置 ≤ 0 时关闭；`field_last_chg_pwd_time` 为空视为需改密；
  距上次改密天数 ≥ 周期时返回 true（`checkPwdChange` 接口与登录 metadata 共用）。

### 3.3 密码策略常量（SysOrgUserService）

| 常量 | 值/含义 |
| --- | --- |
| `PASSWORD_MIN_LENGTH` / `PASSWORD_MAX_LENGTH` | 6 / 32 |
| `EMAIL_PATTERN` / `PHONE_11_PATTERN` | 登录名禁用形态（邮箱格式 / 11 位纯数字） |
| `KEY_PWD_REPEAT_LIMIT` | 新密码不得与最近 N 次相同（common_setting，TYPE_SYSTEM） |
| `KEY_PWD_CHANGE_CYCLE` | 定期改密周期（天，≤0 关闭） |
| `KEY_LOGIN_EMAIL_ENABLE` / `KEY_LOGIN_PHONE_ENABLE` | 邮箱/电话登录开关 |

### 3.4 SysOrgRoleService（角色/权限维护）

- `saveRole` / `updateRole`：主表字段 + 全量替换 `sys_org_role_element` / `sys_org_role_auth`（先删后插，同事务）；
  update 的 `field_code` 无条件赋值（允许清空）；
- `authOptions`：权限按 `sys_org_auth.field_model` 分组返回（分组标题取各模块 application.yml 的 `MODEL_NAME`）；
- 系统内置管理员角色：`SYSTEM_ADMIN_ROLE_ID = "0".repeat(32)`，`ensureSystemAdminRole` 幂等创建并绑定管理员用户；
- 角色删除、启停用接口未提供。

### 3.5 SysOrgRolePreviewService（权限预览）

- 节点类型：`element`（组织架构）/ `role`（角色）/ `auth`（权限）；
- 用户节点（`field_org_type = 3` 且非虚拟）的角色按登录模型同一四来源取：直属人员元素、所属岗位、所属虚拟组织、
  直属组织架构链路（机构/部门）；
- 虚拟组织不展开上级（防 虚拟 ↔ 上级 互相引用成环）。

### 3.6 SysOrgAddressBookService（地址本）

- 只读查询主表，仅返回启用节点；
- `tree`：`parentId` 为空返回根级；`limitRange` 非空时以范围节点为根，且「范围内」= 节点自身在范围内或其任一祖先在范围内
  （`field_hierarchy LIKE '%/{id}/%'` 匹配）；
  SQL 内固定追加 `AND field_org_type NOT IN (5, 6)`，**角色/群组永久不进入地址本树**（即使调用方传入 `orgTypes`）；
- `list`：仅关键字分页查询，保持通用（传 `orgTypes = [5]` 即返回角色分页，供「角色」页签复用）；
  `load`：按 id 列表回填展示信息，不做类型/范围过滤;
- 组织管理页右侧列表（`SysOrgElementMapper#VoWhereClause`，`selectVoList` / `countVoList` 共用）同样固定追加
  `AND e.field_org_type NOT IN (5, 6)`，避免角色镜像行与群组行因 `field_parent_id IS NULL` 命中根级分支。

## 4. 启动任务（SysStartupTask）

org 模块相关的启动初始化依序执行：

| 序 | 任务 | 说明 |
| --- | --- | --- |
| 1 | `initAdminUser` | 创建内置管理员（`ADMIN_USER_ID = "0".repeat(32)`，登录名 admin），密码经 BCrypt 加密走标准 insert（同落 pwd_history） |
| 2 | `syncAuthsFromRolesYml` | 将 `properties/sys/org/roles.yml` 的 ROLE_LIST/ROLE_MAP 增量同步到 `sys_org_auth`（不覆盖人工数据） |
| 3 | `ensureSystemAdminRole` | 幂等创建 SYS_ADMIN 角色并绑定管理员用户 |
| 4 | `cacheModelNames` | 缓存各模块 application.yml 的 MODEL_KEY/MODEL_NAME（权限分组标题来源） |

后续 `registerSysTasks` / `syncSettingsFromYml` / `syncDictFromYml` 为全局任务（任务注册、SETTING 段、dict.yml 码值导入）。

## 5. 配置约定

- `properties/sys/org/roles.yml`：权限码中文名与描述（7 个 `SYS_ORG_*` 权限码，含 v1.1 新增的 `SYS_ORG_GROUP_ADMIN` 群组管理员），由启动任务增量同步；
- `properties/sys/org/dict.yml`：`org_element_type`（1 机构/2 部门/3 人员/4 岗位/5 角色/6 群组）、`org_account_status`（0 禁用/1 正常/2 锁定/3 密码过期/4 注销）、`org_job_status`（0 离职/1 在职/2 停职/3 休假）、`org_group_type`（`COMMON` 公共/`PERSONAL` 个人）；
- `properties/sys/org/application.yml`：`MODEL_KEY = SYS-ORG`、`MODEL_NAME = 组织架构和权限模块`，另有 process_template 分类供流程模块取审批人字段；
- 密码策略与登录开关配置键常量定义于 `common/setting/properties/CommonSettingProperties`（`KEY_PWD_REPEAT_LIMIT = "pwd_repeat_limit"`、`KEY_PWD_CHANGE_CYCLE = "pwd_change_cycle"`、`KEY_LOGIN_EMAIL_ENABLE = "login_email_enable"`、`KEY_LOGIN_PHONE_ENABLE = "login_phone_enable"`，TYPE_SYSTEM 段），存于 `common_setting`，经 `CommonSettingService` 读取，覆盖顺序：环境变量 `CS_*` > SETTING 默认值 > 代码兜底。

## 6. 关键 SQL（Mapper XML 要点）

| XML | 要点 |
| --- | --- |
| SysOrgElementMapper.xml | `VoBaseColumns`（父级名称 JOIN + CASE 归一 leader/phone/email/address）、`VoWhereClause`（固定 `field_org_type NOT IN (5, 6)` 排除角色/群组 + parentId 空 → `field_parent_id IS NULL OR ''`，`selectVoList` / `countVoList` 共用）、`selectVoList` 白名单排序、`updateEnable` / `updateHierarchy` / `updateParentId` / `countChildren` |
| SysOrgUserMapper.xml | `BaseColumns` / `NormalColumns` 双列集合、insert 仅扩展列（公共列由 Dao 双写主表）、`updatePassword` 专用、`selectByLoginName/Email/Phone`（LoginResultMap 含 password，仅登录用）、`selectByIdWithFields` / `selectListWithFields`（按可见性切列） |
| SysOrgAddressBookMapper.xml | `selectTree` 固定 `field_org_type NOT IN (5, 6)`（角色/群组不进入树）、`limitRange` 过滤（`hierarchy LIKE`）、仅启用节点；`selectList` 保持通用（`orgTypes = [5]` 返回角色，供角色页签） |
| SysOrgRoleMapper.xml | `selectListByUserId` / `selectIdNameListByUserId`（四来源 UNION，见 3.5）、role_element / role_auth 增删查 |
| SysOrgUserPwdHistoryMapper.xml | `deleteExcess`（保留最近 N 条，LIMIT 大数 + OFFSET 写法） |

## 7. 异常与约束回查

| 场景 | 行为 |
| --- | --- |
| 未登录访问鉴权接口 | 抛 `UNAUTHORIZED`（GlobalExceptionHandler 统一返回） |
| 已登录无权限 | 抛 `FORBIDDEN` |
| 登录名/密码错误、账号禁用、账号状态异常 | 登录接口 `IllegalArgumentException`，统一错误文案「账号或密码错误」（不泄露具体原因） |
| 新父级为自身或后代 | `validateParentChange` 拒绝（防环） |
| 删除存在直接下级的节点 | 拒绝删除 |
| 密码长度不符 / 与历史重复 | changePwd 拒绝并提示 |
| 请求携带密码调 update | 一律忽略（密码仅经 changePwd 修改） |
