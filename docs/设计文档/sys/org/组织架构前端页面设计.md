# 组织架构前端页面设计

> 本文档描述组织架构（org）模块前端页面的路由、布局与交互，依据现有实现
> （`frontend/src/views/org/` 9 个页面、`frontend/src/api/org.js`、`frontend/src/router/index.js`、`frontend/src/views/HomeView.vue`、公共组件 `AddressBook.vue` / `ChangePwdDialog.vue`）回写。
> 后端接口约定见 [组织架构接口清单.md](./组织架构接口清单.md)，数据结构见 [组织架构表结构.md](./组织架构表结构.md)。

## 1. 页面目标与入口

- 页面清单：

| 页面 | 路由 | 组件 | 菜单入口 | 路由权限（meta.auth） |
| --- | --- | --- | --- | --- |
| 组织架构管理 | `/org` | OrgManageView.vue | 组织架构 → 当前组织架构（所有登录用户可见） | 无（登录即可） |
| 新建组织架构 | `/org/create` | OrgFormView.vue（新建模式） | 无菜单（列表页「创建」按钮进入） | 无（按钮按权限显隐） |
| 编辑组织架构 | `/org/edit/:id` | OrgFormView.vue（编辑模式） | 无菜单 | 无；动态路由 `meta.tab: 'name'` |
| 组织架构详情 | `/org/detail/:id` | OrgDetailView.vue | 无菜单 | 无；动态路由 `meta.tab: 'name'` |
| 角色管理 | `/role` | RoleManageView.vue | 系统管理 → 权限管理 → 角色管理 | SYS_ORG_ROLE_ADMIN / SYS_ORG_ADMIN |
| 新建角色 | `/role/create` | RoleFormView.vue（新建模式） | 无菜单 | 同角色管理 |
| 编辑角色 | `/role/edit/:id` | RoleFormView.vue（编辑模式） | 无菜单 | 同角色管理；`meta.tab: 'name'` |
| 权限预览 | `/rolePreview` | RolePreviewView.vue | 系统管理 → 权限管理 → 权限预览 | SYS_ORG_ROLE_ADMIN / SYS_ORG_ADMIN |
| 群组管理 | `/org/group` | GroupManageView.vue | 组织架构 → 群组（所有登录用户可见）+ 顶栏「多人」图标双入口 | 无（登录即可，数据按可见性过滤） |
| 新建群组 | `/org/group/create` | GroupFormView.vue（新建模式） | 无菜单（列表页「创建」按钮进入） | 无（登录即可） |
| 编辑群组 | `/org/group/edit/:id` | GroupFormView.vue（编辑模式） | 无菜单 | 无；动态路由 `meta.tab: 'name'` |
| 群组详情 | `/org/group/detail/:id` | GroupDetailView.vue | 无菜单 | 无；动态路由 `meta.tab: 'name'` |
| 个人资料 | `/profile` | ProfileView.vue | 无菜单（顶栏用户区下拉【个人信息】进入，v1.2） | 无（登录即可，本人自助不设权限码） |

- 页面类型：列表/树页（左右双栏）+ 独立表单页 + 独立详情页 + 权限预览页（左右双栏）+ 三段式列表页（群组，无左侧树）+ 本人自助表单页（个人资料，三卡片纵向堆叠）。
- 主要角色：组织架构管理员、人员维护者、权限管理员、群组管理员；群组页面对所有登录用户开放（数据级可见性过滤：个人群组仅本人、公共群组按可见范围，管理员全部）；个人资料页为登录用户本人。
- 路由守卫（`router/index.js`）：未登录访问业务页重定向登录页；访问声明 `meta.auth` 的页面且无对应权限时重定向首页（菜单已按权限过滤）；`/changePwd` 强制改密页仅需登录态。
- 菜单高亮：`HomeView.vue` 的 `activeMenu` 将 `/org/group*` 先归约到 `/org/group`（判断在 `/org/` 之前，避免群组页被误归约、误高亮「当前组织架构」）、其余 `/org/*` 归约到 `/org`、`/role/*` 归约到 `/role`，子路由（新建/编辑/详情）保持列表页菜单项高亮；`/profile` 不落任何菜单前缀、不参与归约（无菜单归属，高亮为空即可）。
- 顶部标签卡片：新建/编辑页保存成功后、详情页返回后经 `markTabToClose(route.path)` 关闭自身标签并跳回列表页。
- 群组双入口：左侧菜单「组织架构 → 群组」+ 顶栏「多人」图标按钮（均无权限要求，菜单 auth 为空串，所有登录用户可见）。
- 列表页刷新：`OrgManageView` / `RoleManageView` / `GroupManageView` 为 KeepAlive 页签，`onActivated` 二次进入时重载列表（首次进入由 `onMounted` 加载，保留筛选与分页状态）。
- 顶栏用户区（v1.2）：头像 + 用户名 + 部门名外包 `el-dropdown`（`trigger="hover"`），下拉项【个人信息】（跳 `/profile`）与【退出登录】（复用既有登出链路 `handleLogout`：logout 接口 → 清 store / localStorage / 标签页记录 → 提示）；独立【登出】按钮已移除。头像优先图片头像（本人资料 `avatarAttId` 经 `profileStore` 统一 blob 加载），无头像回退用户名首字符 `el-avatar`；资料页换头像后经同一 store 即时同步顶栏。

## 2. 组织架构管理页布局

```text
┌──────────────────────────┬────┬──────────────────────────────────────────────┐
│     左侧：组织架构树        │ 拖 │  筛选条件区（四分栅栏：名称 | 编号 | 类型 | 启用状态） │
│   ▸ 根节点                │ 拽 │──────────────────────────────────────────────│
│     ▸ 机构A               │ 条 │  排序区（创建时间/更新时间/编码）│ 按钮区（查询/创建/置为无效） │
│       ▸ 部门A-1           │    │──────────────────────────────────────────────│
│       ▸ 部门A-2           │    │  分页查询结果列表（首列复选框，末列：详情/编辑/停用启用）      │
│     ▸ 机构B               │    │                                              │
└──────────────────────────┴────┴──────────────────────────────────────────────┘
```

- 默认 25% : 75% 左右分栏，中间拖拽条可手动调整占比（限制 15% ~ 40%）。
- 右侧区域自上而下：筛选条件区 → 排序区/按钮区 → 分页结果列表。

## 3. 左侧树

- 以「根节点」为树头虚拟入口（`__root__`），懒加载展开。
- 树节点仅查询机构（`field_org_type = 1`）与部门（`field_org_type = 2`）两类节点，调用
  `POST /backend/sys/org/addressbook/tree`（`orgTypes: [1, 2]`）。
- 节点前置图标区分类型：机构使用办公建筑图标（橙），部门使用学校图标（绿），根节点使用首页图标（蓝）。
- 默认展开「根节点」并点中它；点击任意节点后，右侧列表切换为查询该节点的直接下级
  （根节点 → `field_parent_id` 为空）。

## 4. 右侧列表区

### 4.1 筛选条件区

四分栅栏排列（`el-row` + `el-col :span="6"`）：

| 字段 | 控件 | 默认值 |
| --- | --- | --- |
| 名称 | 文本输入（模糊匹配） | 空 |
| 编号 | 文本输入（模糊匹配） | 空 |
| 类型 | 下拉：不限/机构/部门/人员/岗位 | 人员 |
| 启用状态 | 下拉：不限/启用/停用 | 启用 |

类型与启用状态选项来自 dict 码值（`org_element_type` / `yes_no`），首项「不限」（值为 null），查询条件为空时后端不过滤。

### 4.2 排序区与按钮区

- 排序区提供三个可排序字段：创建时间、更新时间、编码；仅允许单条件排序。
- 默认选中「创建时间 + 降序」；点击已选中字段切换升/降序，点击未选中字段选中并默认降序。
- 选中项样式：外框 + 文本结尾上下箭头（↓ 降序 / ↑ 升序）；未选中项无外框。
- 按钮区：查询（按当前筛选/排序刷新，回第 1 页）、创建（跳转 `/org/create`，携带当前点中树节点与当前类型筛选作为默认上级/类型 query：`parentId`/`parentName`/`orgType`）、置为无效（对勾选行逐条调用删除接口，二次确认，完成后整树重新挂载刷新）。
- 按钮区权限显隐（前端按登录用户权限码预判，最终由后端 `ElementResolver` 兜底）：创建、置为无效按钮需 `SYS_ORG_ADMIN` / `SYS_ORG_ELEMENT_ADMIN` / `SYS_ORG_ELEMENT_ADD`（系统管理员 `SYS_ADMIN` 自动放行）任一权限才显示；查询按钮所有登录用户可见。

### 4.3 分页结果列表

- 首列为复选框列，末列为操作列（详情 / 编辑 / 停用或启用），不展示任何 id 字段。
- 列表列根据查询类型动态展示：

| 查询类型 | 列表字段 |
| --- | --- |
| 机构 | 名称、编码、负责人、联系电话、联系邮箱、联系地址、状态、创建时间 |
| 部门 | 名称、编码、负责人、联系电话、联系地址、状态、创建时间 |
| 人员 | 姓名、工号、登录名、性别、联系电话、联系邮箱、状态、创建时间 |
| 岗位 | 名称、编码、状态、创建时间 |
| 不限（兜底） | 名称、编码、类型、状态、创建时间 |

- 类型筛选选「不限」时由公共列兜底展示；枚举值经 dict 码值转文本（类型、性别、启用状态）。
- 操作列按钮：详情（跳转 `/org/detail/:id`）、编辑（跳转 `/org/edit/:id`）、停用/启用（二次确认，行内切换）。
- 操作列权限显隐（前端按登录用户权限码预判，最终由后端 `ElementResolver` 兜底）：编辑、停用/启用按钮需 `SYS_ORG_ADMIN` / `SYS_ORG_ELEMENT_ADMIN` / `SYS_ORG_ELEMENT_EDIT`（系统管理员 `SYS_ADMIN` 自动放行）任一权限才显示；无编辑权限时操作列仅显示详情（列宽相应收窄）。
- 分页组件：`total, prev, pager, next, sizes`，页大小 10/20/50/100，切页大小回第 1 页；总数取 `metadata.total`。

## 5. 新建 / 编辑页（独立路由，`OrgFormView.vue`）

- 页面宽度 100%；表单字段名与字段值按 2:3 固定比例排版（`label-width="40%"`，两列栅格布局下每个字段行内 label 占 40%、内容占 60%）。

- 新建模式（`/org/create`）：打开时先调用 `GET /backend/common/initID` 预取 32 位对象 ID 赋给 `fieldId`（遵循 docs/开发规范.md 第 9 节）；默认上级/类型取自列表页路由 query（`parentId`/`parentName`/`orgType`），缺省根节点 + 机构；二次从列表页进入时实例复用，监听 route query 变化同步默认值。
- 编辑模式（`/org/edit/:id`）：按路由 id 调用 `GET /backend/sys/org/element/load` 回填表单；保存调用 `PATCH /update`。
- 保存成功后关闭标签卡片并返回 `/org` 列表页；新建/编辑共用同一表单组件，按路由区分模式。
- 公共字段：名称（必填）、编码（必填）、类型（新建可选、编辑禁用）、上级（地址本选择，仅机构/部门）、是否虚拟组织、启用状态。
- 机构专有字段：负责人（地址本选人员）、联系电话、联系邮箱、联系地址。
- 部门专有字段：负责人、联系电话、联系地址。
- 人员专有字段：登录名（必填，前端预校验不可为邮箱格式/11 位纯手机号）、密码（仅新建必填；编辑/查看页不在表单维护密码，通过按钮区「修改密码」弹窗修改，保存时未填的密码字段从请求体中删除）、性别（默认男）、生日（日期选择）、在岗状态（默认在职）、联系电话、联系邮箱、联系地址。
- 岗位专有字段：负责人。
- 类型/在岗状态/性别下拉选项由 dict 码值提供（`org_element_type` / `org_job_status` / `gender`，number 值）。
- 编辑模式按钮区（返回 + 修改密码 + 保存）：当编辑对象为人员（类型=3）且当前用户具备修改密码权限（`SYS_ORG_ADMIN` / `SYS_ORG_USER_MANAGER`，或为本人）时，显示「修改密码」按钮；点击弹出修改密码弹窗（输入新密码 + 二次确认，两值一致且非空校验），提交调用 `PATCH /backend/sys/org/user/changePwd`，成功后关闭弹窗并提示。
- 保存按钮权限显隐：新建模式需 `SYS_ORG_ADMIN` / `SYS_ORG_ELEMENT_ADMIN` / `SYS_ORG_ELEMENT_ADD`（系统管理员 `SYS_ADMIN` 自动放行）任一权限才显示；编辑模式需 `SYS_ORG_ADMIN` / `SYS_ORG_ELEMENT_ADMIN` / `SYS_ORG_ELEMENT_EDIT` 任一权限才显示。无保存权限时按钮区仅剩返回（及可用的修改密码），最终由后端 `ElementResolver` 兜底。
- 新建模式按钮区（返回 + 保存）：不提供修改密码（新建时通过表单密码字段设置初始密码）。

## 6. 详情页（独立路由，`OrgDetailView.vue`）

- 路由 `/org/detail/:id`，按 id 调用 `GET /backend/sys/org/element/load` 加载后只读展示，页面提供「返回」「编辑」按钮（编辑跳转 `/org/edit/:id`）。
- 「编辑」按钮权限显隐：需 `SYS_ORG_ADMIN` / `SYS_ORG_ELEMENT_ADMIN` / `SYS_ORG_ELEMENT_EDIT`（系统管理员 `SYS_ADMIN` 自动放行）任一权限才显示；无编辑权限时按钮区仅剩返回（及可用的修改密码），最终由后端 `ElementResolver` 兜底。
- 按钮区：当详情对象为人员（类型=3）且当前用户具备修改密码权限（`SYS_ORG_ADMIN` / `SYS_ORG_USER_MANAGER`，或为本人）时，额外提供「修改密码」按钮；点击弹出修改密码弹窗（输入新密码 + 二次确认，校验同编辑页），提交调用 `PATCH /backend/sys/org/user/changePwd`。
- 排版与新建/编辑页保持一致：默认一行两字段，字段名:字段值 = 2:3（label 40% / 内容 60%）；长内容字段（联系地址）一行一字段，字段名:字段值 = 2:8（label 20% / 内容 80%）。
- 实现方式：自定义 flex 网格（`form-page.css` 的 `.detail-grid` / `.detail-item` / `.is-full`），不使用 `el-descriptions`（其非垂直模式单元格 colspan 恒为 1，无法实现长字段整行 2:8 布局）；两列布局的奇偶占位以空占位项补齐（`buildDetailGridFields`）。
- 按节点类型动态组装字段：公共字段名称、编码、类型、上级、是否虚拟、启用状态（el-tag 标签）、创建时间、更新时间；机构/部门/岗位展示负责人；机构/部门/人员展示联系电话、联系地址（长字段）；机构/人员展示联系邮箱；人员额外展示登录名、性别、生日、在岗状态。枚举值经 dict 码值转文本。

## 7. 角色管理页（`RoleManageView.vue`，`/role`）

- 三段式列表页（筛选区 → 工具区 → 列表区），白底卡片容器。
- 筛选条件区：角色名（文本）、编码（文本）、是否启用（下拉：不限/是/否，dict `yes_no`，默认「是」）；输入框回车触发查询。
- 工具区：左侧排序区（创建时间/更新时间/编码，单条件排序，默认创建时间降序，交互同 4.2）；右侧按钮区（查询、创建）。
- 列表区：**无复选框列**（角色禁止批量操作，无启停用/删除操作列）；列 = 角色名、编码、创建时间、更新时间、是否启用（el-tag：启用 success / 停用 danger）；末列操作列（编辑，跳转 `/role/edit/:id`）。
- 页面入口由菜单与路由 `meta.auth`（SYS_ORG_ROLE_ADMIN / SYS_ORG_ADMIN）控制，页面内按钮不再做权限预判，最终权限由后端 `RoleResolver` 兜底。
- 分页组件与页大小同 4.3；总数取 `metadata.total`。

## 8. 角色新建 / 编辑页（`RoleFormView.vue`，`/role/create`、`/role/edit/:id`）

- 新建模式：`onMounted` 先经 `getInitID()` 预取 32 位 ID，并加载权限可选项；编辑模式：按路由 id 调用 `GET /backend/sys/org/role/load` 回填（含关联组织架构与已选权限）。
- 表单字段：

| 字段 | 控件 | 必填 | 说明 |
| --- | --- | --- | --- |
| 角色名 | 文本输入 | 是 | sys_org_role.field_name |
| 编码 | 文本输入 | 否 | 权限码（前端 hasAuth 判定依据），编辑可清空 |
| 是否启用 | el-switch | 是 | 默认启用 |
| 组织架构 | AddressBook 组件（multi，org-type=ALL） | 否 | 地址本复选，独占一行（label 20% / 内容 80%），关联 sys_org_role_element |
| 权限 | 按 `sys_org_auth.field_model` 分组 Card 复选 | 否 | 独占一行（label 20% / 内容 80%）；可选项经 `GET /backend/sys/org/role/authOptions` 加载，分组标题取各模块 MODEL_NAME；已选项回显自 `authIds` |

- AddressBook 多选值以 `;` 分隔（`elementIdsText` / `elementNamesText`），保存时拆分回 `elementIds` 数组；
- 保存请求体 `{ fieldId, fieldName, fieldCode, fieldEnable, elementIds, authIds }`：新建 POST `/save`、编辑 PATCH `/update`（关联表全量替换）；成功后关闭标签卡片返回 `/role`。
- 页面入口由菜单与路由 `meta.auth` 控制，页面内不设权限预判，最终权限由后端 `RoleResolver` 兜底。

## 9. 权限预览页（`RolePreviewView.vue`，`/rolePreview`）

- 左右双栏（默认 25%，拖拽限制 15%~40%），白底卡片容器。
- 左侧树：懒加载地址本树，`orgTypes: [1, 2, 3, 4]` 全类型（后端仅返回启用节点）；根节点虚拟入口 `__root__`；节点图标按类型区分（机构橙/部门绿/人员蓝/岗位灰，虚拟组织红星，根节点蓝）。
- 节点点击：仅「人员且非虚拟组织」节点发起权限预览（`POST /backend/sys/org/preview/preview`），其他节点清空右侧展示、不发起请求。
- 右侧展示：单字段列表格（无表头），行为——组织架构名称、关联组织架构（el-tag 列表，来自 `sys_org_role_element`）、角色列表（el-tag，四来源汇总，停用角色灰色）、权限列表（el-tag warning，名称+编码）、权限树。
- 权限树（嵌入表格单元格，懒加载 `POST /backend/sys/org/preview/treeChildren`）：根为选中组织架构；`element` 节点展开直接关联角色、直属上级组织架构与直接关联虚拟组织（子节点带来源前缀，如「岗位：xxx」）；`role` 节点展开直接绑定权限；`auth` 为叶子。切换人员节点时权限树重挂并默认展开根节点。
- 虚拟组织不展开上级组织架构（防虚拟 ↔ 上级互相引用成环，与后端一致）。
- 页面入口由菜单与路由 `meta.auth` 控制，最终权限由后端 `RoleResolver` 兜底。

## 10. 群组管理页（`GroupManageView.vue`，`/org/group`，v1.1）

- 三段式列表页（筛选区 → 工具区 → 列表区），白底卡片容器，**无左侧树**（群组不参与组织架构树，树字段 NULL/level 1）。
- 筛选条件区：名称（文本）、类型（下拉：不限/公共/个人，dict `org_group_type`）、是否全员可见（下拉：不限/是/否）；回车触发查询。
- 工具区：左侧排序区（创建时间/更新时间/名称，单条件排序，默认创建时间降序，交互同 4.2）；右侧按钮区（查询、创建、删除）——创建按钮对所有登录用户可见（普通用户进表单后类型锁定个人）；删除为批量操作，仅对勾选中可管理的行生效（无权限行跳过并在确认与结果中提示）。
- 列表区：首列复选框（批量删除）；列 = 名称、类型、成员数、所有人、全员可见、状态（el-tag）、创建时间；末列操作列（详情始终显示，编辑/删除按行级 `canManage` 显隐，与后端 `checkMaintainable` 同口径：管理员可全部公共群组与自己的个人群组，普通用户仅自己的个人群组）。
- 数据按当前登录人可见性过滤（VisibleClause，见核心业务设计「群组管理」）；分页组件与页大小同 4.3，总数取 `metadata.total`。

## 13. 个人资料页（`ProfileView.vue`，`/profile`，v1.2）

- 本人自助页面：登录即可访问（后端 `ProfileResolver` 不设权限码，登录且账号启用即可），无菜单归属——菜单配置无新增项、`activeMenu` 归约不处理（`/profile` 不落任何菜单前缀，高亮为空）；路由 `path: '/profile'`、`name: 'OrgProfile'`、`meta: { title: '个人资料', tab: 'name' }` 复用单标签；不设 parent（面包屑仅「个人资料」）与 `meta.auth`。
- 入口：顶栏用户区下拉【个人信息】（见第 1 节顶栏用户区说明）。
- 布局：`el-card` 三卡片纵向堆叠（间距 16px），公共类复用 `styles/form-page.css`（`page-card` / `page-header` / `page-form`），页面专属样式仅头像区与关联账号渠道行。

### 13.1 头像卡片

- 64px 圆形预览：`profileStore.avatarUrl` 存在渲染 `<img>`（blob URL），否则回退登录用户名首字符 `el-avatar`（与顶栏同口径）。
- 【上传头像】（`el-upload` 手动、不配 action、`accept="image/*"`、不显示文件列表）：选中文件后按 `Attachment.vue` 先例组装 FormData `{file, modelName="sys_org_user", modelId=登录用户ID, key="profile"}` 调附件 upload 接口；取返回附件 `fieldId` 后删除旧头像附件（删除失败仅提示「旧头像清理失败，不影响新头像使用」，不回滚本次上传），经 `profileStore.applyAvatarAttId` 刷新——顶栏 `HomeView` 消费同一 store 即时同步。
- 【移除头像】：二次确认后删除附件并经 `profileStore.applyAvatarAttId(null)` 清空（顶栏即时回退首字符）；当前无头像时按钮禁用。
- 单张语义：`profile/load` 返回的 `avatarAttId` 取 `sys_att_main` 中 `modelName+modelId+key=profile` 且 `field_enable=1` 的 `field_create_time` 降序最新一条。

### 13.2 基本资料卡片（保存按钮置 `el-card #header` 的 `.header-btns`）

| 字段 | 控件 | 校验 / 说明 |
| --- | --- | --- |
| 用户名 | 文本输入 | 必填「请输入用户名」；保存后端同步 `sys_org_element.field_name` 并重算拼音两列（组织架构树与拼音检索即时反映新名） |
| 登录名 | 文本输入 disabled（placeholder「登录名不可修改」） | 只读，不参与提交（后端亦不更新） |
| 手机号 | 文本输入 | 非空时 `^1[3-9]\d{9}$`，blur 触发 |
| 邮箱 | 文本输入 | 非空时邮箱格式，blur 触发 |
| 性别 | 下拉（0=其他 1=男 2=女，码值与后端 dict gender 一致，文案同 `OrgFormView` 先例） | 默认男 |
| 生日 | `el-date-picker`（type=date，`YYYY-MM-DD`） | 可空，不晚于当天（自定义 validator） |
| 联系地址 | textarea（`maxlength=500`、`show-word-limit`、3 行） | 长度 ≤ 500；长内容一行一字段（`:span="24"`） |

- 排版：`label-width="40%"` + `:span="12"`（一行两字段），地址除外。
- 保存：前端 validate 通过后回传登录态 `fieldId`（`userStore.userInfo.fieldId`）供后端一致性断言，`saveProfile` 成功提示「保存成功」并重载 `loadProfile` 回显落库后最新数据；登录态缺失提示警告不发请求。

### 13.3 关联账号卡片

- `openidBindEnabled=false`（默认）：整卡 `el-alert`（info、不可关闭）「第三方账号绑定未开启(管理员可在系统设置中开启)」，不渲染渠道行。
- 开启后微信 / QQ 各一行（`el-row` 三栏 `4/13/7`）：
  - 未绑定：显示「未绑定」+【绑定】按钮；
  - 已绑定：显示「已绑定:第三方昵称(绑定时间:bindTime 原样展示)」+【解绑】按钮（二次确认「确定解除绑定的{渠道名}账号吗?」，成功后重载）；
  - 渠道凭证未配置（`wechatEnabled` / `qqEnabled=false`）：绑定按钮禁用，行尾灰字「未配置」（开关字段缺省视为已开启，避免后端未返回时误禁）。
- 【绑定】：调 `POST /openid/bindUrl` 取授权页地址后 `window.location.href` 整页跳转（跳转发起后本页卸载，失败恢复按钮态并提示）。
- 回跳结果提示：第三方 callback 以 `302` 回 `/profile?bind={channel}:{reason}`，`onMounted` 读 `route.query.bind` 渲染 `ElMessage`（`success` → success「{渠道}账号绑定成功」；`disabled` / `unconfigured` → warning；`expired` / `oauth_error` / `dup` → error，文案分别为「绑定会话已过期,请重新发起绑定」「第三方授权失败,请重试」「该{渠道}账号已被其他账号绑定」）后 `router.replace({ path: '/profile' })` 清理 query，防刷新重复提示。

### 13.4 头像跨页联动（profileStore）

- 顶栏 `HomeView` 与资料页 `ProfileView` 共享 `stores/profile.js` 的 `useProfileStore`：`applyAvatarAttId` 统一做附件 blob 拉取与失败回退（revoke 并置 null，回退首字符），`reset()` 登出时 revoke blob URL 使会话级缓存失效；头像上传 / 移除后顶栏即时同步。

## 16. 待确认事项

- 「置为无效」当前按物理删除实现（删除主表 + 扩展表）；如后续需要软删除/作废标记，需同步调整后端实现与表结构。
