# 公式定义器功能设计方案（v1.4）

- 公式定义器是本工程的**公共表达式服务**：公式解析校验引擎 + 函数注册中心 + 统一执行入口 + 可视化公式组件（FormulaDesigner 弹窗），不是某个表单的附属输入框。
- 落地顺序依据 [docs/开发计划.md](../开发计划.md) 依赖图：`公式定义器 → 自定义表单`、`公式定义器 → 流程管理改造`，须先于 v1.5 / v1.7 交付；v1.9 消息通知文本配置同样消费本模块。
- 模块 key 为 `formula`，包 `com.eric.base.sys.formula`，表 `sys_formula`，权限码 `SYS_FORMULA_ADMIN`。
- 源文档：[公式定义器-方案.md](公式定义器-方案.md)（需求）、[AI对公式定义器的开发建议.md](AI对公式定义器的开发建议.md)（外部建议，本文逐条裁决后吸收，冲突处以本仓库规范与需求文档为准）。

## 0. 需求还原与关键裁决

### 0.1 需求还原

| 需求点（公式定义器-方案.md） | 落地语义 |
| --- | --- |
| 支持对业务模型的字段读取（含如何让前端获取到业务模型字段） | 字段定义**不新建台账**：复用数据源模块 `GET /backend/sys/datasource/targets`（各模块 Provider 声明的 resultFields），公式组件左树「业务模型」节点由其聚合；运行期取值经注册函数 `DS_QUERY` 走数据源统一执行入口（A6/A7） |
| 支持对组织架构的字段读取 | 一期注入组织架构上下文系统变量（当前用户 / 部门，出自会话 `UserUtil`）；任意人员/部门字段读取由 org 模块注册取值函数承接，列二期（随 v1.7 审批人规则细化） |
| 公式计算（数字、数组、逻辑判断、日期、字符串、数据整合） | 后端表达式引擎（AviatorScript）+ 内置函数注册中心，九类函数见 §2.2 |
| 支持校验和模拟计算 | `POST /backend/sys/formula/validate`（语法/类型/依赖检查）+ `POST /backend/sys/formula/simulate`（受限沙箱试算）；组件右下模拟区即调这两个接口 |
| 相关模块代码存放在 `sys/formula` | 包 `com.eric.base.sys.formula`，根模块 `sys`；AI建议的 `common/formula` 不采纳（AGENTS 规定 common 包仅 base/cache/config/exception/properties/resolver/session/setting/utils 九类，业务模块一律在 sys 下，先例 datasource/number） |
| 组件：a-model 弹窗，左树 + 右上公式 + 右下模拟 | 本仓库前端为 Element Plus，`a-model` 落地为 `el-dialog` 弹窗组件 `components/formula/FormulaDesigner.vue`（§7） |

### 0.3 关键设计决策（ADR 摘要）

| # | 决策 | 理由 |
| --- | --- | --- |
| A1 | **校验与执行的唯一权威在后端**；前端编辑器只做输入辅助（高亮、插入、提示），不做最终语法裁决 | AI建议自身提示 Math.js 双引擎一致性风险；v1.4 不引入前端解析引擎，`validate` 接口即权威，避免前后端两套语法各自漂移 |
| A2 | 后端引擎选 **AviatorScript**（pom 新增依赖，版本以 `backend/pom.xml` 为准），不选 QLExpress / SpEL / 自研 AST | 见 §0.4 选型对比；沙箱可裁剪（类白名单、循环上限）、自定义函数注册自然（`getName()` + `execute`）、编译缓存成熟、支持 lambda/seq，JDK 21 兼容 |
| A3 | **函数走代码注册中心，不建 `sys_formula_function` 表**：内置函数由公式模块实现，模块扩展函数经 SPI `FormulaFunctionProvider` 注册 | 对齐数据源 A3（可执行逻辑必须代码承载，先例 `SysDatasourceProvider`）；函数清单经 `/functions` 接口暴露给前端，天然实现「前后端共用一份定义」；AI建议的注册表 JSON 结构直接作为 SPI 的元数据模型 |
| A4 | **业务模型/组织架构取值不直连 Mapper**：数据面只经两通道——上下文变量（消费方注入）+ 注册函数（`DS_QUERY` 走数据源入口、org 取值函数由 org 模块注册） | 公式引擎不持有任何业务查询逻辑；越权面与数据边界全部收口到既有模块（数据源已内置「执行期委托目标 action 鉴权」，先例 `SysDatasourceService#execute`） |
| A5 | **字段/变量引用统一 `${code}` 占位符**（扩展支持两级路径投影 `${list.field}`）；存储态即 `${}` 形态，执行前由引擎替换为合法标识符并构建映射 | 对齐既有两处先例：流程触发条件 `${field}`（`SysProcessTemplateService`）、数据源运行时变量 `${CURRENT_USER_ID}`（`SysDatasourceVar`）；变量码约束 `[a-zA-Z_][a-zA-Z0-9_]*`，替换无歧义可逆 |
| A6 | **左树数据源复用聚合、不另建模型字段表**：`/options` 返回「变量 + 业务模型（targets 聚合）+ 函数」三组节点 | 直接回答需求点「如何配置出可让前端获取到业务模型字段」——各模块声明 Provider 即自动进入公式组件，无需公式模块维护第二份字段台账（避免两处同步漂移） |
| A7 | 鉴权分层：命名公式管理接口 `SYS_FORMULA_ADMIN`；`options/functions/validate/simulate` **登录即可** | 公式组件被各业务页面内嵌使用（v1.5 表单设计者、v1.7 流程配置者未必持有公式管理角色）；数据边界由取数函数委托承担（A4）；模拟计算入参由调用方自负 |
| A8 | **公式间依赖联动（拓扑排序、循环检测）不进 v1.4**：一期只提供「单公式变量依赖提取」（save 时解析落 `field_dependencies`），联动执行归 v1.5 表单引擎 | AI建议第五节场景（A=数量×单价 → B/C 联动重算）本质是表单字段联动需求，需消费方的变更事件源；公式模块无变更事件源，提前实现是空转。表单引擎拿 `field_dependencies` 即可自建依赖图 |

### 0.4 引擎选型对比

| 方案 | 优势 | 劣势 | 结论 |
| --- | --- | --- | --- |
| AviatorScript | 轻量、编译缓存、函数注册自然、沙箱可裁剪（类白名单 / 循环上限 / 禁 Java 反射调用）、支持集合与 lambda | 需新增依赖 | **采用** |
| QLExpress | 规则场景表达力强 | 体积大、语法面宽（Java 调用面裁剪成本高）、社区活跃度一般 | 不采用 |
| SpEL | Spring 自带零依赖 | 语法面向 Spring 对象图，函数注册别扭；`SimpleEvaluationContext` 收紧后表达力不足 | 不采用 |
| 自研 AST | 语法完全可控 | 开发与测试成本高，v1.4 排期不允许 | 不采用（`${}` 解析层自研，语义层交给引擎，见 §2.1） |

## 2. 概念模型

### 2.1 表达式语法

公式文本 = **`${code}` 变量引用 + 注册函数调用 + 字面量与运算符**。示例：

```text
ROUND(${applyAmount} * ${taxRate}, 2)                      -- 数值计算
IF(${applyAmount} > 10000, "需部门审批", "无需审批")          -- 逻辑判断
SUM(${expenseDetails.fieldAmount})                          -- 明细汇总（路径投影）
CONCAT(${deptName}, "-", ${applicantName})                  -- 字符串整合
DATEDIFF(TODAY(), ${startDate}) > 3                         -- 日期比较（返回 BOOLEAN）
DS_QUERY("calendar.my-created", {"fieldName": "周报"})       -- 经数据源取数
```

| 语法元素 | 规则 | 说明 |
| --- | --- | --- |
| 变量引用 `${code}` | `code` ∈ `[a-zA-Z_][a-zA-Z0-9_]*`，由调用方在上下文声明 | 执行前引擎将 `${code}` 替换为标识符 `code` 并构建映射（A5）；显示层原样呈现 `${}`，消费方存什么算什么 |
| 路径投影 `${list.field}` | 仅两级；`list` 为数组变量，`field` 为元素 Map 的键 | 投影为字段数组后供集合函数消费，覆盖明细表汇总场景（行内计算 v1.4 直接对元素变量操作，随 v1.5 落地） |
| 函数调用 | 函数名全局唯一（注册中心查重），参数与返回类型按注册元数据校验 | 只允许调用注册过的函数（§6.3） |
| 运算符/字面量 | 交给 Aviator 词法/语法分析 | 校验错误行号、原因原样透出 |

### 2.2 函数体系与注册中心

内置函数九类（一期范围，名称与签名以代码注册元数据为准，`/functions` 接口透出）：

| 分类 | 函数（首批） | 用途 |
| --- | --- | --- |
| MATH 数学 | ABS、ROUND、CEIL、FLOOR、POWER | 数值计算 |
| LOGIC 逻辑 | IF、AND、OR、NOT、IFNULL | 条件判断 |
| COMPARE 比较 | EQ、NE、GT、GTE、LT、LTE | 数值/文本比较 |
| STRING 字符串 | CONCAT、SUBSTRING、LENGTH、TRIM、REPLACE | 字符串处理 |
| DATE 日期 | NOW、TODAY、DATEADD、DATEDIFF、YEAR、MONTH | 日期运算 |
| COLLECTION 集合 | SUM、AVG、MAX、MIN、COUNT、COUNTIF、SUMIF | 明细/数组统计（入参为变量或路径投影） |
| CONVERT 转换 | TO_NUMBER、TO_STRING、TO_DATE | 类型转换 |
| SYSTEM 系统 | CURRENT_USER、CURRENT_DEPT、CURRENT_ROLE | 会话上下文（服务端注入，不信任前端传值） |
| DATA 取数 | DS_QUERY(code, body) | 经数据源统一入口取业务模型数据（A4） |

**注册中心**：`FormulaFunctionRegistry`（启动期收集）+ SPI `FormulaFunctionProvider`（各模块实现，如 org 注册 `ORG_*`、datasource 注册 `DS_QUERY`）。函数元数据模型对齐 AI建议的 JSON 结构：`functionCode / functionName / category / description / parameters[{name,type,required,defaultValue}] / returnType`——同一份元数据既驱动前端函数面板与插入模板，也驱动后端参数类型校验，天然「前后端共用函数定义」。

### 2.3 两类公式与上下文

| | 内联公式 | 命名公式（`sys_formula`） |
| --- | --- | --- |
| 存放 | 消费方自身配置 JSON（如 v1.5 表单字段配置、v1.7 流程分支配置） | `sys_formula` 表，管理员维护 |
| 引用方式 | 配置里直接存 `expression` 文本 | 消费方按 `field_code` 引用，执行时加载启用中的公式 |
| 适用 | 绑定具体业务对象的一次性公式 | 跨模块复用的公共公式（如「含税金额」口径） |
| 校验/试算 | 同一套 `/validate` `/simulate` | 同一套，另在 save/update 时强制校验通过 |

`FormulaContext`（执行上下文，只读）：消费方传入变量表（包装为不可变 Map）+ 服务端注入系统变量（当前用户/部门/角色/时间，出自 `UserUtil`）。公式**无赋值能力**，不修改原始数据。

返回类型枚举 `SysFormulaReturnType`：`NUMBER / STRING / BOOLEAN / DATE / ARRAY`。`SysFormulaType`：`FIELD / CONDITION / VALIDATION / VISIBILITY / WORKFLOW / CUSTOM`（对齐 AI建议 formula_type 分类，仅作分类标记，不改变执行语义）。

## 3. 总体架构与执行流程

### 3.1 架构图

```text
消费方（v1.5 表单设计器 / v1.7 流程配置 / v1.9 通知配置 / 独立管理页）
   │ ①配置：components/formula/FormulaDesigner.vue（el-dialog 弹窗）
   │    GET /backend/sys/formula/options    → 左树（变量 / 业务模型 / 函数）
   │    GET /backend/sys/formula/functions  → 函数面板（分类/参数/说明）
   │ ②编辑：POST /backend/sys/formula/validate  { expression, expectedReturnType, vars[] }
   │ ③试算：POST /backend/sys/formula/simulate  { expression, vars{}, expectedReturnType }
   ▼
SysFormulaDesignerController ── authorize(sys.formula.*)            ← FormulaResolver（登录即可）
SysFormulaController        ── authorize(sys.formula.list|load|save|update|enable|delete)
                                                                    ← FormulaResolver（SYS_FORMULA_ADMIN）
   ▼
service/engine
   ├─ FormulaEngine            # 统一执行入口：${} 解析 → Aviator 编译（缓存）→ 受限执行 → 类型适配
   ├─ FormulaContext           # 只读变量上下文 + 系统变量注入
   └─ FormulaFunctionRegistry  # 内置函数 + SPI 收集（FormulaFunctionProvider）
   ▼
数据面（引擎不直连任何 Mapper）
   ├─ DS_QUERY → SysDatasourceService#execute（内部已委托目标 action 鉴权）
   └─ ORG_*   → org 模块注册的取值函数（二期）

命名公式管理面：/list /load /save /update /enable /delete → SysFormulaService → sys_formula
```

### 3.2 模拟计算时序（示例：含税金额）

```text
公式：ROUND(${applyAmount} * ${taxRate}, 2)
  1. 前端模拟区填入 vars = { applyAmount: 1000, taxRate: 0.13 }，POST /simulate
  2. FormulaResolver 放行（登录即可）→ SysFormulaSimulateService
  3. 资源限制检查：表达式长度 ≤ 上限、变量个数 ≤ 上限、变量值序列化体积 ≤ 上限
  4. FormulaEngine：解析 ${} → 变量码映射；Aviator 编译（命中 LRU 编译缓存则复用）
  5. 注入 FormulaContext（调用方 vars + 服务端系统变量；只读包装）
  6. 受限执行（独立执行线程 + 超时上限；Aviator Options.MAX_LOOP_COUNT 封顶）
  7. 结果类型适配（NUMBER → BigDecimal 规整），返回
  → 响应 { success: true, result: 130.00, resultType: "NUMBER" }
  任一步失败 → { success: false, errors: [{ code: "CS_FORMULA_*", message }] }，HTTP 仍 200，语义见 §5.3
```

### 3.3 依赖分析与联动边界

- save/update 及 validate 时解析表达式提取变量依赖，命名公式落 `field_dependencies`（JSON 数组）；内联公式由 validate 响应返回 `dependencies`，由消费方自行存储。
- 消费方（v1.5 表单引擎）以 `dependencies` 建有向图做联动重算、循环检测与失效引用检查（字段删除/禁用/改型）——**联动执行不在公式模块**（A8）。
- 公式引用失效变量（如字段下线）不阻断保存，由 validate 报告、消费方决定处置；命名公式启动期不做失效告警（变量本就是调用方运行期注入，静态无真相）。

| `sys_formula` | `KEY idx_formula_type (field_type)` | 按类型检索公式（消费方按类型+启用状态拉候选） |

说明：

- **不建** `sys_formula_function`（A3，代码注册中心）、**不建** `sys_formula_dependency`（A8，依赖落 JSON 列）、**不建** `sys_formula_version`（版本管理列三期，见 §9）。
- **不加** `business_type / business_id`（AI建议有）：v1.4 命名公式定位为全局公共公式库；业务私有公式走内联形态存消费方配置。待 v1.5/v1.7 出现「公式归属某个业务对象」的真实诉求再立项扩展，不在本期表结构预留。
- **不存** `expression_json`（AI建议建议双存）：执行以 Aviator 编译缓存为准，编辑器重建以 `field_expression` 文本为准，双份结构化表达式的同步成本大于收益；`field_dependencies` 已承载结构化信息中消费方真正需要的那部分。

## 5. 接口设计

统一前缀 `/backend/sys/formula`；列表请求体 `{ body, pages: { pageNo, pageSize, needPage } }`，总数经 `metadata.total`；响应统一 `BaseResponse`。

### 5.1 接口清单

| 接口 | 方法 | 鉴权动作 | 鉴权口径 |
| --- | --- | --- | --- |
| `/list` | POST | `sys.formula.list` | `SYS_FORMULA_ADMIN`（命名公式分页列表，支持 fieldCode/fieldName/fieldType/fieldEnable 筛选） |
| `/load?fieldId=` | GET | `sys.formula.load` | `SYS_FORMULA_ADMIN` |
| `/save` | POST | `sys.formula.save` | `SYS_FORMULA_ADMIN`（保存前强制 validate 通过） |
| `/update` | PATCH | `sys.formula.update` | `SYS_FORMULA_ADMIN` |
| `/enable` | PATCH | `sys.formula.enable` | `SYS_FORMULA_ADMIN`（请求体 `{ fieldId, fieldEnable }`） |
| `/delete?fieldId=` | DELETE | `sys.formula.delete` | `SYS_FORMULA_ADMIN` |
| `/options` | GET | `sys.formula.options` | 登录即可（左树聚合：系统变量组 + 业务模型组（数据源 targets）+ 函数分组） |
| `/functions` | GET | `sys.formula.functions` | 登录即可（函数注册中心清单，含分类/参数/返回值/说明） |
| `/validate` | POST | `sys.formula.validate` | 登录即可（语法/类型/依赖检查，纯静态分析无副作用） |
| `/simulate` | POST | `sys.formula.simulate` | 登录即可（受限沙箱试算） |

权限码 `SYS_FORMULA_ADMIN` 增补进 `properties/sys/formula/roles.yml`（`ROLE_LIST` + `ROLE_MAP`，随库 `sys_org_auth` 由既有启动任务增量同步）；`ACTION_*` 常量定义在 `SysFormulaConstants`，风格对齐 `SysDatasourceConstants`。FormulaResolver 分支：管理六动作 `hasAnyRole(SYS_FORMULA_ADMIN)`，组件四动作 `resolveLoggedIn()`；`SYS_ADMIN` 由 `BaseResolver` 自动放行，不重复列举。

### 5.2 校验与试算契约

```jsonc
// POST /backend/sys/formula/validate 请求体
{
  "expression": "ROUND(${applyAmount} * ${taxRate}, 2)",
  "expectedReturnType": "NUMBER",
  "vars": [ { "code": "applyAmount", "type": "NUMBER" }, { "code": "taxRate", "type": "NUMBER" } ]
}
// 响应 data：vars 缺省 = 宽松模式（变量视为未知，仅做语法与函数校验）
{ "syntax": true, "returnType": "NUMBER", "dependencies": ["applyAmount", "taxRate"], "errors": [] }

// POST /backend/sys/formula/simulate 请求体
{
  "expression": "ROUND(${applyAmount} * ${taxRate}, 2)",
  "vars": { "applyAmount": 1000, "taxRate": 0.13 },
  "expectedReturnType": "NUMBER"
}
// 响应 data
{ "success": true, "result": 130.00, "resultType": "NUMBER" }
```

### 5.3 错误语义（新增异常码，风格对齐 `CS_DATASOURCE_*`）

| 码 | 场景 |
| --- | --- |
| `CS_FORMULA_NOT_FOUND` | 公式编码/ID 不存在，或命名公式已停用 |
| `CS_FORMULA_CODE_DUPLICATED` | 保存时公式编码重复 |
| `CS_FORMULA_EXPRESSION_TOO_LONG` | 表达式长度超上限 |
| `CS_FORMULA_SYNTAX_INVALID` | 词法/语法错误（附引擎错误信息与位置） |
| `CS_FORMULA_FUNCTION_NOT_FOUND` | 调用了未注册函数 |
| `CS_FORMULA_TYPE_MISMATCH` | 参数/返回类型与注册元数据或 expectedReturnType 不符 |
| `CS_FORMULA_VARIABLE_INVALID` | 变量码不合法（不符合标识符约束）或路径投影格式错误 |
| `CS_FORMULA_EXECUTE_FAILED` | 执行期失败（除零、空值拒绝、集合规模超限等） |
| `CS_FORMULA_EXECUTE_TIMEOUT` | 执行超时 |

## 6. 安全设计

1. **沙箱白名单**：仅允许调用注册中心内函数；Aviator 关闭 Java 方法反射调用面（`Options.ALLOWED_CLASS_SET` 最小集），禁止 `System`/`Runtime`/IO/网络类。
2. **资源限制**（常量收口 `SysFormulaConstants`）：表达式长度上限、变量个数上限、变量值序列化体积上限、`Options.MAX_LOOP_COUNT`、执行超时（独立执行线程 + Future 超时）、编译缓存 LRU 容量上限。
3. **只读上下文**：变量表包装为不可变 Map，公式无赋值/副作用；系统变量仅服务端注入，不信任前端传入的 `CURRENT_*` 覆盖。
4. **取数收口（A4）**：公式不出现 HTTP/SQL；业务数据只经 `DS_QUERY`（复用数据源「能力白名单 + 委托鉴权 + 投影」链路）与模块注册的取值函数，权限、超时、缓存策略随被调用模块既有语义。
5. **统一兜底**：空值（`IFNULL` 语义 + 显式报错可配）、除零、类型转换失败均有确定性结果或 `CS_FORMULA_EXECUTE_FAILED`，不允许裸异常穿透到 Controller 之外；执行异常记日志（表达式摘要 + 错误码，**不落变量值明文**，防敏感业务数据进日志）。
6. **模拟计算边界**：`/simulate` 仅在资源限制内执行，入参由调用方自负；管理员预判命名公式可复用 `/simulate`，不单设预览接口（对齐数据源范围裁决先例）。
