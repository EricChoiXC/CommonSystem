**委托鉴权验证深度说明（任务书预置的降级分支）**：

- **未登录（UNAUTHORIZED）路径**：HTTP 通道不可直达——`/simulate` 自身在 Controller 层已要求登录，DS_QUERY 的委托鉴权只会发生在已登录会话内。该项以**组件接口未登录拒绝（§1.4）+ 单测佐证**覆盖。
- **无目标权限（FORBIDDEN）路径**：现库唯一目标动作 `sys.calendar.list` 在 `CalendarResolver` 中映射 `resolveLoggedIn()`（任一启用账号放行），**不存在可构造的「无目标权限」HTTP 账号**，故 FORBIDDEN 无法经 HTTP 触发。该项降级为：`FormulaDataFunctionsTest.authorizationExceptionFromDatasourcePropagatesAsIs`（mock 数据源抛 `AuthorizationException("FORBIDDEN")`，断言函数层原样透出不吞不改）+ BUG-1 修复后委托鉴权真实走通（D2/D3 证明 `AuthorizationHelper.authorize` 在执行线程上以调用方身份判定）。

**NOTE-2（承载口径，非缺陷）**：DS_QUERY 透出的数据源错误码（CS_DATASOURCE_*）与鉴权异常经引擎统一兜底包装为 `CS_FORMULA_EXECUTE_FAILED`、原文（含原错误码文本）保留在 message 中——符合 API 文档 4.11.4/4.11.6「组件接口以 `data.errors` 承载、code ∈ CS_FORMULA_*」与方案 §6.5「不允许裸异常穿透」；`FormulaDataFunctionsTest` 中「引擎按前缀统一识别」的注释措辞指函数层透传语义，未改（不构成行为缺陷）。

## 5. 发现并修复的缺陷

### BUG-1（P1，已修复并回归）：执行线程无调用方身份——DS_QUERY 委托鉴权与 CURRENT_* 会话函数经 HTTP 全数失效

| 项 | 内容 |
| --- | --- |
| 现象（修复前实测） | ① `DS_QUERY("calendar.list", nil)` → `CS_FORMULA_EXECUTE_FAILED: 公式执行失败: AuthorizationException: 登录已过期，请重新登录`（委托鉴权视会话为未登录）；② `CURRENT_USER()`/`CURRENT_ROLE()` 已登录时返回 `null`；③ 单测全绿（mock 了数据源服务）而集成实测必挂——mock 屏蔽了真实鉴权链路 |
| 根因 | `CurrentUserHolder` 为请求线程 ThreadLocal；`FormulaEngine#executeRestricted` 将表达式提交到 `formula-engine-executor` 线程池求值，DS_QUERY 委托 `SysDatasourceService#execute` 的 `AuthorizationHelper.authorize` 与 SYSTEM 函数内的 `UserUtil.getCurrentUser()` 都在**执行线程**上读 ThreadLocal——恒为空 → 委托鉴权抛 UNAUTHORIZED、会话函数得 null。`FormulaContext` 的系统变量注入在 HTTP 线程完成故不受影响（`${SYS_CURRENT_USER_ID}` 正常） |
| 修复 | `FormulaEngine#executeRestricted`：提交前在调用方线程捕获 `CurrentUserHolder.get()` 的 userId，执行任务内先 `set` 再求值、`finally` 中 `clear()`——池线程串行执行无串号，超时 `cancel(true)` 场景 finally 仍兜底清理；调用方本就未登录（null）时不注入，测试路径行为不变 |
| 影响 | 仅 `sys/formula/service/engine/FormulaEngine.java`（+1 import、executeRestricted 提交体包装）；不改接口路径/方法/鉴权口径 |
| 回归 | 修复后：D2/D3/D4（DS_QUERY 真实取数）、S5（CURRENT_*）全部实测通过；`./mvnw test` 全量 **1188 tests，0 failures，BUILD SUCCESS**（含 FormulaEngineTimeoutTest/SysFormula*Test/FormulaDataFunctionsTest 等 108 个 formula 单测）。独立复核会话（第三会话）再次全量重跑六项验证与管理全流程，结果与首验逐项一致，回归再次 **1188 tests，0 failures，BUILD SUCCESS** |
