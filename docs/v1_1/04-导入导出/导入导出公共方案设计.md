### 3.2 标准接口族

每个需要导入导出的模块，在其既有 Controller 上新增三个端点（沿用模块既有 `@RequestMapping` 前缀，下表以 `/{模块路径}` 指代，如 `/backend/sys/dict`）：

| 接口 | 方法 | 请求 | 响应 | 鉴权动作（示例命名） |
| --- | --- | --- | --- | --- |
| `/{模块路径}/export` | POST | `{ body, params, pages }`（`BaseRequest` 包装，条件与 `/list` 同构；导出无视分页、全量） | `ResponseEntity<Resource>` xlsx 文件流 | `sys.{模块}.{资源}.export` |
| `/{模块路径}/import` | POST | `multipart/form-data`：`file`（xlsx）+ `params`（JSON 字符串，导入配置） | `BaseResponse<ImportResultVo>` | `sys.{模块}.{资源}.import` |
| `/{模块路径}/template` | POST | `{ body, params }`（与 `/export` 同构；模板生成可按筛选条件附带值域提示） | `ResponseEntity<Resource>` xlsx 文件流（空模板） | `sys.{模块}.{资源}.template` |

- 路径与 HTTP 方法符合 `AGENTS.md` 第 3 节接口表（`/import` POST、`/export` POST）；`/template` 为本方案新增的通用动作，需同步补入 `docs/开发规范.md` 第 4 节通用接口表与 `AGENTS.md` 第 3 节接口表（见 10.3）。
- 模板下载为何独立 `/template` 而非复用 `/export` 空数据：两者鉴权语义不同（模板下载应低于导出权限）、响应语义不同（无数据 vs 全量数据）、前端按钮独立。备选与决策记录见 Q2。

### 3.3 数据流转

**导出**：Controller `authorize(ACTION_EXPORT)` → 组装 `BaseRequest` 条件 → `Service#selectList(body, pages)`（`needPage=false` 全量）→ 模块转换函数 `List<T> → List<导出VO>` → `ImportExportService#export(rows, voClass)`：解析 `@Export` 生成动态头（`dict` 字段取 `SysDictService#itemsByTypeCode` 构建 显示值映射 后转换）→ `ImportExportUtils#export` 写出字节 → `ResponseEntity<Resource>` 附件流返回。

**导入**：Controller `authorize(ACTION_IMPORT)` → `ImportExportService#importExcel(file, params, voClass, rowHandler, toEntity)`：
1. 文件前置校验（非空、扩展名 `.xlsx`）；
2. `ImportExportUtils#explan` 解析为 `List<VO>`（含表头一致性校验）；
3. 行级通用校验：`required` 非空、`dateFormat` 解析、`dict` 显示值 → 码值回转（回转失败记行错误）；
4. 模块扩展校验：逐行回调 `rowHandler.validate(row, rowNo)`；
5. 分批写库：按 200 条/批调用 `toEntity(vo)` 转实体后 `IBaseService#insert`（批间单事务，见 6.4）；
6. 组装 `ImportResultVo` 返回（`ignoreError=true` 时失败行跳过并计入 `errors`，见 6.3）。

**模板**：Controller `authorize(ACTION_TEMPLATE)` → `ImportExportUtils#template(voClass)` 生成仅含标题行的 xlsx → 文件流返回。

## 4. 报文契约

### 4.1 导入请求

- **定稿形态：`multipart/form-data`**，两个字段：
  - `file`：导入 xlsx 文件（`@RequestParam("file") MultipartFile`，required）；
  - `params`：导入配置 JSON 字符串（可选），公共开关见 6.3，其余键由具体导入业务自定义。
- **响应**：`BaseResponse<ImportResultVo>`，导入结果在 `data`（非列表接口，不使用 `metadata.total`）。
- **与标准.md 的差异（修正点）**：标准.md 原文为请求体 `{ "body": "文件流字节", "params": {...} }` 的 JSON 包装。本方案改为 multipart，理由：
  1. JSON 携带文件字节需前端将 File 读为 base64，内存峰值约为文件的 2.3 倍（编码膨胀 + 双份持有），与「分批导入 200 条」的降内存目标矛盾；
  2. 工程已有 multipart 先例（i18n 导入、附件上传），Spring `MultipartFile` + `CS_ATT_MAX_FILE_SIZE`（50MB）超限拦截开箱即用；JSON 包装则绕过该拦截，需自实现大小校验；
  3. `@Parameter` 文档化、Swagger UI 调试、错误口径（超限由容器统一报错）均以 multipart 更成熟。
  该修正属「实现导致设计变更」，需回写标准.md（见 10.3），评审确认后执行。
- 错误口径：文件为空 / 非 `.xlsx` 扩展名 / 表头与模板不一致 / 无数据行 → `IllegalArgumentException` → `BAD_REQUEST`（对齐 F7 与 i18n 先例）。

### 4.2 导出请求

- 请求体：`BaseRequest` 包装 `{ body, params, pages }`；`body` 为查询条件实体（字段名与 Model 一致，与 `/list` 同构），`pages` 可省略（导出恒为全量，不取 `metadata.total`）。
- 响应：`ResponseEntity<Resource>`，`Content-Type: application/octet-stream`，`Content-Disposition: attachment; filename*=UTF-8''{urlencoded 文件名}`；文件名规则 `{资源}_{yyyyMMddHHmmss}.xlsx`（i18n 先例为 `translations_{model}.xlsx`，统一改为带时间戳命名，i18n 一并切换）。
- Swagger 注解：`@ApiResponse(responseCode="200", content=@Content(mediaType=APPLICATION_OCTET_STREAM_VALUE, schema=@Schema(type="string", format="binary")))`（`AGENTS.md` 第 3 节对非 JSON 响应的既有要求）。

### 4.3 模板请求

- 请求体：`{ body, params }`（与 `/export` 同构；`body` 有值时模板可按条件附带值域提示行，默认仅标题行）。
- 响应：同 4.2 文件流；文件名规则 `{资源}_template.xlsx`。

## 5. `@Export` 注解设计

### 5.1 定义（设计契约示意）

```java
package com.common.system.common.base.annotation;

@Target(ElementType.FIELD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Export {
    /** 中文名称：导入文件标题行的标题；不填写取字段名（驼峰原样） */
    String name() default "";
    /** 字典名：dict.yml 的字典 type_code；导入导出时做码值↔显示值转换 */
    String dict() default "";
    /** 是否必填（仅导入校验：null 与空串均视为空）；默认 false */
    boolean required() default false;
    /** 日期时间格式（Date / LocalDateTime 字段生效，String 字段忽略）；默认 yyyy-MM-dd HH:mm:ss */
    String dateFormat() default "yyyy-MM-dd HH:mm:ss";
    /** 排序：导入导出文件中的列序；未设置的字段按声明顺序追加在有值字段之后 */
    int order() default -1;
}
```

### 5.2 语义细则

| 参数 | 导出行为 | 导入行为 | 边界口径 |
| --- | --- | --- | --- |
| `name` | 标题行文本 | 标题行比对基准 | 空值取 Java 字段名（如 `fieldCode`），不转下划线 |
| `dict` | 码值 → 显示值写出；`sys_dict_item` 无对应项时**原样写码值**并记 warn 日志（不失败） | 显示值 → 码值回转；无对应码值记**行错误**「无效码值」 | 字典名必须为 `dict.yml` 已登记的 `type_code`；转换映射仅取启用项（`itemsByTypeCode` 口径），键为 `field_value`、值为 `field_name` |
| `required` | 不参与 | null / 空串 → 行错误「{标题} 不能为空」 | 导出无影响 |
| `dateFormat` | `Date/LocalDateTime` 按格式写文本 | 文本按格式解析；失败 → 行错误「日期格式错误」 | 仅对时间类型字段生效；`String` 字段忽略该参数 |
| `order` | 列序 | 列序（读取按列名匹配，不依赖固定下标，见 5.3） | `order` 相同按声明顺序稳定排序；`-1`（未设置）字段按声明顺序追加在有值字段之后 |

### 5.3 注解应用边界

- `@Export` **只标注在各模块自定义的导入导出 VO 类**上（如 `SysDictItemImportVo`），不在 `BaseModel` / 实体类上标注——各模块按业务自行配置导入导出字段集（标准.md 原意），避免实体字段集与导出列强耦合。
- **不引入 EasyExcel 原生 `@ExcelProperty` / `@DateTimeFormat` 等注解**：公共方案统一走 `@Export` + 反射构建动态头/映射读取，避免一个 VO 上两套注解并存、口径漂移（决策记录见 Q4 附带项）。
- 读取容错：`explan` 按「列名 → 字段」映射解析（非固定下标），列序变化/列缺失仅报缺失列错误，不串列。

## 6. 公共业务层与 BaseController 公共方法

### 6.1 `ImportExportUtils`（静态工具类，设计契约示意）

```java
package com.common.system.common.utils;

public final class ImportExportUtils {
    /** 将列表数据导出为 xlsx 字节（按 @Export 注解构建标题行与列序；dict 显示值转换由调用方完成） */
    public static <T> byte[] export(List<T> list, Class<T> clazz);

    /** 将 xlsx 输入流解析为列表（表头与 @Export 标题逐一比对，不一致抛 IllegalArgumentException） */
    public static <T> List<T> explan(InputStream in, Class<T> clazz);

    /** 生成仅含标题行的空模板 xlsx 字节 */
    public static <T> byte[] template(Class<T> clazz);

    /** 自定义字段导出：列元数据由 modelMap 运行时给定（见 6.1.1），返回 xlsx 字节 */
    public static byte[] export(List<Map<String, String>> list, List<Map<String, String>> modelMap);

    /** 自定义字段解析：按 modelMap 的 name↔field 映射读入，返回以 field 为 key 的行列表 */
    public static List<Map<String, String>> explain(InputStream in, List<Map<String, String>> modelMap);
}
```

- **与标准.md 签名的差异（修正点）**：标准.md 原文 `EasyExcel export(List<T>, Class<T>)` 返回 `EasyExcel` 类型、`List<T> explan(EasyExcel, Class<T>)` 以 `EasyExcel` 为入参——`EasyExcel` 是入口构造器而非数据载体，该签名不可落地。修正为：导出返回 `byte[]`（对齐 i18n 先例的字节输出 + `ByteArrayResource` 包装）、解析入参为 `InputStream`。方法名 `explan` **保留标准.md 原拼写**（评审可决是否更名 `parse`，见 Q5）。
- 无状态、不注入 Bean；`dict` 字段的显示值映射由 `ImportExportService` 预构建后传入内部重载（静态工具不依赖 `SysDictService`）。

#### 6.1.1 自定义字段通道（`Map` 模型，v1.1 增量）

- **适用场景**：导出/导入列不固定、随业务数据变化的场景，典型为 i18n 翻译维护——列 = 启用的语言码，列数随语言配置变化（F3 动态头），无法为每个语言组合维护固定 VO。该通道与 6.1 固定 VO 通道（`@Export` 注解 + VO 类）并存，互不替代；i18n 后端仍保留自实现（9.1），不强制迁移，公共方法落地后 i18n 可选切换以收敛重复代码。
- **方法契约**（上方代码块末两个方法；本次增量只新增这两个，不改动既有三个方法）：

```java
/** 将列表数据导出为 .xlsx 文件（自定义字段通道；用户原始表述返回 EasyExcel，修正口径见下方「签名差异」） */
public static byte[] export(List<Map<String, String>> list, List<Map<String, String>> modelMap);

/** 将 .xlsx 文件数据解析为 Map<String, String> 列表（自定义字段通道；用户原始表述首参为 EasyExcel，修正口径见下方「签名差异」） */
public static List<Map<String, String>> explain(InputStream in, List<Map<String, String>> modelMap);
```

- **签名差异（与用户原始表述的两处修正，随 6.1 修正口径一并确定）**：
  1. `export` 返回 `EasyExcel` → 修正为 `byte[]`：`EasyExcel` 是入口构造器而非数据载体，不可返回；文件流响应需 `ByteArrayResource` 包装字节（对齐 i18n 先例与 4.2 报文契约）；
  2. `explain` 首参 `EasyExcel excel` → 修正为 `InputStream in`：`EasyExcel` 是构造器而非已读入的数据；标准.md 固定 VO 通道同位置签名（`List<T> explan(EasyExcel, Class<T>)`）即按此修正（Q5），自定义通道与固定 VO 通道保持一致。
  上述签名修正若评审不同意，则本通道两个方法不落地（无替代签名，见 Q8）。
- **方法名口径**：自定义通道按用户原文命名为 `explain`；固定 VO 通道按 Q5 保留标准.md 原拼写 `explan`——同一工具类内两通道方法名拼写并存不一致，若 Q5 评审更名 `explan` → `parse`，建议连同本通道一并统一（如统一 `explain`），实施时以评审结论为准。
- **`modelMap` 契约**：`List<Map<String, String>>`，每项描述一列，即「Model 类 + `@Export` 注解字段」的运行时形态（固定 VO 通道中由注解反射解析出的元数据，本通道改由调用方手工构建或由 VO 反射生成，见下方「模块侧构建 `modelMap` 的两种方式」）。示例（i18n 翻译维护）：

```json
[
  { "field": "fieldKey",  "name": "资源名",         "required": "true" },
  { "field": "fieldZhCN", "name": "中文翻译" },
  { "field": "fieldEnUS", "name": "英文(美国)翻译" }
]
```

  键语义（与 `@Export` 同名参数对齐）：

| 键 | 必填 | 语义 | 导出行为 | 导入行为 |
| --- | --- | --- | --- | --- |
| `field` | 是 | 列字段名 = 数据行 `Map` 的 key；对应 VO 上 `@Export` 标注字段的 Java 字段名 | 按 key 取行数据，缺失/null 写空串 | 解析结果 `Map` 的 key |
| `name` | 否 | 标题行文本，同 `@Export.name` | 标题行写出 | 标题行比对基准；空值取 `field` 原样（不转下划线） |
| `required` | 否 | 导入必填校验，同 `@Export.required`；`Map` 值为字符串，`"true"`（忽略大小写）视为必填 | 不参与 | null / 空串 → 行错误「{name} 不能为空」 |
| `dict` | 否 | 预留扩展键，语义同 `@Export.dict`（`type_code`） | 预留，首版不实现 | 预留，首版不实现 |
| `dateFormat` | 否 | 预留扩展键，语义同 `@Export.dateFormat` | 预留，首版不实现 | 预留，首版不实现 |

- **行为口径**：
  - **导出**：标题行 = `modelMap` 各项 `name`（依序），列序 = `modelMap` 顺序；数据行按 `field` 取值，`modelMap` 未声明的 key 不导出（隐式列过滤）；`list` 为空时仅写出标题行（与 `template` 空模板形态一致）；
  - **导入**：按标题行文本与 `field` 的映射解析，**不依赖固定列序**（列序变化 / 列缺失仅报缺失列错误，不串列，与固定 VO 通道读取容错口径一致，见 5.3）；表头与 `modelMap` 不一致 → `IllegalArgumentException`（→ `BAD_REQUEST`，对齐 4.1 错误口径）；`required` 项为空（null / 空串）→ 行错误，行错误汇集口径与固定 VO 通道一致（`ignoreError` 开关，6.3）；返回的 `Map` 仅含 `modelMap` 声明的 `field`，文件中多余的列不返回；
  - **边界**：公共业务层（`ImportExportService` / `BaseCrudController` 公共方法 / `/template` 接口）**不覆盖本通道**——自定义列的模板生成、码值转换、行级业务校验、写库均由调用方模块自理（i18n 现状即此形态）；`dict`/`dateFormat` 若评审要求首版实现，语义随固定 VO 通道（5.2），需同步扩展 `ImportExportService` 的码值映射构建入口（默认不做，Q8）。
- **模块侧构建 `modelMap` 的两种方式**（实施时二选一，模块自定）：
  1. **手工构建**：模块在 Service 内按当前业务状态组装（如 i18n：固定列「资源名」+ 按启用语言动态追加列，`LinkedHashMap` 保序）；
  2. **VO 反射生成**：为场景定义带 `@Export` 注解的 VO（含固定列），经 `ImportExportUtils` 新增的反射辅助方法（如 `buildModelMap(Class<?> voClass)`，命名实施时定）解析注解生成 `modelMap`，再由模块按需追加动态列——固定列元数据复用注解声明，避免双份维护。

#### 6.1.2 `ImportExportService` 与本通道的关系

- `ImportExportService` 的 `export / importExcel / template`（6.2）均基于固定 VO 通道签名（`Class<T>` 泛型），**本期不为 Map 通道增加重载**：Map 通道的调用方（当前仅 i18n 类动态列场景）自行调用 `ImportExportUtils` 两个静态方法并自理校验与写库；
- 若后续出现第二个及以上 Map 通道接入方，再评估在 `ImportExportService` 增设 Map 重载（承担码值转换与分批写库），届时补设计文档，不预留占位代码。

### 6.2 `ImportExportService`（公共导入导出业务层）

- 位置：`com.common.system.common.base.service.ImportExportService`（`@Service`，基础层直接实现类）。
- 依赖：`SysDictService`（码值转换取数）。common 侧依赖 sys 模块 Service 有现状支撑（F4：`common.base` 已引用 `sys.org.model.SysOrgUser`）；若评审要求严格单向依赖，备选方案为在 `common.base` 定义 `DictLookup` 接口由 dict 模块实现（依赖倒置，+1 接口文件），见 Q3。
- 核心方法契约：

```java
/** 导出：码值转换 + Excel 写出 */
public <T> byte[] export(List<?> rows, Class<T> exportVoClass);

/** 导入编排：解析 → 通用校验 → 码值回转 → 模块校验(rowHandler) → 分批 insert(toEntity) → 汇总 */
public <V, T extends BaseModel> ImportResultVo importExcel(

```

### 6.3 导入配置公共开关（`params`）

| 键 | 类型 / 默认 | 语义 |
| --- | --- | --- |
| `ignoreError` | `boolean` / `false` | `false`：任一行校验失败即抛 `IllegalArgumentException`（首个错误），整体回滚；`true`：校验失败行跳过并计入 `errors`，其余行继续（写库阶段异常仍整批失败回滚并计入） |
| `fullUpdate` | `boolean` / `false` | 「是否全量更新」开关位：公共层仅透传不解释，语义由具体导入业务定义（如「全量」= 先清后插 / 覆盖策略），模块在 `rowHandler` / 转换函数中消费 |

其余 `params` 键由具体导入业务自由扩展，公共层不校验未知键。

### 6.4 分批与事务口径

- 「分批导入（200 条一批）」落实为**写库批次**：每 200 条调用一次 `insert`（常量 `IMPORT_BATCH_SIZE = 200`）；
- 事务口径：**单事务**（`ImportExportService#importExcel` 标注 `@Transactional`）——行数在数万级时事务开销可接受，一致性最好；`ignoreError=true` 的「跳过失败行」在校验阶段完成（失败行不进入写库列表），不拆分事务。数据量进一步增长时再演进为分批事务 + 断点续传（不在本期）。

### 6.6 `BaseCrudController` 公共方法（设计契约示意）

```java

protected ResponseEntity<Resource> exportExcel(BaseRequest<?> request, String fileNamePrefix,
        Class<?> exportVoClass, Function<List<T>, List<?>> converter);

/** 公共导入：multipart file + params → 编排导入 → BaseResponse<ImportResultVo> */

        Class<V> importVoClass, ImportRowHandler<V> rowHandler, Function<V, T> toEntity);

/** 公共模板：空模板文件流响应 */
protected ResponseEntity<Resource> exportTemplate(String fileNamePrefix, Class<?> voClass);
```

- **依赖注入（向后兼容）**：`exportExcel / importExcel` 需要公共 `ImportExportService`（模板走静态 `ImportExportUtils`，不需要）。`BaseCrudController` 保留既有 3 参构造并委托新增的 4 参构造（第 4 参为 `ImportExportService`，未接入导入导出的模块传 `null`）：**既有模块 Controller 无需改动即可继续编译**；接入模块改用 4 参构造传入，公共方法入口对 `null` 做守卫（抛 `IllegalStateException` 提示未接入）。不采用基类字段注入（与工程统一的构造器注入风格冲突）。

- **OpenAPI 注解留在各 Controller 方法**：公共 `protected` 方法无法承载方法级注解，模块接入时按 10.1 的注解模式逐方法标注；`@Operation.description` 以「鉴权动作 <ACTION 常量值>；」开头。
- `converter`（实体 → 导出 VO）与 `toEntity`（导入 VO → 实体）为模块提供的纯转换函数：字段搬运、装饰字段（如创建人姓名）在此完成；`dict` 字段的码值↔显示值转换由公共层完成，模块转换函数不需处理。

## 7. 标准导入逻辑（口径冻结）

对应标准.md「标准导入逻辑」五步，落点如下：

| 步骤 | 落点 | 失败口径 |
| --- | --- | --- |
| 1. 获取导入配置 | `params` JSON 解析（6.3 公共开关 + 业务自定义键） | JSON 非法 → `BAD_REQUEST` |
| 2. 获取导入文件、验证格式 | 非空 + 扩展名 `.xlsx` 校验；大小由 `CS_ATT_MAX_FILE_SIZE` 拦截 | 非法 → `BAD_REQUEST` |
| 3. 验证数据格式符合 MODEL 要求 | `explan` 表头比对 + `required` / `dateFormat` 通用校验 | 行错误（`ignoreError` 决定跳过或中止） |
| 4. 验证数据合法性和正确性 | 模块 `rowHandler.validate(row, rowNo)`（唯一性、引用存在性等业务校验） | 行错误（同上） |
| 5. 分批导入（200 条一批） | `IMPORT_BATCH_SIZE=200` 写库批次，单事务 | 写库异常 → `ERROR` 整体回滚 |

### 8.1 API 封装（`api/common.js` 追加）

```javascript
/** 导入（multipart：file + params JSON 字符串） */
```

### 8.2 拦截器 blob 修复（公共方案的必要前置）

现状主实例（`api/index.js`）对 `responseType:'blob'` 响应无透传分支，存在两处缺陷（F5）：

1. **成功响应被误拆包**：blob 响应进入成功拦截器后 `response.data` 是 Blob，`res.code` 为 `undefined`，`res.code === 'SUCCESS'` 不成立，直接落入「请求失败」拒绝分支——`api/i18n.js#exportTranslations` 走主实例，导出成功响应无法返回到调用方（前端导出功能在当前实现下不可用），必须修复；
2. **HTTP 401 时错误消息取不到**：错误分支 `error.response.data.message` 在 blob 响应下是 Blob 对象，取不到 `message`，提示退化为 `error.message`（"Request failed with status code 401"）。

修复设计（`api/index.js` 响应拦截器）：

- 成功分支：`config.responseType === 'blob'` 时，若 `Content-Type` 含 `application/json`（HTTP 200 + 业务失败 JSON），将 Blob `text()` 解析后按既有 `code` 逻辑处理；否则**原样放行 response**（不解包）；
- 错误分支：`error.response.data instanceof Blob` 且为 JSON 时，先 `await blob.text()` 解析 `BaseResponse` 取 `message` 再走统一提示。

> 修复涉及全局拦截器，i18n 既有导出（`I18nTranslationManageView.vue#handleExport` 直接消费 `response.data`）与 `api/attachment.js` 自建 `blobRequest` 均需回归验证（9.2、12）。

### 8.4 公共导入弹窗 `components/ImportDialog.vue`

- **结构**（对应标准.md「导入弹窗」四要素）：

## 10. 鉴权与接口文档同步约束（AGENTS 强制项落地清单）

### 10.1 每模块新增动作的强制清单

接入导入导出的模块，须同批完成：

1. `properties` 常量类新增 `ACTION_IMPORT` / `ACTION_EXPORT` / `ACTION_TEMPLATE`（值 `sys.{模块}.{资源}.import / .export / .template`），静态引用禁止手写字符串；
2. 模块 Resolver（继承 `BaseResolver`）补 `case` 分支：导入/导出/模板动作放行给该模块管理角色（如 `SYS_DICT_ADMIN`、`SYS_I18N_ADMIN`）；`SYS_ADMIN` 由基类自动放行，不再列举；
3. Controller 方法入口 `authorize(...)`；
4. `@Operation(summary=中文动作名, description="鉴权动作 <ACTION 常量值>（权限说明）；…")`；`file` / `params` 参数补 `@Parameter(description=…, required=…)`；
5. 文件流方法补 `@ApiResponse(content=@Content(mediaType=APPLICATION_OCTET_STREAM_VALUE, schema=@Schema(type="string", format="binary")))`。

### 10.2 权限码口径

- **不新增 `roles.yml` 角色码**：导入导出动作复用各模块既有管理角色（dict → `SYS_DICT_ADMIN`、i18n → `SYS_I18N_ADMIN`、org → 既有 `SYS_ORG_*` 管理码，以此类推）；

## 11. 错误处理汇总

| 场景 | 错误码 | 来源 |
| --- | --- | --- |
| 未登录 / 无权限 | `UNAUTHORIZED` / `FORBIDDEN` | `authorize(...)` 统一口径 |
| 文件为空 / 非 `.xlsx` / 无数据行 / 表头不一致 | `BAD_REQUEST` | `IllegalArgumentException` → `GlobalExceptionHandler` |
| 行级校验失败（required / 日期 / 码值 / 业务） | `ignoreError=false` → `BAD_REQUEST`（含首个行错误）；`=true` → `SUCCESS` + `errors` 明细 | `ImportExportService` |
| 文件超 50MB | 容器 multipart 拦截（`CS_ATT_MAX_FILE_SIZE`） | Spring |
| 写库异常 | `ERROR`（整体回滚） | `GlobalExceptionHandler` 兜底 |
