## 导入导出

在 BaseController 中创建公共的 import/export 方法，创建标准规范；
同步优化当前 i18n 多语言模块的导入导出；

* 前置注解
  增加 @Export 注解，注解添加在 Model 类的字段上，各个模块根据各自的导入导出字段业务配置自己的导入导出的Model类；
  注解参数：
```
name : 中文名称，导入文件标题行的标题，不填写取字段名；
dict : 字典名，码值、枚举字段使用，配置值为 dict.yml 的字典名，导入导出时需将其进行码值和显示值的转换；
required : 是否必填，默认为 false；
dateFormat : 日期时间格式，默认为 yyyy-MM-dd HH:mm:ss；
order : 排序，在导入导出文件中显示的顺序，默认为字段在 Model 类中的顺序；
```

* 工具类
  在 common.utils 中创建 ImportExportUtils 类，提供导入导出工具类；包含接口如下：
```
byte[] export(List<T> list, Class<T> clazz); # 将列表数据导出为 .xlsx 文件字节
List<T> explain(InputStream in, Class<T> clazz); # 将 .xlsx 文件数据解析为列表（表头与 @Export 标题逐一比对，不一致抛 IllegalArgumentException）
```

  签名修正说明（2026-11-09 评审确认，Q5 / Q8；口径详见同目录《导入导出公共方案设计》6.1）：原稿 `export` 方法以 `EasyExcel` 为返回类型、原解析方法以 `EasyExcel` 为入参，该签名不可落地——`EasyExcel` 是入口构造器而非数据载体，不能作为返回值或已读入的数据使用；修正为导出返回 `byte[]`（文件流响应以 `ByteArrayResource` 包装字节）、解析入参为 `InputStream`；方法名统一为 `explain`（2026-11-09 评审 Q5 结论，不保留原稿拼写，固定 VO 通道与自定义 Map 通道两通道统一）。

- 导入标准

请求报文：`multipart/form-data`，两个字段：

- `file`：导入 xlsx 文件（required）；
- `params`：导入配置 JSON 字符串（可选），公共开关如失败是否忽略（ignoreError）、是否全量更新（fullUpdate）等，由具体导入业务定义。

修正说明（2026-11-09 评审确认，Q1；口径详见同目录《导入导出公共方案设计》4.1）：原稿请求报文为 JSON 包装（`body` 携带文件字节、`params` 为导入配置对象），修正为 multipart，理由：
1. JSON 携带文件字节需前端将 File 读为 base64，内存峰值约为文件的 2.3 倍（编码膨胀 + 双份持有），与「分批导入 200 条」的降内存目标矛盾；
2. 工程已有 multipart 先例（i18n 导入、附件上传），Spring `MultipartFile` + `CS_ATT_MAX_FILE_SIZE`（50MB）超限拦截开箱即用；JSON 包装则绕过该拦截，需自实现大小校验；
3. `@Parameter` 文档化、Swagger UI 调试、错误口径（超限由容器统一报错）均以 multipart 更成熟。

响应报文： 标准响应格式

导入弹窗：
提供一个导入弹窗，弹窗内包括：
1. 导入模板下载按钮：下载空数据的模板 .xlsx 文件
2. 导入文件，标准限 .xlsx 格式；
3. 导入配置，如是否忽略失败、是否全量更新等，由具体导出业务定义；
4. 确认导入和取消按钮

标准导入逻辑：
1. 获取导入配置；
2. 获取导入文件，验证文件格式；
3. 验证导入文件的数据格式是否符合其 MODEL 类要求；
4. 验证数据合法性和正确性；
5. 分批导入（200条一批）；

- 导出标准
- 导出/导入模板下载：
1. 请求报文：标准请求格式
2. 响应报文：标准响应格式，data 为导出文件流

* 自定义字段导入导出

  适用于导出列不固定、随业务数据变化的场景（如 i18n 翻译维护：列 = 启用的语言，列数随语言配置变化）；该场景不为每次导入导出定义固定 VO 类，数据行与列元数据均以 `Map<String, String>` 承载。在 ImportExportUtils 中增加两个方法处理自定义场景的导入导出：

```
byte[] export(List<Map<String, String>> list, List<Map<String, String>> modelMap); # 将列表数据导出为 .xlsx 文件
List<Map<String, String>> explain(InputStream in, List<Map<String, String>> modelMap); # 将 .xlsx 文件数据解析为 Map<String, String> 列表
```

  modelMap 为 Model 类 + @Export 注解字段形成的列表（动态列由调用方在运行时追加），如：

```json
[
  { "field": "fieldKey",  "name": "资源名",         "required": "true" },
  { "field": "fieldZhCN", "name": "中文翻译" },
  { "field": "fieldEnUS", "name": "英文(美国)翻译" }
]
```

  modelMap 项的键：
  - field：列字段名，即数据行 Map 的 key，对应 Model 类上 @Export 标注字段的字段名；
  - name：标题行文本，同 @Export.name，不填写取 field 原样；
  - required：可选，导入必填校验，同 @Export.required；Map 值为字符串，"true"（忽略大小写）视为必填；
  - dict / dateFormat：预留扩展键，语义与 @Export 同名参数一致，首版不实现。

  行为口径：
  - 导出：标题行取 modelMap 各项 name，列序 = modelMap 顺序；数据行按 field 取值，key 缺失或值为 null 写空串；modelMap 未声明的 key 不导出；
  - 导入：按标题行文本与 field 的映射解析（按列名匹配、不依赖固定列序，与固定 VO 通道读取容错口径一致），列缺失报错；required 项为空（null / 空串）记行错误；返回 Map 的 key 为 field，仅含 modelMap 声明的列；
  - 签名说明：导出返回 byte[]、解析入参 InputStream、方法名 explain，与固定 VO 通道的工具类签名修正口径一致（详见同目录《导入导出公共方案设计》6.1）；
  - 公共业务层（ImportExportService / BaseController 公共方法）不覆盖本通道：自定义列的码值转换、行校验、写库由调用方模块自理。
