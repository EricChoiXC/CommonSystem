# 前端改动清单（草案）

> 遵循 AGENTS 第 6 节：接口一律经 `src/api/index.js` 的 axios 实例以 `/backend/...` 相对路径请求；
> 列表页三段式「筛选区 → 工具区 → 列表区」；新建/编辑共用一个表单组件，查看为独立只读组件；
> 样式复用 `list-page.css` / `form-page.css`，不在页面内重复定义。

## 1. 路由与菜单

### 1.1 `router/index.js` 新增 4 条路由

| 路径 | name | 组件 | meta |
| --- | --- | --- | --- |
| `/org/group` | `GroupManage` | `views/org/GroupManageView.vue` | `{ title: '群组', parent: '组织架构' }` |
| `/org/group/create` | `GroupCreate` | `views/org/GroupFormView.vue` | `{ title: '新建群组', parent: '组织架构' }` |
| `/org/group/edit/:id` | `GroupEdit` | `views/org/GroupFormView.vue` | `{ title: '编辑群组', parent: '组织架构', tab: 'name' }` |
| `/org/group/detail/:id` | `GroupDetail` | `views/org/GroupDetailView.vue` | `{ title: '群组详情', parent: '组织架构', tab: 'name' }` |

- **不设 `meta.auth`**：所有登录用户都可访问（普通用户按后端数据范围过滤）。
- 动态路由 `meta.tab: 'name'` 复用单标签。

### 1.2 `HomeView.vue` 改动

| 改动 | 说明 |
| --- | --- |
| 顶栏新增「多人」按钮 | 位于 `.header-user-box` 内、日程按钮之后；SVG 多人图形；`@click="router.push('/org/group')"`；所有登录用户可见 |
| `menus` 配置 | 「组织架构」菜单组下新增菜单项 `{ title: '群组', path: '/org/group', auth: '' }`，位于「角色」之后；`auth: ''` 表示所有登录用户可见 |
| `activeMenu` | 新增前置判断 `if (path.startsWith('/org/group')) return '/org/group'`，**必须放在** `path.startsWith('/org/') → '/org'` 之前，否则群组页会误高亮「当前组织架构」 |

> 结论（已确认）：**双入口**——顶部右上角「多人」图标 + 「组织架构」菜单组下的「群组」菜单项。
> 两处跳转目标一致（`/org/group`），不做权限差异；菜单项 `auth` 留空即可（普通用户也要能看到自己的群组）。
> 实现时注意 `filterMenuNode` 对空 `auth` 的处理：确认其语义为「不校验」，若现有实现把空 `auth` 当作「无权限」，
> 需显式改为 `auth: null` 或补一个 `alwaysVisible` 标记（以 `HomeView.vue` 现有菜单项的实际写法为准）。

## 2. `AddressBook.vue` 改造

### 2.1 新增 props

| prop | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `showRole` | Boolean | `false` | 是否显示「角色」页签（角色单选/多选，结果为角色 id） |
| `showGroup` | Boolean | `false` | 是否显示「群组」页签（**仅在 `orgType` 含人员时生效**，结果为人员 id） |

> 也可用 `tabs: ['tree','query','role','group']` 的数组形式，更灵活但改动面更大。推荐两个布尔 prop，
> 与现有 `props` 风格（扁平、语义化）一致。

### 2.2 页签结构

```vue
<el-tabs v-model="activeTab">
  <el-tab-pane label="组织架构树" name="tree"> ... </el-tab-pane>
  <el-tab-pane label="查询" name="query"> ... </el-tab-pane>
  <el-tab-pane v-if="showRole" label="角色" name="role"> ... </el-tab-pane>
  <el-tab-pane v-if="groupTabVisible" label="群组" name="group"> ... </el-tab-pane>
</el-tabs>
```

- `groupTabVisible = computed(() => props.showGroup && resolveOrgTypes(props.orgType).includes(3))`。

### 2.3 角色页签

- 表格列：名称、编码、是否启用（`fixed` 无）；`multi` 时首列复选框。
- 数据源：
  - 方案 A：`queryAddressBookList({ body: { keyword, orgTypes: [5], limitRange: props.limitRange }, pages })`
  - 方案 B：新增 `queryAddressBookRoleList(...)`。
- 关键字查询：上层关键字框 `handleSearch` 切到 `query` 页签的现有行为保持不变；角色页签内提供自己的关键字刷新或复用同一关键字。
  推荐：**角色页签提供独立的「刷新」按钮**，避免改动现有 `handleSearch` 语义。
- 已选合并：新增 `roleSelectedRows` + `handleRoleSelectionChange` + `restoreTableSelection(roleTableRef, roleList)`。

### 2.4 群组页签

- 左侧：可见群组列表（`queryAddressBookGroupList({ body: { keyword }, pages })`），点击选中一个群组。
- 右侧：该群组成员表格（`queryAddressBookGroupUsers({ groupId, orgTypes: orgTypes.value })`），多选/单选。
- 已选合并：新增 `groupSelectedRows` + `handleGroupSelectionChange` + 恢复逻辑。
- 未选中群组时右侧展示 `el-empty description="请选择左侧群组"`。
- 群组页签的选择结果进入统一的 `selected` 数组，最终 `handleConfirm` 回填人员 id/名称，与现有逻辑一致。

### 2.5 需要注意的既有实现细节

- `restoreTableSelection` 目前只有 `treeTableRef` / `queryTableRef` 两个分支（`if (tableRef === treeTableRef) ... else ...`），
  新增两个表格后需改为**映射表**（`Map<tableRef, selectedRowsRef>`），否则角色页签的恢复会写错到查询页签。
- `handleRowClick` 单选逻辑对角色/群组页签同样适用，但群组页签的右侧是成员（人员），单选应选中人员；
  角色页签单选应选中角色。二者都复用 `pick(row)`，`fieldOrgType` 对角色为 5，前端展示时需能识别。
- `orgTypeText` 依赖 dict `org_element_type`，加入 5/6 后自动支持，无需改映射。

### 2.6 `api/org.js` 改动

| 函数 | 说明 |
| --- | --- |
| `resolveOrgTypes` | `ALL` 保持 `[1,2,3,4]`（不含 5/6）；**新增** `ORGDEPTPOSTPERSON: [1,2,3,4]`（语义化别名，供群组「可见用户」使用）；注释补充 5=角色、6=群组 |
| `queryAddressBookRoleList` | 方案 B 专用；方案 A 不需要 |
| `queryAddressBookGroupList` | `POST /backend/sys/org/addressbook/groupList` |
| `queryAddressBookGroupUsers` | `POST /backend/sys/org/addressbook/groupUsers` |
| `queryGroupList` / `loadGroup` / `saveGroup` / `updateGroup` / `deleteGroup` | 群组维护五件套 |

## 3. 新增页面

### 3.1 `GroupManageView.vue`（`/org/group`）

参考 `OrgManageView.vue` 与 `RoleManageView.vue` 的结构，但**无左侧树**：

```text
┌──────────────────────────────────────────────────────────────┐
│ 筛选区：[名称] [类型] [是否全员可见]                          │
│ 工具区：[创建时间↓][更新时间][名称]        [查询][创建][删除] │
│ 列表区：☐ | 名称 | 类型 | 成员数 | 所有人 | 全员可见 | 状态 | 操作 │
└──────────────────────────────────────────────────────────────┘
```

- 类型筛选：`el-option` 来自 dict `org_group_type`；普通用户（非管理员）该筛选禁用或只保留「个人」。
- 列表操作列：详情 / 编辑 / 删除；删除二次确认。
- 批量删除：逐条调用 `deleteGroup`，全部完成后刷新（与 `OrgManageView#handleInvalid` 一致）。
- 权限预判：`canManage(row)` = 管理员 || (`PERSONAL` && `fieldOwnerId === 当前用户 id`)；
  编辑/删除按钮按此显隐，`SYS_ORG_GROUP_ADMIN` / `SYS_ORG_ADMIN` 走 `hasAuth`。

### 3.2 `GroupFormView.vue`（`/org/group/create`、`/org/group/edit/:id`）

- 新建：`getInitID()` 取 ID；默认类型：普通用户 `PERSONAL`（禁用下拉），管理员默认 `COMMON`。
- 编辑：`loadGroup(id)` 回填；普通用户打开非自己的群组时后端已拒绝（页面显示错误并返回）。
- 类型切换：`COMMON` ⇄ `PERSONAL` 时清空「可见用户」（个人类型隐藏该字段并清空值）。
- 成员/可见范围用 `AddressBook`：
  - 成员：`org-type="PERSON"`、`multi`、`septarator=";"`。
  - 可见范围：`org-type="ORGDEPTPOSTPERSON"`（机构/部门/岗位/人员，已确认采纳），`multi`；空白时提示「不选择时默认全员可见」。
    该语义需在 `api/org.js#resolveOrgTypes` 中新增映射（见 2.6），不可复用 `ALL`（`ALL` 为 `[1,2,3,4]`，语义上等价，但命名不达意）。
- 保存：`saveGroup` / `updateGroup`，成功后 `markTabToClose(route.path)` + `router.push('/org/group')`。

### 3.3 `GroupDetailView.vue`（`/org/group/detail/:id`）

- 复用 `form-page.css` 的 `.detail-grid` / `.detail-item` / `.is-full`（不使用 `el-descriptions`）。
- 字段：名称、类型、所有人、全员可见（`COMMON` 且无可见范围时显示「是」）、成员（el-tag 列表，独占一行）、可见范围（el-tag 列表，独占一行）、启用状态、创建时间、更新时间。
- 按钮区：返回 / 编辑（按 `canManage` 显隐）。

## 4. 现有页面调整

| 页面 | 改动 |
| --- | --- |
| `OrgManageView.vue` | 类型筛选下拉新增 5/6 会导致误查 ⇒ **不新增**；保持 4 项即可（后端已排除 5/6） |
| `OrgFormView.vue` | `ORG_TYPE_OPTIONS` 来自 dict，加入 5/6 后会出现「角色/群组」选项 ⇒ 必须**前端过滤**，仅保留 1~4；`AddressBook` 的 `org-type` 保持不变（`ORGDEPT` / `PERSON` 天然排除） |
| `RoleFormView.vue` | 「组织架构」`AddressBook` 的 `org-type="ALL"` 需改为显式类型数组或新增 `ALL_NOROLE` 语义，确保不含 5/6。推荐给 `resolveOrgTypes` 增加 `ELEMENT: [1,2,3,4]` 并让 `ALL` 保持 `[1,2,3,4]`（即本来就不含），确认现状即可 |
| `RolePreviewView.vue` | 树 `orgTypes: [1,2,3,4]` 不变；后端已排除群组镜像行（群组无 `field_is_virtual`，且不在 1/2/3/4） |
| `TodoSendView.vue` / `CalendarFormView.vue` / `TemplateFormView.vue` | 默认不显示角色/群组页签，无需改动；若需要「按群组选人」可后续开启 `show-group` |
| `ui.vue` | 公共组件样例页可补充 `show-role` / `show-group` 示例（可选） |

> **重点**：`OrgFormView` 的类型下拉必须过滤 5/6，否则用户可通过界面创建 `field_org_type = 5/6` 的元素，
> 而后端 `validateCommon` 会拒绝——体验差且暴露实现细节。

## 5. 样式与交互一致性清单

- [ ] 列表页使用 `.filter-form` + `el-col :span="6"`，输入框回车触发查询。
- [ ] 工具区左侧 `sort-area` 单选排序，选中项 `.active` + `.sort-arrow`，默认创建时间降序。
- [ ] 列表首列复选框（有批量操作时），末列操作列 `fixed="right"`，不展示主键。
- [ ] 分页 `layout="total, prev, pager, next, sizes"`，`page-sizes [10,20,50,100]`，切页大小回第 1 页。
- [ ] 表单页 `label-width="40%"` + `:span="12"`，长字段独占一行（label 20%）。
- [ ] 操作按钮放在 `el-card` 的 `#header` 内 `.page-header > .header-btns`。
- [ ] 启停用/删除二次确认。
- [ ] KeepAlive 页面在 `onActivated` 重载列表（列表页）。
