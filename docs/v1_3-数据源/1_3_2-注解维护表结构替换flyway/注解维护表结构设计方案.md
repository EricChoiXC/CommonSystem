# 注解维护表结构设计方案（1_3_2）

- 以 Java 注解声明表结构（对齐 A8 `@DatasourceField` 先例的「注解声明 + 扫描归一」模式），启动期由同步引擎比对 `information_schema` 生成并执行 DDL，**纯替换 Flyway**。

## 2. 概念模型

```text
注解声明层                     模型归一层                    执行层
@TableSource ─┐
@DataSource  ─┼─ 实体类 ──→ SourceTableScanner ──→ TableDef（含 ColumnDef/IndexDef）
@ColumnField ─┘                                    │
                                              fail-fast 校验
                                                   ▼
                                     SourceSchemaDiffer（information_schema 实际结构）
                                                   ▼
                                     ChangeSet[]（分级：L1/L2/L3）
                                                   ▼
                          ┌──────────────┬──────────────┐
                          │ VALIDATE     │ INSTALL      │ APPLY      ← CS_SOURCE_SYNC_MODE
                          │ 只报告       │ 仅新增缺失   │ L1 执行/L2 告警/L3 fail-fast
                          └──────────────┴──────────────┘
                                                   ▼
                          common_source_sync_log（审计，只增不改）
```

| 概念 | 定义 |
| --- | --- |
| 标注表 | 类级标注 `@TableSource` 的实体类对应的表；引擎的唯一管辖范围 |
| managed 表 | 当前标注表 ∪ `common_source_sync_log` 中出现过的历史标注表；后者失去标注时输出孤儿告警（疑似误删标注），永不执行任何 DDL |
| 未标注表 | 引擎完全不触碰（含 ERP 侧表、后续接入前的存量表） |
| ChangeSet | 一次比对产出的变更集合，每条含级别（L1/L2/L3）、变更类型、DDL 文本、涉及表/列 |
| 公共列模板 | 按实体基类推导的内建列：`BaseModel` → `field_id` 主键；`MainModel` → `field_id` + 审计五列 |

## 3. 注解定稿（回应方案分析 §3 #1~#13）

### 3.1 类级注解

```java
package com.eric.base.common.source.annotation;

/** 表定义注解。RUNTIME / TYPE */
public @interface TableSource {
    /** 表名（snake_case，全局唯一），必填 */
    String name();
    /** 表 COMMENT，必填（数据库设计文档同步依赖） */
    String comment();
    /** 索引定义 */
    TableIndex[] indexes() default {};
    /** 主键列集声明（F19-DOC-005 补充评审新增，2026-11-17）：默认空 = 现行为（BaseModel 内建 field_id 主键）；
     *  非空 = 显式声明主键列集，引擎不再内建 field_id，主键列本身以 @ColumnField 业务列声明
     *  （nullable 必须为 false），支持组合主键与单列非 field_id 主键；数组顺序即 PRIMARY KEY 列序 */
    String[] primaryKeyColumns() default {};
}
```

```java
/** 逻辑数据源归属声明（分组元数据；引擎仅透传到 TableDef 与报告分组，不影响 DDL）。RUNTIME / TYPE */
public @interface DataSource {
    /** 逻辑数据源名，约定与模块 key 对齐（如 calendar） */
    String name();
}
```

```java
/** 索引定义（仅作为 @TableSource.indexes() 成员，不独立标注）。RUNTIME；@Target({}) 空目标在编译期阻断独立标注（对齐 Spring @ComponentScan.Filter 先例） */
public @interface TableIndex {
    /** 索引名，表内唯一 */
    String name();
    /** 索引列（支持组合索引，按数组顺序） */
    String[] columns();
    /** 是否唯一索引 */
    boolean unique() default false;
    /** 索引类型（预留 FULLTEXT） */
    IndexType type() default IndexType.BTREE;
}
```

- `autoUpdate` 属性**废除**：门禁统一收口到环境级 `CS_SOURCE_SYNC_MODE`（§5.2），不允许表级绕过（裁决：表级默认 `true` 过于危险）。
- `ENGINE=InnoDB` / `CHARSET=utf8mb4` 为引擎内建统一默认，**不开放表级属性**（#12；如未来需要再增属性）。
- `primaryKeyColumns()` 主键列集声明（F19-DOC-005 补充评审新增，2026-11-17）：默认空 = 现行为（BaseModel 内建 `field_id` 主键）；非空 = 显式声明主键列集，引擎**不再内建 `field_id`**，主键列本身以 `@ColumnField` 业务列声明（`nullable` 必须为 false），支持组合主键与单列非 field_id 主键；数组顺序即 `PRIMARY KEY` 列序。仅 `BaseModel` 开放（`MainModel` + 非空一律 fail-fast，见 §3.3/§3.5）。

### 3.2 字段级注解

```java
/** 列定义注解。RUNTIME / FIELD */
public @interface ColumnField {
    /** 列名（field_ 前缀 snake_case，表内唯一），必填 */
    String name();
    /** 列 COMMENT，必填 */
    String comment();
    /** 列类型枚举，必填（无默认，杜绝拼写魔法值） */
    ColumnType type();
    /** 长度：STRING 必填（≥1）；DECIMAL 表达精度；其余类型忽略 */
    int length() default -1;
    /** 小数位：仅 DECIMAL 使用 */
    int decimalLength() default 0;
    /** 是否可空，默认 false */
    boolean nullable() default false;
    /** 字面量默认值；未设置用 {@link #DEFAULT_NONE} 哨兵（区分「无默认值」与「默认空串」） */
    String defaultValue() default DEFAULT_NONE;
    /** 函数式默认值（先例 DEFAULT CURRENT_TIMESTAMP / ON UPDATE CURRENT_TIMESTAMP），与 defaultValue 互斥 */
    DefaultFunction defaultFunction() default DefaultFunction.NONE;
    /** 哨兵常量：字面量需要该值时须走 defaultFunction 扩展或调整哨兵（实践中不可能出现） */
    String DEFAULT_NONE = "__CS_NONE__";
}
```

**继承业务列的重声明规则（D5）**：`MainModel` 声明的 `fieldName` / `fieldCode` 属业务列，各表长度不一（VARCHAR(100)/(200)/(500)），引擎**不提供魔法默认**——需要入列的实体**在子类重新声明同名字段并标注 `@ColumnField`**（Java 字段遮蔽 + Lombok 生成同名读写器覆盖父类实现，行为兼容，单测验证）；未重声明的继承字段不进列清单。已评估「引擎内建默认长度 + 表级覆盖属性」「`MainModel` 上直接标注」两案，均因双源真相/无法表达表级差异被否。

> comment 文案口径（F19-BE-005 落地回写，2026-11-16）：`@ColumnField.comment` / `@TableSource.comment` 以实际库列/表 COMMENT 为准（`@ColumnField` 的短文案示例仅为示意），否则 VALIDATE 比对在 COMMENT 上必产 diff——试点 `SysDatasource` 六列标注取 `V1_01_046` 实际 COMMENT，与「dev 库 VALIDATE 零 diff」验收一致。

### 3.3 公共列内建模板（#7、#13、#11）

按实体基类推导（对齐 A8 fieldId 内建先例），**不开放主键/公共列标注**（`ColumnField` 无 `primaryKey` 属性，从草稿删除）：

| 基类 | 内建列 | 说明 |
| --- | --- | --- |
| `BaseModel` | `field_id VARCHAR(32) NOT NULL PRIMARY KEY` | 固定最前 |
| `MainModel` | 上述 + `field_creator_id VARCHAR(32) NULL`、`field_create_time TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP`、`field_updater_id VARCHAR(32) NULL`、`field_update_time TIMESTAMP NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP`、`field_enable BIT(1) NOT NULL DEFAULT b'1'` | 固定最后；与 37 个实体的继承分化及既有库结构逐一吻合（`field_update_time` 含 `DEFAULT CURRENT_TIMESTAMP`，F19-DOC-001 评审修正，对齐 `V1_01_046`） |

- 事实核对：流水/日志类（`SysLogOperation`、`SysTaskHistory`、`SysAttOperation` 等）继承 `BaseModel`，天然无审计列——AGENTS.md「流水类只增不改」惯例由继承关系表达，无需额外开关。
- 列清单 = 内建主键（最前）+ 显式标注业务列（声明序）+ 内建审计列（最后）。
- **公共列模板条件化（F19-DOC-005 补充评审裁决，2026-11-17）**：`@TableSource.primaryKeyColumns()` 非空时模板条件化——`BaseModel` + 非空 `primaryKeyColumns` → **无任何内建列**（含 `field_id`），全部列（含主键列）走 `@ColumnField` 业务列标注（主键列 `nullable` 必须为 false）；`MainModel` **不开放**该属性（`MainModel` + 非空 `primaryKeyColumns` 一律 fail-fast）。裁决结论：批准仅 `BaseModel` 开放——9 张目标表均无审计列，`MainModel` 场景无现实需求且语义易混淆；`BaseModel` 缺省（`primaryKeyColumns` 为空）行为与现引擎逐字节一致，既有 35 张标注表语义零变化（回归断言由 F19-BE-011 承担）。

### 3.5 扫描校验规则（fail-fast 清单，对齐 A8 先例）

启动扫描期（`SourceTableScanner`）与注册组装期逐条校验，违例抛 `IllegalStateException` 阻断启动：

1. 表名 / 列名 / 索引名匹配 `[a-z][a-z0-9_]*`；列名必须 `field_` 前缀（全工程规范）；
2. 表名全局唯一、列名表内唯一、索引名表内唯一；
3. `comment` 必填非空（表与列）；
4. `STRING` 必须显式 `length ≥ 1`；`DECIMAL` 必须显式 `length ≥ 1`；
5. `defaultValue` 与 `defaultFunction` 互斥（哨兵判定）；`defaultValue` 字面量类型与列类型粗校验（数字列收数字、时间列收字面量格式）；
6. 索引 `columns` ⊆ 该表列集合（含内建列）；
7. 标注类必须继承 `BaseModel` / `MainModel`（决定公共列模板）；
8. `@ColumnField` 不允许标注在 `static` / `synthetic` 字段；
9. 子类重声明字段的类型必须与被遮蔽的父类字段一致；
10. `primaryKeyColumns` 非空时：声明列集必须 ⊆ 该表业务列集合（每个主键列都有同名 `@ColumnField` 业务列标注）；
11. `primaryKeyColumns` 非空时：每个主键列 `nullable` 必须为 false；
12. `primaryKeyColumns` 非空且基类为 `MainModel`：fail-fast（该属性仅 `BaseModel` 开放，见 §3.3）。

> 规则 10~12 为 F19-DOC-005 补充评审新增（2026-11-17）；违例同既有规则口径：启动期抛 `IllegalStateException` 阻断启动。

## 4. DDL 生成与同步语义矩阵

### 4.1 DDL 生成规则（MySQL 8.4 + Connector 8.4.0）

- `CREATE TABLE` 输出形态对齐既有脚本风格：列定义 → `PRIMARY KEY (field_id)` → 索引 → `ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='...'`；
- 类型映射见 §3.4；`BOOLEAN` → `BIT(1)`（先例 `field_enable`）；
- 标识符（表/列/索引名）全部经 §3.5 正则白名单校验后以 `${}` 拼接进 Mapper XML，值类参数用 `#{}`——DDL 无绑定变量是 MySQL 限制，注入面由白名单收口。
- 实现口径定稿（F19-BE-003 落地回写，2026-11-16）：可空渲染——非可空 `NOT NULL`，可空且无默认值仅 `DEFAULT NULL`（省略 `NULL` 关键字），可空且带默认值 `NULL DEFAULT ...`（与 `V1_01_046` 逐列吻合）；`ADD COLUMN` 不带 `AFTER` 定位（新列追加表尾，列序不影响按列名比对的 diff 语义）；`ADD INDEX` 用 `ADD [UNIQUE] INDEX` 语法、不写 `USING BTREE`；`ALTER COLUMN SET DEFAULT` 仅变更默认值、不改 `ON UPDATE` 子句（该子句变更走 `MODIFY COLUMN` 全量重定义）；函数式默认值 `CURRENT_TIMESTAMP` 允许 `TIMESTAMP`/`DATETIME` 列，`ON UPDATE CURRENT_TIMESTAMP` 仅 `TIMESTAMP` 列；`TEXT`/`JSON` 列禁止任何默认值；字面量默认值（数字、`b'0'/b'1'`）经正则白名单后原样输出；引号内容统一 `''` 转义与反斜杠翻倍；生成语句不带结尾分号（执行器按单条语句提交）。

### 4.2 diff 算法

| 读取源 | 字段 |
| --- | --- |
| `information_schema.TABLES` | TABLE_NAME / ENGINE / TABLE_COMMENT / TABLE_COLLATION |
| `information_schema.COLUMNS` | COLUMN_NAME / DATA_TYPE / COLUMN_TYPE / IS_NULLABLE / COLUMN_DEFAULT / EXTRA / COLUMN_COMMENT / CHARACTER_MAXIMUM_LENGTH / NUMERIC_PRECISION / NUMERIC_SCALE |
| `information_schema.STATISTICS` | INDEX_NAME / NON_UNIQUE / SEQ_IN_INDEX / COLUMN_NAME / INDEX_TYPE |

比对范围 = 标注表 ∪ managed 表；产出 `ChangeSet[]` 并分级。比对仅在内存进行，21+ 表的开销为毫秒级；「快照 hash 免比对」列为可选优化（P2），首版不做。

### 4.3 同步语义矩阵（硬问题 #1 定稿）

| 变更类型 | 级别 | APPLY | INSTALL | VALIDATE |
| --- | --- | --- | --- | --- |
| 缺失表 | L1 | CREATE TABLE | CREATE TABLE | 报告 |
| 缺失列 | L1 | ADD COLUMN | ADD COLUMN | 报告 |
| 缺失索引（含唯一） | L1 | ADD INDEX | ADD INDEX | 报告 |
| VARCHAR 扩长 / DECIMAL 精度提升（注解 > 实际） | L1 | MODIFY | 不执行 | 报告 |
| 列默认值变更 | L1 | ALTER SET DEFAULT | 不执行 | 报告 |
| ON UPDATE 子句变更 | L1 | MODIFY（全量重定义） | 不执行 | 报告 |
| 列 COMMENT / 表 COMMENT 变更 | L1 | ALTER MODIFY / ALTER COMMENT | 不执行 | 报告 |
| 列可空收紧（NULL → NOT NULL） | L2 | 告警不执行 | 不执行 | 报告 |
| 列可空放宽（NOT NULL → NULL，实际 > 注解） | L1 | MODIFY | 不执行 | 报告 |
| 注解 < 实际的长度收窄 / 类型不兼容变更 | L3 | **fail-fast 启动失败** | 不执行 | 报告 |
| 同表同时出现「缺失列 + 孤儿列」（疑似改名/搬家） | L3 | **fail-fast 启动失败**（改名必须显式 DataMigration） | 不执行 | 报告 |
| 注解中删除的字段（实际孤儿列） | L2 | 告警不删列 | 不执行 | 报告 |
| 索引定义差异（列集/唯一性/类型/名称） | L2 | 告警不执行（重建=删+加，不自动） | 不执行 | 报告 |
| 实际多余索引 / 多余索引名 | L2 | 告警不删 | 不执行 | 报告 |
| ENGINE / CHARSET 与内建默认不一致 | L2 | 告警不改建 | 不执行 | 报告 |
| 实际主键（列集/顺序）与注解声明不一致 | L2 | 告警不执行（引擎永不修改主键，改主键走人工 SQL） | 不执行 | 报告 |
| managed 表失去标注（疑似误删注解） | L2 | 告警，永不 DROP | 不执行 | 报告 |

- **L1**：结构安全或无损变更，APPLY/INSTALL 自动执行；APPLY 模式下单条执行失败即抛异常阻断启动（对齐 Flyway 失败语义），失败详情落 `common_source_sync_log`。
- **L2**：有歧义或需人工裁决，只告警（日志 WARN + 审计报告），任何模式都不执行。
- **L3**：有数据丢失风险，APPLY 模式 fail-fast 阻断启动并在异常信息中给出处理指引（手工 SQL 或 DataMigration）；VALIDATE 模式仅报告。
- **引擎永不执行** `DROP TABLE` / `DROP COLUMN` / `RENAME`，硬编码于执行器。
- 组合差异口径（F19-BE-004 落地回写，2026-11-16）：同列存在 L3（收窄/不兼容）时该列全部 DDL 暂缓（整列人工裁决）；同列存在 L2（可空收紧）时仅阻断会隐式执行收紧的 MODIFY 全量重定义类 DDL（扩长/精度/ON UPDATE/注释/去默认），仅动默认值子句的 `SET DEFAULT` 保留执行——任何 L1 DDL 不得隐式执行 L2 收紧动作；同表「缺失列 + 孤儿列」时缺失列仍报 L1 ADD COLUMN、孤儿列并入改名疑似项 L3（改名对按注解声明序 × 实际 ORDINAL_POSITION zip 配对进明细，数量不等配对 min 个并完整列两侧清单）；ENGINE/CHARSET 差异合并为一条 L2 告警（明细分列差异项）；managed 孤儿表已被人工删除（库中不存在）时无结构可比、不产告警。
- 主键比对口径（F19-DOC-005 补充评审新增，2026-11-17）：主键读取源 = `information_schema.STATISTICS` 中 `INDEX_NAME='PRIMARY'` 行按 `SEQ_IN_INDEX` 排序取列集（与既有索引三源读取同一通道）；主键差异任何模式仅 L2 告警、不执行（引擎永不 DROP/ADD/修改 PRIMARY KEY，改主键走人工 SQL）；PRIMARY 不在二级索引比对范围、不计入 L1 缺失索引。

### 4.4 managed 表与孤儿告警

managed = 当前标注表 ∪ `common_source_sync_log.field_tables` 出现过的历史表。历史标注表失去 `@TableSource` 时输出 L2 告警（疑似误删注解），引擎不执行任何 DDL；恢复标注后自动重新纳入比对。

> managed 清单实现口径（F19-BE-005 落地回写，2026-11-16）：§5.3 审计表无独立 `field_tables` 列，历史表清单由 `common_source_sync_log.field_changes` JSON 的 `$.table` 经 `JSON_TABLE` 提取去重（XML 内实现）——仅覆盖产生过变更的表：从未产生 diff 的表失去标注时不进历史清单、不产孤儿告警（恢复标注后重新纳入比对的能力不受影响）。

## 5. 同步引擎与门禁（硬问题 #4、#5、#6 定稿）

### 5.1 执行流程

```text

  └→ CommonSourceSyncService.sync()
       1. 解析 CS_SOURCE_SYNC_MODE（默认 VALIDATE）
```

数据迁移（第十三个启动任务）在表结构同步**之后**执行（先结构后数据）。

### 5.2 环境门禁（三段式配置）

配置键定稿 `CS_SOURCE_SYNC_MODE`（方案分析 §7 原始裁决写作 `CS_DS_SYNC_MODE`；F19-DOC-001 评审批准改名——`DS` 与 `sys_datasource` 取数配置语义冲突）：

| --- | --- | --- |
| VALIDATE（默认，代码兜底） | 只比对出报告落审计表 + WARN 日志，不执行任何 DDL，不阻断启动 | test / prod 常态 |
| INSTALL | 仅执行「缺失对象新增」子集（建表/加列/加索引），不执行任何修改类变更 | prod 全新库首次部署（一次性设置环境变量） |
| APPLY | L1 自动执行、L2 告警、L3 fail-fast | dev 开发态（本地启动参数显式开启） |

- 属部署运行参数，**不入 `common_setting`**（对齐 `CS_API_DOCS_ENABLED` 先例）；不新增模块 `application.yml`（引擎无 SETTING 段需求，避免无消费方的 yml）。
- 裁决中「dev=APPLY、test/prod=VALIDATE」由部署侧环境变量落实，代码兜底取更安全的 VALIDATE。

## 6. DataMigration SPI（硬问题 #2 定稿）

```java
package com.eric.base.common.source.spi;

/** 数据迁移 SPI：承载注解表达不了的数据回填（纯替换 Flyway 后的唯一数据通道）。 */
public interface SourceDataMigration {
    /** 迁移编码：DM-{yyyyMMdd}-{nnn}，全局唯一；禁止复用已 SUCCESS 的 code，语义调整须新 code */

```

| 项 | 约定 |
| --- | --- |
| 注册 | Spring Bean 收集（对齐 `SysDatasourceRegistry` 模式），构造期校验 code 格式与全局唯一（fail-fast） |
| 执行时机 | 第十三个启动任务，表结构同步之后 |
| 幂等 | 查 `common_source_migration_log` 存在 SUCCESS 记录则跳过 |
| 失败 | 写 FAILED 审计行并抛异常阻断启动（对齐 Flyway 失败语义） |
| 实现 | 迁移逻辑内可用 JdbcTemplate / 模块 Dao；复杂回填（游标分批）对齐 `SysOrgElementService#backfillPinyin` 先例 |
| 首例 | `V1_01_038` 流程模板默认值回填改写为 SourceDataMigration 实现（F19-BE-007） |

> 实现口径（F19-BE-006 落地回写，2026-11-17）：SPI 契约与上表一致，未调整。执行清单在构造期完成排序——`order()` 升序、并列按 `code` 字典序（保证同日多迁移顺序确定，不依赖 Bean 注册顺序）；code 格式（`DM-\d{8}-\d{3}` 全匹配）与全局唯一校验同为构造期 fail-fast。主入口 `migrate()` 返回 void（第十三个启动任务调用，不消费返回值，执行汇总走 INFO 日志）；`JdbcTemplate` 经 `ObjectProvider` 惰性注入（口径同 §5.1 回写段），不可用时入口 WARN 跳过；无已注册迁移 INFO 跳过且不取锁。自举时机为「获锁后、执行前」——`CREATE TABLE IF NOT EXISTS` 自举 `common_source_migration_log`（DDL 复用 `CommonSourceSyncService.BOOTSTRAP_MIGRATION_LOG_DDL` 逐字一致，自举幂等，覆盖表结构同步未获锁跳过时该审计表缺失的场景）。审计行 `field_id` 由应用侧 `IDUtil.initID()` 生成、`field_creator_id` 取引擎系统身份（内置管理员 `'0'×32`），`field_start_time` / `field_end_time` 由 Service 显式写入（开始/结束时刻，FAILED 行同样写结束时刻与耗时），`field_create_time` 走库默认；幂等判定经 Dao `existsSuccess(code)`（存在 SUCCESS 行跳过）。迁移失败落 FAILED 审计行（`field_error` 异常链口径对齐 `CommonSourceSyncService#describeError`）后原异常重新抛出——RuntimeException 原样重抛、受检异常包装为 `IllegalStateException`，审计写入自身失败仅记日志不吞原始异常。

> 实现口径（F19-BE-007 落地回写，2026-11-17）：首例迁移 `SysProcessTemplateDefaultBackfillMigration` 落地于 `com.eric.base.sys.process.migration`（首个业务侧迁移实现包，后续各模块迁移类建议随各自模块建 `migration` 子包）。code=`DM-20261117-001`（当日首例，nnn 自 001 起）、name=「流程模板默认标记补录（默认模板 backfill）」、order=`100`——order 序号空间约定补充：首例占 100，后续迁移自 101 起依次递增；如出现须排在首例之前执行的历史迁移，取 1~99（执行清单按 order 升序、并列按 code 字典序，见 F19-BE-006 回写段）。SQL 以类内 `private static final String` 文本块常量逐字承接 V1_01_038 的 UPDATE 语句（含 ROW_NUMBER 窗口、`default_cnt = 0` 守护条件与生成列 `field_default_unique` 分类唯一键兜底口径，禁止手工拼串），等价性由单测从 test classpath 读取原脚本提取 UPDATE 文本、按「去注释行 + 压缩空白 + 去结尾分号」归一后断言逐字一致（常量反射读取 + mock 执行捕获实参双通道防漂移）；`JdbcTemplate` 经 `ObjectProvider` 惰性注入（口径同 §5.1），migrate() 入口判空 WARN 跳过（执行器侧同样判空，双保险）。另有 JDBC 级守卫式校验单测：DriverManager 直连真实 MySQL、独立临时 schema（绝不触碰开发库）自建最小表造三类数据，验证置默认/不改动/幂等语义，连不上 MySQL 经 assumeTrue 自动 skip——迁移 SQL 在真实 MySQL 上的语义与幂等验证属本例验收口径，全应用空库冷启动验证属 F19-INT-001。V1_01_038 脚本存档保留不改动；其余 21 脚本数据类语句核对结论（仅 V1_01_019 / V1_01_038 两条 UPDATE，无 INSERT——初始数据全部由 Java 启动任务 + yml 通道承接）登记于任务清单 §6 后「存量数据类语句迁移登记清单」。

## 9. 包结构与命名

```text
com.eric.base.common.source
├─ annotation   # TableSource / DataSource / TableIndex / ColumnField / DataSourceField
├─ enums        # ColumnType / IndexType / DefaultFunction / SyncMode / ChangeLevel
├─ model        # TableDef / ColumnDef / IndexDef / SchemaChange（含 ChangeLevel）

├─ ddl          # SourceDdlGenerator（MySQL 8.4 方言）
├─ diff         # SourceSchemaDiffer（information_schema 读取 + 比对分级）

├─ spi          # SourceDataMigration
├─ dao          # CommonSourceSyncLogDao / CommonSourceMigrationLogDao
└─ tool         # SourceSchemaExportTool（反向生成工具，main 入口）
```

- 命名对齐 common 层先例（`CommonSettingService` / `CommonModuleService`）；无 Controller / Resolver / request / response / roles.yml（无 HTTP 接口 → 无 ACTION_* 常量、无权限码、无 Swagger 注解义务）。
- Mapper XML 落 `resources/mappers/common/source/`。
- AGENTS.md §2 common 包清单需增列 `source`（F19-DOC-003）。

## 10. 范围边界

**In Scope**：注解族五件套、扫描器与公共列模板、DDL 生成器（MySQL 方言）、diff 与三级语义矩阵、同步引擎（三模式门禁 + GET_LOCK + 审计）、DataMigration SPI 及首例、反向生成工具、存量 21 表标注 adopt、A8 注解迁移、Flyway 移除与文档重写。

**Out of Scope（后续演进，不阻塞本期）**：
- 多数据库方言（仅 MySQL 8.4）；
- 字段改名/删列/索引重建的自动化（L2/L3 只报告）；
- 快照 hash 免比对优化（P2）；
- 表级 ENGINE/CHARSET 定制、FULLTEXT 索引；
- 注解表达视图/存储过程；
- 与字段级可见性、数据源取数配置的功能耦合。
