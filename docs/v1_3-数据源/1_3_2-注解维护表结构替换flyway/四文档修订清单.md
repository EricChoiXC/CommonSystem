### 1-3 「数据库与迁移」整节重写（§4）【裁决项 ①②】

- 位置：§4 数据库与迁移「迁移」段（字段段与树形表段保留不动）。
- 现口径：「**迁移**：目录 `db/migration/`，命名 `V{大版本}_{小版本}_{序号}__{英文下划线描述}.sql`。当前最新为 `V1_01_045`，新脚本从 `V1_01_046` 起递增，不得复用或跳回旧序号；**改表结构必须同时补脚本**。与 ERP 工程合并部署时，`V1_01_020` 等 ERP 专属脚本保留在 ERP 侧执行，…」。
- 目标口径：标题改「**数据库与表结构维护**」，整段重写为注解引擎口径：
  - 表结构由实体注解（`@TableSource` / `@ColumnField` / `@TableIndex`）声明，启动期同步引擎按 `CS_SOURCE_SYNC_MODE` 比对/执行（VALIDATE 只报告、INSTALL 仅补缺失、APPLY 执行 L1 告警 L2 阻断 L3）；
  - **改表 = 改实体注解**，不再新增迁移脚本（「改表结构必须同时补脚本」规则废止）；引擎永不 DROP TABLE / DROP COLUMN / RENAME，改名/删列/收窄走手工 SQL 或 DataMigration（L2/L3 指引）；
  - 数据回填 = 新增 `SourceDataMigration` 实现（code 格式 `DM-yyyyMMdd-nnn`、SUCCESS 幂等跳过、FAILED 阻断启动），不再写 SQL 数据脚本；
  - `db/migration/` 21 个脚本与 `flyway_schema_history` 为只读历史档案，保留不读写、不再新增；
  - ERP 合并部署边界一句保留但指向注解口径（详见迁移说明）。
- 依据：设计方案 §4.3、§5、§6、§7.3。
