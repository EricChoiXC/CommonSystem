# 系统模块UI设计文档

## 1. 文档说明

### 1.1 文档用途与维护规则

- 本文档用于承接 [系统模块需求文档](D:/Program/erp/docs/系统模块/系统模块需求文档.md) 中已经明确的页面、入口、布局分区、前端交互约束与页面状态规则。
- 本文档是系统模块前端页面设计基线，服务于后续页面实现、路由规划、菜单装配、接口联调与测试用例编写。
- 当前阶段先输出可评审主文档骨架与全局规则，对大范围模块采用“先总后分”的写法；各模块详细页面章节可继续按任务清单迭代补齐。
- 当需求文档、功能边界或权限规则发生变更时，必须先更新需求文档，再同步回写本文档对应章节。

### 1.2 AI使用约定

- AI Agent 在补全文档时，必须先读取本仓库 `AGENTS.md`、`docs/开发规范.md` 与本模块需求文档。
- 页面显隐、按钮禁用、可编辑性、异常提示必须引用需求文档中的业务权限与业务规则，不得由 UI 文档单独改写业务事实。
- 页面控件命名、页面名称、页面入口名称在 `3.3 页面承接总表`、各模块页面清单与后续任务清单中必须保持一致。

### 1.3 文档职责边界

- 本文档负责页面清单、页面目标、导航入口、布局骨架、字段展示分区、操作与状态约束。
- 本文档不负责详细业务流程真相定义；业务规则、角色权限归属仍以需求文档为准。
- 本文档不展开 API 路径、请求响应字段明细、数据库表结构与迁移脚本。

## 3. 全局UI规则

### 3.1 输出对象与承接关系

- 本文档输出对象包括：后台管理页面、业务弹窗、详情页、列表页、树选择弹窗、个人待办类页面。
- 本文档将被以下文档承接：
  - [系统模块API接口设计文档](D:/Program/erp/docs/系统模块/系统模块API接口设计文档.md)
  - [系统模块数据库设计](D:/Program/erp/docs/系统模块/系统模块数据库设计.md)
  - [系统模块开发任务清单](D:/Program/erp/docs/系统模块/系统模块开发任务清单.md)

### 3.2 全局导航与路由约束

- 前端基础路径前缀统一为 `/`。
- 系统模块页面统一归入“系统管理”一级菜单。
- 后台维护类页面优先采用“列表页 + 新增/编辑页或弹窗 + 详情抽屉/详情页”的标准结构。
- 个人工作类页面优先归入“我的工作台”或顶部待办入口，不直接混入后台维护菜单。

### 3.4 关键用户场景

- 系统管理员进入系统管理菜单，维护组织架构、角色、流程模板、编号规则、码值字典等系统主数据。
- 普通业务用户在业务页面中调用地址本选择弹窗、附件组件、流程提交入口和我的待办类页面完成日常处理。
- 监管角色进入流程监管、待办监管、审计记录页面进行只读型监管与特权审批。

### 3.5 通用页面规则

- 列表页默认包含：页头、筛选区、表格区、分页区；如存在批量操作，则在表格上方展示批量条。
- 表单页默认包含：页头、基础信息区、关联信息区、状态提示区、底部操作区。
- 详情页默认包含：摘要区、关键状态区、分组信息区、流转/操作记录区。
- 所有带权限的操作按钮必须依据后端返回的权限结果或前端预判结果决定显隐；前端显隐仅作体验优化，不替代后端鉴权。
- 所有启停用操作必须二次确认，并明确提示启停用影响范围。

## 4. 模块级页面设计

### 4.1 组织架构模块

#### 4.1.1 模块目标与边界

- 承接组织架构、机构、部门、人员、岗位、角色、群组与地址本选择的页面设计。
- 包含查询、普通读取、完整读取、新建、编辑、启停用、角色分配与群组维护相关页面。

#### 4.1.2 模块页面承接清单

- 组织架构管理页
- 机构新增/编辑页
- 部门新增/编辑页
- 人员新增/编辑页
- 岗位新增/编辑页
- 角色管理页
- 群组管理页（/org/group，三段式列表页，无左侧树）
- 群组新增/编辑页（/org/group/create、/org/group/edit/:id）
- 群组详情页（/org/group/detail/:id，只读）
- 地址本选择弹窗（含「角色」/「群组」页签）

#### 4.1.3 关键页面约束

- 组织架构管理页应支持树与列表联动，能够区分机构、部门、人员、岗位节点；树与列表固定排除角色（5）/群组（6）镜像行（不参与树）。
- 人员新增/编辑页必须区分“本人可编辑字段”与“管理员/维护者可编辑字段”。
- 角色管理页应覆盖角色基本信息、角色权限、角色分配三个视图。
- 群组页面对所有登录用户开放（菜单「组织架构→群组」+ 顶栏「多人」图标双入口）：管理页按可见性过滤展示，编辑/删除按行级维护权限显隐；表单页普通用户类型锁定「个人」，可见用户选择器限机构/部门/岗位/人员，空提示「不选择时默认全员可见」。
- 地址本选择弹窗必须支持组织架构树、岗位列表与目标回填；v1.1 起支持「角色」页签（showRole 开启，分页表格+独立刷新）与「群组」页签（可选类型含人员时自动显示，左侧可见群组列表+右侧成员人员表格）。

### 4.2 附件模块

#### 4.2.1 模块目标与边界

- 承接附件后台监管页面与通用附件组件设计。

#### 4.2.2 模块页面承接清单

- 附件管理页
- 通用附件组件

#### 4.2.3 关键页面约束

- 附件管理页仅附件管理员可访问。
- 通用附件组件需支持上传、下载、删除三类能力，并允许由业务页面控制按钮显隐。

### 4.3 流程机制模块

#### 4.3.1 模块目标与边界

- 承接流程模板维护、流程实例读取、特权审批监管相关页面设计。

#### 4.3.2 模块页面承接清单

- 流程模板管理页
- 流程模板新增/编辑页
- 流程实例详情页
- 流程监管页

#### 4.3.3 关键页面约束

- 模板页必须体现节点顺序、审批人规则、是否允许收回等配置项。
- 流程实例详情页必须展示流程状态、节点流转、审批意见与待办联动结果。
- 流程监管页允许管理员特权审批，但需保留明显的特权操作提示。

### 4.4 编号机制模块

#### 4.4.1 模块目标与边界

- 承接编号规则维护、测试预览、启停用与特权操作页面设计。

#### 4.4.2 模块页面承接清单

- 编号规则管理页
- 编号规则新增/编辑页
- 编号预览/测试弹窗

#### 4.4.3 关键页面约束

- 页面需显式展示规则编码、适用单据、前缀、日期段、流水长度、重置周期、组织范围、启用状态。
- 预览/测试弹窗需清晰反馈匹配规则结果与失败原因。

### 4.5 待办模块

#### 4.5.1 模块目标与边界

- 承接个人待办、已办、通知、关注与监管查询页面设计。

#### 4.5.2 模块页面承接清单

- 我的待办页
- 我的已办页
- 我的通知页
- 我的关注页
- 待办监管页

#### 4.5.3 关键页面约束

- “我的”类页面只展示当前用户自己的记录。
- 待办监管页仅监管查看，不开放代办、改状态、删除等动作。
- 所有处理按钮需跳转来源业务页面，由来源模块进行最终鉴权。

### 4.6 审计模块

#### 4.6.1 模块目标与边界

- 承接审计记录后台查询页面设计。

#### 4.6.2 模块页面承接清单

- 审计记录页

#### 4.6.3 关键页面约束

- 页面仅审计管理员可访问。
- 页面以查询和明细读取为主，不提供编辑能力。

### 4.7 码值模块

#### 4.7.1 模块目标与边界

- 承接码值字典主数据维护页面设计。

#### 4.7.2 模块页面承接清单

- 码值字典管理页
- 码值字典新增/编辑页

#### 4.7.3 关键页面约束

- 字典管理页需同时支撑主表与明细配置的维护。
- 非管理员仅允许查询、读取，不开放维护入口。

### 4.8 多语言模块

#### 4.8.1 模块目标与边界

- 承接语言清单维护、翻译矩阵维护、翻译部署三组后台页面，以及登录页语言下拉与顶部栏语言切换的全局改动（v1.1 新增）。
- 页面归「系统管理 → 多语言管理」分组，分组整体按 `SYS_I18N_ADMIN` 控制可见性，无权限用户不可见菜单、直访路由被拦截。

#### 4.8.2 模块页面承接清单

- 语言管理页（`/i18nLanguage`，标准三段式列表页；新建/编辑用弹窗，操作列含启停用、编辑、设默认、删除，均二次确认；默认语言行的删除/停用/设默认操作禁用）
- 翻译维护页（`/i18nTranslation`，模块单选 + 多语言矩阵；单元格内直接编辑，提交经 diff 确认弹窗；支持按资源行 × 语言重置、Excel 导入导出）
- 翻译部署页（`/i18nDeploy`，单「部署」按钮 + 执行结果展示，二次确认后执行，执行中防重复提交）
- 登录页语言下拉（免鉴权语言列表，默认语言置顶且默认选中；所选语言随登录请求提交）
- 顶部栏语言切换下拉（铃铛/日程旁；切换即更新页面与组件文案，仅 localStorage 记忆，不落库）

#### 4.8.3 关键页面约束

- 三个维护页面与登录/顶部改动点文案统一走 `$t`，语言包经 `/locales/{code}.json` 动态接口按需懒加载。
- 翻译矩阵资源列固定左侧，语言列按排序号升序、超宽出横向滚动条；提交仅提交 diff 改动项，无改动时提交按钮不可用。
- Element Plus 组件文案（分页、弹窗按钮、日期选择器等）随语言切换联动。
