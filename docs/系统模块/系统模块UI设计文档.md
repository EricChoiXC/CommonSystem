# 系统模块UI设计文档

## 1. 文档说明

### 1.1 文档用途与维护规则

- 本文档用于承接 [系统模块需求文档](D:/Program/erp/docs/系统模块/系统模块需求文档.md) 中已经明确的页面、入口、布局分区、前端交互约束与页面状态规则。
- 本文档是系统模块前端页面设计基线，服务于后续页面实现、路由规划、菜单装配、接口联调与测试用例编写。
- 当前阶段先输出可评审主文档骨架与全局规则，对大范围模块采用“先总后分”的写法；各模块详细页面章节可继续按任务清单迭代补齐。
- 当需求文档、功能边界或权限规则发生变更时，必须先更新需求文档，再同步回写本文档对应章节。

### 1.2 AI使用约定

- AI Agent 在补全文档时，必须先读取本仓库 `AGENTS.md`、`docs/开发规范.md` 与本模块需求文档。
- 页面显隐、按钮禁用、可编辑性、异常提示必须引用需求文档中的业务权限与业务规则，不得由 UI 文档单独改写业务事实。
- 页面控件命名、页面名称、页面入口名称在 `3.3 页面承接总表`、各模块页面清单与后续任务清单中必须保持一致。

### 1.3 文档职责边界

- 本文档负责页面清单、页面目标、导航入口、布局骨架、字段展示分区、操作与状态约束。
- 本文档不负责详细业务流程真相定义；业务规则、角色权限归属仍以需求文档为准。
- 本文档不展开 API 路径、请求响应字段明细、数据库表结构与迁移脚本。

### 3.1 输出对象与承接关系

- 本文档输出对象包括：后台管理页面、业务弹窗、详情页、列表页、树选择弹窗、个人待办类页面。

### 3.2 全局导航与路由约束

- 前端基础路径前缀统一为 `/`。
- 系统模块页面统一归入“系统管理”一级菜单。
- 后台维护类页面优先采用“列表页 + 新增/编辑页或弹窗 + 详情抽屉/详情页”的标准结构。
- 个人工作类页面优先归入“我的工作台”或顶部待办入口，不直接混入后台维护菜单。
- 顶栏用户区（头像 + 用户名 + 部门名）为 `el-dropdown`（hover 触发），下拉项【个人信息】（进入 `/profile` 个人资料页）与【退出登录】；独立【登出】按钮自 v1.2 起移除，退出登录仅经该下拉项（两种入口的登出链路等价：清空会话与标签页记录）。
- 顶栏用户区头像优先展示图片头像（本人资料 `avatarAttId` 经附件接口 blob 加载，与资料页共享 profileStore 即时同步），无头像时回退用户名首字符文字头像。

### 3.4 关键用户场景

- 系统管理员进入系统管理菜单，维护组织架构、角色、流程模板、编号规则、码值字典等系统主数据。
- 普通业务用户在业务页面中调用地址本选择弹窗、附件组件、流程提交入口和我的待办类页面完成日常处理。
- 监管角色进入流程监管、待办监管、审计记录页面进行只读型监管与特权审批。

### 3.5 通用页面规则

- 列表页默认包含：页头、筛选区、表格区、分页区；如存在批量操作，则在表格上方展示批量条。
- 表单页默认包含：页头、基础信息区、关联信息区、状态提示区、底部操作区。
- 详情页默认包含：摘要区、关键状态区、分组信息区、流转/操作记录区。
- 所有带权限的操作按钮必须依据后端返回的权限结果或前端预判结果决定显隐；前端显隐仅作体验优化，不替代后端鉴权。
- 所有启停用操作必须二次确认，并明确提示启停用影响范围。

## 4. 模块级页面设计

### 4.1 组织架构模块

#### 4.1.1 模块目标与边界

- 承接组织架构、机构、部门、人员、岗位、角色、群组与地址本选择的页面设计。
- 包含查询、普通读取、完整读取、新建、编辑、启停用、角色分配与群组维护相关页面。

#### 4.1.2 模块页面承接清单

- 组织架构管理页
- 机构新增/编辑页
- 部门新增/编辑页
- 人员新增/编辑页
- 岗位新增/编辑页
- 角色管理页
- 群组管理页（/org/group，三段式列表页，无左侧树）
- 群组新增/编辑页（/org/group/create、/org/group/edit/:id）
- 群组详情页（/org/group/detail/:id，只读）
- 地址本选择弹窗（含「角色」/「群组」页签）
- 个人资料页（/profile，v1.2，本人自助：无菜单归属，顶栏用户区下拉【个人信息】进入，路由 `meta.tab` 复用单标签、不参与菜单高亮）

#### 4.1.3 关键页面约束

- 组织架构管理页应支持树与列表联动，能够区分机构、部门、人员、岗位节点；树与列表固定排除角色（5）/群组（6）镜像行（不参与树）。
- 人员新增/编辑页必须区分“本人可编辑字段”与“管理员/维护者可编辑字段”。
- 角色管理页应覆盖角色基本信息、角色权限、角色分配三个视图。
- 群组页面对所有登录用户开放（菜单「组织架构→群组」+ 顶栏「多人」图标双入口）：管理页按可见性过滤展示，编辑/删除按行级维护权限显隐；表单页普通用户类型锁定「个人」，可见用户选择器限机构/部门/岗位/人员，空提示「不选择时默认全员可见」。
- 地址本选择弹窗必须支持组织架构树、岗位列表与目标回填；v1.1 起支持「角色」页签（showRole 开启，分页表格+独立刷新）与「群组」页签（可选类型含人员时自动显示，左侧可见群组列表+右侧成员人员表格）。
- 个人资料页（v1.2）为本人自助页面：登录即可访问（`ProfileResolver` 不设权限码），三卡片布局——头像卡片（上传/移除，单张语义：上传新头像成功后删除旧头像附件，无头像回退首字符）、资料表单（用户名可编辑、登录名只读、手机/邮箱/地址/性别/生日，保存按钮置 `el-card #header`）、关联账号卡片（总开关关闭时整卡提示，开启后微信/QQ 各一行，凭证未配置置灰）；详细布局见 [组织架构前端页面设计](../设计文档/sys/org/组织架构前端页面设计.md)。

#### 4.2.1 模块目标与边界

- 承接附件后台监管页面与通用附件组件设计。

#### 4.2.2 模块页面承接清单

### 4.3 流程机制模块

#### 4.3.1 模块目标与边界

- 承接流程模板维护、流程实例读取、特权审批监管相关页面设计。

#### 4.3.2 模块页面承接清单

- 流程模板管理页
- 流程模板新增/编辑页
- 流程实例详情页
- 流程监管页

#### 4.3.3 关键页面约束

- 模板页必须体现节点顺序、审批人规则、是否允许收回等配置项。
- 流程实例详情页必须展示流程状态、节点流转、审批意见与待办联动结果。
- 流程监管页允许管理员特权审批，但需保留明显的特权操作提示。

### 4.4 编号机制模块

#### 4.4.1 模块目标与边界

- 承接编号规则维护、测试预览、启停用、删除保护与特权操作页面设计（v1.5 已实现）。
- 菜单入口：【后台管理】→【编号机制】→【编号管理】（三级分组）；路由 `/number`（列表页）、`/number/create`（新建）、`/number/edit/:id`（编辑，`meta.tab: 'name'` 复用单标签，`activeMenu` 将 `/number` 前缀路由归约到 `/number`）。叶子菜单显示权限绑定 `SYS_NUMBER_ADMIN` / `SYS_NUMBER_RULE_EDITOR`（后台管理菜单组 `auth` 为空、权限下放子项声明；`SYS_ADMIN` 经超管短路天然可见）。

#### 4.4.2 模块页面承接清单

- 编号规则管理页（`/number`，三段式列表页 + 页内预览测试弹窗）
- 编号规则新增/编辑页（`/number/create`、`/number/edit/:id`，共用一个表单组件按路由区分模式）
- 编号预览/测试弹窗（列表页内弹窗，不单独建路由）
- 编号规则组件 NumberRuleComposer（公共组件，嵌入编辑页整行；契约见 [前端公共组件](前端公共组件.md)）

#### 4.4.3 关键页面约束

- 列表页显式展示规则编码、规则名称、所属模型、所属模型字段、启用状态与创建/更新时间；规则组成片段（文本 / 日期 / 流水 / 随机）由 NumberRuleComposer 在编辑页承载，列表页不展开。
- 启停用必须二次确认：启用时提示将自动停用同接入项其他已启用规则（切换式启用）；已产生取号明细的规则删除被拒（仅可停用），删除确认需提示该保护。
- 预览/测试弹窗基于当前计数器顺延模拟（不推进计数器、不落库），需清晰反馈样例编号与校验失败原因。

#### 4.4.4 [PAGE-SYS-014] 编号规则管理页

##### 页面元信息

#### 4.10.7 数据源取数消费方式（非独立页面）

- 消费面权限口径：菜单入口仅对 `SYS_DATASOURCE_ADMIN` 展示，但 `options` / `targets` / `query` 接口登录即可——无权限用户虽看不到管理菜单，其业务页面仍可经数据源取数；取数越权由执行期委托目标 action 鉴权收敛（需求文档第 11 章、API 文档 4.10.5）。
- 方式一（页面直调）：页面按 `code` 调 `queryDatasource({ code, body, pages, sortField, sortOrder })`，`body` 只传增量过滤条件（固定条件由服务端强制、同名 key 覆盖调用方条件）；列头以 `metadata.fields` / `options.fields` 为准渲染，**不假设固定列**（R04）；分页 `layout="total, prev, pager, next, sizes"`、`page-sizes [10,20,50,100]`；`sortField` 须命中目标能力可排序白名单，非法值由后端回退默认排序。示例见样例代码 §4.2「我的日程」直调 `calendar.my-created`。
- 方式二（通用组件）：`components/DatasourceTable.vue`，props `code`（可选 `filters` / `sortField`），内部完成 `options` → 列头渲染 → `queryDatasource` 取数编排，适合快速搭建数据源驱动列表页。已随 F18-FE-005 纳入 v1.8（2026-11-17 落地），组件契约已同步 `docs/系统模块/前端公共组件.md`「九. 数据源表格组件」，消费以该契约为准。
- 数据源选择交互：消费页面如需让用户挑选数据源，用 `getDatasourceOptions()` 填充 `el-select`（label 为数据源名称，可按 `sourceType` 加 CODE/CUSTOM 辅助标记）；选项含 `fields` 有效字段集，与执行结果 `metadata.fields` 一致，可用于列头预渲染；`options` 不暴露固定条件原文，前端不可也不需感知固定条件内容。
- 码值翻译：执行结果为原始值（如 `fieldType=PERSONAL`），码值显示名由消费方页面按码值模块自行翻译（TBD 裁决结论 1）；消费页面在渲染列时对枚举/码值字段按码值模块转换后再展示。

#### 4.11.3 关键页面约束

- 编辑器只做输入辅助、权威校验在后端（方案 A1）：CodeMirror 6 进一期（TBD① 裁决，2026-11-16，随 F14-DOC-001 落定；回退预案 `el-input type="textarea"` 保留不删）；前端不做最终语法裁决，validate 接口即权威。
- 保存期强制校验：save / update 时 `fieldExpression` 先经 validate 同源校验（语法 / 函数注册 / 参数与返回类型 / 变量码约束），校验不过即拒绝保存（API 文档 4.11.4）；公式引用失效变量不阻断保存，由 validate 报告、消费方决定处置。
- 系统变量（`CURRENT_USER` / `CURRENT_DEPT` / `CURRENT_ROLE` 等会话上下文）为服务端注入语义，不可被前端赋值覆盖（后端不信任前端传入的 `CURRENT_*` 覆盖），模拟区不为其生成赋值行（见 4.11.7）。
- 左树业务模型节点来自数据源 targets 聚合（`GET /backend/sys/datasource/targets`，各模块 Provider 声明的 resultFields），公式模块**不另建字段台账**（方案 A6）；Provider 下线后左树业务模型组随之变化，公式引用失效变量由 validate 报告、不阻断保存。
- 启停用与删除均须二次确认；停用或删除后消费方按 `field_code` 执行报 `CS_FORMULA_NOT_FOUND`（API 文档 4.11.4）。
- 模拟区赋值仅用于沙箱试算，入参由调用方自负（API 文档 4.11.5），不代表任何真实业务数据授权；`/simulate` 仅在资源限制内执行（表达式长度 / 变量个数 / 序列化体积 / 循环次数 / 超时上限，常量收口 `SysFormulaConstants`）。

##### 左树节点（前端组装：`getFormulaOptions()` 命名公式条目 + `getFormulaFunctions()` 函数元数据 + 数据源 targets + `availableVars` 外部追加）

| 节点组 | 内容 | 插入语义 |
| --- | --- | --- |
| 变量 | 系统变量（当前用户 / 部门 / 角色等会话上下文，服务端注入）+ 组织架构上下文（一期注入当前用户 / 部门，出自会话 `UserUtil`；org 任意字段读取 `ORG_*` 二期随 v1.7 注册）+ `availableVars` 外部追加变量声明 | 双击或【插入】按钮写入编辑区，变量插入 `${code}` |
| 业务模型 | 复用数据源 `GET /backend/sys/datasource/targets` 聚合的「能力 → 字段」两级节点——各模块声明 Provider 即自动进入公式组件，公式模块不另建字段台账（方案 A6） | 双击字段节点或【插入】按钮写入编辑区；明细汇总场景以路径投影 `${list.field}` 书写 |

| 命名公式 | 启用中的命名公式条目（`GET /backend/sys/formula/options`，元素 `{ fieldCode, fieldName, fieldType, fieldReturnType }`，不暴露表达式原文） | 双击或【插入】按钮写入 `${fieldCode}`（消费方按编码引用、执行时加载启用中的公式，API 文档 4.11.4） |

##### 编辑区（右上）

- 底座：**CodeMirror 6**（TBD① 已裁决进一期，版本以 `frontend/package.json` 实装为准）——语法高亮 + 括号匹配 + `${}` / 函数 token 提示；回退预案 `el-input type="textarea"`（monospace + 插入按钮 + validate 错误行号提示）保留不删。
- 校验联动：编辑后调 `validateFormula({ expression, expectedReturnType, vars })`，`errors` 数组按「错误码 + message（附引擎错误信息与位置/行号）」可读展示（如 `CS_FORMULA_SYNTAX_INVALID` 附语法错误位置），同时展示返回的 `dependencies` 变量依赖；编辑器只做输入辅助、权威校验在后端 validate（方案 A1），前端不做最终语法裁决。
- vars 口径：弹窗以已知变量声明（左树变量组 + `availableVars`）构造 `vars` 入参（元素 `{ code, type }`）；`vars` 缺省 = 宽松模式（变量视为未知，仅语法与函数校验）、非空 = 严格模式（按注册元数据校验参数 / 返回类型并比对 `expectedReturnType`，API 文档 4.11.4）。

##### 函数面板

- 数据来自 `getFormulaFunctions()`，元素为函数元数据 `{ functionCode, functionName, category, description, parameters: [{ name, type, required, defaultValue }], returnType }`；按分类折叠展示函数名 / 参数 / 说明，前后端共用一份注册定义。
- 插入语义：选中函数按注册元数据 `parameters` 生成「函数名(占位参数…)」占位参数模板写入编辑区；`DS_QUERY(code, body)` 为取数函数，经数据源统一执行入口取业务模型数据（数据边界委托见本节权限口径）。

##### 模拟区（右下）

- 赋值行：按声明 vars（弹窗声明 + `availableVars` 追加）生成「变量码（只读）+ 赋值控件」行，控件随变量 `type` 选型——NUMBER 数字输入、STRING 文本、BOOLEAN 开关、DATE 日期选择、ARRAY 以 JSON 文本输入；**系统变量（`CURRENT_USER` / `CURRENT_DEPT` / `CURRENT_ROLE`）为服务端注入语义，不生成赋值行**（后端不信任前端传入的 `CURRENT_*` 覆盖）。
- 试算：【试算】按钮调 `simulateFormula({ expression, vars, expectedReturnType })`；成功展示 `result`（NUMBER 经 BigDecimal 规整）+ `resultType`；失败 `success=false`，`errors` 数组（元素 `{ code, message }`，`code` ∈ `CS_FORMULA_*`，HTTP 仍 200）可读展示，**失败不阻断弹窗操作**（可继续编辑、校验、再试算）。
- 边界：模拟赋值仅用于沙箱试算，入参由调用方自负（API 文档 4.11.5）；管理员预判命名公式复用 `/simulate`，不单设预览接口（对齐数据源范围裁决先例）。

##### 组件 props 契约（v1.5 / v1.7 内嵌预留）

| prop | 语义 | 说明 |
| --- | --- | --- |
| `visible` | 弹窗显隐控制 | 内嵌消费方控制打开 / 关闭 |
| `availableVars` | 外部追加变量声明 | 如 v1.5 表单字段声明（含明细行数组变量，支持 `${list.field}` 路径投影场景）；并入左树变量组、validate `vars` 入参与模拟区赋值行 |
| `functionCategories` | 函数分类过滤 | 仅展示指定分类；缺省 = 全部九类 |
| `expectedReturnType` | 期望返回类型 | 作为 validate / simulate 的 `expectedReturnType` 入参；类型不符报 `CS_FORMULA_TYPE_MISMATCH` |
| `expression` | 公式文本（v-model） | 弹窗【确认】将编辑后的表达式回写 v-model（管理表单页回写 `fieldExpression`；内联消费方回写自身配置 JSON） |

##### 内嵌消费承接（v1.5 / v1.7 可从本节独立读通）

- v1.5 自定义表单——字段自动计算：字段配置内嵌 FormulaDesigner 编写内联公式，`availableVars` 传表单字段声明（含明细行数组变量）、`expectedReturnType` 随字段类型；validate 返回 `dependencies` 供表单引擎自建依赖图做联动重算 / 失效引用检查（方案 A8，联动执行不在公式模块）。
