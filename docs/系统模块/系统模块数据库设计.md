# 系统模块数据库设计

## 1. 文档说明

### 1.1 文档用途与维护规则

- 本文档用于承接 [系统模块需求文档](D:/Program/erp/docs/系统模块/系统模块需求文档.md)，建立系统模块数据库设计基线。
- 当前阶段优先冻结模块级表对象、主从关系、命名规则与迁移承接入口，不提前展开详细字段表。
- 所有表结构调整必须与后续 Flyway 脚本保持同步，不允许只改文档不补迁移。

### 1.2 文档职责边界

- 本文档负责模块对象边界、表清单、关系类型、公共字段约束、命名规范与待补数据设计任务。
- 本文档当前不展开字段级 DDL、索引明细、外键脚本和分区脚本。
- 业务流程、权限语义不在本文档定义，以需求文档为准。

### 1.3 AI使用约定

- AI Agent 在补充表设计前，必须先核对需求文档中的业务对象和 API 文档中的接口分组。
- 未经确认的字段、索引、唯一约束，不得在骨架阶段写成既定事实。
- 如果表名与需求原文存在歧义，应在“待确认事项”中显式记录。

## 3. 全局数据规则

### 3.1 输出对象与承接关系

- 本文档输出对象包括：表目录、关系边界、后续 Flyway 脚本分组依据、实体类命名依据、Mapper 分组依据。
- 本文档将被以下文档承接：
  - [系统模块API接口设计文档](D:/Program/erp/docs/系统模块/系统模块API接口设计文档.md)
  - [系统模块开发任务清单](D:/Program/erp/docs/系统模块/系统模块开发任务清单.md)

### 3.2 公共字段与命名规则

- 所有字段统一使用 `field_` 前缀。
- 公共字段优先复用：
  - `field_id`
  - `field_code`
  - `field_name` / `field_subject`
  - `field_creator_id`
  - `field_create_time`
  - `field_updator_id`
  - `field_update_time`
  - `field_enable`
- 表名、字段名、索引名统一使用下划线命名法。
- Flyway 脚本命名遵循 `V{版本号}__{英文下划线描述}.sql`。

### 3.3 关系与建模规则

- 一对一扩展表用于承载不同节点类型的差异字段，公共树节点信息应放在主表。
- 多对多关系优先使用显式关系表，不直接在主表上存逗号拼接字段。
- 审计表按年度分表设计，具体分表策略与归档策略在详细任务阶段确认。
- 流程、待办、附件等监管型对象应保留操作记录或状态轨迹表。

## 4. 模块数据模型骨架

### 4.1 组织架构模块

#### 4.1.1 模块目标与数据边界

- 承接组织架构树节点、不同类型节点扩展信息、角色、权限与分配关系，以及 v1.1 的角色组织架构镜像行与群组（公共/个人，含成员与可见范围明细）。

#### 4.1.2 当前已识别表对象

| 表名                        | 中文名       | 关系定位       |
|---------------------------|-----------|------------|
| `sys_org_element`         | 组织架构表     | 组织树主表（另维护角色 `field_org_type = 5` 与群组 `field_org_type = 6` 镜像行，不参与树） |
| `sys_org_org`             | 机构表       | 与组织架构表一对一  |
| `sys_org_dept`            | 部门表       | 与组织架构表一对一  |
| `sys_org_user`            | 人员表       | 与组织架构表一对一  |
| `sys_org_post`            | 岗位表       | 与组织架构表一对一  |
| `sys_org_post_user`       | 岗位人员表     | 人员与岗位多对多   |
| `sys_org_auth`            | 权限表       | 权限主表       |
| `sys_org_role`            | 角色表       | 角色主表（另在 `sys_org_element` 维护 `field_org_type = 5` 镜像行） |
| `sys_org_role_element`    | 角色分配表     | 角色与组织架构多对多 |
| `sys_org_role_auth`       | 角色权限表     | 角色与权限多对多   |
| `sys_org_virtual_user`    | 虚拟组织架构归属表 | 组织架构与人员多对多 |
| `sys_org_group`           | 群组表       | 与组织架构表一对一（`field_org_type = 6`，镜像行不参与树） |
| `sys_org_group_user`      | 群组-成员表   | 群组与人员多对多（复合主键，全量替换） |
| `sys_org_group_viewer`    | 群组-可见范围表 | 群组与组织架构节点多对多（仅公共群组，复合主键，全量替换） |

#### 4.1.3 当前冻结的建模方向

- `sys_org_element` 作为统一树节点主表，扩展表承载机构、部门、人员、岗位、群组差异字段。
- 角色与组织架构对象、角色与权限对象均使用关系表建模。
- 角色（`field_org_type = 5`）以 `sys_org_role` 为主表、群组（`field_org_type = 6`）以 `sys_org_group` 为主表，
  写入时同事务维护 `sys_org_element` 镜像行（树字段 NULL / level 1，不参与树；镜像行 `field_code` 角色存编码、群组恒空串）。
- 群组三表由迁移 `V1_01_039__sys_org_group_schema.sql` 承接（utf8mb4、无外键、`IF NOT EXISTS`），
  约束由应用层（`SysOrgGroupService`）保证；存量角色镜像行不迁移（明确决策，仅写路径增量维护）。
- 地址本弹窗直接消费组织架构与岗位相关对象，不单独新增地址本主表。
- `sys_org_user` 由迁移 `V1_01_042__sys_org_user_openid.sql`（v1.2）新增 `field_openid` 列（JSON DEFAULT NULL，
  列注释「第三方账号绑定信息(JSON)」，位于 `field_last_chg_pwd_time` 之后，**无索引**）：JSON 结构固定为
  `{ "wechat": { "openid", "unionid", "nickname", "bindTime" }, "qq": { "openid", "nickname", "bindTime" } }`
  （`bindTime` 为 `yyyy-MM-dd HH:mm:ss` 格式字符串），结构化 POJO `SysOrgUserOpenidDo`（Jackson 序列化，禁手工拼 JSON 串）；
  openid 全局唯一，绑定前经 `SysOrgUserMapper.countDuplicateOpenid`（JSON 路径 `field_openid->>'$.wechat.openid'` /
  `$.qq.openid` 提取查重）校验，人员量级下不建函数索引；解绑移除对应渠道键，两渠道均空时整列置 NULL。
- `common_setting` 新增配置项 `system.openid_bind_enable`（v1.2，bool，默认 `false`，第三方账号绑定总开关）：
  登记于 `properties/common/application.yml` 的 `SETTING.system` 段，启动经 `CommonSettingService#syncFromYml`
  增量同步入表；管理员经系统设置页修改（`PATCH /backend/common/setting/update`），运行时实时读库（无缓存）。
  渠道 OAuth 凭证为部署级配置，另入 `sys/org/application.yml` 的 `SETTING.openid` 段
  （`wechat_app_id` / `wechat_app_secret` / `qq_app_id` / `qq_app_secret` / `redirect_base`，两层结构禁三层嵌套；
  `GET /common/setting/load` 只返回 system 类型，凭证不下发前端；环境变量覆盖 `CS_ORG_WECHAT_APP_ID` 等
  五项经 `application.properties` 桥接键三段式，`redirect_base` 默认 `http://localhost:5173`，生产必须经
  `CS_ORG_OAUTH_REDIRECT_BASE` 覆盖为对外可达地址）。

### 4.8 多语言模块

#### 4.8.1 模块目标与数据边界

- 承接语言清单、资源登记、翻译文本与用户语言登记（v1.1 新增，迁移脚本 `V1_01_040__sys_i18n_schema.sql`）。

#### 4.8.2 当前已识别表对象

| 表名 | 中文名 | 关系定位 |
| --- | --- | --- |
| `sys_i18n_language` | 语言表 | 语言清单（`field_default` 全局仅一条，应用层互斥切换；`field_code` 索引） |
| `sys_i18n_key` | 资源表 | 资源登记（key 仅随资源文件扫描产生，D5；`(field_model, field_key)` 联合索引） |
| `sys_i18n_translation` | 翻译表 | 翻译文本（`(field_key, field_language)` 索引；业务唯一由代码层保证，不建唯一约束，便于重置删插） |
| `sys_i18n_user_language` | 用户语言表 | 用户语言登记（`field_user_id` 为主键，一人一条） |

#### 4.8.3 当前冻结的建模方向

- 全部字段 `field_` 前缀、`utf8mb4`、不建外键、`IF NOT EXISTS` 幂等，公共字段含 `field_id` / `field_creator_id` / `field_create_time` / `field_updater_id` / `field_update_time` / `field_enable`。
- `sys_i18n_translation.field_update_time` 兼任「人工编辑标记」：非空 = 人工已编辑（人工编辑、Excel 导入均视为人工），启动/部署同步不覆盖；为空 = 资源文件导入，资源值可覆盖。注意：日志/流水类表「不设 `field_update_time`」的先例不适用于本表，该字段在此有业务语义。
- 翻译表 `field_language` 存语言码（`sys_i18n_language.field_code`），用户语言表 `field_language_id` 存语言表 ID——两者引用方式不同，为既定设计。
- 删除语言的应用层级联（D4）：同事务删除该语言全部翻译、已选该语言的用户语言登记改绑默认语言（不删行）。

### 4.9 模块组开关模块（v1.1 新增）

#### 4.9.1 模块目标与数据边界

- 承接模块组（module-group）开关状态：按模块组粒度对一组接口做运行期整体启停，表由启动同步按各模块 `moduleGroup.yml` 的 `module-group` 段增量维护（v1.1 新增，迁移脚本 `V1_01_043__common_module_group_schema.sql`）。
- 模块组与各模块 `moduleGroup.yml` 声明按 `field_key` 逻辑关联，**不做物理外键**；本特性仅此一张表。

#### 4.9.2 当前已识别表对象

| 表名 | 中文名 | 关系定位 |
| --- | --- | --- |
| `common_module_group` | 模块组状态表 | 配置型主表（`field_key` 全局唯一，`uk_module_key` 兜底） |

#### 4.9.3 当前冻结的建模方向

- 表结构以 `V1_01_043__common_module_group_schema.sql` 为准（`CREATE TABLE IF NOT EXISTS` 幂等、`utf8mb4`、无外键）：`field_id VARCHAR(32)` 主键；`field_key VARCHAR(200) NOT NULL`（kebab-case，全局唯一，幂等同步键与 `@ModuleGroup(moduleGroupKey)` 注解引用键）；`field_name VARCHAR(200) NOT NULL`；`field_enable BIT(1) NOT NULL DEFAULT b'1'`（0 关闭 / 1 开启，遵循全工程启用位惯例）；`field_remark VARCHAR(200) NULL`；`field_update_time TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP`。唯一索引 `uk_module_key (field_key)`——`field_key` 是幂等同步键与注解引用键，缺失唯一约束会在重复/并发同步时插入重复行（先例 `common_setting` 的 `uk_setting_type_key`）。
- **公共字段裁剪声明**：本表与 `common_setting` 同为配置型表，**无** `field_creator_id`、`field_create_time`、`field_updater_id`——只维护「元信息 + 启用状态 + 更新时间」（`common_setting` 建表脚本已声明同样理由）；`field_update_time` 由数据库 `DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` 自动维护，不依赖应用层写入更新人/更新时间；保留 `field_enable` 承载开关状态本身。
- 数据生命周期：无初始化 `INSERT` 语句，Flyway 只建结构；全部数据经第 10 个启动任务扫描 `classpath*:properties/**/moduleGroup.yml` 增量维护——不存在插入（`field_enable` 默认开启）、已存在只回写 `name` / `remark`（**`field_enable` 一律不动**，管理员关闭后重启不得被 yml 重置）、yml 移除记录保留（不删除、不改状态、不加下线标记，可人工清理）；首批数据仅 `calendar`、`org-group`（`third-party` 仅设计占位、不建 yml）。
- 实体与 Mapper 落点：`CommonModule extends BaseModel`（`com.eric.base.common.module.model`，命名遵循 `common/setting` 先例），Dao / Mapper 一对一，XML 落 `resources/mappers/common/module/`；基础 SQL 全落 XML——全量查询（按 `field_key` 排序）、按 `field_key` 查询、按 `field_key` 批量回写元信息（仅 `name` / `remark`）、`/enable` 通道更新（按 `field_id` 更新 `field_enable`）。
