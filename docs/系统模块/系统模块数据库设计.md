# 系统模块数据库设计

## 1. 文档说明

### 1.1 文档用途与维护规则

- 本文档用于承接 [系统模块需求文档](D:/Program/erp/docs/系统模块/系统模块需求文档.md)，建立系统模块数据库设计基线。
- 当前阶段优先冻结模块级表对象、主从关系、命名规则与迁移承接入口，不提前展开详细字段表。
- 所有表结构调整必须与后续 Flyway 脚本保持同步，不允许只改文档不补迁移。

### 1.2 文档职责边界

- 本文档负责模块对象边界、表清单、关系类型、公共字段约束、命名规范与待补数据设计任务。
- 本文档当前不展开字段级 DDL、索引明细、外键脚本和分区脚本。
- 业务流程、权限语义不在本文档定义，以需求文档为准。

### 1.3 AI使用约定

- AI Agent 在补充表设计前，必须先核对需求文档中的业务对象和 API 文档中的接口分组。
- 未经确认的字段、索引、唯一约束，不得在骨架阶段写成既定事实。
- 如果表名与需求原文存在歧义，应在“待确认事项”中显式记录。

## 3. 全局数据规则

### 3.1 输出对象与承接关系

- 本文档输出对象包括：表目录、关系边界、后续 Flyway 脚本分组依据、实体类命名依据、Mapper 分组依据。
- 本文档将被以下文档承接：
  - [系统模块API接口设计文档](D:/Program/erp/docs/系统模块/系统模块API接口设计文档.md)
  - [系统模块开发任务清单](D:/Program/erp/docs/系统模块/系统模块开发任务清单.md)

### 3.2 公共字段与命名规则

- 所有字段统一使用 `field_` 前缀。
- 公共字段优先复用：
  - `field_id`
  - `field_code`
  - `field_name` / `field_subject`
  - `field_creator_id`
  - `field_create_time`
  - `field_updator_id`
  - `field_update_time`
  - `field_enable`
- 表名、字段名、索引名统一使用下划线命名法。
- Flyway 脚本命名遵循 `V{版本号}__{英文下划线描述}.sql`。

### 3.3 关系与建模规则

- 一对一扩展表用于承载不同节点类型的差异字段，公共树节点信息应放在主表。
- 多对多关系优先使用显式关系表，不直接在主表上存逗号拼接字段。
- 审计表按年度分表设计，具体分表策略与归档策略在详细任务阶段确认。
- 流程、待办、附件等监管型对象应保留操作记录或状态轨迹表。

## 4. 模块数据模型骨架

### 4.1 组织架构模块

#### 4.1.1 模块目标与数据边界

- 承接组织架构树节点、不同类型节点扩展信息、角色、权限与分配关系。

#### 4.1.2 当前已识别表对象

| 表名                        | 中文名       | 关系定位       |
|---------------------------|-----------|------------|
| `sys_org_element`         | 组织架构表     | 组织树主表      |
| `sys_org_org`             | 机构表       | 与组织架构表一对一  |
| `sys_org_dept`            | 部门表       | 与组织架构表一对一  |
| `sys_org_user`            | 人员表       | 与组织架构表一对一  |
| `sys_org_post`            | 岗位表       | 与组织架构表一对一  |
| `sys_org_post_user`       | 岗位人员表     | 人员与岗位多对多   |
| `sys_org_auth`            | 权限表       | 权限主表       |
| `sys_org_role`            | 角色表       | 角色主表（另在 `sys_org_element` 维护 `field_org_type = 5` 镜像行） |
| `sys_org_role_element`    | 角色分配表     | 角色与组织架构多对多 |
| `sys_org_role_auth`       | 角色权限表     | 角色与权限多对多   |
| `sys_org_virtual_user`    | 虚拟组织架构归属表 | 组织架构与人员多对多 |
| `sys_org_group`            | 群组表      | 与组织架构表一对一（`field_org_type = 6`） |
| `sys_org_group_user`       | 群组-成员表   | 群组与人员多对多 |
| `sys_org_group_viewer`     | 群组-可见范围表 | 群组与组织架构节点多对多（仅公共群组） |

#### 4.1.3 当前冻结的建模方向

- `sys_org_element` 作为统一树节点主表，扩展表承载机构、部门、人员、岗位差异字段。
- 角色与组织架构对象、角色与权限对象均使用关系表建模。
- 地址本弹窗直接消费组织架构与岗位相关对象，不单独新增地址本主表。

### 4.2 附件模块

#### 4.2.1 模块目标与数据边界

- 承接附件元数据、文件实体和附件操作轨迹。

#### 4.2.2 当前已识别表对象

| 表名 | 中文名 | 关系定位 |
| --- | --- | --- |
| `sys_attachment_main` | 附件记录表 | 附件业务主表 |
| `sys_attachment_file` | 附件文件表 | 与附件记录表一对一 |
| `sys_attachment_operation` | 附件操作记录表 | 与附件记录表一对多 |

#### 4.2.3 当前冻结的建模方向

- 附件元数据与文件存储信息分表，便于后续支持不同存储介质。
- 上传、下载、删除等操作需保留操作轨迹。

### 4.3 流程机制模块

#### 4.3.1 模块目标与数据边界

- 承接流程模板、模板节点、流程实例、实例节点、流转记录与审批记录。

#### 4.3.2 当前已识别表对象

| 表名 | 中文名 | 关系定位 |
| --- | --- | --- |
| `sys_process_template` | 流程模板 | 模板主表 |
| `sys_process_template_node` | 流程节点 | 与模板一对多 |
| `sys_process_main` | 流程实例 | 实例主表 |
| `sys_process_main_node` | 流程实例节点 | 与实例一对多 |
| `sys_process_main_workitem` | 流程流转记录 | 与实例一对多 |
| `sys_process_main_audit` | 流程审批记录 | 与流转记录一对一 |

#### 4.3.3 当前冻结的建模方向

- 模板与实例分层建模，不允许业务单据直接复用模板表落审批结果。
- 审批意见与流转记录分表，便于区分节点流转和审批结论。

### 4.4 编号机制模块

#### 4.4.1 模块目标与数据边界

- 承接编号规则主数据与规则明细配置。

#### 4.4.2 当前已识别表对象

| 表名 | 中文名 | 关系定位 |
| --- | --- | --- |
| `sys_number_rule` | 编号规则 | 规则主表 |
| `sys_number_rule_detail` | 编号规则明细配置 | 与规则一对多 |

#### 4.4.3 当前冻结的建模方向

- 规则主表管理适用对象与启用状态，明细表承载前缀、日期段、流水号等组成片段。
- 正式取号流水是否单独建表，待详细任务确认。

### 4.5 待办模块

#### 4.5.1 模块目标与数据边界

- 承接待办主记录、通知接收人、未处理人、已处理人和关注关系。

#### 4.5.2 当前已识别表对象

| 表名 | 中文名 | 关系定位 |
| --- | --- | --- |
| `sys_notify_main` | 待办记录 | 待办/通知主表 |
| `sys_notify_main_receive` | 通知接收人 | 与主表一对多 |
| `sys_notify_main_todo` | 未处理人 | 与主表一对多 |
| `sys_notify_main_done` | 已处理人 | 与主表一对多 |
| `sys_notify_main_start` | 关注待办 | 与主表一对多 |

#### 4.5.3 当前冻结的建模方向

- 待办、通知、关注共享主表，但通过子表区分接收与处理状态。
- 关注子表命名存在 `start/star` 歧义，详细阶段需统一。

### 4.6 审计模块

#### 4.6.1 模块目标与数据边界

- 承接系统所有关键增删改操作的年度审计记录。

#### 4.6.2 当前已识别表对象

| 表名 | 中文名 | 关系定位 |
| --- | --- | --- |
| `sys_audit_{yyyy}` | 审计记录 | 按年分表的审计主表 |

#### 4.6.3 当前冻结的建模方向

- 审计按年分表，具体分表创建策略、冷热数据保留策略在详细任务中明确。
- 当前不拆独立明细表，除非后续审计内容结构复杂到需要主从分离。

### 4.7 码值模块

#### 4.7.1 模块目标与数据边界

- 承接码值字典主表与字典明细项。

#### 4.7.2 当前已识别表对象

| 表名 | 中文名 | 关系定位 |
| --- | --- | --- |
| `sys_dict_main` | 码值表 | 字典主表 |
| `sys_dict_detail` | 码值明细 | 与主表一对多 |

#### 4.7.3 当前冻结的建模方向

- 公共类码值与模块独立码值可共用表结构，通过分类字段区分。
- 枚举值字段长度需满足 50 字符以内的统一规范。
