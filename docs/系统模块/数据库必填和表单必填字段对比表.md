# 数据库必填 vs 表单必填 字段对比表

## 说明

- **DB NOT NULL**：数据库字段定义有 `NOT NULL`（含主键和 NOT NULL DEFAULT 的字段）
- **DB NOT NULL + DEFAULT**：数据库字段有 `NOT NULL` 但同时有 `DEFAULT` 默认值，插入时可不传（由数据库自动填充）
- **表单必填（业务校验）**：Service 层 `validate()` 方法中明确校验为必填的字段
- 未标注"表单必填"的字段在 Service 层未做非空校验，提交时可为空
- 本表汇总公共系统（sys / common 模块）全部表的字段，按模块分组

## 三、关键发现总结

### 3.1 数据库 NOT NULL 但无业务校验（表单可为空）
这些字段在数据库层面是 NOT NULL（多为有默认值），但 Service 层未做非空校验，提交时可不传（依赖数据库默认值）：

- 所有 `field_enable`（默认 `b'1'`）
- 所有 `field_create_time`（默认 `CURRENT_TIMESTAMP`）
- 所有 `field_status` 类默认值字段（如 `DRAFT` / `WAITING` / `ZERO`）
- `sys_org_element.field_level`（默认 1）
- `sys_org_element.field_is_virtual`（默认 `b'0'`）
- `sys_org_user.field_gender`（默认 0）
- `sys_org_user.field_job_status`（默认 1）
- `sys_org_user.field_account_status`（默认 1）

### 3.2 数据库 NOT NULL 且业务校验必填
这些字段是严格必填的（数据库 NOT NULL + 业务校验）：

- **名称类**：`field_name`（几乎所有主表）
- **编码类**：`field_code`（sys_org_element）
- **类型/状态类**：`field_org_type`（组织架构元素）

### 3.3 特殊业务约束
- **人员创建**：密码不能为空（编辑时不更新）
