# 一. 地址本

1. 提供组织架构的选择

2. 要求实现弹窗，弹窗界面分上中下三层；

3. 上层为唯一文本输入框输入关键字，和查询按钮；

4. 下层为已选项显示和确认、取消按钮；

5. 中层分两个页签，将受“可选组织架构类型”影响而显示；

6. 中层第一页签：组织架构树：划分左右两个区域，左侧为从根节点点击展开的组织架构层级关系，此处的点击不会选中数据，而是将查询以该数据作为上级节点的组织架构数据列出在右侧区域；由右侧区域进行数据选中。

7. 中层第二页签：查询页签：此处为常用的列表分页查询，只根据上层的关键字输入框进行查询

8. 组件绑定参数如下：

   | 参数名     | 说明                                                         |
   | ---------- | ------------------------------------------------------------ |
   | fieldId    | 关联的id值字段，必填                                         |
   | fieldName  | 关联的名称值字段，必填                                       |
   | orgType    | 可选的组织架构类型，默认'ALL'<br />ALL - 全部（机构/部门/岗位/人员，不含角色/群组）<br />ORG - 机构<br />DEPT - 部门<br />ORGDEPT - 机构或部门<br />PERSON - 人员<br />POST - 岗位<br />PERSONPOST - 人员或岗位<br />ORGDEPTPOSTPERSON - 机构/部门/岗位/人员（群组「可见用户」选择语义化别名，等价 ALL） |
   | multi      | 是否多选，默认 `false`                                       |
   | septarator | 多选的分隔符，默认';'，要求仅限符号                          |
   | limitRange | 限制的组织架构范围，默认为空，填入组织架构的 `fieldId` 值数组，限制范围体现在组织架构树的根节点，和列表查询默认条件上 |
   | callback   | 确认选择后的回调函数                                         |
   | disabled   | 是否禁用（只读展示不可打开选择弹窗），默认 `false`           |
   | showRole   | 是否显示「角色」页签，默认 `false`；仅开启时渲染，角色无层级无左侧树，仅一张分页表格（名称/编码/是否启用），数据固定按角色类型（`orgTypes=[5]`）查询（复用关键字列表查询接口，无新接口），回填角色 id 与名称 |

   > v1.1 起「群组」页签不设开关 prop：`orgType` 可选类型含人员(3) 时自动渲染，左侧为当前登录人可见群组分页列表（点选群组，非选值），右侧为该群组成员人员分页表格（数据经 `groupList` / `groupUsers` 接口，按群组批量选人），勾选结果为人员 id 与名称（非群组 id）；树/查询/角色/群组四类表格勾选恢复互不串扰。

# 五. 分类表格选择器组件

1. 提供「按树形分类筛选主表、勾选主表记录回填」的选择能力：弹窗左侧为树形分类（懒加载，选中项作为主表指定字段的等值查询条件，「全部」清除分类条件），右侧为主表分页列表（支持名称模糊过滤），勾选主表记录后确认回填；与「四. 树形选择器组件」的区别：树形选择器直接选择分类节点回填，本组件回填的是分类条件下筛选出的主表记录。

2. 组件绑定参数如下：

   | 参数名        | 说明                                                         |
   | ------------- | ------------------------------------------------------------ |
   | fieldId       | 关联的id值字段，必填                                         |
   | fieldName     | 关联的名称值字段，必填                                       |
   | treeUrl       | 分类树懒加载接口url，必填（POST，请求体 `{ fieldParentId, ...treeParams }`，按 fieldParentId 返回直接下级） |
   | tableUrl      | 主表列表接口url，必填（POST，请求体 `{ body: { [categoryField], fieldName, ...tableParams }, pages: { pageNo, pageSize, needPage }, sortField, sortOrder }`，分页总数经 `metadata.total` 返回） |
   | categoryField | 主表分类条件字段名，必填（等值匹配，如客户 `fieldCateId` / 项目 `fieldCategoryId`） |
   | columns       | 右侧列表显示列配置，必填，数组项 `{ prop, label, width?, minWidth?, formatter? }` |
   | labelField    | 树节点名称显示字段，默认 `fieldName`                         |
   | multi         | 是否多选，默认 `false`（单选；仅「其他xxx」等多值字段显式传 `multi`，多选跨页累积勾选，`false` 时点击行单选） |
   | septarator    | 多选的分隔符，默认';'，要求仅限符号                          |
   | treeParams    | 请求树节点时额外携带的固定参数，默认 `{}`                    |
   | tableParams   | 请求主表列表时额外携带的固定参数（合并进 body），默认 `{}`   |
   | callback      | 确认选择后的回调函数                                         |

3. 当前适用场景（两场景分类树接口均返回 `field_id` / `field_name` / `field_parent_id` / `is_leaf` 等公共字段）：

   | 场景             | treeUrl                                      | tableUrl                               | categoryField       | 右侧列表列                                     |
   | ---------------- | -------------------------------------------- | -------------------------------------- | ------------------- | ---------------------------------------------- |
   | 业务单位 + 单位分类 | `/backend/erp/mdm/unitCategory/list`      | `/backend/erp/mdm/unit/list`           | `fieldCateId`       | 业务单位名称、单位类型、状态、统一社会信用代码 |
   | 项目 + 项目分类  | `/backend/erp/project/category/list`         | `/backend/erp/project/main/list`       | `fieldCategoryId`   | 项目名称、项目编号、项目状态、负责人           |

4. 说明：
   - 左侧选中分类后右侧按 `categoryField` 等值查询；未选分类（或点「全部」）时返回主表全量。客户页与组件默认行为一致，仅匹配当前分类；项目列表页（`/project`）与合同列表页（`/contract`）例外：选中父分类时会包含其全部后代子分类下的项目 / 合同（后端按分类范围（含后代）IN 查询）。
   - 已选项回显仅限当前页已加载的记录；跨页已选项无法自动定位，翻页后勾选即可跨页累积。

# 七. 导入弹窗

`components/ImportDialog.vue`：导入导出公共方案（v1.1）的前端公共导入弹窗，内置模板下载、文件选择与校验、导入配置区与结果渲染四要素；文案走 vue-i18n（`frontend.common.importExport.*`），在 `components/index.js` 注册后按名引用。

1. 组件契约

   | 项 | 说明 |
   | -------------- | ------------------------------------------------------------ |
   | v-model | 控制弹窗显隐 |
   | props.title | 弹窗标题 |
   | props.templatePath | 模板下载接口路径（如 `/backend/sys/dict/template`）；有值才渲染模板下载按钮 |
   | props.templateBody | 模板下载请求体，默认 `null` |
   | props.configFields | 导入配置区动态渲染配置，`{ key, label, type: 'switch'\|'select', options, defaultValue }`；公共开关 `ignoreError` / `fullUpdate` 组件内置渲染，业务键追加在后 |
   | props.maxSize | 文件大小上限，默认 `50 * 1024 * 1024`（50MB，对齐 `CS_ATT_MAX_FILE_SIZE`） |
   | emits | `update:modelValue`（显隐）、`confirm`（携带 `{ file, params }`，未选文件不给确认） |

2. 内置行为

   - 模板下载：调 `api/common.js#importTemplate(templatePath, templateBody)` 后经 `utils/download.js#downloadBlob` 触发保存，失败 `ElMessage.error`。
   - 文件选择：`el-upload`（`drag`、`auto-upload=false`、`limit=1`、`accept=".xlsx"`），选中即校验扩展名（`.xlsx` 不区分大小写）与大小（`maxSize`）。
   - 结果渲染：确认后由调用方执行 `api/common.js#importExcel(path, file, params)`，导入结果（`ImportResultVo`：`total / success / failed / errors[{row, field, message}]`）由弹窗内置渲染成功 / 失败计数与 `errors` 明细；扩展字段（如 i18n 的 `skippedKeys / skippedLanguages`）由页面 `onConfirm` 回调补充展示。
   - 页面接入：只 import `api/common.js` 具名函数（`exportExcel` / `importExcel` / `importTemplate`）与 `utils/download.js#downloadBlob`，不写裸 axios / 裸 URL；先例接入方 `DictManageView.vue`、`I18nTranslationManageView.vue`、`Attachment.vue`（`saveBlob` 切换 `downloadBlob`）。

# 八. 编号规则组件（NumberRuleComposer）

`components/NumberRuleComposer.vue`（v1.5）：编号规则可视化配置受控组件，value 协议即 `sys_number_rule.field_rule` 的 JSON 对象（`{ "items": [...] }`，结构见 `docs/v1_5-编号功能/编号机制实现方案.md` §2）；规则 JSON 由后端统一校验（C1~C5）与序列化存储，前端不手工拼串。已在 `components/index.js` 注册，样例页 `views/ui.vue` 有演示块（演示依赖后端预览接口）。

1. 组件契约

   | 项 | 说明 |
   | -------------- | ------------------------------------------------------------ |
   | props.value    | 编号规则对象 `{ items: [...] }`（有序数组，渲染按数组顺序拼接）；传 `null` 按 `{ items: [] }` 处理；组件不做原地修改，任何变更深拷贝生成新对象回传 `onChange` |
   | props.onChange | 变更回调（受控模式，宿主持值提交） |
   | props.fieldName | 组件在宿主表单中的字段名（编号规则编辑页传 `"fieldRule"`）；宿主复用（如分类编辑页 `fieldCodeRule`）时以该参数声明归属字段 |
   | props.disabled | 是否禁用（整体只读），默认 `false` |

2. 三区布局

   - 上：插入按钮——文本 / 流水号 / 日期时间 / 随机数四类；
   - 中：已插入项列表——左移 / 右移按钮排序（首末项按钮置灰，不依赖拖拽）、删除、选中高亮；
   - 下：选中项属性面板——公共 `name`；`id` 不渲染不可编辑；text `text`（maxlength 32）；datetime `format`（白名单下拉 allow-create + 自定义 pattern 受限提示）；seq `start` / `length` / `padZero` / `resetPeriod`（NONE/DAY/WEEK/MONTH/YEAR）；random `numericOnly=false` 时 `min` / `max` 置灰。

3. seq 项 id 锁定（D5）：`item.id` 由组件在前端新增时生成（`ci-` 前缀 + 12 位十六进制小写，`crypto.getRandomValues`，自动查重），任何逻辑不改已有项 id、无 id 编辑与重生成入口——已保存规则的 seq 项 id 是取号计数器锚点（`sys_number_record.field_serial_id`），变更会造成重号 / 断号，后端 C7 校验兜底。

4. 实时预览：属性变更深度监听防抖 500ms 调 `api/number.js#renderNumberPreview({ rule, count: 3 })`（请求序号守卫防竞态、卸载清理定时器）；响应 `errors: [{ code, itemId, message }]`（C1~C5）就地红字逐条显示，不弹 ElMessage；请求失败静默降级。预览接口无副作用（不推进计数器、不落库）且登录即可，供「分类编辑页」等无编号权限的宿主复用。

5. 宿主复用与提交：组件只负责编辑与展示，保存由宿主随表单提交 value；分类等非固定接入场景由后端 `SysNumberRuleService#validateConfig` 校验、`SysNumberGenerateService#acquireByConfig` 取号（见编号机制实现方案 §1.3）；编号规则标准宿主为 `views/number/NumberFormView.vue`（编辑保存仅提交 `{ fieldId, fieldCode, fieldName, fieldRule }`，seq 项 id 由组件原样透传）。

# 九. 数据源表格组件（DatasourceTable）

`components/DatasourceTable.vue`（v1.8，任务 F18-FE-005）：数据源取数消费的通用只读表格（消费方式见 `docs/系统模块/系统模块UI设计文档.md` 4.10.7 方式二）——宿主只传数据源编码，组件内部完成「options → 列头渲染 → query 取数」编排，适合快速搭建数据源驱动列表页。已在 `components/index.js` 注册，样例页 `views/ui.vue` 有演示块（演示依赖后端运行与默认数据源 `calendar.list`）。

1. 组件契约

   | 项 | 说明 |
   | -------------- | ------------------------------------------------------------ |
   | props.code | 数据源编码（默认或自定义，如 `calendar.list`），必填；变更后回第 1 页重走完整编排（options 重查 + query） |
   | props.filters | 调用方增量过滤条件 `{ 字段key: 值 }`，默认 `null`——固定条件由服务端强制、同名 key 服务端覆盖调用方条件，宿主只传增量；深度监听，变更后回第 1 页重走完整编排 |
   | props.sortField | 默认排序字段，须 ∈ 目标能力可排序白名单（`sortable=true` 汇总集），非法值由后端回退目标能力默认排序；变更后同步排序态并回第 1 页重走编排 |
   | defineExpose.refresh | 宿主手动刷新：回第 1 页并重走完整编排（options 重查 + query） |

2. 消费面权限口径：`options` / `query` 登录即可（UI 文档 4.10.7）；取数越权由执行期委托目标 action 鉴权收敛（如 `calendar.list` → `sys.calendar.list`），组件内不做权限判断。

3. 内置行为

   - 编排：挂载后调 `api/datasource.js#getDatasourceOptions()` 按 `code` 命中条目，以 `options.fields` 预渲染列头；失败或未命中给出空态提示，不再请求 query；命中后调 `queryDatasource({ code, body: filters || null, pages, sortField, sortOrder })` 取数。
   - 动态列（R04 不假设固定列）：`el-table`（border + stripe）按有效返回字段集渲染 `el-table-column`（prop=field.key、label=field.label、min-width 按类型自适应、show-overflow-tooltip）；`metadata.fields` 每次查询后校验，与当前列头不一致时以 `metadata.fields` 为准渲染；总数取 `metadata.total`。
   - 排序：`field.sortable === true` 的列启用表头点击排序（`sortable="custom"` + `@sort-change`，自定义排序不排前端数据，改查后端——变更后的 sortField / sortOrder 放进下一次 query，回第 1 页），非可排序列不可排序；取消排序回退 `props.sortField` 默认值。
   - 时间格式化：`field.type` 为 `DATE` / `DATETIME` 的列对值做格式化展示（`YYYY-MM-DD` / `YYYY-MM-DD HH:mm:ss`，后端 `java.util.Date` 序列化为毫秒时间戳）；其余类型原样展示，空值显示 `-`。
   - 码值翻译：执行结果为原始值（如 `fieldType=PERSONAL`），码值显示名由消费方页面按码值模块自行翻译（TBD 裁决结论 1），组件不做枚举翻译。
   - 分页：`el-pagination`，`layout="total, prev, pager, next, sizes"`、`page-sizes [10,20,50,100]`，默认第 1 页、每页 10 条；切页大小回第 1 页。
   - 竞态防护：请求序号守卫，`code` / `filters` / `sortField` 变更触发的重编排使在途响应作废，不回写旧数据。

4. 接入方式

   - `components/index.js` 注册后按名引用（`import { DatasourceTable } from '@/components'`），页面只经 `api/datasource.js` 取数、不写裸 axios / 裸 URL。
   - 样例页 `views/ui.vue` 演示块：`<DatasourceTable code="calendar.list" sort-field="fieldStartTime" />`（演示依赖后端运行与默认数据源 `calendar.list` 登录可用，`fieldStartTime` / `fieldCreateTime` 为该源可排序字段）。
   - 竞态与空态由组件内置；宿主需要自定义筛选区时把条件组装进 `filters` 即可，固定条件语义由服务端保证，前端不可也不需感知固定条件内容。

# 十. 公式设计器组件（FormulaDesigner）

`components/formula/FormulaDesigner.vue`（v1.4，任务 F14-FE-006）：公共表达式服务的前端编排弹窗（设计依据：UI 文档 4.11.7、公式定义器功能设计方案 §7）——`el-dialog` 弹窗布局为左树（四组节点）+ 右上编辑区（CodeMirror 6 底座 + validate 联动）+ 右中函数面板 + 底部模拟区；编辑器只做输入辅助，表达式合法性权威校验在后端 `validate`（方案 A1），前端不做语法解析裁决。弹窗固定 `append-to-body` 直挂 body 顶层渲染，可安全嵌套在宿主弹窗或表格单元格内使用（流程设计器条件分支明细表、并行分支与节点配置弹窗即嵌套用例）。已在 `components/index.js` 注册（内部底座子组件 `FormulaCodeEditor` 为弹窗编辑区封装，不进统一出口、不单列），样例页 `views/ui.vue` 有演示块（演示依赖后端运行与登录态）。

1. 布局与交互

   - 左树（el-tree）四组节点，弹窗首次打开并行加载清单（置位后不重复拉取，单个接口失败对应分组空态、不阻断弹窗打开）：变量 = 固定系统变量三枚（`SYS_CURRENT_USER_ID` / `SYS_CURRENT_DEPT_ID` / `SYS_CURRENT_ROLE`，服务端注入语义）+ `availableVars` 外部追加（与系统变量同码不重复出节点）；业务模型 = 数据源 targets 聚合的「能力 → 字段」两级节点（方案 A6，公式模块不另建字段台账）；函数分类 = 按注册元数据九类分组（MATH / LOGIC / COMPARE / STRING / DATE / COLLECTION / CONVERT / SYSTEM / DATA）；命名公式 = `options` 启用条目（只暴露元信息，不暴露表达式原文）。
   - 节点插入：双击节点或【插入】按钮写入编辑区并保持光标其后——变量插入 `${code}`、业务模型字段插入 `${能力code.字段}`（路径投影形态）、函数按注册元数据 `parameters` 生成「函数名(占位参数…)」模板、命名公式插入 `${fieldCode}`（执行期按编码加载）；分组 / 分类层 / 空态节点无插入语义。
   - 右上编辑区：CodeMirror 6 底座（`FormulaCodeEditor`：高亮、`${}`/函数 token 补全、插入写入光标处）+ validate 联动——编辑防抖 500ms 自动调 `/validate`（请求序号守卫防过期结果覆盖），`errors` 逐条「错误码 + message」可读展示、`dependencies` 变量依赖以 tag 展示、返回类型与语法状态展示；错误 message 中解析得到行号（`line N` / `lineNumber: N` / 「第 N 行」）时在编辑器对应行打标。
   - 函数面板：按分类折叠展示函数编码 / 名称 / 参数签名（`name:type` 逗号连接）/ 说明，【插入】写入占位参数模板；`functionCategories` 有值时仅展示指定分类并提示「已按传入分类过滤」。
   - 模拟区：赋值行 = validate 返回 `dependencies` ∪ `availableVars` 声明（排除 `SYS_CURRENT_` 前缀系统变量——后端不信任前端传入覆盖，不生成赋值行），已有行保留赋值不清空、新依赖码自动补行；控件随 type 选型（NUMBER 数字输入、STRING 文本、BOOLEAN 开关、DATE 日期选择、ARRAY JSON 文本）；【试算】成功展示 `result` + `resultType`，失败展示 `errors`，**失败不阻断弹窗操作**（可继续编辑、校验、再试算）。
   - 弹窗开关与回写：每次打开以 `props.expression` 重新同步编辑文本并重置校验 / 试算态与赋值行；遮罩 / 右上角 × / ESC / 取消仅回传显隐，不回写表达式；【确认回写】先经 `update:expression` 回写表达式文本、再 emit `confirm`（载荷 = 最终表达式文本），随后关闭弹窗；表达式为空也允许确认（由消费方 / 保存期校验兜底）。

2. 组件 props 契约

   | 参数名 | 类型 | 必填 | 默认值 | 说明 |
   | --- | --- | --- | --- | --- |
   | visible | Boolean | 否 | `false` | 弹窗显隐控制（`v-model:visible`） |
   | availableVars | Array | 否 | `[]` | 外部追加变量声明，元素 `{ code, type?, label? }`（type ∈ NUMBER/STRING/BOOLEAN/DATE/ARRAY，缺省按 STRING 处理）；并入左树变量组、validate 的 vars 入参与模拟区赋值行 |
   | functionCategories | Array | 否 | `[]` | 函数分类过滤（如 `['MATH','LOGIC']`），仅作用于左树函数分类组与函数面板；空/缺省 = 全部九类 |
   | expectedReturnType | String | 否 | `''` | 期望返回类型（NUMBER/STRING/BOOLEAN/DATE/ARRAY），作为 validate / simulate 的 `expectedReturnType` 入参；空 = 不传跳过比对 |
   | expression | String | 否 | `''` | 公式文本（v-model 语义，`${}` 形态原样存取）；弹窗每次打开以该值同步编辑区，确认回写经 `update:expression` / `confirm` 回传 |

3. 事件契约

   | 事件名 | 说明 |
   | --- | --- |
   | update:visible | 弹窗显隐变更时回传（遮罩 / × / ESC / 取消 / 确认回写均触发） |
   | update:expression | 【确认回写】时回传编辑区表达式文本（与 confirm 同步发生，先于 confirm） |
   | confirm | 【确认回写】时触发，载荷为最终表达式文本，随后关闭弹窗 |

   v-model 语义：`expression` 为 v-model（`v-model:expression`，与 `v-model:visible` 同形态）——管理表单页确认后回写 `fieldExpression`，内联消费方（v1.5 表单 / v1.7 流程）回写自身配置 JSON。

4. 依赖接口与错误展示语义

   - `GET /backend/sys/formula/options`（命名公式条目元信息）、`GET /backend/sys/formula/functions`（函数元数据清单）、`POST /backend/sys/formula/validate`（静态校验，vars 为声明式数组 `[{ code, type }]`）、`POST /backend/sys/formula/simulate`（模拟执行，vars 为赋值式对象 `{ code: value }`，与 validate 形态不同不可混用）——组件四接口登录即可（A7 分层）；另依赖 `GET /backend/sys/datasource/targets`（业务模型节点聚合，A6 不另建字段台账）。
   - 错误展示语义：validate / simulate 校验失败 HTTP 仍 200，以 `data.errors` 数组 `{ code, message }`（`code` ∈ `CS_FORMULA_*`）逐条可读展示，不阻断弹窗操作；接口异常（网络等）仅 ElMessage 警告，校验服务不可用不制造本地伪错误。

5. validate vars 口径（组件内裁量，注释与实现一致）：已知变量声明 = 系统变量 + `availableVars`；表达式当前引用的根变量码（`${code}` 与 `${code.field}` 路径投影均取根码，客户端粗提取仅用于装配入参、不做合法性裁决）全部落在已知声明内时，按引用集合传 vars（严格模式——避免未引用的声明被后端严格核对误报「声明的变量未被表达式引用」）；引用了未知变量（模型能力 / 命名公式码等运行期变量）或无任何引用时不传 vars 字段 = 宽松模式。

6. v1.5 / v1.7 内嵌预留：`availableVars` 为 v1.5 自定义表单预留（传表单字段声明，含明细行数组变量支持 `${list.field}` 路径投影）；`functionCategories` 为分类过滤扩展位；`expectedReturnType` 随消费场景取值（v1.7 流程条件分支传 `BOOLEAN`、v1.9 消息通知模板传 `STRING`）。

7. 样例登记：`views/ui.vue`（路由 `/ui`）——【打开公式设计】按钮打开弹窗，绑定 `v-model:visible` / `:expression`（初始示例 `ROUND(${applyAmount} * ${taxRate}, 2)`）/ `expected-return-type="NUMBER"` / `:available-vars`（applyAmount、taxRate 两变量声明）/ `@confirm` 回写；演示块下方等宽展示当前回写表达式原文。
