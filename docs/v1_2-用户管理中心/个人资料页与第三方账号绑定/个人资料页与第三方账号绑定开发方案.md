# 个人资料页与第三方账号绑定开发方案

> 来源：[补充功能实现方案（人工初设版）.md](./../补充功能实现方案（人工初设版）.md) 「个人资料页」「个人头像」「第三方账号绑定」三节。
> 状态：人工初设 → 方案细化，关键决策已确认（5.1 用户名可编辑/登录名只读、5.7 绑定总开关默认关闭），可进入开发。
> 编写日期：2026-11-11。代码事实基于当前 master（迁移脚本最新 `V1_01_041__sys_org_element_pinyin.sql`）。

## 1. 背景与目标

1. **个人资料页**：为登录用户提供区别于「组织架构用户编辑页」（管理员视角）的**本人自助维护**页面。入口从顶栏用户区的悬停下拉进入（【个人信息】/【退出登录】），并移除顶栏现有的独立【登出】按钮。页面维护：个人头像、用户名、登录名、手机、邮箱、联系地址、性别、关联账号（微信/QQ 绑定）。
2. **个人头像**：在个人资料页提供头像上传，复用附件公共通道绑定 `field_model_id = sys_org_user.field_id`、`field_key = "profile"`；头像同时回显到顶栏用户区。
3. **第三方账号绑定**：支持微信、QQ 账号绑定，**仅限对已存在账号绑定**，不支持第三方注册。`sys_org_user` 增加 `field_openid`（JSON）保存第三方 openid 信息，相同 openid 不允许重复绑定。

不在本方案范围：用户信息拓展、信息设置、用户个人偏好、账号锁定/冻结/待激活、密码策略和重置（初设版同名空章节，另行成册）；组织架构列表页面与导入导出（已由 [组织架构列表页面与导入导出改造方案.md](./../组织架构列表页面与导入导出/组织架构列表页面与导入导出改造方案.md) 单独成册）。

### 2.2 差距清单

1. `sys_org_user` 缺 `field_openid` JSON 列及对应实体字段、查重 SQL。
2. 无个人资料「本人自助」接口组（load/save），现有人事维护接口以 `documentId` 为核心、面向管理员权限码。
3. 无第三方 OAuth 绑定通道：无微信/QQ 应用配置项、无授权跳转/回调/解绑接口、无 state 防 CSRF 机制。
4. 头像无落地位置：附件通道可用但无「单张头像」约定（取哪条、旧头像如何清理），顶栏无图片头像展示能力。
5. 顶栏无用户区下拉菜单；个人资料页无路由、无页面、无 api 函数。

## 4. 详细设计

### 4.1 数据库

**迁移脚本**：`V1_01_042__sys_org_user_openid.sql`

```sql
ALTER TABLE sys_org_user
    ADD COLUMN field_openid JSON DEFAULT NULL COMMENT '第三方账号绑定信息(JSON)' AFTER field_account_status;
```

- 头像**不加列**：按初设落附件通道（`sys_att_main` 绑定 `field_model_id = sys_org_user.field_id`、`field_key = "profile"`），不冗余存头像 URL/ID。
- `field_openid` 结构固定，按工程规范建 POJO `SysOrgUserOpenidDo`（Jackson 序列化，禁手工拼 JSON 串）：

```json
{
  "wechat": { "openid": "o1", "unionid": "u1", "nickname": "昵称", "bindTime": "2026-11-11 10:00:00" },
  "qq":     { "openid": "o2", "nickname": "昵称", "bindTime": "2026-11-11 10:00:00" }
}
```

- **openid 查重**（Mapper XML，新增于 `resources/mappers/sys/org/SysOrgUserMapper.xml`）：

```sql
SELECT COUNT(*) FROM sys_org_user
 WHERE field_openid->>'$.wechat.openid' = #{openid}
    OR field_openid->>'$.qq.openid'     = #{openid}
```

  MySQL 8 JSON 路径提取即满足；`sys_org_user` 为组织内人员量级，不做函数索引（如后续量级增长再评估加 `(CAST(field_openid->>'$.wechat.openid' AS CHAR(64)))` 类函数索引）。
- 流水/审计不变更；本表已有公共字段齐全，无需其他调整。

### 4.2 后端：个人资料接口（本人自助）

**常量与鉴权**（新增 `SysOrgProfileProperties` / `ProfileResolver`，包 `sys/org/properties`、`sys/org/resolver`）：

| 常量 | 值 | 判定 |
| --- | --- | --- |
| `ACTION_LOAD` | `sys.org.profile.load` | 登录且启用 |
| `ACTION_SAVE` | `sys.org.profile.save` | 登录且启用 |
| `ACTION_BIND` | `sys.org.profile.bind` | 登录且启用 |
| `ACTION_UNBIND` | `sys.org.profile.unbind` | 登录且启用 |

- **不新增权限码**、`roles.yml` 无变更：本接口组为「本人自助」语义，不设 `SYS_ORG_*` 管理码；`SYS_ADMIN` 由 `BaseResolver` 自动放行。
- **越权面控制**：接口一律**不接收 userId/fieldId 参数**，Service 内部一律以 `UserUtil.getCurrentUserId()` 定位被操作对象——从根上排除「A 修改 B」的越权路径，resolver 无需按 `documentId` 判定。

**接口清单**（新增 `SysOrgProfileController`，类级 `@Tag(name="个人资料")`，路径前缀 `/backend/sys/org/profile`）：

> 继承方式（代码事实）：`authorize(action, …)` 在 `BaseCrudController` 中；非 CRUD 的先例（`SysOrgAddressBookController`）**不继承基类**，自行注入 Resolver 并实现私有 `authorize(String action)`（未登录抛 `UNAUTHORIZED`、无权限抛 `FORBIDDEN`，复用 `AuthorizationException` + `GlobalExceptionHandler`）。`SysOrgProfileController` 沿用该先例。

| 接口 | 方法 | 动作 | 说明 |
| --- | --- | --- | --- |
| `/backend/sys/org/profile/load` | GET | `sys.org.profile.load` | 加载当前登录用户资料：`fieldName`（JOIN `sys_org_element`）、`fieldLoginName`、`fieldPhone`、`fieldEmail`、`fieldAddress`、`fieldGender`、`fieldBirthday`、`fieldJobStatus`、`fieldAccountStatus`（只读展示）、`avatarAttId`（见 4.3）、`openid`（绑定状态，含第三方昵称与绑定时间）、`openidBindEnabled`（`system.openid_bind_enable` 总开关）、`wechatEnabled` / `qqEnabled`（**总开关开启且该渠道凭证齐全**才为 true，前端据此显隐绑定入口） |
| `/backend/sys/org/profile/save` | POST | `sys.org.profile.save` | 保存可编辑字段，请求体 `SysOrgProfileSaveRequest` |
| `/backend/sys/org/profile/openid/bindUrl` | POST | `sys.org.profile.bind` | 请求体 `{ channel: "wechat" \| "qq" }`；生成 `state`（Redis `openid_bind_state:{state}` → `{userId, channel}`，TTL 300 秒，一次性），拼装第三方授权页地址返回 `{ bindUrl }` |
| `/backend/sys/org/profile/openid/callback` | GET | **无需鉴权** | 第三方浏览器回调（无 Authorization header），须加 `@SecurityRequirements` 空注解；校验总开关（关闭 → `fail_reason=disabled`）→ 校验 state → code 换 access_token/openid → 查重 → 写 `field_openid` → `302` 跳回 `{redirect_base}/profile?bind=wechat:success`（失败为 `fail_reason=disabled/dup/unconfigured/expired`） |
| `/backend/sys/org/profile/openid/unbind` | POST | `sys.org.profile.unbind` | 请求体 `{ channel }`；从 `field_openid` 移除对应键，两渠道均空则整列置 `NULL` |

**save 字段与校验**：

| 字段 | 可编辑 | 规则 |
| --- | --- | --- |
| `fieldPhone` | 是 | 非空时校验手机号格式（`^1[3-9]\d{9}$`） |
| `fieldEmail` | 是 | 非空时校验邮箱格式 |
| `fieldAddress` | 是 | 长度 ≤ 500（与表列一致） |
| `fieldGender` | 是 | 枚举 0/1/2 |
| `fieldBirthday` | 是 | 日期，不晚于当天 |
| `fieldName`（用户名） | 是（**已确认**，见 5.1） | 非空；保存时同步 `sys_org_element.field_name`，并按同款逻辑重算拼音列（`PinyinUtil.toPinyin` / `toPinyinShort`，后端统一重算，前端不传、不可直改，与 `SysOrgElementService#save/update` 幂等口径一致） |
| `fieldLoginName` | 否，只读回显（**已确认**） | 登录名是账号唯一标识（唯一键 `uk_org_user_login_name`、审计关联），本人不可改，仅管理员在组织架构维护 |

- 校验失败抛模块业务异常交 `GlobalExceptionHandler`；编辑须带被操作对象 `fieldId` 的通用约束在本人语义下由「会话用户即对象」等价满足，`save` 请求体仍回传 `fieldId` 做一致性断言（与会话用户不符即拒绝，防并发换号后脏提交）。
- 审计字段（`field_updater_id` / `field_update_time`）随既有 BaseModel 更新链路自动维护。

### 4.3 后端：个人头像

- **上传**：复用 `POST /backend/sys/att/main/upload`，`modelName = "sys_org_user"`、`modelId = 当前用户 fieldId`、`key = "profile"`；`ACTION_UPLOAD` 登录即可，无需新鉴权。
- **单张语义**（通用附件组件是多附件列表形态，需自行约定）：上传新头像成功后**删除旧头像附件**（`DELETE /backend/sys/att/main/delete?fieldId=旧附件ID`）；`AttResolver#resolveDelete` 允许「上传者本人」删除，天然满足。删除失败不回滚上传，前端提示后重试即可（下次上传会再清理）。
- **展示**：`profile/load` 返回 `avatarAttId` = `sys_att_main` 中 `field_model_name='sys_org_user' AND field_model_id=当前用户 AND field_key='profile'` 的**最新一条**（`field_create_time` 降序取一）。前端经 `GET /backend/sys/att/main/view?fieldId=avatarAttId`（带 Authorization 的 axios，`responseType: 'blob'`）拉取文件流转 `URL.createObjectURL` 展示——`<img src>` 直连会缺 token，不可用。
- **登录响应不含头像**（不动 login 接口）；顶栏在 `HomeView` 挂载时调 `loadProfile` 换取 `avatarAttId` 后 blob 加载，资料页内换头像后通过事件/store 通知顶栏刷新。

### 4.4 后端：第三方账号绑定

**OAuth 流程**（微信扫码 / QQ 互联，均走标准授权码模式）：

```text
个人资料页【绑定微信】
  → POST /openid/bindUrl {channel:"wechat"}（登录态）
      后端：校验总开关 openid_bind_enable（关闭 → 明确错误）→ 校验渠道凭证齐全
            生成 state 存 Redis（绑 userId+channel，TTL 300s，一次性）
      返回第三方授权页 URL（redirect_uri = {redirect_base}/backend/sys/org/profile/openid/callback）
  → 浏览器跳转第三方授权页，用户确认
  → 第三方 302 GET /openid/callback?code=xx&state=xx（浏览器跳转，无 token）
      后端：取并删 Redis state（过期/不存在 → fail_reason=expired）
            以 app_id+app_secret+code 换 access_token、openid、unionid(微信)
            查重：已有用户绑定相同 openid → fail_reason=dup
            写 field_openid（记录 openid/unionid/nickname/bindTime）→ 302 /profile?bind=wechat:success
  → 前端 ProfileView 读取 query 提示结果并清理地址栏
```

**配置分层**（两类配置、两个落点，均为 `SETTING.{field_type}.{field_key}` 两层结构——`CommonSettingService#syncSettings` 只解析两层，三层嵌套无法入库）：

1. **总开关**（管理员运行时可切）：`properties/common/application.yml` 的 `SETTING.system` 段新增 `openid_bind_enable: false`（默认关闭），与 `login_email_enable` 等开关并列；启动时经 `CommonSettingService#syncFromYml` 增量同步入 `common_setting`，运行时经 `PATCH /backend/common/setting/update`（SYS_ADMIN）修改，设置页 `CommonSettingView.vue` 的 `CONFIG_META` 增加该行元数据。
2. **应用凭证**（部署级，不入设置页）：`properties/sys/org/application.yml` 新增 `SETTING.openid` 段（`field_type = "openid"`）；`GET /setting/load` 只返回 `system` 类型，openid 段不会下发前端，满足 secret 不外泄：

```yaml
# properties/common/application.yml（system 段增量）
SETTING:
  system:
    openid_bind_enable: false   # 第三方账号绑定总开关，默认关闭

# properties/sys/org/application.yml（新增 openid 段）
SETTING:
  openid:
    wechat_app_id: ""
    wechat_app_secret: ""
    qq_app_id: ""
    qq_app_secret: ""
    redirect_base: ""           # 回调基础地址，如 https://erp.example.com
```

对应环境变量覆盖（`application.properties` 三段式，仅凭证类）：`CS_ORG_WECHAT_APP_ID` / `CS_ORG_WECHAT_APP_SECRET` / `CS_ORG_QQ_APP_ID` / `CS_ORG_QQ_APP_SECRET` / `CS_ORG_OAUTH_REDIRECT_BASE`。读取统一经 `CommonSettingService`：开关 `getBooleanValue(TYPE_SYSTEM, "openid_bind_enable")`（缺失按 false），凭证 `getValue("openid", key)`；总开关与凭证**同时满足**才判定渠道开放。

**业务规则**：

1. **仅绑定不注册**：绑定动作入口均在登录态（`ACTION_BIND`），第三方回调只对持有有效 state 的会话生效——未注册用户无法借道注册。
2. **相同 openid 不可重复绑定**：写库前 `4.1` 查重 SQL 计数 > 0 即拒绝（`fail_reason=dup`）；查重与写入同事务，接受内部系统量级下极小的并发窗口（见 6.4）。
3. **解绑**：不限制「至少保留一个绑定方式」（本系统不支持第三方登录，解绑不影响登录能力）；解绑后该渠道状态立即可被他人绑定。
4. **总开关**：`bindUrl` 与 `callback` 均校验 `openid_bind_enable`（关闭时 callback 直接回 `fail_reason=disabled`，防止关闭开关后存量跳转仍可完成绑定）；第三方昵称仅作绑定信息展示缓存，**不回写** `sys_org_element.field_name`。

### 4.5 前端

**顶栏改造**（`HomeView.vue`）：

- 用户区（头像 + 用户名 + 部门名）外包 `el-dropdown`（`trigger="hover"`），下拉项【个人信息】（跳 `/profile`）、【退出登录】（复用现有 `handleLogout`：调 logout 接口 → 清 store/localStorage → 提示）。
- **移除独立【登出】按钮**；文字头像升级：`avatarAttId` 存在时渲染 `<img>`（blob URL），否则维持首字符 `el-avatar`。
- `/profile` 不进菜单：菜单配置无新增项，`activeMenu` 归约无需处理（`/profile` 不落任何菜单前缀，高亮为空即可）。

**个人资料页**（新增 `views/org/ProfileView.vue`，路由 `path: '/profile'`、`name: 'OrgProfile'`、`meta: { title: '个人资料', tab: 'OrgProfile' }`）：

- 布局：`el-card` 容器 + `form-page.css` 风格，三块——
  1. **头像卡片**：圆形头像预览 + 「上传头像」（`el-upload` 手动，选图后经附件 upload 接口上传、成功后删旧 + 重载 `loadProfile`）+ 「移除头像」（删附件）。不用通用 `Attachment.vue`（多附件列表形态），但数据链路（modelName/modelId/key=profile）与初设「使用附件组件」的附件绑定约定完全一致——此为对初设字面的小偏离，见 5.3。

## 6. 风险

1. **OAuth 回调依赖公网部署**：`redirect_base` 必须外网可达，本地无法端到端联调回调；开发期以默认关闭的总开关降级（见 5.7），联调需在配置了回调域名的环境进行（微信/QQ 开放平台需先备案应用与回调域名）。
2. **state 安全**：一次性、TTL 300 秒、绑定 userId，callback 先删后验（Redis 原子 `GETDEL`，经既有 `RedisConfig` 的 `RedisTemplate<String, Object>`，值对象直接 JSON 序列化存储；Spring Data Redis `opsForValue().getAndDelete()` 原生支持），防重放与 CSRF；`app_secret` 仅服务端持有。
3. **用户名联动**：本人改用户名将同步组织架构树与拼音列（`PinyinUtil` 重算逻辑与 `SysOrgElementService` 同款、幂等）；组织架构列表页关键字检索依赖拼音列，改名后检索即时生效，无额外同步风险。
4. **openid 查重并发**：JSON 列无唯一约束，查重-写入存在理论竞态窗口；内部系统并发极低，接受该风险，后续如出现并发绑定再引入行锁或唯一辅助表。
5. **头像 blob 展示**：每次进入应用多一次 `loadProfile` + 一次附件 view 请求；附件 view 有登录鉴权与文件流开销，后续可加浏览器侧内存缓存（store 缓存 blob URL，登出即失效）。

## 7. 验收标准

1. 顶栏悬停用户区出现下拉【个人信息】【退出登录】，独立【登出】按钮移除；两种退出路径均清空会话与标签页记录。
2. `/profile` 页可展示并保存手机、邮箱、联系地址、性别、生日、用户名（保存后 `sys_org_element.field_name` 与拼音列同步更新，组织架构树与检索即时反映新名）；登录名只读。重新登录/刷新数据一致。
3. 头像上传后资料页与顶栏即时更新，旧头像附件被删除；未上传头像时顶栏显示用户名首字符；移除头像后回退首字符显示。
4. 绑定微信/QQ 后 `load` 返回绑定状态（渠道、第三方昵称、绑定时间）；**相同 openid 再次绑定任一账号被拒绝**并回跳失败提示；解绑后状态清除且他人可绑定该 openid。
5. **总开关验证**：`openid_bind_enable=false`（默认）时，前端关联账号卡片显示未开启提示、后端 `bindUrl` 拒绝并提示；`callback` 对关闭状态下的请求返回 `fail_reason=disabled`；管理员在系统设置页开启且凭证齐全后，绑定入口可用。
6. 越权验证：以用户 A 的 token 调 profile 接口仅能读写 A 自身数据（接口无 id 参数，`fieldId` 不一致即拒绝）。
7. `cd backend && ./mvnw test`（含 `ApiDocsTest`）与 `cd frontend && npm run build` 通过；新增接口 `@Operation` 均以「鉴权动作 …」开头，callback 标注无需鉴权。

## 10. 实现偏离勘误（2026-11-12）

> PF5-INT-001 全链路联调发现并已修复的实现偏离，逐条列出方案原文与实现终态；第 5 节已确认决策的结论本身不受影响，接口路径、HTTP 方法、`ACTION_*` 常量、resolver 分支零改动。实测详见 [01-联调记录.md](./01-联调记录.md) V2.0。六处文档同步（PF5-DOC-001）已按实现终态回写。

| # | 项 | 方案原文 | 实现终态 |
| --- | --- | --- | --- |
| DEF-1 | callback state 取删（4.4 / 6.2 / D11） | 「Redis 原子 `GETDEL`，经既有 `RedisConfig` 的 `RedisTemplate<String, Object>`，Spring Data Redis `opsForValue().getAndDelete()` 原生支持」 | `getAndDelete` 依赖 Redis **服务端** GETDEL 命令（≥6.2）；低版本 Redis（如 5.0.x Windows 便携版）抛 `RedisCommandExecutionException`，被全局兜底转 200 JSON 错误页，违反「任何失败均 302」。实现终态：`SysOrgProfileService#takeState` 优先 `getAndDelete()`（≥6.2 原子路径不变），捕获 `DataAccessException` 降级 GET+DEL 两段取删（非原子，并发窗口与 6.4 查重口径同量级、内部系统可接受）；state 值损坏 / 反序列化失败按 expired 处理（回调为浏览器 302 导航，不向浏览器抛 500）；Redis 宕机异常上抛不做静默 |
| DEF-2 | 附件软删除（**既有代码缺陷**，非本特性引入，方案未涉及——原计划「附件模块零改动」） | 「上传 / 删除复用附件既有接口，无附件侧代码改动」（4.3） | `SysAttMainMapper.xml#updateEnable` 与 `SysAttFileMapper.xml#updateIsDelete` 写死 `parameterType="string"`，而接口传 `@Param boolean` → 参数绑定 ClassCastException，附件删除（含公共组件 `Attachment.vue` 与头像「删旧」链路）一律 500——原始迁移提交即存在，首次被实际调用踩中。实现终态：两处 XML 移除 `parameterType`（MyBatis 按实参解析），属既有缺陷修复，影响全部附件删除调用方而非仅头像 |
| DEF-3 | 生日校验（4.2「日期，不晚于当天」） | 按「不晚于当天」字面口径实现（时间戳 `.after(todayEnd)` 比较） | `JacksonConfig` 将 date-only 字符串解析为本地零点，「明天零点」恰等于当天上界被放行（边界漏放）。实现终态：按本地日历日比较（`toInstant().atZone(APP_ZONE).toLocalDate().isAfter(LocalDate.now())`），与无时区解析口径一致，提交「明天」（date-only）亦拒绝 |
| DEF-4 | `avatarAttId` 组装（4.3「最新一条」） | 「`sys_att_main` 中 …以 `field_create_time` 降序取最新一条」，未限定启用状态 | 软删除（`field_enable=0`）的旧头像同样命中「最新一条」，导致「移除头像后 load 仍返回已删除附件ID」。实现终态：查询补 `field_enable=true` 条件后再取 `field_create_time` 降序最新一条 |
| DEVIATION-1 | `redirect_base` 默认值（4.4 yml 示例字面） | `redirect_base: ""`（空串默认） | 空默认使「任何失败均 302 带 fail_reason」契约在未显式配置环境不可达（callback 回 400「回调地址未配置」）。实现终态：`properties/sys/org/application.yml` 的 `SETTING.openid.redirect_base` 默认值设为 `http://localhost:5173`（本机前端 dev server，启动经 `syncSetting` 自动落库）；生产部署必须经环境变量 `CS_ORG_OAUTH_REDIRECT_BASE`（或 `common_setting` 表 `openid.redirect_base`）覆盖为对外可达地址。4.4 节 yml 示例中的 `redirect_base: ""` 字面以本条为准 |

补充：DEVIATION-2（记录性偏离）——单测原断言「redirect_base 缺失 → null → 400」分支保留：对被显式清空的部署仍是合理兜底（无法构造 302 目标），Swagger 已注解该设计行为；DEVIATION-1 的默认值使实际部署不再触达该分支。修复涉及文件：`SysOrgProfileService.java`（takeState + 生日边界 + avatarAttId 过滤）、`SysAttMainMapper.xml` / `SysAttFileMapper.xml`（parameterType）、`properties/sys/org/application.yml`（redirect_base 默认值）及对应单测增量。
