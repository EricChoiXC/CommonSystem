## 1. 资料维护（验收 2）

**结论：BLOCKED（实测全部受阻）+ 静态走查通过 + 1 项 DEVIATION**

### 1.1 admin 与 20260001 load 核对字段全集
- 步骤：分别以 admin、20260001 登录取 token，GET /backend/sys/org/profile/load，核对响应字段全集（用户名/登录名只读/手机/邮箱/地址/性别/生日/avatarAttId/openid 绑定状态）。
- 预期：200，字段全集与方案 SysOrgProfileResponse 一致。
- 实测：**BLOCKED**——登录 POST /sys/org/user/login 无法执行：本子代理执行通道被宿主权限层封锁（tool:bash 与 CUA computer_act 均被拒「sub-agent with explicit write_paths may only run read-only targets」；只读子代理 shell 白名单仅文件检查类命令，curl/mysql/redis 全部拦截）。无 token 可用。佐证：无 token 调 load 得 {"code":"UNAUTHORIZED","message":"登录已过期，请重新登录"}（web_fetch 实测），鉴权拦截生效。
- 结论：BLOCKED

### 1.2 save 修改 20260001 手机/邮箱/地址/性别/生日后 load 复验一致
- 步骤：POST /backend/sys/org/profile/save（fieldId=20260001 用户 ID，各字段新值）→ 重新 load 比对 → 重登再比对。
- 预期：save SUCCESS，load/重登数据一致。
- 实测：**BLOCKED**（无 token，同 1.1）。
- 结论：BLOCKED

### 1.3 改 fieldName 后 SQL 直查 sys_org_element 拼音重算生效
- 步骤：save 改 fieldName → mysql 直查 field_name/field_pinyin/field_pinyin_short。
- 预期：三列同步更新，拼音口径 PinyinUtil。
- 实测：**BLOCKED**（mysql.exe 无法执行，同执行通道封锁）。静态走查（grep 证据）：SysOrgProfileService.java L269-276「element 主表的 field_name/field_pinyin/field_pinyin_short 与审计字段经（SysOrgUserDao#update）一次落地」+ L275-276 PinyinUtil.toPinyin/toPinyinShort 后端统一重算、前端不传不可直改——实现口径与方案一致。
- 结论：BLOCKED（实测）/ 实现口径静态核对一致

### 1.4 save 的 fieldId 与会话不一致被拒
- 步骤：以 20260001 token 调 save，body.fieldId=admin 的 ID（00000000-…-0000）。
- 预期：业务错误拒绝。
- 实测：**BLOCKED**（无 token）。静态走查（grep 证据）：SysOrgProfileService.java L234 `if (null == request || !Objects.equals(request.getFieldId(), currentUserId))` —— 一致性断言在 Service 层实现，不一致即拒，与验收 6 口径一致。
- 结论：BLOCKED（实测）/ 校验逻辑静态核对存在

### 1.5 格式校验逐项触发（手机 ^1[3-9]\d{9}$ / 性别非 0/1/2 / 生日晚于当天 / 地址超 500）
- 步骤：save 分别提交 4 组非法值，逐项确认拒绝消息。
- 预期：逐项业务错误。
- 实测：**BLOCKED**（无 token）。静态走查（grep 证据）：SysOrgProfileService.java L72 `PHONE_PATTERN = Pattern.compile("^1[3-9]\\d{9}$")`；SysOrgProfileSaveRequest.java L19 注释「字段级格式校验（手机号 ^1[3-9]\d{9}$、生日不晚于当天等）由 SysOrgProfileService 实现」。性别/地址校验代码位置未逐行核对（走查范围受限，补跑时核对）。
- 结论：BLOCKED（实测）

### 1.6 save 带 fieldLoginName 不生效
- 步骤：save body 附带 fieldLoginName=新登录名 → load 复核登录名未变。
- 预期：登录名只读，不生效。
- 实测：**BLOCKED**（无 token）。静态走查（grep 证据）：SysOrgProfileController.java L85「登录名只读不接收」、SysOrgProfileSaveRequest.java 无 fieldLoginName 字段——请求模型层面即不可能生效。
- 结论：BLOCKED（实测）/ 只读语义静态核对成立


## 2. 头像（验收 3）

**结论：BLOCKED（实测全部受阻）+ 三端形态静态走查一致**

### 2.1 上传形态确认（grep SysAttMainController / Attachment.vue）
- 步骤：确认上传接口形态与前端组件参数。
- 实测（走查，grep 证据）：
  - SysAttMainController L72 `@PostMapping("/upload")`，multipart 参数 `file / modelName / modelId / key(可空)`（L64-79 注释与 @Parameter 注解）；GET `/view`（L110）、DELETE `/delete`（L129）。
  - Attachment.vue L161-164：`formData.append('modelName', props.fieldModelName)`、`formData.append('modelId', props.fieldModelId)` 后 `uploadAttachment(formData)`；预览经 `viewAttachment(row.fieldId)`（L178-180）取 blob。
  - 头像参数应为 `modelName=sys_org_user、modelId=<用户ID>、key=profile`。
- 结论：走查一致（PASS，代码层）

### 2.2 为 20260001 上传小文件 → load 得 avatarAttId
- 步骤：$TMPDIR 造几个字节的文件，POST /backend/sys/att/main/upload（multipart），再 GET profile/load 取 avatarAttId。
- 预期：upload 返回附件 fieldId；load 返回 avatarAttId=新附件 ID。
- 实测：**BLOCKED**（multipart POST 需执行通道与 token，均不可得；web_fetch 仅只读 GET 且无法带 multipart/自定义头）。
- 结论：BLOCKED（实测）

### 2.3 SQL 查 sys_att_main 旧附件被删（单张语义）+ 第二张复验
- 步骤：传第二张头像后 mysql 直查 sys_att_main（modelName=sys_org_user、modelId=<用户ID>、key=profile）应仅剩一条。

- 结论：BLOCKED（实测）/ 单张语义组装走查一致

### 2.4 GET /backend/sys/att/main/view?fieldId=<id> 带 token 取回 + 删除附件后 load 回 null

## 3. 绑定开关矩阵（验收 5）

**结论：FAIL（callback 实测不符）+ 其余实测 BLOCKED + 关键走查一致**

### 3.1 关闭态 POST /openid/bindUrl {"channel":"wechat"} → 业务错误「未开启」
- 步骤：以登录 token 调 bindUrl。
- 预期：业务错误「第三方账号绑定未开启」（openid_bind_enable=false 默认态）。
- 实测：**BLOCKED**（POST 需 token 与执行通道，均不可得）。开关关闭态已由 GET /common/setting/load 实测确认（openid_bind_enable=false，见 G3）。走查（grep 证据）：SysOrgProfileService L295 `throw new IllegalArgumentException("第三方账号绑定未开启")`；Controller L112 错误口径列表「绑定渠道无效/第三方账号绑定未开启/微信绑定未配置/QQ绑定未配置/回调地址未配置」。
- 结论：BLOCKED（实测）/ 关闭态拒绝逻辑走查一致

### 3.2 GET /openid/callback?state=不存在值（无 token）→ 预期 302 fail_reason=expired
- 步骤：web_fetch 直调三个变体：带伪造 state、空 state、无参。
- 预期：302 重定向到 {redirect_base}/profile?bind=fail_reason=expired（Controller L126-127 注释约定：「state 经 getAndDelete 一次性取删，伪造/过期/重放/缺参均回 expired（缺参不落 JSON 错误页，方案 5.5）」）。
- 实测：**FAIL（真实响应，web_fetch 三次）**——三个变体全部返回 HTTP 200 + JSON：`{"code":"ERROR","message":"系统异常，请稍后重试或联系管理员","data":null,"metadata":null}`。既非 302，也非 fail_reason=expired，且「缺参不落 JSON 错误页」约定被违反。
- 根因定界：未完成。异常可能发生在 ① RedisTemplate getAndDelete 调用（序列化器/连接异常）或 ② redirect_base 未配置时的 302 组装环节；无后端日志执行通道，定界待补跑。该分支属方案 R1 降级路径（无公网环境下的可测部分），应可独立于凭证工作。
- 结论：**FAIL**

### 3.3 redis-cli 造 openid_bind_state:{state}（SET EX 300）→ callback 首调消费、复用 expired
- 步骤：redis-cli SET 带含 userId/channel 的 JSON → callback 首调 → 复用再调。
- 实测：**BLOCKED**（redis-cli 不可执行）。走查（grep 证据）：SysOrgProfileService L107「state 有效期（方案 4.4）：TTL 300 秒，回调取删（getAndDelete 原子）」、L314、L351 `.getAndDelete(STATE_KEY_PREFIX + ...)`、L353-354 null → "expired"——一次性语义实现存在。
- 结论：BLOCKED（实测）

### 3.4 开关注入矩阵：true+凭证缺失 → bindUrl「未配置」；已造 state 的 callback → disabled；改后即时生效
- 步骤：经管理员设置保存接口把 system.openid_bind_enable 置 true（CommonSettingController 形态走查：L70 `@PatchMapping("/update")`，body 为 Map<String,String>，「入口直接判 SYS_ADMIN，不走 resolver」）→ 逐格验证 → 还原 false。
- 实测：**BLOCKED**（PATCH 需 admin token 与执行通道）。走查（grep 证据）：Controller L138-141 回调复验顺序「（过期/伪造/缺参回 expired）、复验总开关（disabled）与渠道凭证（unconfigured）、授权码换第三方用户信息（oauth_error）、openid 查重（计数>0 即 dup）」，fail 值枚举 success/expired/disabled/unconfigured/oauth_error/dup 与方案一致。
- 结论：BLOCKED（实测）

### 3.5 测完还原 openid_bind_enable=false
- 实测：不适用——开关从未被成功改动（3.4 BLOCKED），无还原动作欠账；当前值 false 已由 GET /common/setting/load 实测复核（见 G3 与清理记录）。
- 结论：不适用（无脏状态）
