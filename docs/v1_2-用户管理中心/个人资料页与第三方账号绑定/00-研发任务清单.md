### 1.2 当前版本范围

- 版本目标：新增本人自助「个人资料页」（顶栏悬停下拉进入，移除独立【登出】按钮），支持手机 / 邮箱 / 联系地址 / 性别 / 生日 / **用户名**维护（登录名只读）；头像经附件公共通道（`sys_org_user` + `key="profile"`）上传与顶栏展示；微信 / QQ 账号绑定（`sys_org_user.field_openid` JSON 列，仅绑定不注册，openid 唯一），受 `common_setting` 总开关 `openid_bind_enable` 控制（**默认关闭**）。
- **In Scope**
  - 数据库：`V1_01_042__sys_org_user_openid.sql`（`sys_org_user` + `field_openid` JSON 列，不加索引）；`SysOrgUser` 实体补字段；`SysOrgUserOpenidDo` POJO；`SysOrgUserMapper.xml` 补列 + openid 查重 SQL。
  - 后端资料：`SysOrgProfileProperties`（4 个 `ACTION_*`）+ `ProfileResolver`（登录且启用，无新权限码，roles.yml 零变更）+ `SysOrgProfileController`（非 CRUD 先例形态）+ `SysOrgProfileService`（本人语义，`UserUtil.getCurrentUserId()` 定位对象）+ `SysOrgProfileSaveRequest` / `SysOrgProfileResponse`。
  - 后端头像：`profile/load` 组装 `avatarAttId`（`sys_att_main` 按 `modelName+modelId+key=profile` 取最新一条）；上传 / 删除复用附件既有接口，**无附件侧代码改动**。
  - 后端配置：`common/application.yml` `SETTING.system` 增 `openid_bind_enable: false`；`sys/org/application.yml` 新增 `SETTING.openid` 段（渠道凭证 + `redirect_base`）；`application.properties` 三段式环境变量；`CommonSettingView.vue` `CONFIG_META` 增开关行。
  - 后端绑定：`POST /openid/bindUrl`（校验总开关与凭证 → state 存 Redis TTL 300s 一次性）+ `GET /openid/callback`（无需鉴权，校验开关与 state → code 换 openid → 查重 → 写库 → 302 回前端）+ `POST /openid/unbind`；OAuth 微信 / QQ 直连 HTTP，零新依赖（引入 SDK 需评审）。
  - 前端：`HomeView.vue` 用户区 `el-dropdown`（个人信息 / 退出登录）+ 图片头像（blob 加载）+ 移除【登出】按钮；`views/org/ProfileView.vue`（`/profile` 路由，头像卡片 + 资料表单 + 关联账号卡片三块）；`api/org.js` 增 4 函数。
  - 文档：方案第 8 节清单六处（见第 8 节）。
  - 测试：`SysOrgProfileService` / openid 读写与查重单测、`mvnw test` 全量（含 `ApiDocsTest`）、`npm run build`。
- **Out of Scope**
  - 不做第三方登录（本方案仅绑定，登录仍走账号密码 / 邮箱 / 电话既有通道）。
  - 不做通过微信 / QQ 注册新账号。
  - 不动 `SysOrgUserController` / `SysOrgElementService` 管理侧人员维护接口（profile 为独立本人语义接口组；用户名同步只调用 `PinyinUtil` 同款重算，不改 element 服务行为）。
  - 不改附件模块（`SysAttMainController` / `AttResolver`）代码，仅新增调用方。
  - 不做「账号锁定/冻结/待激活」「密码策略」「用户信息拓展」「信息设置」「个人偏好」（初设版空章节，另行成册）。
  - 不做多 openid / 绑定审计（openid JSON 列结构固定，后续需求再拆表，方案 5.4）。

### 1.3 任务拆解规则

- 按方案第 9 节 T1–T7 依赖顺序承接，编号规则 `PF<模块>-<层级>-<序号>`，模块划分与方案 T 编号映射：
  - `PF1` 数据库与实体（T1）
  - `PF2` 个人资料后端（T2、T3）
  - `PF3` 配置与绑定后端（T4）
  - `PF4` 前端接入（T5、T6）
  - `PF5` 联调验收与文档同步（T7）
- 顺序：先数据 / 实体 → 资料接口骨架 → 资料实现 → 配置 → 绑定通道 → 前端 → 联调验收 → 文档同步。
- **强顺序约束**：
  - `PF2-BE-002` 依赖 `PF1-DB-001`（load/save 写 `sys_org_user`，实体字段先行避免冲突）与 `PF2-BE-001`（常量与骨架）；
  - `PF3-BE-002` 依赖 `PF1-DB-001`（`field_openid` 列与查重 SQL）、`PF2-BE-001`（`ACTION_BIND/UNBIND` 常量与 `ProfileResolver` 分支）、`PF3-BE-001`（总开关与凭证配置）；
  - `PF4-FE-001` 依赖 `PF2-BE-002`（`loadProfile` 返回 `avatarAttId`）；`PF4-FE-002` 依赖 `PF2-BE-002`、`PF3-BE-002`（绑定接口就绪）；
  - `PF5-DOC-001` 最后收口（文档须反映最终实现）。
- 文档同步不默认「顺手更新」：列为显式任务 `PF5-DOC-001`；代码内 Swagger 注解随 `PF2-BE-002` / `PF3-BE-002` 同批提交（AGENTS 第 3 节强制）；`AGENTS.md` 迁移序号行修正随 `PF1-DB-001` 同批。
- 任务状态：创建时全部为 `TODO`。

- 来源文档：方案「4.4」；`RedisConfig`（`RedisTemplate<String, Object>`）；`@SecurityRequirements` 先例（`InitController` / `CommonSettingController#load`）

  - `backend/src/main/java/com/eric/base/sys/org/service/SysOrgProfileService.java`（+绑定逻辑；OAuth HTTP 客户端可拆独立类如 `sys/org/service/OpenidClient.java`，实施定）
- 产出物：

| 接口 | 方法 | 请求 | 响应 | 鉴权动作 |
| --- | --- | --- | --- | --- |
| `/backend/sys/org/profile/openid/bindUrl` | POST | `{ channel: "wechat" \| "qq" }` | `{ bindUrl }`（第三方授权页地址） | `sys.org.profile.bind` |
| `/backend/sys/org/profile/openid/callback` | GET | 第三方 302 回跳 `?code&state`（或错误 `?state`） | **302** 跳 `{redirect_base}/profile?bind={channel}:{success \| fail_reason}` | **无需鉴权**（D9） |
| `/backend/sys/org/profile/openid/unbind` | POST | `{ channel }` | `BaseResponse<Void>` | `sys.org.profile.unbind` |

  - bindUrl 流程：校验总开关（关闭 → 业务错误「未开启」）→ 校验渠道凭证齐全（缺失 → 业务错误「未配置」）→ 生成 `state`（UUID）→ Redis `openid_bind_state:{state}` 写 `{userId, channel}` TTL 300s → 按渠道拼授权页地址（`redirect_uri = {redirect_base}/backend/sys/org/profile/openid/callback`）
  - callback 流程：`opsForValue().getAndDelete()` 原子取删 state（不存在/过期 → `fail_reason=expired`；D11 一次性防重放）→ 复验总开关（关闭 → `fail_reason=disabled`，D5）→ code 换 access_token / openid（微信另取 unionid；QQ 走互联接口）→ `countDuplicateOpenid` 查重（>0 → `fail_reason=dup`）→ 写 `field_openid`（记录 openid / unionid / nickname / bindTime）→ 302 回前端；任何失败均 302 带 `fail_reason`，不返回 JSON 错误页
  - unbind：从 `field_openid` 移除对应渠道键，两渠道均空则整列置 NULL（方案 4.4；解绑不影响登录能力）
  - Swagger：三方法 `@Operation` 以「鉴权动作 …」开头（callback 为「无需鉴权（第三方浏览器回调，无 Authorization header）」）；callback 补 `@SecurityRequirements` 空注解（D9，**不改 SecurityConfig**）
  - 单测：state 过期/复用拒绝、总开关关闭拒绝、查重拒绝、unbind 移除单渠道与双空置 NULL、openid JSON 序列化往返
- 验收标准：相同 openid 再次绑定被拒（验收 4）；开关关闭时 bindUrl 拒绝且 callback 回 `disabled`（验收 5）；`app_secret` 不出服务端
- 验证方式：`cd backend && ./mvnw test`（新增单测 + `ApiDocsTest`）；端到端回调依赖公网环境，随 PF5-INT-001 联调
