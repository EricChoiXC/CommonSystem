### 1.3 任务拆解规则

- 按方案第 10 节 T1–T11 依赖顺序承接，编号规则 `OL<模块>-<层级>-<序号>`，模块划分与方案 T 编号映射：
  - `OL1` 数据库与拼音基建（T1、T2）
  - `OL2` 查询改造（T3）
  - `OL3` 权限与清理（T4）
  - `OL4` 导入导出后端（T5、T6）
  - `OL5` 前端接入（T7、T8、T9）
  - `OL6` 联调验收与文档同步（T10、T11）
- 顺序：先数据 / 拼音 → 查询 → 权限 → 导入导出（公共层重载先行、Controller 后接）→ 前端 → 联调验收 → 文档同步。
- **强顺序约束**：
  - `OL1-BE-002`（生成与回填）依赖 `OL1-DB-001`（列存在）与 `OL1-BE-001`（工具类与依赖）；
  - `OL2-BE-001` 依赖 `OL1-DB-001`（VoResultMap 增列与 JOIN 改造同在 XML，先行避免冲突）；
  - `OL4-BE-001` 依赖 `OL2-BE-001`（converter 消费 `fieldParentCode` / `fieldLeaderCode` 关联列）；
  - `OL4-BE-002`（Controller）依赖 `OL3-BE-001`（`ACTION_*` 常量与 resolver 分支）与 `OL4-BE-001`（公共层重载与 VO）；
  - `OL5-FE-001` 依赖 `OL2-BE-001` 与 `OL4-BE-002`（T8 依赖 T3 的方案约束由此覆盖）；`OL5-FE-003`（ImportDialog 增强）无后端依赖，可在 Wave 3 期间提前；
  - `OL6-DOC-001` 最后收口（文档须反映最终实现）。
- 文档同步不默认「顺手更新」：列为显式任务 `OL6-DOC-001`；代码内 Swagger 注解随 `OL2-BE-001` / `OL4-BE-002` 同批提交（AGENTS 第 3 节强制）；`AGENTS.md` 迁移序号行修正随 `OL1-DB-001` 同批（方案 4.1 勘误项）。
- 任务状态：创建时全部为 `TODO`。
