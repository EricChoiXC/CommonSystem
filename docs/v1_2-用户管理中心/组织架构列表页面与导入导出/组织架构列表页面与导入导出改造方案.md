# 组织架构列表页面与导入导出改造方案

> 来源：[补充功能实现方案（人工初设版）.md](./补充功能实现方案（人工初设版）.md) 「组织架构列表页面」「组织架构导入导出」两节。
> 状态：人工初设 → 方案细化，供评审后进入开发。
> 编写日期：2026-11-10。代码事实基于当前 master（迁移脚本最新 `V1_01_040__sys_i18n_schema.sql`）。

---

## 1. 背景与目标

1. **组织架构列表页面**：现有「当前组织架构」（`OrgManageView.vue`）是「左树 + 右表」形态，只能按树节点逐级查看直接下级。新增一个**全层级平铺列表页**，支持按类型（机构/部门/人员/岗位）、关键字（名称/编号/拼音/拼音简称）、启用状态检索全量组织架构元素；同时为 `sys_org_element` 增加拼音全称/简称两列，随名称自动维护，支撑关键字检索。
2. **组织架构导入导出**：在上述页面提供导入/导出按钮。导出按当前查询条件产出 xlsx；导入提供「导入方式 / 导入组织机构 / 失败处理」设置，模板按导入类型四选一。复用 v1.1 已落地的公共导入导出通道（dict 为试点），将原预留的 `sys.org.user.import/export` 动作作废，替换为 `sys.org.element.import/export`。

不在本方案范围：第三方账号绑定、账号锁定/冻结/待激活、密码策略、个人头像、个人资料页、用户信息拓展、登录设备、个人偏好、信息设置（见初设版后续章节，另行成册）。

### 2.2 差距清单

1. `sys_org_element` 缺 `field_pinyin` / `field_pinyin_short` 列，且无拼音生成与存量回填机制。
2. 列表查询不支持「全层级平铺」与「单关键字四列模糊」（现有条件均为独立精确/单列模糊）。
3. `SysOrgElementVo` 无创建人/更新人名称，列表页无法展示这两列。
4. 无 `/backend/sys/org/element/export|import|template` 接口与四类导入导出 VO。
5. 缺权限码 `SYS_ORG_ELEMENT_IMPORT` / `SYS_ORG_ELEMENT_EXPORT`（roles.yml、Properties、Resolver 三处）。
6. 前端缺平铺列表页、路由、菜单项、`activeMenu` 归约。
7. 公共通道 `importExcel` 目前只支持「纯 insert」落库（`IBaseService#insert`），不满足「覆盖 / 新增并覆盖」需求（见 5.4 决策）。

## 4. 数据库改造

### 4.1 迁移脚本 `V1_01_041__sys_org_element_pinyin.sql`

```sql
ALTER TABLE sys_org_element
    ADD COLUMN field_pinyin       VARCHAR(1000) DEFAULT NULL COMMENT '名称拼音全称(小写,后端按 field_name 自动生成)' AFTER field_name,
    ADD COLUMN field_pinyin_short VARCHAR(300)  DEFAULT NULL COMMENT '名称拼音简称(首字母小写,后端按 field_name 自动生成)' AFTER field_pinyin;
```

- 列长度按 `field_name VARCHAR(200)` 上限估算（每汉字全拼 ≤6 字母），实际名称远短于此；**不加索引**——关键字检索为 `%kw%` 前缀通配，B+ 树索引无效，组织架构数据量（万级内）全表扫描可接受。
- 序号从 `V1_01_041` 起递增（当前最新 `V1_01_040`）。
- ⚠️ 现状勘误：AGENTS.md「数据库与迁移」一节记载「当前最新为 V1_01_038」已过时，随本批顺手修正为 040（本方案实施后为 041）。

### 4.2 存量数据回填

SQL 无法做汉字转拼音，回填由启动任务承接（符合「启动期初始化统一追加到 `SysStartupTask#run`」约束）：

- `SysStartupTask` 新增**第九个启动任务** `backfillElementPinyin()`，调 `SysOrgElementService#backfillPinyin()`；
- 回填口径：`WHERE field_pinyin IS NULL OR field_pinyin_short IS NULL` 按 `field_id` 分批（每批 500）执行，幂等可重跑；
- 之后新写入/改名数据由 `save` / `update` 前向维护（见 5.2），启动任务仅在存量缺口时生效。

### 4.3 拼音生成规则

| 规则 | 说明 |
| --- | --- |
| 全称 `field_pinyin` | 逐字转全拼小写连写；字母/数字原样保留（转小写）；空格与标点剔除。例：`测试部A1` → `ceshibua1` |
| 简称 `field_pinyin_short` | 逐字取拼音首字母小写连写，其余同上。例：`测试部A1` → `csba1` |
| 多音字 | pinyin4j 默认取第一读音（如「重庆」取 `chongqing`）。**接受该局限**：关键字检索同时命中名称/编号原文，误读仅影响拼音维度；不做人工修正入口 |
| 维护时机 | 仅由后端在 `save` / `update` 时按 `field_name` 重算，前端不传、用户不可改；名称未变也重算（幂等，逻辑简单） |

## 5. 后端改造

### 5.1 拼音工具 `common/utils/PinyinUtil`

- 新增依赖：`com.belerweb:pinyin4j:2.5.1`（Maven Central，MIT，约 200KB）至 `backend/pom.xml`。
- `PinyinUtil` 提供静态方法 `toPinyin(String name)`、`toPinyinShort(String name)`，空串安全（返回 null，不抛异常）。
- 放置 `common/utils` 符合规范（可复用小逻辑工具类，与 `IDUtil`、`StringUtil` 同级）。

### 5.2 Service / 实体 / XML

- `SysOrgElement` 实体与 `SysOrgElementVo` 增加 `fieldPinyin` / `fieldPinyinShort`；`SysOrgElementVo` 增加 `fieldCreatorName` / `fieldUpdaterName`。
- `SysOrgElementService#save` / `#update`：在 `validateCommon` 通过后调用 `vo.setFieldPinyin(PinyinUtil.toPinyin(vo.getFieldName()))` 等两行完成生成。
- `SysOrgElementMapper.xml`：
  - `BaseColumns` / `SysOrgElementResultMap` / `SysOrgElementVoResultMap` / `insert` / `update` 补两列（update 用 `<if test="model.fieldPinyin != null">`，与其他列一致）；
  - `VoBaseColumns` 增加 `cu.field_name AS field_creator_name`、`uu.field_name AS field_updater_name`，`VoJoinClause` 增加 `LEFT JOIN sys_org_element cu ON cu.field_id = e.field_creator_id`、`uu` 同理（parent/leader 已有同形态 JOIN 先例）。

### 5.3 平铺查询与关键字检索

`SysOrgElementQuery` 增加：

```java
/** 全层级平铺查询：true 时忽略 parentId 语义，返回所有层级元素（组织架构列表页用） */
private Boolean flat;
/** 单关键字：对 field_name / field_code / field_pinyin / field_pinyin_short 四列 OR 模糊匹配 */
private String keyword;
```

`SysOrgElementMapper.xml#VoWhereClause` 调整：

```xml
<choose>
    <when test="query.flat != null and query.flat">  <!-- 平铺：不拼 parent 条件 -->
    </when>
    <when test="query.parentId != null and query.parentId != ''">
        AND e.field_parent_id = #{query.parentId}
    </when>
    <otherwise>
        AND (e.field_parent_id IS NULL OR e.field_parent_id = '')
    </otherwise>
</choose>
<if test="query.keyword != null and query.keyword != ''">
    AND ( e.field_name LIKE CONCAT('%', #{query.keyword}, '%')
       OR e.field_code LIKE CONCAT('%', #{query.keyword}, '%')
       OR e.field_pinyin LIKE CONCAT('%', #{query.keyword}, '%')
       OR e.field_pinyin_short LIKE CONCAT('%', #{query.keyword}, '%') )
</if>
```

- `selectVoList` / `countVoList` 均复用 `VoWhereClause`，自动获得新条件；`NOT IN (5,6)` 永久排除不变。
- `Service#normalizeQuery` 补 `flat` 空值归一与 `keyword` trim。
- 现有 `fieldName` / `fieldCode` 独立条件保留（当前组织架构页仍用），列表页只用 `keyword`。
- **兼容性**：`flat` 缺省为 null 时行为与现状完全一致，树页不受影响。

### 5.4 导入导出接口与公共层增强

#### 5.4.1 接口定义（沿用 dict 试点形态）

| 接口 | 方法 | 鉴权动作 | 权限 |
| --- | --- | --- | --- |
| `/backend/sys/org/element/export` | POST（body 为查询条件） | `sys.org.element.export` | `SYS_ORG_ADMIN` / `SYS_ORG_ELEMENT_ADMIN` / `SYS_ORG_ELEMENT_EXPORT` |
| `/backend/sys/org/element/import` | POST multipart（`file` + `params`） | `sys.org.element.import` | `SYS_ORG_ADMIN` / `SYS_ORG_ELEMENT_ADMIN` / `SYS_ORG_ELEMENT_IMPORT` |
| `/backend/sys/org/element/template` | POST（body 携带 `orgType`） | `sys.org.element.template` | 同 export |

- 新增 `SysOrgElementProperties.ACTION_EXPORT / ACTION_IMPORT / ACTION_TEMPLATE` 与 `ROLE_SYS_ORG_ELEMENT_EXPORT / ROLE_SYS_ORG_ELEMENT_IMPORT` 常量；`ElementResolver` 增加三个 case 分支（`SYS_ADMIN` 由 `BaseResolver` 自动放行，分支不列举）。
- `roles.yml` 的 `ROLE_LIST` 增补两个权限码、`ROLE_MAP` 增补名称与描述，与代码同批提交。
- Swagger：三个接口补 `@Operation`（description 以「鉴权动作 …」开头）与文件流 `@ApiResponse`；`orgType` 参数语义在 description 中说明。

#### 5.4.2 导出

- 请求体与列表查询同构：`{ body: { orgType, keyword, enable } }`（导出恒全量，不带分页）。
- **限定单一类型**：`orgType` 必须为 1~4，为空或非法时返回 `BAD_REQUEST`「请先选择具体的组织架构类型再导出」——四类模板列不同，无法产出单一文件；前端在类型筛选为「全部」时禁用导出按钮兜底。
- 新增四个导出 VO（`response/` 包，`@Export` 注解驱动列序与标题）：

| VO | 列（需求原文口径） | dict 转换 |
| --- | --- | --- |
| `SysOrgElementOrgExportVo` | 编号、名称、是否启用、上级组织架构编号、是否虚拟组织、联系电话、联系邮箱、联系地址 | 是否启用/是否虚拟 → `yes_no` |
| `SysOrgElementDeptExportVo` | 编号、名称、是否启用、上级组织架构编号、是否虚拟组织、联系电话、联系地址 | 同上 |
| `SysOrgElementUserExportVo` | 编号、名称、是否启用、上级组织架构编号、是否虚拟组织、联系电话、联系邮箱、联系地址、性别、出生日期、登录名、在职状态、账号状态 | 性别 → `gender`；在职状态 → `org_job_status`；账号状态 → `org_account_status`；出生日期 `dateFormat="yyyy-MM-dd"` |
| `SysOrgElementPostExportVo` | 编号、名称、是否启用、上级组织架构编号、是否虚拟组织、负责人编号 | — |

- 「上级组织架构编号」「负责人编号」由 converter 从 `SysOrgElementVo` 的 `fieldParentName`/`fieldLeaderName` 之外的关联取值：复用 `selectVoList`（flat=true）已 JOIN 的 `pe`（parent），需**补充导出用关联列**——在 `VoBaseColumns` 增补 `pe.field_code AS field_parent_code`、`leader.field_code AS field_leader_code`，Vo 增补 `fieldParentCode` / `fieldLeaderCode`（列表页不展示，仅导入导出消费）。
- 文件名 `org_element_{orgType}_{yyyyMMddHHmmss}.xlsx`；导出与模板列一致，round-trip 可回传导入（dict 先例口径）。

#### 5.4.3 导入

- 请求 `params`（JSON）业务键：

| 键 | 含义 | 取值 | 默认 |
| --- | --- | --- | --- |
| `orgType` | 导入组织机构 | 1=机构 2=部门 3=人员 4=岗位 | 必填，决定解析模板与落库分支 |
| `importMode` | 导入方式 | `ADD` 新增 / `OVERWRITE` 覆盖 / `ADD_OVERWRITE` 新增并覆盖 | `ADD`（保守默认，评审可调） |
| `ignoreError` | 失败处理（公共开关） | true=忽略失败行继续，false=任一行失败整体回滚 | false（终止） |

- 模板接口按 `body.orgType` 返回对应四套空模板（列同 5.4.2），文件名 `org_element_template_{orgType}.xlsx`。
- 落库语义：
  - `ADD`：全部按新增处理；
  - `OVERWRITE`：按「同类型 + `field_code`」匹配库中记录，命中则更新（含上级/专有字段，父级变更走既有 `update` 层级重算），未命中记行错误「编号不存在，无法覆盖」；
  - `ADD_OVERWRITE`：命中即更新、未命中即新增。
- 行级校验（`ImportRowHandler`，位于 `SysOrgElementService` 或独立类）：
  - `field_code` 在**同类型内**唯一：批内查重 + 与库中查重（`OVERWRITE` 模式下库中命中 0 或 >1 条均报错）；
  - 上级组织架构编号必须存在且启用（存在性按 `field_code` + `field_org_type` 反查；不做上下级类型组合约束，与现有保存接口口径一致）；
  - 岗位负责人编号必须存在且为人员类型；
  - 人员行：登录名非空且唯一（批内 + 库中，对齐 `uk_org_user_login_name`）；性别/在职状态/账号状态经 dict 显示值回转后落在码值域内；出生日期格式 `yyyy-MM-dd`。
- 人员初始密码（模板无密码列）：导入新增人员统一使用初始密码常量（BCrypt 加密后入库），本方案定为 `Abc@123456`，在实现中置于 `SysOrgElementProperties` 常量并注释「待『密码策略和重置』章节配置化后迁移到 `common_setting`」。⚠️ 该值需随「密码策略」方案一并评审确认。
- **公共层增强**：`ImportExportService#importExcel` 现有签名固定走 `IBaseService#insert`，无法表达「按编号覆盖更新」。新增重载：

```java
@Transactional
public <V> ImportResultVo importExcel(MultipartFile file, Map<String, Object> params,
        Class<V> importVoClass, ImportRowHandler<V> rowHandler,
        BiConsumer<V, Integer> rowConsumer)  // V=解析行, Integer=序号；模块自行 insert/update
```

  - 解析、通用校验（required/dateFormat/dict）、行级校验、错误汇总、单事务、分批日志等逻辑与原实现完全一致，仅将「`toEntity + baseService.insert`」替换为 `rowConsumer` 回调；原五参签名保留并委托新重载（dict 零改动）。
  - Element 侧 `rowConsumer` 内部按 `importMode` 分流到 `SysOrgElementService#save`（复用层级重算）与按编号预查后的 `#update`。
- 导入结果沿用 `ImportResultVo`（total / success / failed / errors），前端由 `ImportDialog` 内置渲染。

#### 5.4.4 预留动作清理

- 删除 `SysOrgUserProperties.ACTION_IMPORT` / `ACTION_EXPORT` 两个常量（全库零引用，含注释一行说明「导入导出已迁移至 SysOrgElementProperties，见 v1.2 组织架构导入导出」）。
- `UserResolver` 无对应分支，无需改动。

## 6. 前端改造

### 6.1 路由与菜单

- 新增路由：`path: '/orgList'`，`name: 'OrgElementList'`，组件 `views/org/OrgElementListView.vue`，`meta: { title: '组织架构列表', parent: '组织架构' }`。
- **新建/编辑/查看不新增路由**，复用现有 `/org/create`、`/org/edit/:id`、`/org/detail/:id`（按钮跳转时带 `orgType` query 参数，表单页已支持）。
- 菜单：组织架构组内「当前组织架构」后插入 `{ title: '组织架构列表', path: '/orgList', auth: '' }`（列表查询后端不设权，菜单对登录用户可见；导入导出按钮在页内按 `hasAuth` 控显）。
- `activeMenu`：`/orgList` 为叶子路径，不落入任何现有前缀归约（`'/orgList'.startsWith('/org/') === false`），默认 `return path` 即高亮自身，**无需新增归约行**。路径选 `/orgList` 而非 `/org/list`，避免落入 `/org/` 前缀归约被误高亮「当前组织架构」。

### 6.2 页面 `OrgElementListView.vue`

标准三段式列表页（基准 `list-page.css`，无左侧树）：

- **筛选区**（`el-form.filter-form`，一行四列）：
  - 类型：`el-select`（机构/部门/人员/岗位，**默认人员**；含「全部」选项供浏览，导出时校验需具体类型）；
  - 关键字：`el-input`（placeholder「名称 / 编号 / 拼音 / 拼音简称」，回车触发查询）；
  - 启用状态：`el-select`（启用/停用/全部，**默认启用**）；
  - 第四列留白（保持一行四列栅格）。
- **工具区**：左侧 `sort-area` 单条件排序（创建时间/更新时间/编号，默认创建时间降序）；右侧按钮：查询、**新增**（`hasAuth(SYS_ORG_ELEMENT_ADD)`，跳 `/org/create?orgType=当前筛选`）、**导入**（`hasAuth(SYS_ORG_ELEMENT_IMPORT)`，开 ImportDialog）、**导出**（`hasAuth(SYS_ORG_ELEMENT_EXPORT)`）。
- **列表区**（列固定 8 列，不随类型切换，不展示主键）：复选框、编号、名称、上级组织架构（`fieldParentName`）、状态（启用 tag）、创建时间、创建人（`fieldCreatorName`）、更新时间、更新人（`fieldUpdaterName`）、操作列（详情/编辑/启停用，`fixed="right"`，启停用二次确认，编辑按 `hasAuth(SYS_ORG_ELEMENT_EDIT)` 控显）。
- 分页 `layout="total, prev, pager, next, sizes"`、`page-sizes [10,20,50,100]`，切页大小回第 1 页。

### 6.3 导入弹窗

复用公共 `ImportDialog`，需一处**向后兼容增强**：新增 prop `hideCommonSwitches`（默认 `false` 不影响 dict 既有用法），本页设 `true` 隐藏公共「忽略错误/全量更新」开关，改由 `configFields` 呈现需求要求的三个设置项：

| configField | type | options | 默认 |
| --- | --- | --- | --- |
| 导入方式 `importMode` | select | 新增 / 覆盖 / 新增并覆盖 | 新增 |
| 导入组织机构 `orgType` | select | 机构 / 部门 / 人员 / 岗位 | 人员 |
| 失败处理 `failMode` | select | 忽略 / 终止 | 终止 |

- 模板下载：`templatePath = '/backend/sys/org/element/template'`，`templateBody = { body: { orgType: 弹窗当前选择 } }`，弹窗内切换类型后重新下载即得对应模板（ImportDialog 模板按钮每次点击实时取当前 `templateBody`，实现时核对该取值时机，必要时在页内以 computed 传入）。
- `@confirm` 回调组装提交参数：`{ orgType, importMode, ignoreError: failMode === 'IGNORE' }`，调 `api/common.js#importExcel('/backend/sys/org/element/import', file, params)`。
- 导出：`api/common.js#exportExcel('/backend/sys/org/element/export', { body: { orgType, keyword, enable } })`，配合 `utils/download.js#downloadBlob` 保存；类型为「全部」时按钮禁用并提示。

### 6.4 api/org.js

- 新增 `queryElementFlatList(data)` → `POST /backend/sys/org/element/list`（`body: { flat: true, orgType, keyword, enable }`），JSDoc 注明与树页 `queryElementList` 的差异；
- 新增/编辑/启停用/详情复用既有 `saveElement` / `updateElement` / `enableElement` / `loadElement`；
- 导入导出统一走 `api/common.js`，路径常量定义在页面内（dict 先例口径）。

## 11. 风险与待确认项（评审重点）

1. **拼音依赖选型**：推荐 `pinyin4j 2.5.1`；多音字取默认读音的局限是否接受。
2. **人员导入初始密码** `Abc@123456`：需与「密码策略和重置」章节合并评审，避免两处口径冲突。
3. **编码唯一性口径**：本方案定「同类型内唯一」，与全表唯一存在差异，需确认。
4. **导出限定单一类型**：类型为「全部」时导出被拒，是否接受（替代方案：全量导出用四类型超集列，列语义混杂，不推荐）。
5. **导入方式默认值** `ADD`：若批量初始化为主场景，可改默认「新增并覆盖」。
6. **公共层重载**：`ImportExportService` 新增落库回调重载属公共通道增量，dict 行为零变化，需按公共组件变更评审。
