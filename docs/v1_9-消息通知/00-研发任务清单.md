### 1.2 当前版本范围

- 版本目标：交付统一消息中心模块 `com.eric.base.sys.message`——邮箱 / 手机短信 / 企业微信三渠道的推送方配置、消息模板、公共配置、手动信息推送、信息记录（含人工重试）、待办触发的外部推送、失败自动重试与积压扫描；前端「统一消息中心」菜单组 7 页面 + 「通知待办」组内待办公共配置页 + org 人员表单补企微 userid。
- **In Scope**
  - 数据库：实体注解声明 + 注解同步引擎建表（**不新增迁移脚本**，Flyway 已移除）——`sys_message_sender` / `sys_message_template` / `sys_message_record` 三表 + 索引（三实体标注 `@TableSource` / `@ColumnField` / `@TableIndex`）、`SysOrgUser` 实体补 `field_wecom_userid` 注解字段（W6 跨模块增列）。
  - 后端基建：message 包全量骨架、`MessageCryptoUtil`（AES-256-GCM，W4 口径）、`MessageRenderer`（`${变量}` 渲染）、渠道配置固定 POJO 四件、`messageSendExecutor` 线程池、新依赖 `spring-boot-starter-mail`。
  - 后端服务：sender / template / config / push / record 五 Service；`MessageChannelSender` 接口 + Mail / Sms / WeCom 三适配器；`MessageDispatchEvent` 事务提交后异步投递（CAS 防重）；`SysMessageRetryTask` 定时重试与积压扫描。
  - 待办触发：`SysMessageNotifyEventListener` 消费 `NotifySendEvent`（notify 模块零改动）。
  - 接口与权限：5 Controller 共 19 接口 + Swagger 注解同批；`SysMessageConstants` + `MessageResolver` + `roles.yml`（双码，W2）+ `application.yml`（`SETTING` 段 10 键）+ `dict.yml`（`message_channel` / `message_status`）。
  - 前端：`api/message.js` 19 具名函数、8 个页面（公共配置 / 邮箱配置 / 手机短信配置 / 企业微信配置 / 消息模板 / 信息记录 / 信息推送 / 待办公共配置）、路由与菜单、org 人员编辑表单补 `field_wecom_userid`。
  - 联调：全链路（含三渠道真实或沙箱环境）+ 鉴权矩阵 + 待办触发链路 + 重试链路。
  - 文档：方案 §0.2 修订清单七处 + 方案偏差回写。
- **Out of Scope**
  - 站内 IM / 点对点消息（现状清单第 13 项，维持不做）。
  - 定时发送（W5 已确认**不拓展**；仅 `field_status=0` 语义预留，不落库不加接口）。
  - 退信 / 短信状态回执 / 企微已读回调（W7 已确认不实现）。
  - 退订机制、发送频率限制、营销类批量触达等合规能力。
  - 外部收件人（非组织架构人员的手工地址）。
  - 多实例部署下的队列抢占与任务分片（与多实例 SSE 同批另立）。
  - 记录归档清理策略。
  - 钉钉 / WhatsApp 等新渠道（仅保留 `MessageChannelSender` 扩展点）。
  - notify 模块任何代码改动（待办触发只消费其已发布的 `NotifySendEvent`）。

### 1.3 任务拆解规则

- 编号规则 `MSG<模块>-<层级>-<序号>`，模块划分与方案章节映射：
  - `MSG1` 数据库与模型基建（方案 §2、§8）
  - `MSG2` 发送核心与渠道适配（方案 §4.1–4.5、§6）
  - `MSG3` 待办触发（方案 §4.6、§1.2）
  - `MSG4` 权限与接口（方案 §3、§5、§6）
  - `MSG5` 前端（方案 §7）
  - `MSG6` 联调验收与文档同步（方案 §0.2、§9）
- 顺序：先数据 / 模型 → 发送核心与渠道适配 → 待办触发 → 权限 → 接口（sender / template+config → push / record）→ 前端 → 联调验收 → 文档同步。
- **强顺序约束**：
  - `MSG1-DB-001` / `MSG1-DB-002` / `MSG1-BE-001` 三者并行；
  - `MSG2-BE-001` 依赖 `MSG1-DB-001` + `MSG1-BE-001`（加密工具）；`MSG2-BE-002` 依赖 `MSG1-DB-001`；
  - `MSG2-BE-003` 依赖 `MSG1-BE-001`（POJO / 加密 / 渲染）、`MSG2-BE-001`（默认推送方解析）、`MSG1-DB-001`（记录落库）；
  - `MSG2-BE-004` 依赖 `MSG2-BE-003`；`MSG3-BE-001` 依赖 `MSG2-BE-003`；
  - `MSG4-BE-002~004` 各自依赖对应 Service 与 `MSG4-BE-001`；`MSG4-BE-004` 另依赖 `MSG3-BE-001`；
  - `MSG5-FE-001` 契约冻结即可提前至 Wave 3；`MSG5-FE-002~006` 依赖对应后端接口任务；`MSG5-FE-007` 依赖 `MSG5-FE-002~006`（org 表单部分依赖 `MSG1-DB-002`）；
  - `MSG6-DOC-001` 最后收口（文档须反映最终实现）。
- 文档同步不默认「顺手更新」：列为显式任务 `MSG6-DOC-001`；代码内 Swagger 注解随各 Controller 任务同批提交（AGENTS 第 3 节强制）；AGENTS 第 4 节已改写为「数据库与表结构维护」（注解引擎口径，无迁移序号行），`MSG1-DB-001` 不再涉及 AGENTS 序号修正。
- 任务状态：创建时全部为 `TODO`。
