### 1.2 当前版本范围

- 版本目标：交付可复用取数配置能力——默认数据源（Provider 代码注册）+ 自定义数据源（`sys_datasource` 单表）+ 统一执行入口 `POST /backend/sys/datasource/query`（两段式鉴权），并以【日程】模块为首个接入样例。
- In Scope：
  - `sys_datasource` 建表（迁移 `V1_01_046`）；
  - 数据源模块骨架（常量/枚举/SPI/Registry/Service/Resolver/Controller/Mapper/roles.yml）；
  - 9 个接口：list/load/save/update/enable/delete/options/targets/query；
  - 日程模块接入：`SysCalendarQuery.fieldCreatorId` + Mapper 可选收紧条件 + `SysCalendarDatasourceProvider`（默认数据源 `calendar.list`）；
  - 前端：`api/datasource.js`、管理页（列表/表单/详情）、路由与菜单、`HomeView` 归约。
- Out of Scope（方案 §9 明确不做）：跨数据源 join、写类数据源、SQL 直配数据源、外系统 REST 数据源（v1.9+）、独立预览接口、与字段级可见性结合。
- 影响范围：`backend/src/main/java/com/eric/base/sys/{datasource,calendar}/`、`backend/src/main/resources/{db/migration,mappers,properties}/`、`frontend/src/{api,views,router}/`、`docs/`。

### 1.3 任务拆解规则

- 按「F18 数据源」单模块垂直切片，先文档后契约、先数据后接口、先后端后前端、先联调后收尾。
- 后端骨架按样例代码目录分四步（常量枚举 → SPI+Registry → 模型/Mapper → Service/Resolver → Controller），每步一个主产出与一条验证路径。
- 文档同步不靠「顺手更新」：Wave 0 显式补四份系统模块文档章节，收尾设回查任务。
- 验证基线：`cd backend && ./mvnw test`（含 `ApiDocsTest`）、`cd frontend && npm run build`；集成验证期启动的服务结束前停止。
