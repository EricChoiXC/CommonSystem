# 数据库改动设计（草案）

> 迁移脚本目录：`backend/src/main/resources/db/migration/`
> 命名规则：`V{大版本}_{小版本}_{序号}__{英文下划线描述}.sql`；当前最新 `V1_01_038`，**新脚本从 `V1_01_039` 起**。
> 字段规范：统一 `field_` 前缀；公共字段 `field_id`（VARCHAR(32)，毫秒时间戳 + UUID v4）、`field_code`、`field_name`、
> `field_creator_id`、`field_create_time`、`field_updater_id`、`field_update_time`、`field_enable`（BIT(1) 默认 `b'1'`）。
> 明细/关联表采用复合主键、只增不改；真正的主数据表保留公共字段。

## 1. 迁移脚本拆分建议

| 序号 | 脚本名 | 内容 |

| 1 | `V1_01_039__sys_org_group_schema.sql` | 建 `sys_org_group` / `sys_org_group_user` / `sys_org_group_viewer` |
| 2 | `V1_01_040__sys_org_element_type_comment.sql` | 修正 `sys_org_element.field_org_type` 注释为 `1~6`（仅注释，可选） |

## 2. 建表 DDL 草案

### 2.1 `sys_org_group`（群组扩展表）

```sql
-- 群组扩展表（sys_org_element.field_org_type = 6）
-- 群组不参与组织架构树：对应 sys_org_element 行的 field_parent_id / field_hierarchy 为 NULL，field_level = 1
CREATE TABLE IF NOT EXISTS sys_org_group (
    field_id             VARCHAR(32)  NOT NULL COMMENT '主键ID(与 sys_org_element.field_id 一致)',
    field_type           VARCHAR(20)  NOT NULL DEFAULT 'PERSONAL' COMMENT '群组类型: COMMON=公共 PERSONAL=个人',
    field_owner_id       VARCHAR(32)  DEFAULT NULL COMMENT '所有人ID(PERSONAL=归属人; COMMON=创建人)',
    field_is_all_viewer  BIT(1)       NOT NULL DEFAULT b'1' COMMENT '是否全员可见(由可见范围明细派生: 明细为空则为1)',
    PRIMARY KEY (field_id),
    KEY idx_org_group_type (field_type),
    KEY idx_org_group_owner (field_owner_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='群组扩展表';
```

> 索引说明：`field_type` 支撑列表按类型筛选；`field_owner_id` 支撑「我的个人群组」查询。
> 若后续按 `field_is_all_viewer` 过滤较多，可加组合索引 `(field_type, field_is_all_viewer)`（当前数据量下不必）。

### 2.2 `sys_org_group_user`（群组成员明细表）

```sql
-- 群组-成员关联表：表示该群组包含的用户
CREATE TABLE IF NOT EXISTS sys_org_group_user (
    field_group_id VARCHAR(32) NOT NULL COMMENT '群组ID',
    field_user_id  VARCHAR(32) NOT NULL COMMENT '人员ID(sys_org_element.field_id, field_org_type = 3)',
    PRIMARY KEY (field_group_id, field_user_id),
    KEY idx_org_group_user_user (field_user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='群组-成员关联表';
```

- 二级索引 `field_user_id`：支撑「某人参与了哪些群组」。
- 不设外键（与仓库其它关联表一致）。

### 2.3 `sys_org_group_viewer`（群组可见范围明细表）

```sql
-- 群组-可见范围关联表：仅 field_type = COMMON 时使用，表示可见该群组的组织架构范围
CREATE TABLE IF NOT EXISTS sys_org_group_viewer (
    field_group_id  VARCHAR(32) NOT NULL COMMENT '群组ID',
    field_viewer_id VARCHAR(32) NOT NULL COMMENT '可见范围组织架构ID(sys_org_element.field_id)',
    PRIMARY KEY (field_group_id, field_viewer_id),
    KEY idx_org_group_viewer_viewer (field_viewer_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='群组-可见范围关联表';
```

- 「可见范围向子集覆盖」由 `field_viewer_id` 对应节点的 `field_hierarchy` 前缀匹配实现，无需额外字段。
- 二级索引 `field_viewer_id`：支撑「某组织节点被哪些群组设为可见」。

## 3. 角色（`field_org_type = 5`）的数据库改动

### 3.1 方案 A（推荐）：无新表，仅语义扩展

- `sys_org_role` 结构**不变**。
- `sys_org_element` 新增 `field_org_type = 5` 的行（运行时写入，非迁移）：`field_parent_id = NULL`、
  `field_hierarchy = NULL`、`field_level = 1`、`field_is_virtual = b'0'`。
- 主键与 `sys_org_role.field_id` 一致。
- 索引：现有 `idx_org_element_type` 已覆盖，无需新增。

```sql
-- 仅注释变更（可选）：明确 field_org_type 取值
ALTER TABLE sys_org_element
    MODIFY COLUMN field_org_type INT NOT NULL COMMENT '组织类型: 1=机构 2=部门 3=人员 4=岗位 5=角色 6=群组';
```

> 注意：`ALTER TABLE ... MODIFY COLUMN` 在 MySQL 8 上若仅改注释，元数据操作代价低，可接受。
> 若担心锁表风险，可跳过该脚本，仅在文档中说明。

### 3.2 方案 B：完全不落主表

- 无任何 DDL 变更；`field_org_type = 5` 仅作为常量与码值存在。

### 3.3 存量角色补齐（可选，**不纳入 Flyway**）

见 `01-角色纳入组织架构分析.md` 第 8 节脚本，建议存放为
`docs/v1_1/01-组织架构改动/sql/optional_backfill_org_role_element.sql`，由实施方手工执行。

## 5. 码值与权限码（配置文件，非 SQL）

### 5.1 `properties/sys/org/dict.yml`

```yaml
dict:
  org_element_type:
    name: 组织架构类型
    desc: sys_org_element.field_org_type（1 机构 / 2 部门 / 3 人员 / 4 岗位 / 5 角色 / 6 群组）
    1: 机构
    2: 部门
    3: 人员
    4: 岗位
    5: 角色
    6: 群组
  org_group_type:
    name: 群组类型
    desc: sys_org_group.field_type
    COMMON: 公共
    PERSONAL: 个人
```

> `syncDictFromYml` 为增量导入、不覆盖人工码值；新增两项即可，无需手工 SQL。

### 5.2 `properties/sys/org/roles.yml`

```yaml
ROLE_LIST: ["SYS_ORG_ADMIN", "SYS_ORG_ELEMENT_ADMIN", "SYS_ORG_ELEMENT_ADD",
            "SYS_ORG_ELEMENT_EDIT", "SYS_ORG_ROLE_ADMIN", "SYS_ORG_USER_MANAGER",
            "SYS_ORG_GROUP_ADMIN"]
ROLE_MAP:

    NAME: "群组管理员"
```

> AGENTS 要求「新增权限码必须同时改库与 `roles.yml`，两处同批提交」；本仓库以启动任务同步为库侧落地手段，
> 因此需在发布说明中标注「首次启动后权限码才会出现在 `sys_org_auth`」。

## 6. 索引与查询验证清单

| 查询 | SQL 形态 | 命中索引 |
| --- | --- | --- |
| 可见群组列表（个人） | `field_type = 'PERSONAL' AND field_owner_id = ?` | `idx_org_group_owner` |
| 可见群组列表（公共-全员） | `field_type = 'COMMON' AND field_is_all_viewer = 1` | `idx_org_group_type` |
| 可见群组列表（公共-范围） | `EXISTS (SELECT 1 FROM sys_org_group_viewer ...)` | `idx_org_group_viewer_viewer` + `PRIMARY` |
| 群组成员 | `WHERE field_group_id = ?` | `PRIMARY` |
| 用户所属群组 | `WHERE field_user_id = ?` | `idx_org_group_user_user` |
| 角色镜像行 | `WHERE field_org_type = 5` | `idx_org_element_type` |

## 7. 数据一致性约束（应用层）

| 约束 | 落地位置 |
| --- | --- |
| `field_type = PERSONAL` ⇒ `field_owner_id` 必填 | `SysOrgGroupService#validate` |
| `field_type = COMMON` ⇒ `field_owner_id` 记录创建人（可空的历史数据按创建人回填）；`field_is_all_viewer` 由明细派生 | Service 统一计算 |
| `field_type = PERSONAL` ⇒ 不写 `sys_org_group_viewer`，`field_is_all_viewer = 1` | Service 保存时清理 |
| 群组成员必须是启用人员（`field_org_type = 3`） | Service 校验 `elementDao` |
| 可见范围可选机构/部门/岗位/人员（`field_org_type IN (1,2,3,4)`）；虚拟组织不可选 | Service 校验 |
| 角色镜像行与 `sys_org_role` 同事务 | `SysOrgRoleService` |

> 全部约束**不建外键**，与仓库既有风格一致，靠应用层 + 迁移脚本注释兜底。
