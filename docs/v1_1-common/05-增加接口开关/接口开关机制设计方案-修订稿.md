# 接口开关机制设计方案（修订稿）

> 修订说明：本稿基于原方案 [接口开关机制设计方案.md](接口开关机制设计方案.md)（6 条机制草案）与 2026-11 仓库现状分析整理而成。
> 原方案的 6 条机制骨架**全部保留**；对落地缺失的决策点逐条补齐，修订内容以 **【修订】** 标注并附决策理由。
> 文末附「原方案 → 修订稿差异对照表」。

---

## 1. 目标与非目标

**目标**

1. 按「模块组」粒度对一组接口做**运行期整体启停**：管理员不改代码、不重启即可关闭/恢复一个模块组；
2. 提供模块组的管理面：【系统管理-模块管理】页面 + 后端列表/切换接口；
3. 前端运行期感知：模块关闭后，用户侧菜单与页面有明确的降级表现，而非一堆报错；
4. 单机与多实例部署下开关状态正确收敛。

**非目标**

1. **不替代权限体系**：开关是「模块能不能用」的功能门禁，与「谁能用」的 `ACTION_* + resolver` 鉴权正交；
2. 不做方法级/接口级精细灰度（粒度固定为模块组）；
3. 不提供定时自动启停、生效时间段等高级能力（后续迭代再议）。

## 2. 概念与关键语义

| 概念 | 定义 |
| --- | --- |
| 模块组（module-group） | 接口开关的单位。key 为**全局唯一命名空间**，kebab-case 命名（如 `calendar`、`org-group`） |
| 模块组 ≠ 模块目录 | 一个模块目录可声明多个模块组（如 `sys/org` 可拆 `org-group`）；一个模块组也可覆盖跨模块的业务域（如 `third-party`） |
| 开关归属声明 | Controller 类或方法上的 `@ModuleGroup(moduleGroupKey = "...")`；**方法级覆盖类级** |
| 默认语义 | **无注解 = 不受开关控制（放行）**。这是机制成立的前提：登录、`/init`、`/initID`、`setting/load`、SSE 订阅、swagger 等公共入口均不打注解，天然不受开关影响 |
| 开关与 SYS_ADMIN | 系统管理员**不穿透**模块开关。开关是功能级而非人级门禁，管理员同样被拒，否则无法验证关闭效果；模块管理接口自身不打注解、永远可用 |

**【修订】统一行为语义表**（原方案未定义，全部为新补充）：

| 场景 | 行为 |
| --- | --- |
| 请求命中无注解的 Controller | 放行，进入既有鉴权链路 |
| 已登录 + 命中开启模块组的注解 | 放行，进入既有鉴权链路 |
| 已登录 + 命中关闭模块组的注解 | 返回 `MODULE_DISABLED`（"该模块未开启"），**不进入** Controller 与 resolver |
| 未登录 + 命中关闭模块组的注解 | 放行给后续最终鉴权，返回 `UNAUTHORIZED`。理由：匿名请求无论如何都过不了鉴权，放行可避免向匿名暴露模块开关状态 |
| 注解 key 在 `common_module_group` 中不存在 | 启动期校验告警；运行期按"开启"放行（fail-open），不因误配置扩大故障面 |
| 模块组从 yml 中移除 | 库中记录保留（关闭历史可追溯），不做自动清理 |
| Redis 不可用 | 进程内缓存 + TTL 兜底（见第 9 节），开关功能不受影响 |

## 3. 总体链路

```text
请求
 → CurrentUserFilter（解析 X-Login-Token，注入 CurrentUserHolder）      [既有]
 → ModuleGroupInterceptor.preHandle                                     [新增]
     读 HandlerMethod 上的 @ModuleGroup（方法级 → 类级回退）
     无注解 → 放行；未登录 → 放行；模块组开启 → 放行
     已登录 + 模块组关闭 → 抛 ModuleDisabledException
 → GlobalExceptionHandler → BaseResponse.failure("MODULE_DISABLED", …)  [既有处理器 + 新增分支]
 → Controller authorize(action, documentId)（ACTION_* + resolver）      [既有]
 → 业务逻辑
```

开关判定位于业务鉴权之前：模块未开启时无需再讨论权限，符合「门禁」语义。

## 4. 数据库设计

### 4.1 表结构

**【修订 1】启用位由 `field_status tinyint(1)` 改为 `field_enable BIT(1)`**，遵循全工程启用位惯例（`sys_org_element` 等所有业务表均为 `field_enable BIT(1)` 默认 `b'1'`）。由此切换接口可直接复用全工程 `/enable` + `{ fieldId, fieldEnable }` 请求体约定。

**【修订 2】`field_key` 增加唯一索引**：它是幂等同步键与注解引用键，缺失唯一约束会在重复/并发同步时插入重复行（先例：`common_setting` 的 `uk_setting_type_key`）。

**【修订 3】公共字段裁剪显式声明**：与 `common_setting` 同为配置型表，只维护「元信息 + 启用状态 + 更新时间」，无创建人/创建时间/更新人（`common_setting` 建表脚本已在注释中声明同样理由，本表照此补充声明）。

迁移脚本：`backend/src/main/resources/db/migration/V1_01_043__common_module_group_schema.sql`（当前最新为 `V1_01_042`，序号接续递增）：

```sql
-- =====================================================================
-- V1_01_043: 模块组状态表（接口开关机制）
-- 依据: docs/v1_1-common/05-增加接口开关/接口开关机制设计方案-修订稿.md
-- 模型: common_module_group 模块组开关状态（模块组级接口启停）
-- 关联: field_key 全局唯一，系统启动时按各模块 moduleGroup.yml 的
--       module-group 段增量维护，不做物理外键。
-- 约束: 开关表只维护「模块组元信息 + 启用状态 + 更新时间」，无创建人/创建时间；
--       field_enable 遵循全工程 BIT(1) 启用位惯例。
-- =====================================================================

CREATE TABLE IF NOT EXISTS common_module_group (
    field_id          VARCHAR(32)  NOT NULL COMMENT '主键ID',
    field_key         VARCHAR(200) NOT NULL COMMENT '模块组标识（kebab-case，全局唯一）',
    field_name        VARCHAR(200) NOT NULL COMMENT '模块组名称',
    field_enable      BIT(1)       NOT NULL DEFAULT b'1' COMMENT '模块组状态 0 关闭 1 开启',
    field_remark      VARCHAR(200) NULL COMMENT '模块组描述',
    field_update_time TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (field_id),
    UNIQUE KEY uk_module_key (field_key)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='模块组状态表';
```

### 4.2 实体与落点

- 实体 `CommonModule extends BaseModel`（`fieldId` 之外新增 `fieldKey / fieldName / fieldEnable(Boolean) / fieldRemark / fieldUpdateTime`），命名遵循 `common/setting` 模块先例（`CommonSetting`）。
- 新增 common 层子包 `com.eric.base.common.module`：`annotation / controller / dao / mapper / model / properties / resolver / service / interceptor`（与 `common/setting` 同级同构）。

## 5. 模块组数据来源（moduleGroup.yml）

### 5.1 文件与结构

各模块在 `resources/properties/{common|sys}/{模块}/moduleGroup.yml` 中声明本模块的模块组（由启动期统一扫描，不在 Spring 配置体系内）：

```yaml
module-group:
  calendar:
    name: 日程
    remark: 日程模块
  org-group:
    name: 组织架构-群组
    remark: 组织架构-群组模块
  third-party:
    name: 第三方
    remark: 第三方账号接入模块
  # ... ...
```

**【修订 4】命名与粒度规范**（原方案示例中 `orgGroup` 驼峰与 `third-party` kebab-case 混用）：

1. key 统一 **kebab-case**（`orgGroup` → `org-group`）；key 即注解值与前端常量，禁止大小写混用；
2. key **全局唯一**、一经发布**不复用/不重命名**（重命名视为新模块组，旧组按"yml 移除"保留在库）；
3. `name` 为页面展示中文名，`remark` 为卡片描述，两者必填（缺失时同步任务告警并跳过该条目）。

### 5.2 纳入原则与首批清单

**【修订】纳入原则**：面向最终用户的功能模块才可纳入开关范围；登录认证、组织架构主干、权限、字典、日志、公共配置、定时任务、i18n 等基础设施与系统管理类模块**不纳入**（关闭它们会破坏系统自举能力）。

首批模块组：

| 模块组 key | 名称 | 覆盖范围（Controller） | 说明 |
| --- | --- | --- | --- |
| `calendar` | 日程 | `SysCalendarMainController`（sys/calendar 全部接口） | 现有模块，作为机制验证 |
| `org-group` | 组织架构-群组 | `SysOrgGroupController` | v1.1 群组功能的灰度入口，对应 [01-组织架构改动](../01-组织架构改动/00-改动总览与影响分析.md) |
| `third-party` | 第三方 | （预留，暂无 Controller） | 原方案示例保留为占位，第三方账号接入模块落地时启用 |

其余 Controller 首批不标注；后续追加只需「moduleGroup.yml 加条目 + Controller 加注解」，机制本身无需改动。

## 6. 启动同步（幂等规则）

**【修订 5】补全幂等三边界**（原方案只写"新导入模块默认开启"半句）：

1. **不存在 → 插入**，`field_enable` 默认开启（原方案语义保留）；
2. **已存在 → 只回写元信息**：`name / remark` 变更时更新，`field_enable` **一律不动**——否则管理员关闭后重启即被 yml 重置，机制失效；
3. **yml 中移除 → 库中记录保留**，不删除、不改状态，可人工清理。

实现落点：新增 `CommonModuleService#syncFromYml()`，扫描 `classpath*:properties/**/moduleGroup.yml`（复用 `YmlResourceUtil`，与 `CommonSettingService#syncFromYml`、`SysDictService#syncDictFromYml` 完全同构）；作为**第 10 个启动任务**追加到 `SysStartupTask#run`，不另建 ApplicationRunner：

```java
// 第十个启动任务：扫描 properties/ 下各模块 moduleGroup.yml 的 module-group 段，
// 增量同步模块组到 common_module_group（新导入默认开启，已存在不动开关状态）
syncModulesFromYml();
```

**【修订 6】启动期注解校验**：同步完成后扫描全部 `@ModuleGroup` 注解（经 `RequestMappingHandlerMapping` 取 HandlerMethod，方法级优先），校验 `moduleGroupKey` 在 `common_module_group` 中存在；未知 key 记 **WARN 日志**（不阻断启动），防止注解 key 与 `field_key` 拼写不一致导致开关静默失效。

## 7. @ModuleGroup 注解

```java
@Target({ElementType.TYPE, ElementType.METHOD})
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface ModuleGroup {

    /** 模块组标识，对应 common_module_group.field_key（必填） */
    String moduleGroupKey();
}
```

定义先例：`@SysTask`（sys/task/annotation）。归属 `com.eric.base.common.module.annotation`。

- 支持类级与方法级，**方法级覆盖类级**（原方案未定义优先级，此处为【修订】补充）；
- 只标注在 Controller 上（语义是"这组接口受某模块组开关控制"）；
- 模块管理 Controller（`CommonModuleController`）自身**不打注解**，保证关闭任意模块组后管理面仍可用。

## 8. 模块开关拦截器

### 8.1 注册与范围

**【修订】原方案只说"在 SpringMVC 拦截器中拦截"，仓库当前没有任何 `HandlerInterceptor`**（`SpaWebConfig` 仅做 SPA 静态资源回退），需新增：

- `com.eric.base.common.module.interceptor.ModuleGroupInterceptor`：判定逻辑本体；
- `com.eric.base.common.config.ModuleGroupWebConfig implements WebMvcConfigurer`：注册拦截器（Web 配置集中在 config 包，与 `SecurityConfig` / `SpaWebConfig` 同层），`addPathPatterns("/backend/**")`（与 `project.request.prefix=/backend` 默认值一致，见 `application.properties`）。

拦截器只对 `HandlerMethod` 生效（静态资源、swagger、前端路由回退均非 HandlerMethod，天然不拦）。

### 8.2 判定流程

```java
public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
    if (!(handler instanceof HandlerMethod handlerMethod)) {
        return true;                                   // 非 Controller 请求不拦
    }
    ModuleGroup moduleGroup = AnnotatedElementUtils.findMergedAnnotation(
            handlerMethod.getMethod(), ModuleGroup.class);
    if (null == moduleGroup) {
        moduleGroup = AnnotatedElementUtils.findMergedAnnotation(
                handlerMethod.getBeanType(), ModuleGroup.class);   // 方法级 → 类级回退
    }
    if (null == moduleGroup) {
        return true;                                   // 无注解 = 不受开关控制
    }
    if (null == UserUtil.getCurrentUser()) {
        return true;                                   // 未登录放行给最终鉴权（见第 2 节语义表）
    }
    if (moduleGroupCacheService.isEnabled(moduleGroup.moduleGroupKey())) {
        return true;
    }
    throw new ModuleDisabledException(moduleGroup.moduleGroupKey());
}
```

### 8.3 响应与错误码

**【修订】原方案只说"返回接口未开启错误"，未定义结构**：

- 新增 `com.eric.base.common.exception.ModuleDisabledException extends RuntimeException`；
- `GlobalExceptionHandler` 新增对应 `@ExceptionHandler`，返回 `BaseResponse.failure("MODULE_DISABLED", "该模块未开启，请联系管理员")`（`preHandle` 抛出的异常同样会进入 `@RestControllerAdvice`，与 `AuthorizationException` 处理方式一致）；
- HTTP 状态仍为 200 + code 体系（全工程惯例）；
- `BaseResponse` 的 code `@Schema` 描述同步追加 `MODULE_DISABLED` 错误码（公共模型变更属 AGENTS 强制同步项）；
- 前端 axios 拦截器（`api/index.js`）按需识别该码做统一提示。

## 9. 状态缓存与多实例一致性

**【修订】原方案完全未提状态读取方式——每请求实时查库不可行，多实例一致性必须显式设计。**

新增 `ModuleGroupCacheService`（`com.eric.base.common.module`），设计对齐仓库既有取舍：`ModelCacheService` 注释明确"部署环境默认无 Redis"，故**进程内缓存为主、Redis 广播为可选增强**：

| 场景 | 行为 |
| --- | --- |
| 启动 | 同步任务完成后全量预热缓存 |
| 请求判定 | 读进程内不可变 Map（volatile）；缓存超过 TTL（默认 30 秒）时回源 DB 刷新（表量极小，全量查询代价可忽略） |
| 切换成功 | 更新 DB → 本实例立即刷新缓存 → 尝试 Redis pub/sub 广播失效通知其他实例（best-effort） |
| Redis 不可用 / 广播失败 | 仅记日志，依赖 TTL 收敛，全实例最迟 30 秒一致 |
| DB 异常且无可用缓存 | **放行并告警**（fail-open）：开关属增强管控，不应在 DB 故障时放大为全站拒绝 |
| DB 异常但有缓存 | 沿用上次缓存值并告警 |

> TTL 数值（30s）为默认建议值，常量定义于 `CommonModuleProperties`，联调期可调整。

## 10. 模块维护接口与权限

### 10.1 权限码与 ACTION 常量

**【修订】原方案只说"增加权限：模块组管理员"，未定码名与归属。**

- 权限码：`SYS_MODULE_ADMIN`（沿用 `SYS_*` 命名惯例），定义于 `properties/common/roles.yml`（表属 common 层），**库与 yml 两处同批提交**，经既有 `SysOrgAuthService#syncAuthsFromRolesYml` 增量同步：

```yaml
ROLE_LIST: ["SYS_ADMIN", "SYS_MODULE_ADMIN"]
ROLE_MAP:
  SYS_ADMIN:
    NAME: "系统管理员"
    DESC: "系统管理员"
  SYS_MODULE_ADMIN:
    NAME: "模块组管理员"
    DESC: "维护模块组开关状态（系统管理-模块管理）"
```

- ACTION 常量定义于 `CommonModuleProperties`（静态引用，禁止手写字符串）：

```java
public static final String ACTION_LIST   = "common.module.list";
public static final String ACTION_ENABLE = "common.module.enable";
```

### 10.2 接口清单

**【修订】原方案未定义路径与方法，按接口规范补全**；新增 `CommonModuleController`，路径 `${project.request.prefix}/common/module`，Controller 只做接收/校验/返回并调用 `authorize(...)`，鉴权经新增 `ModuleResolver`：

| 接口 | 方法 | 鉴权动作 | resolver 分支 | 说明 |
| --- | --- | --- | --- | --- |
| `/backend/common/module/list` | POST | `common.module.list` | `isEnabled(user)`：**登录即可访问**，无角色要求 | 【修订】原方案"列表不设权"含糊；模块组列表暴露系统拓扑，定为登录即可、免登录不可访问 |
| `/backend/common/module/enable` | PATCH | `common.module.enable` | `hasAnyRole(user, SYS_MODULE_ADMIN)`（`SYS_ADMIN` 经 `BaseResolver` 自动放行，分支内不重复列举） | 请求体 `{ fieldId, fieldEnable }`，与全工程 `/enable` 约定一致 |

- `list` 遵循 list 通道（请求体 `{ body, pages }`），模块组量小，默认 `needPage=false` 全量返回，`metadata` 不强制携带 total；
- `enable` 成功后执行第 9 节的缓存刷新与广播；
- **操作日志**：【修订】切换属低频敏感操作，Service 层经既有 `LogService`（`@OperationLog` 注解或 `record(LogRecord)`）记录，`action` 用 `common.module.enable`，日志失败不影响主流程。

### 10.3 文档同步（强制）

新增/修改接口同批更新：类级 `@Tag(name="模块管理", ...)`；方法级 `@Operation(summary=中文动作名, description="鉴权动作 <ACTION 常量值>；…")`；`list` 分支 description 写明"登录即可"；`enable` 的请求体字段补 `@Schema(description=…)`。校验方式：`cd backend && ./mvnw -Dtest=ApiDocsTest test`。

### 11.2 运行期感知（原方案缺失，【修订】新增）

**原方案只设计了管理面，未设计用户侧降级**：模块关闭后用户访问对应页面只会收到一批 `MODULE_DISABLED` 报错。补全为两级感知：

1. **状态拉取**：新增 Pinia store `stores/module.js`，登录后（应用初始化）调 `listModules()` 缓存模块组状态；
2. **菜单过滤**：`HomeView.vue` 菜单配置项增加可选 `moduleGroup` 键（首批映射：`/calendar → calendar`、`/org/group → org-group`），菜单按「权限 auth + 模块可用性」双重过滤，已关闭模块的菜单项**隐藏**；
3. **页面空态**：路由守卫检测目标页面所属模块组已关闭时，渲染「模块未开启」空态提示（不重定向首页，避免与无权限重定向语义混淆）；store 数据缺失时按开启放行（fail-open）。

## 13. 待确认事项

以下为默认决策已写入正文、但可在评审时推翻的点：

1. **TTL 取值**：默认 30 秒，多实例收敛上限即该值；
2. **匿名请求策略**：默认放行给最终鉴权（返回 `UNAUTHORIZED`）；若希望统一拒绝可改为直接返回 `MODULE_DISABLED`；
3. **yml 移除的模块组**：默认库中保留不做"已下线"标记；若管理页需要区分下线态，后续加 `field_status` 类标记迭代；
4. **菜单挂载位置**：默认【系统管理 → 后台管理】子组（与「公共配置」并列）；若希望独立一级子组可调整；
5. **首批纳入范围**：默认仅 `calendar`、`org-group` 两个模块组（`third-party` 占位），其余模块按业务需要追加。
