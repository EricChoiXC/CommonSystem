### 1.2 当前版本范围

- 版本目标：新增「模块组」级接口开关机制——管理员不改代码、不重启即可整体启停一组接口，并提供管理面与用户侧降级表现。
- **In Scope**
  - 一张表（`common_module_group`），迁移脚本 `V1_01_043__common_module_group_schema.sql`。
  - 各模块 `moduleGroup.yml` 数据来源与启动同步（第 10 个启动任务：幂等三边界 + 注解 key 校验 + 缓存预热）。
  - `@ModuleGroup` 注解（类级 / 方法级，方法级覆盖类级）、`ModuleGroupInterceptor` + `ModuleGroupWebConfig`（`/backend/**`）、`ModuleDisabledException` → `MODULE_DISABLED` 错误码。
  - `ModuleGroupCacheService`（进程内 TTL 缓存为主，Redis pub/sub 广播为可选增强，DB 故障 fail-open）。
  - 模块维护接口 2 个：`POST /backend/common/module/list`（登录即可）、`PATCH /backend/common/module/enable`（`SYS_MODULE_ADMIN`）；权限码 `SYS_MODULE_ADMIN`（`properties/common/roles.yml`）。
  - 首批标注：`SysCalendarMainController`（类级 `calendar`）、`SysOrgGroupController`（类级 `org-group`）；首批 `moduleGroup.yml` 仅 calendar、org 两个模块创建。
  - 前端：`stores/module.js` 状态 store、`ModuleManageView.vue`（`/module` 四分栏卡片页）、菜单 `moduleGroup` 过滤、路由守卫「模块未开启」空态、axios `MODULE_DISABLED` 统一提示。
- **Out of Scope**
  - 方法级 / 接口级精细灰度（粒度固定为模块组，修订稿第 1 节非目标）。
  - 定时自动启停、生效时间段等高级能力（后续迭代再议）。
  - 替代权限体系（开关是功能门禁，与 `ACTION_* + resolver` 鉴权正交）。
  - `third-party` 模块组落地（仅设计占位，第三方账号接入模块落地时再建 yml 与标注）。
  - ERP 侧改动（本仓库不含 ERP 模块）。
- **影响范围**

| 迁移脚本 | `backend/src/main/resources/db/migration/V1_01_043__common_module_group_schema.sql` |

### 1.3 任务拆解规则

- 按功能切片组织：`MOD0` 基线与文档、`MOD1` 数据与契约、`MOD2` 核心机制（注解/错误链路 → 缓存 → 启动同步 → 拦截器）、`MOD3` 管理面与首批落地（BE→FE）、`MOD4` 联调验收。

### 5.6 MOD2-BE-002 `ModuleGroupCacheService`（TTL 缓存 + 广播 + fail-open）

- 产出物：
  - 进程内不可变 Map（volatile 引用整体替换），TTL（默认 30s，取 `CommonModuleProperties`）超时回源 DB 全量刷新（表量极小，全量查询代价可忽略）
  - 切换成功路径：更新 DB → 本实例立即刷新 → 尝试 Redis pub/sub 广播失效通知其他实例（best-effort，失败仅记日志依赖 TTL 收敛）

  - 供启动同步（全量预热）与管理面（切换后刷新）调用的入口方法
- 验收标准：无 Redis 环境开关判定可用；并发读安全；fail-open 分支有单测

### 8.2 风险
