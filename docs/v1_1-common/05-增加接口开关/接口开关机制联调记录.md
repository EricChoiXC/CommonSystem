## 十二、结论

**MOD4-INT-001 联调验收通过：后端 HTTP 验证（A/B/C/D/E/F 六组共 24 项）与浏览器全链路走查（G1–G6）全部 PASS，未发现缺陷或与设计不符点。**

- 鉴权矩阵：list 登录即可、enable 仅 SYS_MODULE_ADMIN / SYS_ADMIN，FORBIDDEN 文案与 code 正确；
- 开关全链路：拦截发生在业务鉴权之前，三身份（含 SYS_ADMIN）关闭期间一律 `MODULE_DISABLED`（HTTP 200 + 统一响应体），恢复即生效；管理面自身不受开关控制；
- 浏览器全链路：关闭 calendar → 菜单隐藏 + 直访空态（不重定向）→ 管理页恢复开启 → 菜单与页面全部恢复，与需求分册行为语义表逐条一致；
- 匿名策略（D2）：匿名一律 `UNAUTHORIZED`，开关状态不向未登录请求暴露；
- 公共入口零影响：init / initID / login / setting/load / SSE / swagger / api-docs / 无注解 Controller 全部正常；
- 无 Redis（D1）：启动期订阅禁用、运行期广播失败均仅 WARN 依赖 TTL 收敛，切换即时生效、主流程零阻断；
- 操作日志：enable 成功逐次落 `sys_log_operation`，before/after、操作人、业务 ID 完整。

与设计的唯一偏差说明：`common.module.enable` 对**同值重复切换**（true→true）也会记一条 SUCCESS 操作日志并执行 Redis 广播，属 `updateEnable` 口径（影响行数=1 即成功）的自然结果，需求分册未禁止，不视为缺陷。

多实例物理双实例测试未执行（本机仅验证单实例 + 无 Redis 场景）：跨实例失效收敛依赖 TTL（D1，默认 30s）与 Redis pub/sub 广播，两者分支均已由单测与日志证据覆盖，多实例部署项留待实际部署环境验证。
