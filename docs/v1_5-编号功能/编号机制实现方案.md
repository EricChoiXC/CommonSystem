# 编号机制实现方案（v1.5）

- 本机制是对需要自动编号的 field_code 字段提供编号规则配置和自取号功能，也可随业务需要应用到其他地方上。
- 模块 key 为 `number`，对齐 `docs/开发规范.md` 模块表「编号规则 number」与 `docs/系统模块/系统模块需求文档.md` 第 4 章；原草案的 `code` 命名已按 §0 裁决统一改为 `number`。
- 与既有规划的关系：本方案将需求文档 4.1 规划的「主表 + 明细表（sys_number_rule / sys_number_rule_detail）」调整为「规则单表 JSON（field_rule）+ 取号计数表 + 取号明细表」，属设计变更，同步修订清单见 §0.2。

说明：

- `sys_number_record`、`sys_number_record_detail` 属流水类表，不设 `field_enable` / `field_update_time` / `field_updater_id`（对齐 `sys_log_operation`、`sys_task_history` 先例）；作废字段的例外更新见 §5.4。
- 同一接入项（编号字段）下允许配置**多条**编号规则，但同一时刻**至多一条处于启用状态**（固定接入据此定位唯一启用规则）；
- 启用某条规则时（含新建默认启用的 save、enable 启用操作），Service 在同一事务内**自动停用同接入项下原已启用的规则**（切换式启用，不报错拒绝），保证「同接入项启用规则唯一」恒成立；
- 切换不清理历史计数：每条规则取号作用域独立（固定接入 = 规则 `field_id`，见 §5.1），旧规则停用时其计数器行原样保留，再次启用可顺延续号。

## 1. 业务实现

### 1.1 接入编号机制

增加公共配置文件 `numberRule.yml`（文件名全局统一，放在各模块 `properties/{common,sys}/{模块}/` 或业务工程对应目录下，`YmlResourceUtil` 通配 `classpath*:properties/**` 已覆盖扫描），将需要自动编号的字段配置为「接入项」，示例：

```yaml
numberRule:
  purchase-order-code:
    name: "采购订单编号"
    modelName: "ErpPurchaseOrder"
    modelField: "fieldCode"
  process-example-code:
    name: "流程示例编号"
    modelName: "SysProcessExample"
    modelField: "fieldCode"
```

- `modelName` 为业务模型 Java 类 SimpleName，`modelField` 为承接编号的字段名（通常 `fieldCode`）。
- 启动期初始化统一追加到 `sys/task/SysStartupTask#run`：解析全部 `numberRule.yml` 合并为接入项缓存（不另建 ApplicationRunner）；并校验 `sys_number_rule` 中 `field_model_id` 是否仍存在于缓存，失效则输出告警日志。
- 编号规则编辑页的「所属接入项」下拉数据源即该缓存；选定接入项后自动带出 `field_model_name` / `field_model_field`。

### 1.2 配置编号规则

在 【后台管理】 菜单栏中，增加 【编号机制】；
增加 【后台管理】-【编号机制】-【编号管理】 菜单项，访问 `sys_number_rule` 列表页面（路由与菜单见 §7.1），点击【新增】按钮，填写编号规则信息，并保存。

#### sys_number_rule 列表页面

对齐 `list-page.css` 三段式规范：

- 筛选区：关键字（规则编码/名称模糊）、所属模型字段、启用状态，`el-form.filter-form` + `el-col :span="6"`；输入框回车触发查询，启用状态默认「全部」。
- 排序（`sort-area` 单条件）：创建时间、更新时间，默认创建时间降序。
- 显示列（无批量操作，不加复选框，不展示主键）：规则编码、规则名称、所属模型、所属模型字段、是否启用（tag）、创建时间、更新时间；末列操作列 `fixed="right"`：编辑、启停用（二次确认，启用时提示将自动停用同接入项其他已启用规则）、删除（二次确认；已产生取号明细的规则拒绝删除，仅可停用）、预览测试（打开弹窗）。
- 分页：`layout="total, prev, pager, next, sizes"`，`page-sizes [10,20,50,100]`，切页大小回第 1 页。

#### sys_number_rule 编辑页面

新建路由 `/number/create`、编辑路由 `/number/edit/:id`，共用表单组件；操作按钮放 `el-card` `#header` 内 `.page-header > .header-btns`；布局一行两字段（`label-width="40%"` + `:span="12"`）：

```text
|--------------------------------------------------------------|
| 所属接入项(下拉，编辑态只读锁定) | 规则编码(保存后仍可改，Service 查重) |
| 规则名称                        | 是否启用(不在表单内，启停走 enable 接口) |
|--------------------------------------------------------------|
| ${编号规则组件 NumberRuleComposer, fieldName="fieldRule"}      |
|--------------------------------------------------------------|
```

- 「所属接入项」保存后锁定不可改（改动会使既有计数器作用域悬空）；`field_model_id` / `field_model_name` / `field_model_field` 三个字段由下拉选择带出。
- 新建时在 `onMounted` 调 `getInitID()` 取 32 位 ID 赋 `fieldId`；编辑按路由 id 调 `load` 回填（`field_rule` 由后端解析为 JSON 对象返回）。

#### 编号规则组件（NumberRuleComposer）

- **受控复用组件**：props `{ value: SysNumberRuleConfigDo, onChange, fieldName, disabled? }`；
    - `fieldName` 声明其在宿主表单中的字段名（编号规则编辑页为 `fieldName="fieldRule"`），经 Form.Item 绑定；
    - value 协议 = §2.1 的 JSON 对象（前端内存对象随表单提交，由后端统一序列化存储，保证 schema 单一来源）；
- 布局（三区）：
    - 上：可插入项按钮——文本、流水号、日期时间、随机数；
    - 中：已插入项列表，支持排序与删除；提供**左移/右移按钮**保证可用性，拖拽排序作为增强；
    - 下：选中项属性面板（公共：名称；隐藏：id；各类型属性见 §2.2；`numericOnly=false` 时 min/max 置灰）；
- **实时预览**：属性变更防抖调用 `POST /backend/sys/number/preview/render` 展示 3 个样例号；校验失败（C1~C5）就地红字提示；该接口无副作用、登录即可（§4.3），供「分类编辑页」等无编号权限的宿主复用。
- **seq 项 id 锁定**：已保存规则再次编辑时，seq 项的 `item.id` 不可变更（前端隐藏重生成入口；后端校验，见 §3.2 save/update 约束）。
- 组件契约随实现同步 `docs/系统模块/前端公共组件.md`。

### 1.3 非固定方式接入编号规则

- 如【分类 + 单据】 的业务场景，如 【合同分类 - 合同】 下要求不同合同分类的编号规则也不同的场景；
- 分类表添加字段 `field_code_rule`（JSON，结构与 §2.1 一致）；
- 将 NumberRuleComposer 接入分类编辑页面，配置 `fieldName = "fieldCodeRule"`；分类保存时由分类模块后端调用 `SysNumberRuleService#validateConfig` 完成 C1~C5 校验；
- 编号规则保存为 field_model_id=${合同分类id}, field_model_name=${合同分类Model}, field_model_field=${合同的编号字段}
- 单据取号时，业务后端从分类记录读出规则 JSON，调 `SysNumberGenerateService#acquireByConfig(config, scopeKey, modelName, modelId)` 取号；作用域键为 `{modelName}:{分类记录ID}`（§5.1），此时 `sys_number_record.field_rule_id` 为空、`sys_number_record_detail` 照常落明细。

## 2. 规则模型（field_rule JSON）

### 2.1 结构

```json
{
  "items": [
    { "id": "ci-a1b2c3d4e5f6", "type": "text",     "name": "前缀",   "text": "CG" },
    { "id": "ci-b2c3d4e5f6a1", "type": "datetime", "name": "日期",   "format": "yyyyMMdd" },
    { "id": "ci-c3d4e5f6a1b2", "type": "seq",      "name": "流水号", "start": 1, "length": 3, "padZero": true, "resetPeriod": "DAY" },
    { "id": "ci-d4e5f6a1b2c3", "type": "random",   "name": "随机码", "min": 0, "max": 9999, "length": 4, "padZero": true, "numericOnly": true }
  ]
}
```

- `items` **有序**，渲染即按数组顺序拼接；
- `item.id` 由前端新增项时生成，也是流水行 `sys_number_record.field_serial_id` 的取值来源；
- `item.id` 一经保存即为计数器锚点，**编辑规则时 seq 项 id 必须保留原值**（§1.2）。

### 2.2 规则项字段定义

公共属性：`name`（展示名）；隐藏属性：`id`。

| type | 专属属性 | 约束 |
| --- | --- | --- |
| text 文本 | `text` 常量内容 | 非空，1..32 字符 |
| datetime 日期时间 | `format` | 白名单 + 受限自定义（见下）；渲染取**取号时刻**（服务器时区） |
| seq 流水号 | `start` 起始值 / `length` 长度 / `padZero` 补"0" / `resetPeriod` 重置周期 | `start ≥ 0`；`length` 1..9；`resetPeriod ∈ DAY/WEEK/MONTH/YEAR/NONE` |
| random 随机数 | `min` / `max` / `length` / `padZero` / `numericOnly` | `numericOnly=true` 时 `min/max/length` 生效（`min ≤ max`）；`false` 时仅 `length` 生效，字符集 `A-Za-z0-9`，`min/max` 置灰 |

日期格式白名单：`yyyy-MM-dd`、`yyyyMMdd`、`MMdd`、`HHmmss`、`yyyyMMddHHmmss`、`yyyy-MM-dd HH:mm:ss`；自定义 pattern 仅允许 `y M d H m s` 与分隔符 `- / : 空格` 组合（排除歧义字符）。

### 2.3 配置校验规则（保存/启用前强制校验）

| # | 规则 | 违反处理 |
| --- | --- | --- |
| C1 | 流水号（seq）项必须**恰好一个**——它是唯一性锚点，`field_serial_id` 据此定位 | `CRM_NUMBER_RULE_INVALID` |
| C2 | 随机数项**不作为唯一性来源**：每次取号重新生成，不参与计数；唯一性由 seq 保证（C1） | —— |
| C3 | 日期项渲染必须能区分相邻重置周期（联动表见下），否则跨周期重号 | `CRM_NUMBER_RULE_INVALID` |
| C4 | **无日期项**时 `resetPeriod` 必须为 NONE（seq 不重置） | `CRM_NUMBER_RULE_INVALID` |
| C5 | 拼接最大长度 ≤ 64（对齐业务单号列宽 `varchar(64)`）；按「文本 + 日期最大宽 + seq 容量（10^length−1）+ random 宽」估算 | `CRM_NUMBER_RULE_INVALID` |
| C6 | seq 超出 length 容量（如 length=3 且 seq>999）：**取号失败**（对齐需求文档 4.3「流水号已用尽则业务保存/提交失败」；不截断续发，避免超出 C5 的 64 位估算） | `CRM_NUMBER_SERIAL_EXHAUSTED` |
| C7 | 已保存规则的 seq 项 `item.id` 不得变更（变更即换计数器，造成重号/断号） | `CRM_NUMBER_RULE_INVALID` |

C3 联动表（seq 重置周期 ↔ 日期格式要求）：

| seq.resetPeriod | 日期项 format 必须包含 | 反例 |
| --- | --- | --- |
| DAY / WEEK | `y`、`M`、`d` | `MMdd`（缺年，跨年重号）、`HHmmss`（无日期） |
| MONTH | `y`、`M` | `dd`（无月份） |
| YEAR | `y` | —— |
| NONE | 无要求 | —— |
| （无日期项） | resetPeriod 必须为 NONE（C4） | seq 按天重置且单号无日期 → 次日重复 |

WEEK 按 ISO-8601 周年编号（含第一个周四的周为第 1 周），避免跨年周归属歧义。

## 3. 接口设计

路径遵循 `/backend/sys/{模块}/{次级模块}/{方法}`，次级模块沿用 `docs/系统模块/系统模块API接口设计文档.md` 4.4.2 分组（rule / preview / generate / manage）。列表请求体 `{ body, pages: { pageNo, pageSize, needPage } }`，总数经 `metadata.total` 返回；响应统一 `BaseResponse`。

### 3.1 接口总表

| 接口 | 方法 | 鉴权动作（ACTION_*） | 权限 | 说明 |
| --- | --- | --- | --- | --- |
| `/backend/sys/number/rule/list` | POST | `sys.number.rule.list` | 登录即可 | 规则列表（需求 4.2.2「查询不设权」） |
| `/backend/sys/number/rule/load?fieldId=` | GET | `sys.number.rule.load` | ADMIN or EDITOR | 完整信息读取，`field_rule` 解析为对象返回 |
| `/backend/sys/number/rule/save` | POST | `sys.number.rule.save` | ADMIN or EDITOR | 新建保存（默认启用），C1~C5 校验 + 自动停用同接入项原已启用规则（切换启用） |
| `/backend/sys/number/rule/update` | PATCH | `sys.number.rule.update` | ADMIN or EDITOR | 编辑，另校验 C7（seq 项 id 锁定） |
| `/backend/sys/number/rule/enable` | PATCH | `sys.number.rule.enable` | ADMIN or EDITOR | 启停用，请求体 `{ fieldId, fieldEnable }`，启用时校验 C1~C5，并自动停用同接入项下其他已启用规则（切换启用） |
| `/backend/sys/number/rule/delete?fieldId=` | DELETE | `sys.number.rule.delete` | ADMIN or EDITOR | 存在取号明细时拒绝（`CRM_NUMBER_RULE_IN_USE`） |
| `/backend/sys/number/preview/render` | POST | `sys.number.preview.render` | 登录即可 | 预览渲染，**不推进计数器、不落任何记录**；已保存规则与未保存 JSON 均可渲染 |
| `/backend/sys/number/generate/acquire` | POST | `sys.number.generate.acquire` | 登录即可（业务模块自行完成单据鉴权） | 正式取号；同进程业务后端建议直接注入 `SysNumberGenerateService`，本接口保留给跨服务与调试场景 |
| `/backend/sys/number/manage/recordList` | POST | `sys.number.manage.recordList` | 仅 ADMIN | 取号明细查询（按规则/作用域/周期/时间段筛选） |
| `/backend/sys/number/manage/reset` | POST | `sys.number.manage.reset` | 仅 ADMIN | 重置计数器（封存当前行，新行从 start 起），二次确认 |
| `/backend/sys/number/manage/void` | PATCH | `sys.number.manage.void` | 仅 ADMIN | 作废明细，请求体 `{ fieldId, fieldVoidReason }`，不回退计数器 |
| `/backend/sys/number/manage/reissue` | POST | `sys.number.manage.reissue` | 仅 ADMIN | 补号：对已作废明细对应单据按计数器顺延重新取号 |

### 3.2 接口契约明细

**rule/list** — 请求 `{ body: { fieldName?, fieldCode?, fieldModelField?, fieldEnable? }, pages }`；响应 `List<SysNumberRule>`（`field_rule` 原文返回，列表页不解析）。

**rule/load** — 请求 `?fieldId=`；响应 `SysNumberRule`，`field_rule` 解析为 `SysNumberRuleConfigDo` 对象返回（前端 NumberRuleComposer 直接消费）。

**rule/save、rule/update** — 请求体 `SysNumberRule`（含 `fieldRule` 对象）；服务端执行：

1. C1~C5 全量校验（update 另加 C7）；
2. save 校验规则编码查重（对齐 i18n 语言码 Service 层校验先例）；
3. save（新建默认启用）与 enable 启用时，同一事务内自动停用同接入项下原已启用的其他规则（切换启用），保证「同接入项启用规则唯一」，不再以启用冲突报错；
4. `field_model_id` 必须存在于接入项缓存，否则 `CRM_NUMBER_RULE_MODEL_NOT_FOUND`。

**preview/render** — 请求 `{ fieldId?, rule?, count? }`（已保存规则传 `fieldId`；未保存 JSON 传 `rule`，二选一；`count` 默认 3、上限 10）；响应 `{ samples: ["CG20261112-001", "CG20261112-002", "CG20261112-003"], errors: [{ code, itemId, message }] }`。渲染基于当前计数器**顺延模拟**，绝不写库；当前周期已取到 998 时，样例含越界提示（C6 语义）。

**generate/acquire** — 请求 `{ modelName, modelField, modelId }`；响应 `{ code, recordDetailId, reused }`（`reused=true` 表示幂等命中已有编号）。取号流程与失败语义见 §5。

**manage/recordList** — 请求 `{ body: { fieldScopeKey?, fieldRuleId?, fieldPeriod?, voidFlag?, recordTimeBegin?, recordTimeEnd? }, pages }`；响应 `List<SysNumberRecordDetail>`。

**manage/void** — 请求体 `{ fieldId, fieldVoidReason }`；已作废明细重复作废返回原状态（幂等）。

**manage/reissue** — 请求体 `{ fieldId }`（原明细 ID，须已作废）；为原 `field_model_id` 顺延取新号，返回同 generate。原单据须由业务模块在调用前自行校验归属。

### 4.3 鉴权口径说明（含需求偏差）

- **编号规则查询（list）不设权**、**预览（render）登录即可**：render 无副作用、不落库，属纯渲染；后者与需求 4.2.2「编号预览、编号测试：编号管理员 OR 编号规则维护者」存在偏差——原因是 NumberRuleComposer 会被「分类编辑页」等宿主复用，宿主操作者（如合同分类维护者）通常无编号权限，若按需求设权将导致宿主表单内实时预览 403。已在 §0.2 列入需求文档修订清单：预览不落库故放权，「编号测试」能力由预览接口顺延模拟承担，正式流水不受影响。
- **编号生成不单独设权**（需求 4.2.2）：generate 只校验登录，业务单据权限由调用方在取号前完成；`generate/acquire` 的 `AuthorizationContext` 不携带业务单据语义，禁止用本接口替代业务鉴权。
- **特权操作仅 ADMIN**：重置会造成计数器回退风险，作废/补号改变编号可用性，均收敛到编号管理员，操作落操作日志（需求 4.3 审计联动）。

## 5. 取号流程与并发设计

### 5.1 作用域键与周期键

- 作用域键 `field_scope_key`：固定接入 = 规则 `field_id`；非固定接入 = `{modelName}:{宿主记录ID}`（如 `ErpContract:CATEGORY-xxx`）。同一作用域内流水连续，跨作用域互不干扰。
- 周期键 `field_period` 由 seq 项 `resetPeriod` 派生，取号时刻计算：

| resetPeriod | field_period 格式 | 示例 |
| --- | --- | --- |
| NONE | `ALL` | ALL |
| DAY | `yyyyMMdd` | 20261112 |
| WEEK | ISO-8601 周年 `yyyy'W'ww` | 2026W46 |
| MONTH | `yyyyMM` | 202611 |
| YEAR | `yyyy` | 2026 |

### 5.2 计数器原子推进

- 取号在同一业务事务内执行：`INSERT ... ON DUPLICATE KEY UPDATE field_serial_no = LAST_INSERT_ID(field_serial_no + 1)` 原子自增并取回新值（首号按 `start` 初始化），杜绝 `SELECT` 后 `UPDATE` 的竞态；
- 新增 `sys_number_record_detail` 明细行（uk 兜底唯一）；计数器更新与明细落库、业务单据保存同事务，业务回滚则取号一并回滚，不产生跳号；
- 并发下同一计数器行由行锁串行，取号事务保持短小（仅计数器 UPDATE + 明细 INSERT，不夹杂长耗时业务逻辑）；
- 周期切换：当前周期键 ≠ 计数器行周期键时，旧行置 `field_record_finish_time` 封存，插入新周期行从 `start` 起。

### 5.3 幂等与失败语义（对齐 API 文档 4.4.3 冻结方向）

- **幂等**：取号前按 `(field_scope_key, field_model_id)` 查明细，存在未作废明细则直接返回原编号（`reused=true`），重复提交不推进计数器；
- **失败**（业务保存/提交随取号一并失败，返回明确错误信息）：规则不存在 `CRM_NUMBER_RULE_NOT_FOUND`；同接入项无启用规则 `CRM_NUMBER_RULE_DISABLED`（启用唯一性由 save / enable 切换机制保证，取号侧不会命中多条）；流水用尽 `CRM_NUMBER_SERIAL_EXHAUSTED`；规则配置非法 `CRM_NUMBER_RULE_INVALID`；
- 未匹配到规则时**不得回退前端本地生成**（需求 4.3）。

### 5.4 重置、补号、作废语义

| 动作 | 语义 | 计数器 |
| --- | --- | --- |
| 重置 reset | 将作用域（可限定流水项/周期）当前计数器行封存（置 `field_record_finish_time`），下次取号按 `start` 重开 | 封存后回退，**会造成重号**，二次确认 + 操作日志，仅限管理员 |
| 作废 void | 明细置 `field_void_time` / `field_void_reason`，编号不再可用；属流水表「只增不改」的唯一例外更新（仅 void 字段，不改业务字段） | 不回退，避免重号 |
| 补号 reissue | 对已作废明细对应的单据按计数器顺延重新取号，旧号保留作废记录供审计 | 顺延 |

### 5.5 错误码

| 错误码 | 场景 |
| --- | --- |
| `CRM_NUMBER_RULE_INVALID` | 规则配置非法（C1~C5、C7） |
| `CRM_NUMBER_RULE_NOT_FOUND` | 规则不存在 / 接入项未配置 |
| `CRM_NUMBER_RULE_MODEL_NOT_FOUND` | 接入项编码不在 numberRule.yml 缓存 |
| `CRM_NUMBER_RULE_DISABLED` | 规则未启用 |
| `CRM_NUMBER_RULE_DUPLICATED` | 规则编码重复（启用唯一性已由切换机制保证，不再用于启用冲突） |
| `CRM_NUMBER_RULE_IN_USE` | 已产生取号明细，拒绝删除 |
| `CRM_NUMBER_SERIAL_EXHAUSTED` | 流水超出 length 容量（C6） |
