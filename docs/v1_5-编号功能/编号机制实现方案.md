## 1.业务实现

### 接入编号机制

增加公共配置文件 "codeRule.yml" 文件，将需要配置自发号的字段配置到改文件上，示例：

```yaml
codeRule:
  purchase-order-code:
    name: "采购订单编号"
    modelName: "ErpPurchaseOrder"
    modelField: "fieldCode"
  process-example-code:
    name: "流程示例编号"
    modelName: "SysProcessExample"
    modelField: "fieldCode"
```

### 配置编号规则

在 【后台管理】 菜单栏中，增加 【编号机制】；
增加 【后台管理】-【编号机制】-【编号管理】 菜单项，访问 sys_code_rule 列表页面，点击【新增】按钮，填写编号规则信息，并保存。

#### sys_code_rule 列表页面

筛选区：所属模型字段
排序：创建时间、更新时间
显示列：编号规则名称、所属模型、所属模型字段、是否启用、创建时间、更新时间

#### sys_code_rule 编辑页面

```text
|--------------------------------------------------|
| 所属模块(只读) | 编号规则名称 | 是否启用(启停走接口) |
|--------------------------------------------------|
| ${编号规则组件 CodeRuleComposer}                  |
|--------------------------------------------------|
```

#### 编号规则组件（CodeRuleComposer）

- **受控复用组件**：props `{ value: CodeRuleConfig, onChange, fieldName, disabled? }`；
    - `fieldName` 声明其在宿主表单中的字段名（编号规则编辑页为 `fieldName="fieldRule"`），经 Form.Item 绑定；
    - value 协议 = §2.1 的 JSON 对象（前端内存对象随表单提交，由后端统一序列化存储，保证 schema 单一来源）；
- 布局（三区）：
    - 上：可插入项按钮——文本、流水号、日期时间、随机数；
    - 中：已插入项列表，支持排序与删除；提供**左移/右移按钮**保证可用性，拖拽排序作为增强；
    - 下：选中项属性面板（公共：名称；隐藏：id；各类型属性见 §2.2；`numericOnly=false` 时 min/max 置灰）；
- **实时预览**：属性变更防抖调用 `POST /code-rules/preview` 展示 3 个样例号；校验失败（C1~C5）就地红字提示；

### 非固定方式接入编号规则

- 如【分类 + 单据】 的业务场景，如 【合同分类 - 合同】 下要求不同合同分类的编号规则也不同的场景；
- 分类表添加字段 'fieldCodeRule'；
- 将 CodeRuleComposer 接入分类编辑页面，配置 fieldName = "fieldCodeRule"
- 在单据的业务逻辑中，通过代码去找寻分类的编号规则，并调用 service 获取编号

## 2. 规则模型（code_rule JSON）

### 2.1 结构

```json
{
  "items": [
    { "id": "ci-a1b2c3d4e5f6", "type": "text",     "name": "前缀",   "text": "CG" },
    { "id": "ci-b2c3d4e5f6a1", "type": "datetime", "name": "日期",   "format": "yyyyMMdd" },
    { "id": "ci-c3d4e5f6a1b2", "type": "seq",      "name": "流水号", "start": 1, "length": 3, "padZero": true, "resetPeriod": "DAY" },
    { "id": "ci-d4e5f6a1b2c3", "type": "random",   "name": "随机码", "min": 0, "max": 9999, "length": 4, "padZero": true, "numericOnly": true }
  ]
}
```

- `items` **有序**，渲染即按数组顺序拼接；
- `item.id` 由前端新增项时生成，也是流水行 `sys_code_record.field_serial_id` 的取值来源。

### 2.2 规则项字段定义

公共属性：`name`（展示名）；隐藏属性：`id`。

| type | 专属属性 | 约束 |
| --- | --- | --- |
| text 文本 | `text` 常量内容 | 非空，1..32 字符 |
| datetime 日期时间 | `format` | 白名单 + 受限自定义（见下）；渲染取**取号时刻** |
| seq 流水号 | `start` 起始值 / `length` 长度 / `padZero` 补"0" / `resetPeriod` 重置周期 | `start ≥ 0`；`length` 1..9；`resetPeriod ∈ DAY/WEEK/MONTH/YEAR/NONE` |
| random 随机数 | `min` / `max` / `length` / `padZero` / `numericOnly` | `numericOnly=true` 时 `min/max/length` 生效（`min ≤ max`）；`false` 时仅 `length` 生效，字符集 `A-Za-z0-9`，`min/max` 置灰 |

日期格式白名单：`yyyy-MM-dd`、`yyyyMMdd`、`MMdd`、`HHmmss`、`yyyyMMddHHmmss`、`yyyy-MM-dd HH:mm:ss`；自定义 pattern 仅允许 `y M d H m s` 与分隔符 `- / : 空格` 组合（排除歧义字符）。

### 2.3 配置校验规则（保存/启用前强制校验）

| # | 规则 | 违反处理 |
| --- | --- | --- |
| C1 | 流水号（seq）项必须**恰好一个**——它是唯一性锚点，`rule_detail_id` 据此定位 | `CRM_CODE_RULE_INVALID` |
| C2 | 随机数项**不作为唯一性来源**：仅允许与 seq 共存（C1 已保证）；随机数每次取号重新生成，不参与计数 | —— |
| C3 | 日期项渲染必须能区分相邻重置周期（联动表见下），否则跨周期重号 | `CRM_CODE_RULE_INVALID` |
| C4 | **无日期项**时 `resetPeriod` 必须为 NONE（seq 不重置） | `CRM_CODE_RULE_INVALID` |
| C5 | 拼接最大长度 ≤ 64（对齐业务单号列宽 `varchar(64)`）；按「文本 + 日期最大宽 + seq 容量（10^length−1）+ random 宽」估算 | `CRM_CODE_RULE_INVALID` |
| C6 | seq 超出 length 容量（如 length=3 且 seq>999）：**不截断、按实际位数输出**，并输出告警日志（length 仅约束补零宽度） | 运行期告警 |

C3 联动表（seq 重置周期 ↔ 日期格式要求）：

| seq.resetPeriod | 日期项 format 必须包含 | 反例 |
| --- | --- | --- |
| DAY / WEEK | `y`、`M`、`d` | `MMdd`（缺年，跨年重号）、`HHmmss`（无日期） |
| MONTH | `y`、`M` | `dd`（无月份） |
| YEAR | `y` | —— |
| NONE | 无要求 | —— |
| （无日期项） | resetPeriod 必须为 NONE（C4） | seq 按天重置且单号无日期 → 次日重复 |
